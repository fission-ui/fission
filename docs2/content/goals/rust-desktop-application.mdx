A repair changes hands between technicians. One person records the fault, another replaces the part and someone on the next shift checks the result. If the queue, checklist and notes each describe a different copy of the job, the next action is unclear and an unfinished repair can appear ready.

We'll build Harbour Desk around one work-order record. Shared state holds the records, selection and drafts that must survive selection changes. The creation form owns its unfinished fields locally. Components describe the visible regions, while ordinary Rust state methods define which changes are allowed.

The normal desktop app starts empty and lets you create orders. The embedded Web preview uses four fictional records so each workflow can be tried immediately. Both are in-memory: restarting clears the data, and no button pretends to have written a database or contacted a maintenance service.

cd harbour-service-desk
cargo add serde --features derive

## Put the queue and detail panel over one record

A work order needs a stable ID, reported problem, location, requester and due window. The queue summarises it; the detail panel expands it. Both read the same record rather than keeping editable copies that could disagree.

The first checkpoint is read-only apart from creating an order. The normal app starts empty, so the creation form is part of the workflow, not an exercise left to the reader. It requires five bounded text fields and allocates an ID only after validation. “Requested by” is a reported name, not proof of the operator's identity. “Due today” is an explicit choice; this example does not infer dates from a free-form due window.

A newly created order starts open with two incomplete checks. Those checks are a small teaching workflow, not an equipment-specific safety procedure. A real maintenance system would select a checklist appropriate to the equipment and record the evidence it requires.

The documentation preview adds four fictional repairs from `preview/fixtures.rs`. That fixture is never called by `src/lib.rs`. Each normal entrypoint installs the same translations and screen, so copying the project gives you a usable empty app rather than a preview that cannot be reproduced.

The component boundaries follow the visible regions: a queue card, detail panel, summary metric, workspace sidebar and creation form. Read styling from the active theme and messages from the checked-in English and Spanish bundles. The layout stacks its two panels below the expanded breakpoint; it does not reuse one retained widget in multiple responsive branches.

use crate::models::{InspectionCategory, InspectionStep, WorkOrder, WorkOrderPriority, WorkOrderStatus};
use fission::prelude::*;

#[derive(Clone, Debug, PartialEq)]
pub enum DeskFeedback {
    Info(&'static str),
    Error(&'static str),
}
impl DeskFeedback {
    pub fn key(&self) -> &'static str {
        match self { Self::Info(key) | Self::Error(key) => key }
    }
}

#[derive(Clone, Debug, Default, PartialEq)]
pub struct WorkOrderDraft {
    pub title: String,
    pub description: String,
    pub location: String,
    pub requested_by: String,
    pub due_window: String,
    pub due_today: bool,
}

#[derive(Clone, Debug, Default, PartialEq)]
pub struct ServiceDeskState {
    pub work_orders: Vec<WorkOrder>,
    pub selected_work_order: Option<u32>,
    pub feedback: Option<DeskFeedback>,
}
impl GlobalState for ServiceDeskState {}

impl ServiceDeskState {
    pub fn feedback_key(&self) -> Option<&'static str> {
        self.feedback.as_ref().map(DeskFeedback::key)
    }
    pub fn feedback_is_error(&self) -> bool {
        matches!(self.feedback, Some(DeskFeedback::Error(_)))
    }
    pub fn create_order(&mut self, draft: WorkOrderDraft) -> bool {
        if [&draft.title, &draft.description, &draft.location, &draft.requested_by, &draft.due_window]
            .iter().any(|value| value.trim().is_empty() || value.chars().count() > 240)
            || self.work_orders.len() >= 100
        {
            self.feedback = Some(DeskFeedback::Error("service_desk.create.invalid"));
            return false;
        }
        let Some(id) = self.work_orders.iter().map(|order| order.id).max().unwrap_or(0).checked_add(1) else {
            self.feedback = Some(DeskFeedback::Error("service_desk.create.limit"));
            return false;
        };
        self.work_orders.push(WorkOrder {
            id, reference: format!("WO-{id:04}"),
            title: draft.title.trim().into(), description: draft.description.trim().into(),
            location: draft.location.trim().into(), requested_by: draft.requested_by.trim().into(),
            due_window: draft.due_window.trim().into(), due_today: draft.due_today,
            priority: WorkOrderPriority::Normal, status: WorkOrderStatus::Open,
            steps: vec![
                InspectionStep { id: "inspection".into(), title_key: "service_desk.step.record_inspection".into(), category: InspectionCategory::Inspection, complete: false },
                InspectionStep { id: "verification".into(), title_key: "service_desk.step.record_verification".into(), category: InspectionCategory::Verification, complete: false },
            ],
            shift_notes: Vec::new(),
        });
        self.selected_work_order = Some(id);
        self.feedback = Some(DeskFeedback::Info("service_desk.create.created"));
        true
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    fn draft() -> WorkOrderDraft {
        WorkOrderDraft { title: "Inspect scanner dock".into(), description: "Power disconnects when moved".into(), location: "Receiving".into(), requested_by: "Rosa".into(), due_window: "Before Friday handoff".into(), due_today: false }
    }
    #[test]
    fn creation_uses_distinct_ids_and_starts_with_unfinished_checks() {
        let mut state = ServiceDeskState::default();
        assert!(state.create_order(draft()));
        assert!(state.create_order(draft()));
        assert_ne!(state.work_orders[0].id, state.work_orders[1].id);
        assert_eq!(state.selected_work_order, Some(state.work_orders[1].id));
        assert!(state.work_orders.iter().all(|order| order.status == WorkOrderStatus::Open && order.steps.iter().all(|step| !step.complete)));
    }
    #[test]
    fn a_blank_field_and_exhausted_id_do_not_create_an_order() {
        let mut state = ServiceDeskState::default();
        assert!(!state.create_order(WorkOrderDraft::default()));
        assert!(state.work_orders.is_empty());
        assert!(state.create_order(draft()));
        state.work_orders[0].id = u32::MAX;
        assert!(!state.create_order(draft()));
        assert_eq!(state.work_orders.len(), 1);
    }
}

                column_gap: tokens.spacing.m,
                row_gap: tokens.spacing.s,

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid Harbour Desk translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

## Keep handoff behind the workflow rules

Selecting a card stores its ID. A missing selection shows an empty detail state; it does not silently open the first order and make an unrelated repair look selected.

A checklist change and a status change are different transitions. The row calls `state.toggle_step(...)` inside `reduce`; the detail panel calls `state.advance_order(...)` in the same way. The ordinary Rust methods own the rules. There is no separate action declaration or reducer registration to maintain for these component-specific handlers.

Starting work moves an open order into progress. Finishing it requires a non-empty, completed checklist. Clearing a check after an order was marked ready moves it back into progress, so an earlier decision cannot bypass a later correction. A closed order rejects further checklist or status changes. The state tests exercise those cases without relying on a disabled button.

The UI's progress bar is derived from the actual inspection steps. Unlike a guessed percentage, it describes something the user can inspect: completed steps divided by total steps. It is not evidence that a machine is safe; the operator remains responsible for performing and recording the work.

    pub fn create_order(&mut self, draft: WorkOrderDraft) -> bool {

            ],

        });

        self.feedback = Some(DeskFeedback::Info("service_desk.create.created"));

    }

impl ServiceDeskState {
    pub fn toggle_step(&mut self, order_id: u32, step_id: &str) {
        let result = self.work_orders.iter_mut().find(|order| order.id == order_id)
            .ok_or("service_desk.feedback.order_missing")
            .and_then(|order| {
                if order.status == WorkOrderStatus::Closed {
                    return Err("service_desk.feedback.order_closed");
                }
                let step = order.steps.iter_mut().find(|step| step.id == step_id)
                    .ok_or("service_desk.feedback.step_missing")?;
                step.complete = !step.complete;
                // Removing a completed check invalidates an earlier ready decision.
                if !step.complete && order.status == WorkOrderStatus::ReadyForPickup {
                    order.status = WorkOrderStatus::InProgress;
                }
                Ok("service_desk.feedback.step_updated")
            });
        self.feedback = Some(match result { Ok(key) => DeskFeedback::Info(key), Err(key) => DeskFeedback::Error(key) });
    }

    pub fn advance_order(&mut self, order_id: u32) {
        let Some(order) = self.work_orders.iter_mut().find(|order| order.id == order_id) else {
            self.feedback = Some(DeskFeedback::Error("service_desk.feedback.order_missing"));
            return;
        };
        let checks_complete = !order.steps.is_empty() && order.steps.iter().all(|step| step.complete);
        let result = match order.status {
            WorkOrderStatus::Open => { order.status = WorkOrderStatus::InProgress; Ok("service_desk.feedback.started") }
            WorkOrderStatus::WaitingForParts => { order.status = WorkOrderStatus::InProgress; Ok("service_desk.feedback.parts_received") }
            WorkOrderStatus::InProgress if checks_complete => { order.status = WorkOrderStatus::ReadyForPickup; Ok("service_desk.feedback.ready") }
            WorkOrderStatus::InProgress => Err("service_desk.feedback.checklist_incomplete"),
            WorkOrderStatus::ReadyForPickup if checks_complete => { order.status = WorkOrderStatus::Closed; Ok("service_desk.feedback.pickup_recorded") }
            WorkOrderStatus::ReadyForPickup => {
                order.status = WorkOrderStatus::InProgress;
                Err("service_desk.feedback.checklist_incomplete")
            }
            WorkOrderStatus::Closed => Err("service_desk.feedback.order_closed"),
        };
        self.feedback = Some(match result { Ok(key) => DeskFeedback::Info(key), Err(key) => DeskFeedback::Error(key) });
    }
}

pub fn completed_steps(steps: &[InspectionStep]) -> usize {
    steps.iter().filter(|step| step.complete).count()
}

<!-- fission:step id="shift-notes" -->
## Keep each draft attached to its work order

A shift note may be started before another repair needs attention. Keeping one draft string on the detail panel risks losing it when the panel is removed. Keeping one global string risks attaching it to the next selected order. Instead, the app stores drafts by work-order ID.

The input handler reads the current text event and updates only that order's draft. Adding a note trims and validates it, allocates a bounded local identifier and clears only the submitted draft. Rejected input stays available to correct. The test changes between two work orders and checks that neither draft is moved or cleared by the other's submission.

The note is appended to this session's history, not sent to a service. Without an authenticated operator and a trustworthy timestamp, it remains explicitly unattributed. Do not fill those fields with a fictional user or the preview's sample time.

Search checks the reference, equipment description, location and requester. It keeps the selected order if that order still matches; otherwise it selects the first match or no order. A newly created order clears the old search so it cannot disappear behind a filter immediately. Searching with no matches produces an explanation, not an unrelated fallback detail panel.

        match self { Self::Info(key) | Self::Error(key) => key }
    }
}

    pub due_today: bool,

#[derive(Clone, Debug, Default, PartialEq)]
pub struct ServiceDeskState {
    pub work_orders: Vec<WorkOrder>,
    pub selected_work_order: Option<u32>,
    pub feedback: Option<DeskFeedback>,
    pub note_drafts: std::collections::HashMap<u32, String>,
    pub next_note_id: u64,
    pub search_query: String,
}
impl GlobalState for ServiceDeskState {}

impl ServiceDeskState {
    pub fn feedback_key(&self) -> Option<&'static str> {
        self.feedback.as_ref().map(DeskFeedback::key)
    }
    pub fn feedback_is_error(&self) -> bool {
        matches!(self.feedback, Some(DeskFeedback::Error(_)))
    }
    pub fn create_order(&mut self, draft: WorkOrderDraft) -> bool {
        if [&draft.title, &draft.description, &draft.location, &draft.requested_by, &draft.due_window]
            .iter().any(|value| value.trim().is_empty() || value.chars().count() > 240)
            || self.work_orders.len() >= 100
        {
            self.feedback = Some(DeskFeedback::Error("service_desk.create.invalid"));
            return false;
        }
        let Some(id) = self.work_orders.iter().map(|order| order.id).max().unwrap_or(0).checked_add(1) else {
            self.feedback = Some(DeskFeedback::Error("service_desk.create.limit"));
            return false;
        };
        self.work_orders.push(WorkOrder {
            id, reference: format!("WO-{id:04}"),
            title: draft.title.trim().into(), description: draft.description.trim().into(),
            location: draft.location.trim().into(), requested_by: draft.requested_by.trim().into(),
            due_window: draft.due_window.trim().into(), due_today: draft.due_today,
            priority: WorkOrderPriority::Normal, status: WorkOrderStatus::Open,
            steps: vec![
                InspectionStep { id: "inspection".into(), title_key: "service_desk.step.record_inspection".into(), category: InspectionCategory::Inspection, complete: false },
                InspectionStep { id: "verification".into(), title_key: "service_desk.step.record_verification".into(), category: InspectionCategory::Verification, complete: false },
            ],
            shift_notes: Vec::new(),
        });
        self.selected_work_order = Some(id);
        self.search_query.clear();
        self.feedback = Some(DeskFeedback::Info("service_desk.create.created"));
        true
    }
}
impl ServiceDeskState {
    pub fn toggle_step(&mut self, order_id: u32, step_id: &str) {
        let result = self.work_orders.iter_mut().find(|order| order.id == order_id)
            .ok_or("service_desk.feedback.order_missing")
            .and_then(|order| {
                if order.status == WorkOrderStatus::Closed {
                    return Err("service_desk.feedback.order_closed");
                }
                let step = order.steps.iter_mut().find(|step| step.id == step_id)
                    .ok_or("service_desk.feedback.step_missing")?;
                step.complete = !step.complete;
                // Removing a completed check invalidates an earlier ready decision.
                if !step.complete && order.status == WorkOrderStatus::ReadyForPickup {
                    order.status = WorkOrderStatus::InProgress;
                }
                Ok("service_desk.feedback.step_updated")
            });
        self.feedback = Some(match result { Ok(key) => DeskFeedback::Info(key), Err(key) => DeskFeedback::Error(key) });
    }

    pub fn advance_order(&mut self, order_id: u32) {
        let Some(order) = self.work_orders.iter_mut().find(|order| order.id == order_id) else {
            self.feedback = Some(DeskFeedback::Error("service_desk.feedback.order_missing"));
            return;
        };
        let checks_complete = !order.steps.is_empty() && order.steps.iter().all(|step| step.complete);
        let result = match order.status {
            WorkOrderStatus::Open => { order.status = WorkOrderStatus::InProgress; Ok("service_desk.feedback.started") }
            WorkOrderStatus::WaitingForParts => { order.status = WorkOrderStatus::InProgress; Ok("service_desk.feedback.parts_received") }
            WorkOrderStatus::InProgress if checks_complete => { order.status = WorkOrderStatus::ReadyForPickup; Ok("service_desk.feedback.ready") }
            WorkOrderStatus::InProgress => Err("service_desk.feedback.checklist_incomplete"),
            WorkOrderStatus::ReadyForPickup if checks_complete => { order.status = WorkOrderStatus::Closed; Ok("service_desk.feedback.pickup_recorded") }
            WorkOrderStatus::ReadyForPickup => {
                order.status = WorkOrderStatus::InProgress;
                Err("service_desk.feedback.checklist_incomplete")
            }
            WorkOrderStatus::Closed => Err("service_desk.feedback.order_closed"),
        };
        self.feedback = Some(match result { Ok(key) => DeskFeedback::Info(key), Err(key) => DeskFeedback::Error(key) });
    }
}

pub fn completed_steps(steps: &[InspectionStep]) -> usize {
    steps.iter().filter(|step| step.complete).count()
}
impl ServiceDeskState {
    pub fn update_note_draft(&mut self, order_id: u32, text: String) {
        if !self.work_orders.iter().any(|order| order.id == order_id) || text.chars().count() > 1000 {
            return;
        }
        if text.is_empty() { self.note_drafts.remove(&order_id); }
        else { self.note_drafts.insert(order_id, text); }
        self.feedback = None;
    }
    pub fn add_note(&mut self, order_id: u32) {
        let message = self.note_drafts.get(&order_id).map(String::as_str).unwrap_or("").trim().to_owned();
        if message.is_empty() || message.chars().count() > 1000 {
            self.feedback = Some(DeskFeedback::Error("service_desk.feedback.note_empty"));
            return;
        }
        let Some(order) = self.work_orders.iter_mut().find(|order| order.id == order_id) else {
            self.feedback = Some(DeskFeedback::Error("service_desk.feedback.order_missing"));
            return;
        };
        let Some(next_id) = self.next_note_id.checked_add(1).filter(|_| order.shift_notes.len() < 200) else {
            self.feedback = Some(DeskFeedback::Error("service_desk.create.limit"));
            return;
        };
        order.shift_notes.push(crate::models::ShiftNote::draft(format!("local-note-{}", self.next_note_id), message));
        self.next_note_id = next_id;
        self.note_drafts.remove(&order_id);
        self.feedback = Some(DeskFeedback::Info("service_desk.feedback.note_added"));
    }
}

## Run the native app

```sh
cargo test --lib
fission doctor --project-dir .
fission run --project-dir .
```

The tests check creation, identifiers, missing records, handoff rules, corrections to a ready checklist and order-specific notes. They do not prove the rendered layout. Exercise creation, selection, rejected transitions and long notes in the native window, and resize it while the detail panel is open.

To keep records after restart, request repository writes through asynchronous effects. Retain a note draft while its write is pending and report durable success only after the repository accepts it. Authentication, authorisation and equipment-specific safety evidence also belong to that complete workflow; the example does not manufacture them.
