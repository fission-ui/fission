Build a Rust inventory catalogue with server-rendered product routes, stock filters, accessible forms, persistent updates and cache invalidation. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Compose UI while you read. The preview demonstrates filter and stock-status interactions in the browser. Load and update real product records through the SSR app’s data service.

## What you will build

Create a server-rendered product catalogue with product detail routes, a stock filter and an edit form that records inventory changes.

Install the Fission CLI and scaffold the SSR project:

```sh
cargo install cargo-fission
fission init harbour-inventory
cd harbour-inventory
fission add-target ssr --project-dir .
```

## Project layout

```text
harbour-inventory/
├── Cargo.toml                 # generated dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                 # generated desktop entrypoint
│   ├── lib.rs                  # shared app setup
│   ├── app.rs                  # the Fission component shown in this tutorial
│   ├── state.rs
│   ├── models/product.rs
│   ├── effects/inventory.rs
│   └── components/product_table.rs
├── platforms/                  # generated host files after add-target
└── tests/                      # project-specific flow checks
```

`fission init` generates `Cargo.toml`, `fission.toml`, `src/main.rs`, `src/lib.rs` and `src/app.rs`. Add the task modules in the tree as you build the feature. Keep data shared across routes in `GlobalState`, and keep retained interaction such as a disclosure or draft field in the owning `fission_component!`. Request database, filesystem, network and session work through a reducer effect, job or service; never run host work while a component view is being built.

`preview/lib.rs` is a documentation harness. The page compiles each complete `src/app.rs` component into WebAssembly so you can use the same UI while reading. Its host results are deterministic preview states; the target-specific host work described in this tutorial runs in each target project code, not in the browser preview.

## List products with useful stock information

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("Trail mug — 4 available"),
                Text("Field notebook — 0 available"),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```
<!-- fission:file path="preview/lib.rs" -->
```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::TutorialPreview::new(
        "Inventory".to_string(),
        "Review products that need restocking.".to_string(),
        "Filter low stock".to_string(),
        "Low-stock products are shown.".to_string(),
        "All inventory is visible.".to_string(),
    );
    WebApp::<(), _>::new(preview)
        .with_title("Build a product inventory website in Rust")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Update stock through explicit actions

Give each product a stable id and use it in the route. Filter on the server from a validated query value, then show a clear empty result when no product matches. Display stock as text as well as colour so a user can understand the status without relying on colour vision.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            stock: usize = 4,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("Trail mug — current stock"),
                Row(gap: tokens.spacing.m,
                    children: [Button(child: Text("Receive one"),
                            key: "receive-stock",
                            on_press: reduce { preview.stock += 1; }),
                        Button(child: Text(preview.action.clone()),
                            key: "sell-stock",
                            disabled: preview.stock == 0,
                            on_press: reduce { if preview.stock > 0 { preview.stock -= 1; } })]),
                Text(format!("{} available",
                        preview.stock)),
                if preview.stock == 0 { Text("Out of stock") } else { Text("In stock") },
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview a failed stock update".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("The stock update was not saved. The displayed quantity is unchanged.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Show low-stock and failed-save states

Persist a stock adjustment only after validating the submitted quantity and the user's permission. Invalidate or refresh cached product data after a successful write so the catalogue does not keep showing an old count.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
fission doctor --project-dir .
fission run --target ssr --project-dir .
cargo test
fission build --target ssr --project-dir .
fission test --target ssr --project-dir .
```

Expected result: The catalogue filters products, shows stock status, and recovers from empty results or failed updates.
