You’re opening the Harbour Supply stockroom in Troutdale. Before putting a delivery away, the receiver needs to identify the product, check its bin, and compare the count with its reorder point. A name alone is not enough: two products can have the same supplier, and a box in the wrong place can leave the shelf empty while the warehouse total still looks fine.

We’ll build the screen the receiving team uses to check those details and record new stock. The catalogue has five outdoor products; three need attention, including an out-of-stock camp stove. Search by name, SKU, category, supplier, or bin. A receipt updates the product, warehouse total, and reorder summary together. Zero, invalid, or overflowing quantities leave the count alone and explain what needs fixing.

The catalogue stays in memory so you can see each change without configuring a service. We’ll keep inventory truth in shared app state and search and receipt drafts in the dashboard. At the end, we’ll look at what needs to move behind an asynchronous persistence boundary in a real app.

## Start with a useful stock catalogue

Before changing a count, the receiver needs to know exactly which product they’re looking at. The SKU is the reliable identifier; the name, supplier, and bin help match the record to the carton or shelf. Each row also puts the current quantity next to the reorder point, so “Reorder soon” has a clear reason and doesn’t rely on colour alone.

`InventoryProduct` holds those details. Unit cost is stored in cents, not as a floating-point number. That keeps money exact: 1,800 cents is always eighteen dollars, and formatting happens only when we display it.

#[derive(Clone, Debug, PartialEq)]
pub struct InventoryProduct {
    pub id: u32,
    pub sku: String,
    pub name: String,
    pub category: ProductCategory,
    pub supplier: String,
    pub bin: String,
    pub stock: u32,
    pub reorder_point: u32,
    pub unit_cost_cents: u32,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum ProductCategory {
    Drinkware,
    Stationery,
    Cooking,
    WaterTreatment,
    Shelter,
}

impl ProductCategory {
    pub fn translation_key(self) -> &'static str {
        match self {
            Self::Drinkware => "inventory.category.drinkware",
            Self::Stationery => "inventory.category.stationery",
            Self::Cooking => "inventory.category.cooking",
            Self::WaterTreatment => "inventory.category.water_treatment",
            Self::Shelter => "inventory.category.shelter",
        }
    }
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum InventoryFilter {
    All,
    NeedsReorder,
    OutOfStock,
}

pub fn matches_inventory_filter(
    product: &InventoryProduct,
    query: &str,
    filter: InventoryFilter,
    category_label: &str,
) -> bool {
    let query = query.trim().to_lowercase();
    let matches_query = query.is_empty()
        || product.name.to_lowercase().contains(&query)
        || product.sku.to_lowercase().contains(&query)
        || category_label.to_lowercase().contains(&query)
        || product.supplier.to_lowercase().contains(&query)
        || product.bin.to_lowercase().contains(&query);
    let matches_stock = match filter {
        InventoryFilter::NeedsReorder => product.stock <= product.reorder_point,
        InventoryFilter::OutOfStock => product.stock == 0,
        InventoryFilter::All => true,
    };

    matches_query && matches_stock
}

use crate::models::InventoryProduct;

fission_component! {
    pub InventoryProductRow<InventoryState> { product: InventoryProduct }
    view(row, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let stock_status = if row.product.stock == 0 {
            cx.tr("inventory.status.out")
        } else if row.product.stock <= row.product.reorder_point {
            cx.tr("inventory.status.reorder")
        } else {
            cx.tr("inventory.status.in_stock")
        };
        let status_color = if row.product.stock == 0 {
            tokens.colors.error
        } else if row.product.stock <= row.product.reorder_point {
            tokens.colors.warning
        } else {
            tokens.colors.success
        };
    } =>
    Container(
        Grid(
            columns: vec![GridTrack::auto_fit(GridTrack::minmax(
                GridTrack::Points(180.0),
                GridTrack::Fr(1.0),
            ))],
            rows: vec![GridTrack::Auto],
            column_gap: tokens.spacing.l,
            row_gap: tokens.spacing.m,
            children: [
                Column(gap: tokens.spacing.xs, children: [
                    Text(row.product.name)
                        .weight(tokens.typography.font_weight_semibold),
                    Text(format!("{} · {}", row.product.sku, cx.tr(row.product.category.translation_key())))
                        .color(tokens.colors.text_secondary),
                    Text(format!("{}: {} · {}: {}", cx.tr("inventory.supplier"), row.product.supplier, cx.tr("inventory.bin"), row.product.bin))
                        .color(tokens.colors.text_secondary),
                ]),
                Column(gap: tokens.spacing.xs, children: [
                        Text(format!("{} {} · {}", row.product.stock, cx.tr("inventory.units"), stock_status))
                        .color(status_color)
                        .weight(tokens.typography.font_weight_semibold),
                    Text(format!("{} {} {}", cx.tr("inventory.reorder.at"), row.product.reorder_point, cx.tr("inventory.units")))
                        .color(tokens.colors.text_secondary),
                    Text(format!(
                        "${}.{:02} · {}",
                        row.product.unit_cost_cents / 100,
                        row.product.unit_cost_cents % 100,
                        cx.tr("inventory.cost.per_unit"),
                    )),
                ]),
            ],
        ),
    )
    .padding_all(tokens.spacing.m)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.medium)
}

## Find products and record stock receipts

When the delivery arrives, the receiver may know only the supplier or the bin on the shelf label. Search checks name, SKU, category, supplier, and bin. The stock filters narrow the list: “Needs reorder” compares the quantity with the visible threshold, while “Out of stock” shows only products with a zero count.

For now, the receive action adds five units. It belongs to a specific product row, so the reducer receives that product ID and can’t update a different item by mistake. Next, the receiver will enter the amount from the packing slip, and we’ll reject invalid quantities before changing stock.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq)]
pub struct InventoryState {
    pub products: Vec<InventoryProduct>,
    pub feedback: String,
    pub feedback_is_error: bool,
}

impl Default for InventoryState {
    fn default() -> Self {
        Self {
            products: Vec::new(),
            feedback: String::new(),
            feedback_is_error: false,
        }
    }
}

impl GlobalState for InventoryState {}

#[fission_reducer(ReceiveStock)]
pub fn on_receive_stock(state: &mut InventoryState, product_id: u32, quantity: u32) {
    let result = if quantity == 0 {
            Err("inventory.receipt.invalid_quantity".to_string())
    } else if let Some(product) = state
        .products
        .iter_mut()
        .find(|product| product.id == product_id)
    {
        match product.stock.checked_add(quantity) {
            Some(next_stock) => {
                product.stock = next_stock;
                Ok("inventory.receipt.success".to_string())
            }
            None => Err("inventory.receipt.overflow".to_string()),
        }
    } else {
        Err("inventory.receipt.missing_product".to_string())
    };

    match result {
        Ok(message) => {
            state.feedback = message;
            state.feedback_is_error = false;
        }
        Err(message) => {
            state.feedback = message;
            state.feedback_is_error = true;
        }
    }
}

## Validate receipts and make empty results recoverable

The receiver needs to enter the quantity from the packing slip. The dashboard keeps that field local because it is just a draft. When the receiver presses **Receive**, the action sends the parsed number and product ID to `on_receive_stock`. The reducer rejects zero and checks for integer overflow before writing. On error, the count stays unchanged and the message explains what to correct.

Search may also return no products. The empty state should say that the current search or filters caused it and offer a way to restore the catalogue. Clearing the view resets only the search and filter; it must not undo earlier receipts.

Product records belong in `GlobalState`: the summary, reorder notice, and rows all need the same stock values. Search, the active filter, and the receipt draft are local dashboard state, not warehouse facts. When the reducer accepts a receipt, the whole screen reads the updated product list. When it rejects one, no count changes.

Reloading this example restores its starting products. A real app would load inventory from a service and write receipts through an async effect, showing a pending state until the service accepts or rejects the change. Keep product ID and quantity validation with the domain action; the service boundary handles persistence and network errors.

## Run the dashboard

Start the server target from the project root and open the local URL printed by the CLI:

```sh
fission doctor --project-dir .
fission run --target ssr --project-dir .
```

Before packaging, search by SKU, supplier, and bin. Compare the reorder filter with the threshold in each row, then try valid and invalid receipts. A successful receipt updates the product and summary; a rejected one explains the problem without changing the count.

The browser preview keeps its sample records in memory, so a reload restores the starting counts. The SSR app's production state starts empty until a repository loads the catalogue. To keep changes across requests or share them with product-detail routes, persist inventory through an asynchronous repository service. A reducer requests the write; the screen shows pending state and then the service result.
