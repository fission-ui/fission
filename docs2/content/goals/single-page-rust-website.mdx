Visitors should understand what a product does and what to do next without having to hunt for it. We will build a responsive landing page for Fieldnotes, a small-team planning tool, then generate the production site as crawlable HTML with working section links.

The page introduces the product, explains three benefits, answers a common question and gives visitors one clear way to get started. Its section links use ordinary fragment URLs, so the page still works without a client-side router.

Install the Fission CLI and create a Static site project:

```sh
cargo install cargo-fission
fission init fieldnotes-site --template website
cd fieldnotes-site
```

The template provides a Static site entrypoint in `src/main.rs`, route registration and the Web shell in `src/lib.rs`, plus separate page, navigation and footer components. Add the task files from the tree as you work. The lesson's `preview/src/app.rs` is a separate browser harness; the production site uses the template modules and `fission.toml`. Do not copy `preview/lib.rs` into the website.

### Set up the landing-page route and responsive styling

The generated `SitePage` in `src/page.rs` uses `fission_component!`. Extend its home-page branch with the hero, benefit sections, question, and primary action. Give each section one job and a heading that makes the page easy to scan.

Add these metadata and stylesheet settings to the generated `[site]` table:

```toml
[site]
title = "Fieldnotes — simple team planning"
description = "Plan a project, share ownership and keep the next step clear."
base_url = "https://fieldnotes.example.com"
asset_dirs = ["assets"]
css_files = ["assets/landing.css"]
generate_sitemap = true
generate_robots = true
```

In the home component, use Fission's `Text`, `Link`, `Column`, and `SemanticsRegion` widgets. Use normal links for section navigation and keep the main action visible on a narrow screen. Give the hero and sections matching semantic identifiers, then add responsive overrides in `assets/landing.css`. Fission writes those identifiers to `data-fission-semantics`:

```css
[data-fission-semantics="landing-hero"] { max-width: 68rem; margin-inline: auto; padding: clamp(2rem, 8vw, 7rem) 1.25rem; }
[data-fission-semantics="landing-sections"] { display: grid; grid-template-columns: repeat(3, minmax(0, 1fr)); gap: 1.5rem; }
@media (max-width: 48rem) {
  [data-fission-semantics="landing-sections"] { grid-template-columns: 1fr; }
}
```

Make sure the copy and links still work without JavaScript. At phone width, check that every action is visible and that keyboard focus reaches the section links and main action in the right order.

## Write a clear hero and page outline

This first preview is a task card, not the Fieldnotes landing page. Its copy comes through props and its spacing uses theme tokens. Next, build the hero, benefit sections, and question section that the anchor links will target.

<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub StudioWebsite<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("A clear promise for the page visitor"),
                Row(gap: tokens.spacing.m,
                    children: [Text("Features"),
                        Text("Pricing"),
                        Text("Contact")]),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Connect section navigation and the call to action

Give the page one clear H1, a short explanation of who the product helps, and one main action. Add an in-page navigation row with links to stable section IDs such as `#features` and `#questions`. Make each section answer a different question instead of repeating the same sales claim.

The selected section and missing-section message are local to this preview. The published page uses fragment links such as `#features`; it does not need a second copy of its content in app state.
<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub StudioWebsite<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            active_section: usize = 0,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text("Features"),
                    key: "features",
                    on_press: reduce { preview.active_section = 1; }),
                Button(child: Text("Pricing"),
                    key: "pricing",
                    on_press: reduce { preview.active_section = 2; }),
                Text(if preview.active_section == 1 { "Features: one shared Rust app model" } else if preview.active_section == 2 { "Pricing: compare the full plan cost" } else { "Overview: build and ship a Fission app" }),
                Button(child: Text(preview.action.clone()),
                    key: "primary-action"),
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview a missing section".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("This section is not on the page. Choose an available section link.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Check phone and desktop layouts

Check the page at narrow and wide widths. Let columns wrap or stack, keep headings readable, and make sure anchor targets are not hidden under a sticky header. The generated HTML should include the page heading and main copy for search crawlers.

Do not perform I/O during component conversion. Use reducers for state changes, then request host work through an effect, capability, job, or service so the UI stays responsive. The preview control only simulates a failed host operation and its recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run these checks:

```sh
cargo test
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission site serve --project-dir . --host 127.0.0.1 --port 8123
fission test --target static-site --project-dir .
```

You should end up with one descriptive H1, working section links, a clear next action, and crawlable HTML.
