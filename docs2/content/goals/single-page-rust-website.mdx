Build a responsive Rust landing page with a clear hero, useful page sections, anchor navigation, accessible calls to action and a static production build. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Compose UI while you read. The landing page preview runs in the browser. The finished static site emits responsive HTML with working section links and crawlable page copy.

## What you will build

Create a focused landing page for Fieldnotes, a small-team planning tool. The page introduces the product, explains three benefits, answers a common question and gives visitors a direct path to start. Its section links use normal fragment URLs, so the page remains useful without a client-side router.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init fieldnotes-site --template website
cd fieldnotes-site
```

The finished project is organised around the app boundary and the files that own each job:

```text
fieldnotes-site/
├── Cargo.toml
├── fission.toml
├── src/
│   ├── main.rs
│   ├── lib.rs
│   ├── app.rs
│   ├── state.rs
│   └── components/
└── content/index.mdx
```

Fission generates a thin entrypoint for each target and starts the shared app from it. Keep shared UI in `src/app.rs`, and move a reusable presentation piece into `src/components/` when it has a clear job of its own. Use `GlobalState` for data read across screens and Compose `state` for retained interaction owned by one component. Keep host work such as persistence and network requests in a Fission service or effect, then show loading, success or failure in the UI.

The `preview/lib.rs` file is a documentation-only browser harness that mounts the step in the live preview. The `src/app.rs` component is compiled into that preview. Use its Compose patterns in your project, but do not copy the harness or treat its simulated host results as production behavior.

## Write a clear hero and page outline

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("A clear promise for the page visitor"),
                Row(gap: tokens.spacing.m,
                    children: [Text("Features"),
                        Text("Pricing"),
                        Text("Contact")]),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```
<!-- fission:file path="preview/lib.rs" -->
```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::TutorialPreview::new(
        "Fieldnotes".to_string(),
        "Plan your team’s next project.".to_string(),
        "View plans".to_string(),
        "The plan details are visible.".to_string(),
        "The landing page is ready.".to_string(),
    );
    WebApp::<(), _>::new(preview)
        .with_title("Build a single-page website in Rust")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Connect section navigation and the call to action

Write one clear H1, a short explanation of who the product helps and one primary action. Add an in-page contents row with links to stable section ids such as #features and #questions. Keep each section focused on one user question instead of repeating the same sales claim.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            active_section: usize = 0,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text("Features"),
                    key: "features",
                    on_press: reduce { preview.active_section = 1; }),
                Button(child: Text("Pricing"),
                    key: "pricing",
                    on_press: reduce { preview.active_section = 2; }),
                Text(if preview.active_section == 1 { "Features: one shared Rust app model" } else if preview.active_section == 2 { "Pricing: compare the full plan cost" } else { "Overview: build and ship a Fission app" }),
                Button(child: Text(preview.action.clone()),
                    key: "primary-action"),
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview a missing section".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("This section is not on the page. Choose an available section link.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Check phone and desktop layouts

Check the page at narrow and wide widths. Let columns wrap or become vertical, keep headings readable, and make every anchor target visible below the sticky header if you add one. Search crawlers should receive the page heading and main copy in the generated HTML.

Keep I/O outside component conversion and reducers. Send host work through an asynchronous effect or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission test --target static-site --project-dir .
```

Expected result: The page has one descriptive H1, working section anchors, a clear next action, and crawlable HTML.
