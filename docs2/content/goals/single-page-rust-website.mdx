A one-page site still has a navigation problem: visitors need to understand the subject, inspect the relevant detail and decide what to do next. Hiding each section behind application state makes that path harder to share and removes content from the initial document.

We will build Fieldnotes as a real Static site. All sections are present together, and fragment links move between them. There is no sign-up backend in this lesson: the action takes visitors to an explanation rather than pretending to create an account.

## Create the project

```sh
cargo install cargo-fission
fission init fieldnotes-site --template website
cd fieldnotes-site
cargo add serde_yaml
```

Keep the generated `src/main.rs`, which calls `fieldnotes_site::build_site()`. Replace the configuration with the complete small example below; change the reserved example.com origin before publishing.

## Put the whole reading path in the document

The useful behaviour here is the reading path, not a state transition. It does not need retained state, a reducer or an effect. The embedded preview is generated from these actual project files.

The active Fission theme supplies spacing, colours and typography. The stylesheet only limits the document width and makes keyboard focus explicit. Translation keys belong to meaning rather than page position; fragment anchors stay unchanged when the wording changes.

pub mod page;
mod navigation;
mod section;
mod translations;

pub fn site_app() -> fission::site::FissionSite {
    fission::site::FissionSite::new().with_env(translations::create_env())
        .route_widget::<(), _>("/", "Fieldnotes project planning",
            Some("Plan a small project with named owners and visible next steps.".into()),
            page::LandingPage::new())
}
pub fn build_site() -> anyhow::Result<()> {
    fission::site::build_from_cli(site_app())
}

use crate::{navigation::SectionNavigation, section::LandingSection};
use fission::prelude::*;
fission_component! {
    pub LandingPage<()> {}
    view(_page, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(Column(gap: tokens.spacing.xl, children: [
        SectionNavigation(),
        SemanticsRegion(identifier: Some("site-main".into()), child:
            Column(gap: tokens.spacing.xl, children: [
                SemanticsRegion(identifier: Some("site-section:overview".into()), child:
                    Column(gap: tokens.spacing.m, children: [
                        SemanticsRegion(identifier: Some("site-heading-1:top".into()), child:
                            Text(cx.tr("hero.title")).size(tokens.typography.heading1_size)),
                        Text(cx.tr("hero.description")),
                        Link::to(cx.tr("hero.action"), "#features"),
                    ])),
                LandingSection("features", "section.features.title", "section.features.description"),
                LandingSection("questions", "section.questions.title", "section.questions.description"),
            ])),
    ])).padding_all(tokens.spacing.l).bg(tokens.colors.background)
}

use fission::prelude::*;
fission_component! {
    pub LandingSection<()> {
        props { anchor: &'static str, title_key: &'static str, body_key: &'static str }
    }
    view(section, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(identifier: Some(format!("site-section:{}", section.anchor)), child:
        Container(Column(gap: tokens.spacing.m, children: [
            SemanticsRegion(identifier: Some(format!("site-heading-2:heading-{}", section.anchor)), child:
                Text(cx.tr(section.title_key)).size(tokens.typography.heading2_size)),
            Text(cx.tr(section.body_key)),
        ])).padding_all(tokens.spacing.l).bg(tokens.colors.surface))
}

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;
pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in translations must be valid YAML");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}
```

## Add a section without adding navigation state

A fragment is the part of a URL after #. The browser follows it to the element with that id. Fission's `site-section:` identifier emits the destination, while `Link::to` emits the link. There is no active_section field to synchronise with the address bar.

Add trial terms and a navigation link. The reusable section owns its presentation; the parent supplies its meaning and stable anchor.

## Check the document at the sizes people use

Navigation can wrap at a narrow width instead of hiding destinations behind a mouse-only control. Test long translations, keyboard navigation and JavaScript disabled. The browser still owns focus, fragment history and document scrolling; increasing a heading's text size alone would not create its HTML heading semantics.

@media (max-width: 40rem) {
  [data-fission-semantics="site-main"] { min-width: 0; max-width: 100%; overflow-wrap: anywhere; }

## Build and inspect

```sh
fission site build --project-dir .
fission site check --project-dir .
fission site serve --project-dir . --port 8123
curl http://127.0.0.1:8123/
```

The response should contain the heading, every section and links to their fragment IDs. A Static site has no submission handler; add a real SSR or API boundary if a later action needs to save visitor data.
