A search result is a promise. If its title and summary do not match the page people open, the metadata is not helping anyone. We will set route-specific titles, summaries, canonical links, social metadata, structured data and discovery files, then inspect the HTML Fission emits.

Turn Northstar's product site into pages that accurately describe their topic in search results and previews. Search optimisation starts with useful page content and metadata that matches what a visitor finds after opening the link.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init northstar-site --template website
cd northstar-site
cargo add serde_yaml
```

The website template creates a Static site project with a static entrypoint in `src/main.rs`, route registration and the Web shell in `src/lib.rs`, and reusable page, navigation and footer components in their own modules. Add the task files shown in the tree as you work. The preview's `src/app.rs` is a separate, compiled browser harness for the interactive lesson; the production website uses the template modules and `fission.toml`. Do not copy `preview/lib.rs` into the website.

### Put search metadata in the generated HTML

Extend the generated `[site]` configuration in `fission.toml`. A public `base_url` lets Fission produce canonical routes and sitemap entries; page-specific Markdown descriptions override the site-wide fallback.

```toml
[site]
title = "Northstar"
description = "Planning tools for small product teams."
base_url = "https://northstar.example.com"
out_dir = "dist/site"
generate_sitemap = true
generate_robots = true
```

Give every content route a title and description that match its visible subject:

```mdx
---
title: Product inventory for growing teams
description: Track product details, stock levels and recent changes in one shared inventory.
---

# Product inventory

Review current stock and decide what needs attention next.
```

For a custom route rendered by `FissionSite`, attach JSON-LD to that same route. Only describe information a visitor can verify on the page:

```rust
let site = FissionSite::new()
    .route_widget::<WebsiteState, _>(
        "/",
        "Northstar planning tools",
        Some("Planning tools for small product teams.".into()),
        SitePage::new(Page::Home),
    )
    .with_route_structured_data(
        "/",
        [r#"{"@context":"https://schema.org","@type":"WebSite","name":"Northstar"}"#],
    );
```

The custom `SitePage` remains a named `fission_component!`; site metadata and route registration stay in the site builder. Do not add structured data for features the page does not explain.

use fission::prelude::*;
fission_component! {
    pub LocalStorefront<()> {
        state {
            product_page: bool = false,
        }
    }
    view(site, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("northstar.site".to_string()),
        label: Some(cx.tr("site.a11y")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Text(cx.tr("brand")).size(tokens.typography.heading2_size),
                    Spacer(flex_grow: 1.0),
                    Button(
                        child: Text(cx.tr(if site.product_page { "nav.home" } else { "nav.inventory" })),
                        key: "switch-page",
                        on_press: reduce { site.product_page = !site.product_page; },
                    ).semantics_identifier("northstar.nav.product"),
                ]),
                Divider(),
                Column(gap: tokens.spacing.s, children: [
                    Text(if site.product_page {
                        cx.tr("page.inventory.title")
                    } else {
                        cx.tr("page.home.title")
                    })
                    .size(tokens.typography.heading1_size),
                    Text(if site.product_page {
                        cx.tr("page.inventory.description")
                    } else {
                        cx.tr("page.home.description")
                    })
                    .color(tokens.colors.text_secondary),
                    Button(
                        child: Text(cx.tr(if site.product_page { "action.back" } else { "action.explore" })),
                        key: "primary-action",
                        on_press: reduce { site.product_page = !site.product_page; },
                    ).semantics_identifier("northstar.primary-action"),
                ]),
                Container(
                    Column(gap: tokens.spacing.xs, children: [
                        Text(cx.tr("search.preview"))
                            .weight(tokens.typography.font_weight_semibold),
                        Text(if site.product_page {
                            cx.tr("search.inventory.title")
                        } else {
                            cx.tr("search.home.title")
                        }),
                        Text(if site.product_page {
                            cx.tr("search.inventory.description")
                        } else {
                            cx.tr("search.home.description")
                        })
                        .color(tokens.colors.text_secondary),
                        Text(if site.product_page { "/products/inventory/" } else { "/" })
                            .color(tokens.colors.text_secondary),
                    ]),
                )
                .padding_all(tokens.spacing.m)
                .bg(tokens.colors.surface_raised)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.medium),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
    )
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

const SOURCES: [(&str, &str); 2] = [
    ("en-US", include_str!("../i18n/en-US.yaml")),
    ("es-ES", include_str!("../i18n/es-ES.yaml")),
];

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in SOURCES {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid tutorial translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

## Inspect HTML and discovery files

Add JSON-LD only for information visible on the page, then inspect the emitted HTML for the canonical link, description, social preview metadata and structured data. Keep the sitemap and robots file in the built output and test nested URLs directly.

After `fission site build --project-dir .`, inspect the actual files rather than the browser preview:

```sh
rg -n '<title>|name="description"|rel="canonical"|property="og:' dist/site/index.html
rg -n 'schema.org|"@type"' dist/site/index.html
cat dist/site/sitemap.xml
cat dist/site/robots.txt
```

A correct result has a page-matched title and description in the HTML head, the canonical URL on the intended public domain, JSON-LD that matches visible page content, and the expected routes in `sitemap.xml`. `robots.txt` should name that sitemap when `base_url` is set.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The preview switches between two route examples and shows the visible content alongside its search-result metadata. It does not change the actual static site configuration; set each route's metadata in its frontmatter and site configuration.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
cargo test
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission site serve --project-dir . --host 127.0.0.1 --port 8123
fission test --target static-site --project-dir .
```

Expected result: Each route has a useful title, description, canonical URL, and matching structured data where appropriate.
