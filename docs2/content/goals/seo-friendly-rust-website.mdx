Set up a Rust website for search with descriptive titles, page summaries, canonical URLs, social metadata, structured data, a sitemap and robots rules. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Compose UI while you read. Metadata checks in the preview illustrate the page states. The production values must be rendered into each page’s HTML so search crawlers can read them without running JavaScript.

## What you will build

Turn Northstar's product site into pages that accurately describe their topic in search results and previews. Search optimisation starts with useful page content and metadata that matches what a visitor finds after opening the link.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init northstar-site --template website
cd northstar-site
```

The finished project is organised around the app boundary and the files that own each job:

```text
northstar-site/
├── Cargo.toml
├── fission.toml
├── src/
│   ├── main.rs
│   ├── lib.rs
│   ├── app.rs
│   ├── state.rs
│   └── components/
└── fission.toml
```

Fission generates a thin entrypoint for each target and starts the shared app from it. Keep shared UI in `src/app.rs`, and move a reusable presentation piece into `src/components/` when it has a clear job of its own. Use `GlobalState` for data read across screens and Compose `state` for retained interaction owned by one component. Keep host work such as persistence and network requests in a Fission service or effect, then show loading, success or failure in the UI.

The `preview/lib.rs` file is a documentation-only browser harness that mounts the step in the live preview. The `src/app.rs` component is compiled into that preview. Use its Compose patterns in your project, but do not copy the harness or treat its simulated host results as production behavior.

## Write for one search intent

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("Build a Rust website that search engines can understand"),
                Text("A page title matched to the content"),
                Text("A useful search description"),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```
<!-- fission:file path="preview/lib.rs" -->
```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::TutorialPreview::new(
        "Northstar pages".to_string(),
        "Review a page title and search description.".to_string(),
        "Inspect search metadata".to_string(),
        "The page has a topic-specific title and description.".to_string(),
        "Metadata is missing. Add a title and description before publishing.".to_string(),
    );
    WebApp::<(), _>::new(preview)
        .with_title("Build an SEO-friendly website in Rust")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Give every route unique metadata

Set a site title, short site description, canonical base URL, sitemap and robots output in fission.toml. Add page-specific titles and descriptions in Markdown frontmatter. A page title should describe that page, not repeat the company name alone.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            product_page: bool = false,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text(if preview.product_page { "View home page".to_string() } else { "View product page".to_string() }),
                    key: "change-page",
                    on_press: reduce { preview.product_page = !preview.product_page; }),
                Text(if preview.product_page { "Build a product inventory website in Rust" } else { "Build desktop, mobile and Web apps in Rust" }),
                Text(if preview.product_page { "/product/inventory/" } else { "/" }),
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview missing metadata".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("This page has no search description. Add one that matches its content.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Inspect HTML and discovery files

Add JSON-LD only for information visible on the page, then inspect the emitted HTML for the canonical link, description, social preview metadata and structured data. Keep the sitemap and robots file in the built output and test nested URLs directly.

Keep I/O outside component conversion and reducers. Send host work through an asynchronous effect or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission test --target static-site --project-dir .
```

Expected result: Each route has a useful title, description, canonical URL, and matching structured data where appropriate.
