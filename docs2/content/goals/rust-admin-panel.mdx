Compose a responsive Rust administration panel with task-focused navigation, summary cards, selectable tables, validated forms and permission-aware actions. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Fission component while you read. The preview keeps selection and filter state in the component. Load records and check permissions through your app state and server service in the finished admin panel.

## What you will build

Build an admin workspace with a responsive sidebar, summary counts, a read-only records table and an edit flow with a timeline of recent changes.

Install the Fission CLI and scaffold the Web project:

```sh
cargo install cargo-fission
fission init harbour-admin
cd harbour-admin
fission add-target web --project-dir .
```

## Project layout

```text
harbour-admin/
├── Cargo.toml                 # generated dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                 # generated desktop entrypoint
│   ├── lib.rs                  # shared app setup
│   ├── app.rs                  # the Fission component shown in this tutorial
│   ├── state.rs
│   ├── models/task.rs
│   ├── components/task_table.rs
│   └── effects/tasks.rs
├── platforms/                  # generated host files after add-target
└── tests/                      # project-specific flow checks
```

`fission init` generates `Cargo.toml`, `fission.toml`, `src/main.rs`, `src/lib.rs` and `src/app.rs`. Add the task modules in the tree as you build the feature. Keep data shared across routes in `GlobalState`, and keep retained interaction such as a disclosure or draft field in the owning `fission_component!`. Request database, filesystem, network and session work through a reducer effect, job or service; never run host work while a component view is being built.

`preview/lib.rs` is a documentation harness. The page compiles each complete `src/app.rs` component into WebAssembly so you can use the same UI while reading. Its host results are deterministic preview states; the target-specific host work described in this tutorial runs in each target project code, not in the browser preview.

## Build a task-focused dashboard and record list

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Row(gap: tokens.spacing.m,
                    children: [Text("Overview"),
                        Text("Orders"),
                        Text("Customers")]),
                Text("Orders today: 18"),
                Text("Order 1042 — awaiting review"),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```
<!-- fission:file path="preview/lib.rs" -->
```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::TutorialPreview::new(
        "Admin workspace".to_string(),
        "Review records, activity and account access.".to_string(),
        "Review a record".to_string(),
        "The record is selected and its activity is visible.".to_string(),
        "No records are available. Create a record or change the filter.".to_string(),
    );
    WebApp::<(), _>::new(preview)
        .with_title("Build an admin panel in Rust")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Select a record and edit a draft

Keep navigation, selected record and form draft in the smallest state scope that owns them. On a narrow screen, replace the permanent sidebar with a compact section picker and keep the record's important fields visible before secondary details.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            selected: bool = false,
            editing: bool = false,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text(if preview.selected { "Close order".to_string() } else { preview.action.clone() }),
                    key: "select-order",
                    on_press: reduce { preview.selected = !preview.selected; }),
                if preview.selected { Column(children: [Text("Order 1042 — awaiting review"),
                            Text("Customer: Mira Patel"),
                            Button(child: Text("Edit order"),
                                key: "edit-order",
                                on_press: reduce { preview.editing = !preview.editing; }),
                            if preview.editing { Text("Draft status: Ready to ship") } else { Text("Status: Awaiting review") }]) } else { Text(preview.empty.clone()) },
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview denied permission".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("You do not have permission to edit this order. The record has not changed.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Check permissions and explain save failures

Treat permissions as data checked before an action runs. Keep read-only records visually distinct from controls, explain why an action is unavailable, and preserve the selected row when the edit form returns an error.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
fission doctor --project-dir .
fission run --target web --project-dir .
cargo test
fission build --target web --project-dir .
fission test --target web --project-dir .
```

Expected result: An administrator can find a record, edit permitted fields, and understand each save result.
