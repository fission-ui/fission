Check access on the server before rendering a protected page. Hiding an account link or redirecting in the browser does not protect account data. This tutorial adds pending, denied, and allowed states to an account route, then applies the same policy to server actions.

The preview changes session status locally so you can inspect each screen. It is not authentication. In the SSR app, load and verify the session on the server, and do not construct private content until access is confirmed.

Install the Fission CLI and scaffold the SSR project:

```sh
cargo install cargo-fission
fission init harbour-account
cd harbour-account
fission add-target ssr --project-dir .
```

## Project layout

```text
harbour-account/
├── Cargo.toml                 # generated dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                 # generated desktop entrypoint
│   ├── lib.rs                  # shared app setup
│   ├── app.rs                  # the Fission component shown in this tutorial
│   ├── state.rs
│   ├── auth/session.rs
│   ├── routes/account.rs
│   └── effects/session.rs
├── platforms/                  # generated host files after add-target
└── tests/                      # project-specific flow checks
```

`fission init` generates `Cargo.toml`, `fission.toml`, `src/main.rs`, `src/lib.rs`, and `src/app.rs`. Add the feature modules as you build it. Keep data shared across routes in `GlobalState`; keep a view-only choice or draft in the component that owns it. Database, filesystem, network, and session work starts through a reducer effect, job, or service—not while the component view is being built.

`preview/lib.rs` is the documentation harness. It compiles the same component into WebAssembly so you can try the UI while reading. Its host results are deterministic preview states; they do not load a real session or run the server-side work described here.

## Separate public pages from private content

Start with the public account entry point and sign-in screen. The public shell can explain what is protected, but it must not construct the account panel while the session is still being checked. Keep page copy in props and use the active theme through the component context.

<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub ProtectedWorkspace<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("Public: Harbour home"),
                Text("Private: Reports"),
                Text("Sign in before opening reports."),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Preserve a safe return path through sign-in

While session state is loading, render a pending screen. If the visitor is signed out, offer sign-in and keep a safe return path. Build the account panel only after the server confirms access. Hiding a link in the browser is not authorisation.

The next version wires the route decision to the shared session state. Durable session and account data belong in `GlobalState`; only a temporary choice that belongs to this screen should live in retained component state.
<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub ProtectedWorkspace<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            signed_in: bool = false,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text(if preview.signed_in { "Sign out".to_string() } else { preview.action.clone() }),
                    key: "sign-in",
                    on_press: reduce { preview.signed_in = !preview.signed_in; }),
                if preview.signed_in { Column(children: [Text("Private reports"),
                            Text("Revenue this month: $24,800")]) } else { Text(preview.empty.clone()) },
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview an expired session".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("Your session expired. Sign in again before viewing private reports.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Reject expired sessions on the server

The route is not the authorization boundary. Every server action that reads or changes private data must enforce the same policy. Test a fresh browser, a valid session, a revoked session, and a direct action request that never opens the account page.

Keep I/O out of component conversion. Reducers make the state transition and queue asynchronous work; an effect, capability, job, or service performs it without blocking the UI. The preview below simulates a failed host result so you can inspect the message and recovery path. It does not authenticate a user or access a database, network, or filesystem.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
fission doctor --project-dir .
fission run --target ssr --project-dir .
cargo test
fission build --target ssr --project-dir .
fission test --target ssr --project-dir .
```

The route should preserve a safe return path, keep private content out of pending and denied trees, and check authorization again on every protected server request.
