An account page needs more than a condition around its final output. Constructing a private component can register resources and reducers before anything becomes visible. If access is still unresolved, hiding that component afterwards is already too late for the construction boundary.

Here, one selector maps the application's session state to a route decision, and `ProtectedRoute` constructs only the selected branch. Pending access builds the loading screen; signed-out access redirects to sign-in; allowed access constructs the account component. This tutorial teaches that boundary, not credential verification or session creation.

The preview buttons set sample state so you can inspect each route branch; they do not authenticate anyone. In a real app, connect `SessionState` to your own authentication flow. A protected UI route is not server authorisation: the server or service that reads private data must authenticate and authorise every request. See [Server security](/docs/guides/server-site-security/) for the server-side contract.

Install the Fission CLI and scaffold a Web project for the interactive preview:

```sh
cargo install cargo-fission
fission init harbour-account
cd harbour-account
cargo add serde_yaml
fission add-target web --project-dir .
```

```text
│   ├── en-US.yaml
│   └── es-ES.yaml
├── platforms/                  # generated host files after add-target
└── tests/                      # project-specific flow checks
```

`fission init` generates `Cargo.toml`, `fission.toml`, `src/main.rs`, `src/lib.rs`, and `src/app.rs`. Add the feature modules as you build it. Keep data shared across routes in `GlobalState`; keep a view-only choice or draft in the component that owns it. If your app resolves access asynchronously, start that work through a reducer effect, job, or service—not while the component view is being built.

Replace the generated `src/lib.rs` at each stage so a normal launch runs the tutorial app. Its initial session is explicitly signed out because this example has no session resolver. In a connected app, remove that initialisation and hydrate the session through a startup action, leaving it `Loading` until the effect completes. Do not fabricate an authenticated user to make the account route appear to work.

`preview/lib.rs` is the documentation harness. It compiles the same component into WebAssembly so you can try the UI while reading. Its buttons set synthetic session states so you can inspect each route branch; they do not authenticate a visitor or load a real session.

Keep UI copy in English and Spanish bundles. The Web app chooses its locale when it creates the environment; the browser preview uses English. If you later add an in-app language switch, store that choice in `GlobalState` and mirror it into `Env` with `with_sync_env(...)`.

## Preserve a safe return path through sign-in

Keep the session status in `GlobalState` and derive one route decision from it. `ProtectedRoute` builds only the branch that matches the state supplied by your application: a pending screen while access is unresolved, a redirect for a signed-out visitor, or the account component when the application has marked the user as authenticated.

```rust
use crate::screens::*;

fission_component! {
    pub App<AppState>
    view(_app, state, cx) {
        let account_access = account_route_decision(state, &cx.view.env().current_route);
    } =>
    Router::<AppState>::new()
        .with_path(state.current_path.clone())
        .route_component(
            "/",
            PublicAccountEntry,
        )
        .route_component(
            "/account",
            ProtectedRoute::new(account_access, AccountRoute)
                .pending(SessionLoadingRoute),
        )
        .route_component("/sign-in", SignInRoute)
}
```

```rust
use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum SessionState {
    Loading,
    SignedOut,
    Authenticated { display_name: String },
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct AppState {
    pub current_path: String,
    pub session: SessionState,
}

impl Default for AppState {
    fn default() -> Self {
        Self {
            current_path: "/".to_string(),
            session: SessionState::Loading,
        }
    }
}

impl GlobalState for AppState {}

pub fn account_route_decision(
    state: &AppState,
    current_route: &fission::core::env::RouteLocation,
) -> RouteDecision {
    match &state.session {
        SessionState::Loading => RouteDecision::Pending,
        SessionState::SignedOut => RouteRedirect::replace("/sign-in")
            .return_to(current_route)
            .into(),
        SessionState::Authenticated { .. } => RouteDecision::Allow,
    }
}

pub fn route_changed(
    state: &mut AppState,
    action: fission::core::action::ShellRouteChanged,
    _cx: &mut ReducerContext<AppState>,
) {
    state.current_path = action.location.pathname;
}
```

## Keep unavailable access out of the account route

When your application cannot resolve access, map that result to a denied route instead of falling back to the account screen. `ProtectedRoute` builds the denied branch and does not construct the protected component. This example models that route decision; it does not determine whether a session is expired or valid.

The preview adds an unavailable state so you can inspect that branch. It still does not authenticate anyone. Route protection only controls the UI tree. Every server request that reads or changes account data must authenticate and authorise its caller independently. See [Server security](/docs/guides/server-site-security/) for the server-side requirements.

```rust
        let RouteDecision::Redirect(redirect) = account_route_decision(&state, &location) else {
            panic!("signed-out access must redirect");
        };
        assert_eq!(redirect.history, RouteRedirectHistory::Replace);
        assert_eq!(redirect.destination,
            "/sign-in?return_to=%2Faccount%3Ftab%3Drequests%23open");
    }
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env(locale: &str) -> Env {
    let mut env = Env::default();
    env.locale = Locale::from(locale);
    for (bundle_locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid account-route translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(bundle_locale),
            messages,
        });
    }
    env
}
```
