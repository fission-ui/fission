**Status: blocked — this tutorial does not yet meet its native iOS goal.** The current iOS provider cannot read, set or adjust the volume. The earlier memory-backed example made that boundary look like a working feature; it was not one.

Volume inside a media player and the device's volume are different controls. Changing a number in app state demonstrates neither. The diagnostic below requests an actual media-stream reading and reports the host's real result. It contains no slider which suggests that an unsupported system control has been implemented.

## Create a diagnostic project, not a simulated feature

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) first. These commands declare the capability and generate platform inputs; they do not remove the native provider gap.

```sh
cargo install cargo-fission
fission init ios-use-fissions-limited-ios-volume-control-capability
cd ios-use-fissions-limited-ios-volume-control-capability
fission add-target ios --project-dir .
fission add-capability volume-control --project-dir .
cargo add serde_yaml
```

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct VolumeDiagnosticState {
    pub locale: Locale,
    pub pending: bool,
    pub message_key: String,
    pub diagnostic: Option<String>,
}
impl Default for VolumeDiagnosticState {
    fn default() -> Self {
        Self {
            locale: Locale::from("en-US"),
            pending: false,
            message_key: "check.ready".into(),
            diagnostic: None,
        }
    }
}
impl GlobalState for VolumeDiagnosticState {}

pub fn check_host(
    state: &mut VolumeDiagnosticState,
    cx: &mut ReducerContext<VolumeDiagnosticState>,
) {
    if state.pending {
        return;
    }
    state.pending = true;
    state.message_key = "check.pending".into();
    state.diagnostic = None;
    let ok = cx.effects.bind(HostChecked, reduce_with!(host_checked));
    let err = cx
        .effects
        .bind(HostCheckFailed, reduce_with!(host_check_failed));
    cx.effects
        .volume()
        .get_level(VolumeStream::Media)
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(HostChecked)]
fn host_checked(state: &mut VolumeDiagnosticState, cx: &mut ReducerContext<VolumeDiagnosticState>) {
    state.pending = false;
    match cx.input.capability_ok(GET_VOLUME_LEVEL) {
        Some(value) => {
            state.message_key = if true {
                "check.available"
            } else {
                "check.unavailable"
            }
            .into();
            state.diagnostic = Some(format!("{value:?}"));
        }
        None => state.message_key = "check.invalid".into(),
    }
}

#[fission_reducer(HostCheckFailed)]
fn host_check_failed(
    state: &mut VolumeDiagnosticState,
    cx: &mut ReducerContext<VolumeDiagnosticState>,
) {
    state.pending = false;
    match cx.input.capability_error(GET_VOLUME_LEVEL) {
        Some(error) => {
            state.message_key = if error.code == "unsupported" {
                "check.unavailable"
            } else {
                "check.failed"
            }
            .into();
            state.diagnostic = Some(format!("{}: {}", error.code, error.message));
        }
        None => state.message_key = "check.invalid".into(),
    }
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid task translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::VolumeDiagnosticState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Keep the missing integration visible

The default native volume provider has macOS and Linux implementations. Its iOS path returns an unsupported operation for `get_level`, `set_level` and `adjust_level`. Adding the capability declaration does not change that provider.

The diagnostic uses `get_level` because it is read-only. On a desktop whose native provider implements that operation, a reading may be returned. The browser and iOS results must be recorded independently; desktop success does not fill the iOS gap.

A complete tutorial still needs an approved native implementation and a precise account of which volume it controls, followed by physical-device checks. Until then, this page provides integration diagnostics only. It must not be listed as a completed volume-control workflow.
