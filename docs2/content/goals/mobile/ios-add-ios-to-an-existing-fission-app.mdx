Adding iOS should add a host for your application, not a second implementation of it. If the desktop app already owns a journey draft and a prepared plan, the iOS screen should read those same state types and transitions rather than a new set of Swift fields.

The generated host deals with building, launching and packaging the native app. Your routes, components, services and state stay in shared Rust. Target-specific capability providers remain a separate question: adding the target does not make an unsupported host operation work.

## Add the target to the existing project

Start in the app's root. Do not run `fission init` over an existing app, and inspect your current changes before adding a generated target.

```sh
git status --short
fission add-target ios --project-dir .
git diff -- Cargo.toml fission.toml platforms/ios
fission doctor ios --project-dir .
```

The command adds iOS to the target list, creates its host scaffold, synchronizes platform configuration and updates Fission's Cargo features. It does not rewrite your shared application into an iOS-specific screen. Read the resulting `platforms/ios/README.md` and inspect the diff rather than treating generation as an opaque step.

Use [iOS setup](/blog/set-up-rust-ios-development-with-fission/) for Xcode and Rust prerequisites. Those tools are required on the Mac which actually builds the simulator app.

## Connect MobileApp to the same shared core

The worked example is the journey editor from [the reusable-component tutorial](/blog/compose-an-ios-app-from-reusable-fission-widgets/). Its fields accept real place names, and Prepare keeps a snapshot. There is no platform-specific business behavior to duplicate.

For an existing product, keep your own components and state; adapt the thin launcher pattern instead of replacing the app with this example. If you are following from a new practice project, these complete files make the browser and native example self-contained. They use `serde_yaml`, so add it with `cargo add serde_yaml` if it is not already present.

```rust
use super::{
    state::{Journey, JourneyState},
    summary::JourneySummary,
};
use fission::prelude::*;

fission_component! {
    pub JourneyScreen<JourneyState> {
        state {
            origin: String = String::new(),
            destination: String = String::new(),
        }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => SafeArea(
        child: Scroll(
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("journey.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("journey.explanation")),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("language.english")), key: "english",
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                FormControl(
                    label: Some(cx.tr("journey.origin")),
                    required: true,
                    child: TextInput(
                        value: screen.origin.clone(),
                        bind(on_input): to(screen.origin),
                    ),
                ),
                FormControl(
                    label: Some(cx.tr("journey.destination")),
                    required: true,
                    child: TextInput(
                        value: screen.destination.clone(),
                        bind(on_input): to(screen.destination),
                    ),
                ),
                if !screen.origin.trim().is_empty() && !screen.destination.trim().is_empty() {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.draft")),
                        JourneySummary(
                            Journey {
                                origin: screen.origin.trim().to_owned(),
                                destination: screen.destination.trim().to_owned(),
                            },
                            key: "draft-summary",
                        ),
                    ])
                },
                Button(
                    child: Text(cx.tr("journey.prepare")), key: "prepare-journey",
                    disabled: screen.origin.trim().is_empty() || screen.destination.trim().is_empty(),
                    on_press: reduce {
                        state.prepared = Some(Journey {
                            origin: screen.origin.trim().to_owned(),
                            destination: screen.destination.trim().to_owned(),
                        });
                    },
                ),
                if let Some(journey) = &state.prepared {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.prepared")),
                        JourneySummary(journey.clone(), key: "prepared-summary"),
                    ])
                },
            ]))
            .padding_all(tokens.spacing.l),
        ),
    )
}
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid journey translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::JourneyState, env: &mut Env) {
    env.locale = state.locale.clone();
}
```

```rust
pub mod app;
mod i18n;

use app::{JourneyScreen, JourneyState};
use fission::prelude::*;

#[cfg(not(any(target_arch = "wasm32", target_os = "android", target_os = "ios")))]
pub fn run_desktop() -> anyhow::Result<()> {
    DesktopApp::<JourneyState, _>::new(JourneyScreen)
        .with_env(i18n::create_env())
        .with_sync_env(i18n::sync_env)
        .run()
}

#[cfg(any(target_os = "android", target_os = "ios"))]
pub fn run_mobile() -> anyhow::Result<()> {
    MobileApp::<JourneyState, _>::new(JourneyScreen)
        .with_env(i18n::create_env())
        .with_sync_env(i18n::sync_env)
        .run()
}

#[cfg(target_os = "android")]
#[no_mangle]
fn android_main(app_handle: AndroidApp) {
    let _ = MobileApp::<JourneyState, _>::new(JourneyScreen)
        .with_env(i18n::create_env())
        .with_sync_env(i18n::sync_env)
        .run_with_android_app(app_handle);
}

#[cfg(target_arch = "wasm32")]
#[wasm_bindgen::prelude::wasm_bindgen(start)]
pub fn run_web() -> Result<(), wasm_bindgen::JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<JourneyState, _>::new(JourneyScreen)
        .with_env(i18n::create_env())
        .with_sync_env(i18n::sync_env)
        .run()
        .map_err(|error| wasm_bindgen::JsValue::from_str(&error.to_string()))
}
```

## Preserve setup as well as component code

The important native line is `MobileApp::<JourneyState, _>::new(JourneyScreen)`. It names the same state and root component as the Web and desktop launchers. Both translation bundles and environment synchronization are installed on every shell, so moving to iOS does not silently remove localization.

Apply that rule to the rest of your app's setup too. If startup hydration, a route handler, jobs or a design system are part of the shared app, the mobile launcher needs the corresponding setup. A thin shell should not mean an incomplete shell.

Keep the generated target entrypoint pointed at `run_mobile`. Shared reducers still perform synchronous state transitions and request asynchronous work through effects. Moving network requests into a Swift startup file or component conversion would change the application's execution model merely because it gained another target.

## Check the original target and the new one

```sh
cargo test
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Select a simulator with [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/). Repeat the journey, language and snapshot flow on iOS, with the keyboard open and in both orientations. Run the original target again with its normal command; changing Cargo features or shell setup should not hide a regression there.

The generated host smoke test checks that the app starts and its control endpoint responds. It does not establish parity of every feature, keyboard behavior, visual layout or native permission path. Check those capabilities individually and make unsupported operations visible rather than silently substituting simulated data.

For a physical iPhone, follow [the installation guide](/blog/install-a-fission-app-on-a-physical-iphone/) and its signing requirements. Simulator launch and signed-device distribution are different outcomes.
