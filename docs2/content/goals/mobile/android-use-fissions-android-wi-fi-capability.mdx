## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-use-fissions-android-wi-fi-capability
cd android-use-fissions-android-wi-fi-capability
fission add-target android --project-dir .
fission add-capability wifi --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-use-fissions-android-wi-fi-capability/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

## Build the upload preparation screen

Start with a technician preparing an offline inspection report. The screen identifies the work order and lets the technician draft an observation while the report waits to upload. That draft stays in the screen until a real save action is added. The next step requests permission and scans; Fission's Android provider does not join networks or change the device's connection, so the technician uses Android Settings for that.

## Run the Wifi operation through Fission

Keep host work out of component conversion. The button dispatches a typed action, its reducer queues the capability request, and separate completion reducers update the screen. The Web preview installs `MemoryWifiHost` and sends the same operation through Fission’s typed capability path. Its deterministic response is not a claim about device hardware, OS permission or native platform support.

The Web preview uses MemoryWifiHost sample networks. It does not scan nearby Wi-Fi or connect to a real network.

use fission::prelude::*;

#[derive(Debug, Default)]
pub struct WorkOrderState {
    pub pending: bool,
    pub result: Option<String>,
    pub error: Option<String>,
}

impl GlobalState for WorkOrderState {}

#[fission_reducer(RunCapability)]
pub fn run_capability(state: &mut WorkOrderState, ctx: &mut ReducerContext<WorkOrderState>) {
    state.pending = true;
    state.result = None;
    state.error = None;

    let ok: ActionEnvelope = WifiPermissionReceived.into();
    let err: ActionEnvelope = WifiPermissionFailed.into();

    ctx.effects
        .wifi()
        .request_permission(WifiPermissionRequest {
            reason: Some("Scan nearby Wi-Fi networks for the work-site upload connection.".into()),
        })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(WifiPermissionReceived)]
pub fn wifi_permission_received(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    match ctx.input.capability_ok(REQUEST_WIFI_PERMISSION) {
        Some(WifiPermission::Granted) => {
            state.pending = true;
            let ok: ActionEnvelope = CapabilitySucceeded.into();
            let err: ActionEnvelope = CapabilityFailed.into();

            ctx.effects
                .wifi()
                .scan_networks(WifiScanRequest {
                    ssid_prefix: None,
                    include_hidden: false,
                    timeout_ms: Some(5_000),
                })
                .on_ok(ok)
                .on_err(err);
        }
        Some(_) => {
            state.pending = false;
            state.error = Some(
                "Wi-Fi permission was not granted. Connect in Android Settings, then return to this work order."
                    .into(),
            );
        }
        None => {
            state.pending = false;
            state.error = Some("The host completed without a Wi-Fi permission result.".into());
        }
    }
}

#[fission_reducer(WifiPermissionFailed)]
pub fn wifi_permission_failed(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.result = None;
    state.error = Some(ctx
        .input
        .capability_error(REQUEST_WIFI_PERMISSION)
        .map(|error| {
            format!(
                "{}: {}. Connect in Android Settings, then return here.",
                error.code, error.message
            )
        })
        .or_else(|| {
            ctx.input
                .capability_error_message(REQUEST_WIFI_PERMISSION)
                .map(str::to_owned)
        })
        .unwrap_or_else(|| "Android did not return a Wi-Fi permission result.".into()));
}

#[fission_reducer(CapabilitySucceeded)]
pub fn capability_succeeded(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.error = None;
    state.result = ctx
        .input
        .capability_ok(SCAN_WIFI_NETWORKS)
        .map(|value| {
            let names = value
                .networks
                .iter()
                .filter(|network| !network.ssid.is_empty())
                .map(|network| network.ssid.as_str())
                .collect::<Vec<_>>();
            if names.is_empty() {
                "The scan returned no visible network names.".to_string()
            } else {
                format!("Visible network names: {}", names.join(", "))
            }
        });
    if state.result.is_none() {
        state.error = Some("The host completed without the expected typed result.".into());
    }
}

#[fission_reducer(CapabilityFailed)]
pub fn capability_failed(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.result = None;
    state.error = Some(ctx
        .input
        .capability_error(SCAN_WIFI_NETWORKS)
        .map(|error| format!("{}: {}", error.code, error.message))
        .or_else(|| {
            ctx.input
                .capability_error_message(SCAN_WIFI_NETWORKS)
                .map(str::to_owned)
        })
        .unwrap_or_else(|| "The host returned an error without details.".into()));
}

pub fn callback_registry() -> ActionRegistry<WorkOrderState> {
    let mut registry = ActionRegistry::new();
    registry.register(reduce_with!(wifi_permission_received));
    registry.register(reduce_with!(wifi_permission_failed));
    registry.register(reduce_with!(capability_succeeded));
    registry.register(reduce_with!(capability_failed));
    registry
}

fission_component! {
    pub WorkOrderScreen<WorkOrderState> {
        state {
            note_draft: String = String::new(),
        }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let action = with_reducer!(cx.build, RunCapability, run_capability);
        let status = if state.pending {
            cx.tr("work.waiting")
        } else if let Some(error) = &state.error {
            format!("{}: {error}", cx.tr("work.error"))
        } else if let Some(result) = &state.result {
            format!("{}: {result}", cx.tr("work.result"))
        } else {
            cx.tr("work.ready")
        };
    } =>
    SemanticsRegion(
        identifier: Some("work-order-wifi".to_string()),
        label: Some(cx.tr("work.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("work.site"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("work.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("work.asset"))
                    .color(tokens.colors.text_secondary),
                Text(cx.tr("work.context")),
                TextInput(
                    label: Some(cx.tr("work.note.label").into()),
                    placeholder: Some(cx.tr("work.note.placeholder").into()),
                    helper_text: Some(cx.tr("work.note.help").into()),
                    bind: screen.note_draft,
                    multiline: true,
                    semantics_identifier: "work-order.note-draft".to_string(),
                ),
                Button(
                    child: Text(cx.tr("work.action")),
                    key: "run-capability",
                    variant: ButtonVariant::Primary,
                    disabled: state.pending,
                    loading: state.pending,
                    on_press: action,
                ),
                Container(Text(status))
                    .padding_all(tokens.spacing.m)
                    .bg(tokens.colors.background)
                    .border(tokens.colors.border, 1.0)
                    .border_radius(tokens.radii.medium),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}

## Verify the native request on Android

The website preview cannot exercise the native provider. Build and launch this target on a supported emulator or device, then use the feature action from the component above. Check the result the host actually returns, including denial, cancellation or unsupported hardware where those outcomes apply.

Repeat with the feature unavailable, denied or cancelled, as applicable. Confirm the screen preserves the user’s existing data and offers the right recovery step. Use a physical device when the behavior depends on real hardware or an operating-system prompt.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. A release build checks packaging, but none of these commands proves a physical permission or hardware flow works.


### Emulator and connected-device commands

Run these emulator checks from the generated project root:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
```


For a real capability check, use an Android phone that has the required hardware and permission. Connect it with USB or Wi-Fi debugging, confirm its serial, then run the app on that device:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

An emulator can exercise the UI and memory-provider outcomes; it is not evidence that physical hardware or an OS permission flow works.
