## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-understand-fissions-generated-android-project
cd android-understand-fissions-generated-android-project
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-understand-fissions-generated-android-project/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

## Use the generated starter counter

Fission creates a small counter app that is enough to verify install, launch and input without adding unrelated product logic. The browser preview changes only its own counter state; it cannot inspect or change the SDK, emulator, device, linker, signing or package described below.

<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

#[derive(Default, Debug, Clone, PartialEq)]
pub struct CounterState {
    pub count: i32,
}

impl GlobalState for CounterState {}

fission_component! {
    pub CounterApp<CounterState> {}
    view(_app, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("starter-counter".to_string()),
        label: Some("Fission starter counter".to_string()),
        child: Container(
            Column(
                gap: tokens.spacing.l,
                children: [
                    Text("Fission starter counter")
                        .size(tokens.typography.heading1_size),
                    Text(format!("Count: {}", state.count))
                        .size(tokens.typography.display_md_size),
                    Button(
                        child: Text("Increment"),
                        key: "increment",
                        on_press: reduce { state.count += 1; },
                    )
                    .semantics_identifier("counter.increment"),
                ],
            ),
        )
        .padding_all(tokens.spacing.xl)
        .width_length(Length::percent(100.0))
        .height_length(Length::percent(100.0))
        .bg(tokens.colors.background),
    )
}
```

## Understand Fission’s generated Android project

Start at `fission.toml`: it is where the project declares its app identity, targets and capabilities. The shared Rust application is under `src/`; `platforms/android/` contains the generated Gradle host, manifest, capability glue and launch/package scripts. Read `platforms/android/README.md` before changing host configuration. Fission syncs some settings into generated files when you build or change targets, so keep app behavior in Rust and make target/capability changes in the documented configuration rather than patching generated files without checking their source.

## Trace the source into the Android host

Build the target after inspecting the project and host README. The build syncs target configuration and packages the shared Rust library into the Android host. Then inspect the generated manifest and Gradle configuration to see what the host will package.

```sh
fission doctor android --project-dir .
fission build --target android --project-dir .
git diff -- fission.toml platforms/android
fission devices --project-dir .
fission run --target android --project-dir .
```

`git diff` may show no platform changes if the current configuration is already synced. `fission run` launches an emulator or connected device; it does not prove Play signing or physical hardware behavior.
