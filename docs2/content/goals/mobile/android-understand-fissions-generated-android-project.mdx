The generated Android project is a host for the shared Rust app, not another implementation of it. Knowing where that boundary lies makes failures easier to locate: an unchanged Rust screen is not a Gradle dependency problem, and a missing Android permission is not something a Compose component can fix by changing its label.

Here, we follow one small counter from Rust to the installed app. A counter is appropriate for this task because it checks launch and input without adding a service, database or fictitious device workflow. It is not a model for where every application should keep its state.

## Create the project and add Android

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/), then prepare [an emulator](/blog/create-and-launch-a-fission-android-emulator/) or connect [a phone](/blog/run-a-fission-app-on-a-physical-android-phone/).

```sh
cargo install cargo-fission
fission init android-understand-fissions-generated-android-project
cd android-understand-fissions-generated-android-project
fission add-target android --project-dir .
cargo add serde_yaml
```

The generated `src/main.rs` selects a shell entrypoint. Shared app code remains under `src/`; target build inputs live under `platforms/android/`.

## Use a small, observable launch check

This version of the starter counter adds checked-in English and Spanish text, a safe increment limit and a focused Rust test. It is not a verbatim copy of the generated template. Both native and Web entrypoints below launch it.

```rust
use fission::prelude::*;

#[derive(Default, Debug, Clone, PartialEq, Eq)]
pub struct CounterState { pub count: u32 }
impl GlobalState for CounterState {}

impl CounterState {
    pub fn increment(&mut self) { self.count = self.count.saturating_add(1); }
}

fission_component! {
    pub CounterApp<CounterState> {}
    view(_app, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SafeArea(child: Scroll(child: Container(
        child: SemanticsRegion(
            identifier: Some("starter-counter".to_string()),
            label: Some(cx.tr("counter.title")),
            child: Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("counter.title")).size(tokens.typography.heading2_size),
                Text(cx.tr("counter.context")),
                Text(cx.tr("counter.value").replace("{count}", &state.count.to_string())),
                Button(
                    child: Text(cx.tr("counter.increment")),
                    key: "increment",
                    disabled: state.count == u32::MAX,
                    on_press: reduce { state.increment(); },
                ).semantics_identifier("counter.increment"),
            ]),
        ),
    ).padding_all(tokens.spacing.l)))
}

#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn one_action_adds_one_and_the_limit_does_not_overflow() {
        let mut state = CounterState::default();
        state.increment();
        assert_eq!(state.count, 1);
        state.count = u32::MAX;
        state.increment();
        assert_eq!(state.count, u32::MAX);
    }
}
```

pub mod app;
mod translations;

use app::{CounterApp, CounterState};
use fission::prelude::*;

#[cfg(not(any(target_arch = "wasm32", target_os = "android", target_os = "ios")))]
pub fn run_desktop() -> anyhow::Result<()> {
    DesktopApp::<CounterState, _>::new(CounterApp)
        .with_env(translations::create_env())
        .run()
}
#[cfg(any(target_os = "android", target_os = "ios"))]
fn mobile_app() -> MobileApp<CounterState, CounterApp> {
    let app = MobileApp::<CounterState, _>::new(CounterApp)
        .with_env(translations::create_env());
    #[cfg(all(target_os = "android", debug_assertions))]
    let app = app.with_test_control_port(48761);
    app
}
#[cfg(any(target_os = "android", target_os = "ios"))]
pub fn run_mobile() -> anyhow::Result<()> { mobile_app().run() }

#[cfg(target_os = "android")]
#[no_mangle]
fn android_main(app_handle: AndroidApp) {
    let _ = mobile_app().run_with_android_app(app_handle);
}
#[cfg(target_arch = "wasm32")]
#[wasm_bindgen::prelude::wasm_bindgen(start)]
pub fn run_web() -> Result<(), wasm_bindgen::JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<CounterState, _>::new(CounterApp)
        .with_env(translations::create_env())
        .run()
        .map_err(|error| wasm_bindgen::JsValue::from_str(&error.to_string()))

## Trace the files in the order they take effect

Start at `fission.toml`, then follow the generated package script rather than guessing which file owns a setting.

| Boundary | Where to look | What it owns |
| --- | --- | --- |
| Project declaration | `fission.toml` | App identity, targets, capabilities and native module inputs. |
| Shared behaviour | `src/app.rs` and other shared modules | State, reducers, routes and Compose components. |
| Shell selection | `src/lib.rs` | Desktop, Web and mobile entrypoints; Android exports `android_main`. |
| Native compilation | `platforms/android/package-apk.sh` | Cargo target/profile and placement of the resulting Rust shared library. |
| Android host | `platforms/android/java/rs/fission/runtime/FissionActivity.java` | The generated AndroidX GameActivity host and platform glue. |
| Android package | `platforms/android/AndroidManifest.xml`, Gradle files and resources | Activity/library declaration, SDK settings, dependencies and packaged assets. |

The package script builds the Rust library, copies its `.so` into the Android ABI directory, then asks Gradle to assemble the package. The generated host loads that library; the exported mobile entrypoint starts the shared app. A desktop `main` function is not the Android launch path.

Read `platforms/android/README.md` and `native-modules/README.md` before changing host inputs. Keep handwritten Java additions in an external source directory declared through `native.modules`, and declare capabilities with the CLI. Do not maintain a second copy of a generated manifest setting without checking which input regenerates it.

## Build, inspect and launch the same source

```sh
cargo test
fission doctor android --project-dir .
fission build --target android --project-dir .
git diff -- fission.toml platforms/android
fission devices --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
```

Inspect the generated manifest and Gradle files after the build. A clean diff may simply mean the declaration was already synchronised. Review a changed diff before deciding to hand-edit the output; the source of a setting may still be `fission.toml` or the generator.

On the installed app, increment once and compare the label with this source revision. That catches the common mistake of editing a preview whilst the native entrypoint still launches the starter screen from somewhere else.

<!-- fission:checkpoint -->
The result is a traced launch/package path and a small interaction on that build. Rust tests check the counter rule; host startup and interaction are separate checks. None of this qualifies Play signing, hardware capabilities or persistence.
