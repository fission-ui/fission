At Cedar Ridge Outfitters, the closing count finds **17 Trail tarps** in bin **C-12**, while the inventory system still says **18**. A stock adjustment needs a warehouse lead’s review before it is sent to the inventory service. On the shared Android handheld, the app can ask the device to verify that the current user is present before preparing that review.

This screen keeps those decisions separate. A fingerprint or device-credential response verifies a credential enrolled on this device; it does not identify the warehouse lead or grant an inventory role. After a successful check, the adjustment is only marked **ready for server review**. The backend must still check the signed-in account and its permissions before changing the saved quantity. If the prompt is cancelled or the device cannot verify anyone, the proposed count remains intact. A production app must provide its own account-based review route; this example does not implement account sign-in or submit a stock adjustment.

The browser cannot open Android’s biometric prompt, so this preview uses Fission’s real web behavior: standalone biometric authentication is unavailable. You can inspect the recovery message and confirm that the discrepancy stays unchanged. A successful prompt, cancellation, and enrollment check must be exercised in the Android app on an emulator or device.

## Create the Android app and declare biometrics

The adjustment is shared app data, so the app state owns its SKU, system quantity, physical count, and review status. The check itself runs in a reducer after the lead chooses the action. Fission calls the Android host asynchronously and dispatches a later success or failure reducer with its typed result.

## Check the device and verify the warehouse lead

The first button asks the host what authentication methods are available. Only after a usable method is reported does the screen enable **Verify warehouse lead**. This makes an unavailable device a clear recovery path instead of a surprise after the manager has started the approval.

Open the tabs from left to right. The app module separates adjustment state and capability reducers from the screen component. Enter the discrepancy yourself rather than loading a fixture into the preview. Both native and Web entrypoints start with no adjustment; preparing one validates the counts and copies the draft into app state. The Web host remains in place, so its unavailable result is the browser’s actual behaviour rather than a pretend Android prompt.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct StockAdjustment {
    pub reference: String,
    pub sku: String,
    pub product_name: String,
    pub bin: String,
    pub system_quantity: u32,
    pub physical_count: u32,
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum BiometricMethod {
    Fingerprint,
    Face,
    Iris,
    DeviceCredential,
    Other,
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum ApprovalNotice {
    CheckingDevice,
    DeviceAvailable,
    DeviceUnavailable,
    AvailabilityFailed,
    CheckDeviceFirst,
    NoCredential,
    AdjustmentMissing,
    InvalidDraft,
    WaitingForPrompt,
    ResultMissing,
    NotVerified,
    Verified(BiometricMethod),
    PromptCancelled,
    TemporarilyLocked,
    AuthenticationUnavailable,
    AuthenticationFailed,
}

impl ApprovalNotice {
    pub fn translation_key(&self) -> &'static str {
        match self {
            Self::CheckingDevice => "approval.status.checking_device",
            Self::DeviceAvailable => "approval.status.device_available",
            Self::DeviceUnavailable => "approval.status.device_unavailable",
            Self::AvailabilityFailed => "approval.status.availability_failed",
            Self::CheckDeviceFirst => "approval.status.check_device_first",
            Self::NoCredential => "approval.status.no_credential",
            Self::AdjustmentMissing => "approval.status.adjustment_missing",
            Self::InvalidDraft => "approval.status.invalid_draft",
            Self::WaitingForPrompt => "approval.status.waiting_for_prompt",
            Self::ResultMissing => "approval.status.result_missing",
            Self::NotVerified => "approval.status.not_verified",
            Self::Verified(_) => "approval.status.verified",
            Self::PromptCancelled => "approval.status.prompt_cancelled",
            Self::TemporarilyLocked => "approval.status.temporarily_locked",
            Self::AuthenticationUnavailable => "approval.status.authentication_unavailable",
            Self::AuthenticationFailed => "approval.status.authentication_failed",
        }
    }
}

impl BiometricMethod {
    pub fn translation_key(&self) -> &'static str {
        match self {
            Self::Fingerprint => "approval.method.fingerprint",
            Self::Face => "approval.method.face",
            Self::Iris => "approval.method.iris",
            Self::DeviceCredential => "approval.method.device_credential",
            Self::Other => "approval.method.other",
        }
    }
}

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct StockApprovalState {
    pub locale: Locale,
    pub adjustment: Option<StockAdjustment>,
    pub availability: Option<BiometricAvailability>,
    pub checking_device: bool,
    pub authenticating: bool,
    pub verified_with: Option<BiometricMethod>,
    pub message: Option<ApprovalNotice>,
    pub error: Option<ApprovalNotice>,
}

impl GlobalState for StockApprovalState {}

#[fission_reducer(SetApprovalLocale)]
pub fn on_set_approval_locale(state: &mut StockApprovalState, locale: Locale) {
    state.locale = locale;
}

fn device_can_verify(availability: &BiometricAvailability) -> bool {
    availability.supported && (availability.enrolled || availability.device_credential)
}

#[fission_reducer(CheckAndroidBiometrics)]
pub fn on_check_android_biometrics(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    if state.checking_device || state.authenticating {
        return;
    }

    state.checking_device = true;
    state.error = None;
    state.message = Some(ApprovalNotice::CheckingDevice);

    let on_ok = ctx.effects.bind(
        AndroidBiometricsAvailable,
        reduce_with!(on_android_biometrics_available),
    );
    let on_err = ctx.effects.bind(
        AndroidBiometricsUnavailable,
        reduce_with!(on_android_biometrics_unavailable),
    );

    ctx.effects
        .biometrics()
        .availability()
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(AndroidBiometricsAvailable)]
pub fn on_android_biometrics_available(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.checking_device = false;
    let Some(availability) = ctx.input.capability_ok(GET_BIOMETRIC_AVAILABILITY) else {
        state.availability = None;
        state.message = None;
        state.error = Some(ApprovalNotice::AvailabilityFailed);
        return;
    };

    let ready = device_can_verify(&availability);
    state.availability = Some(availability);
    state.error = None;
    state.message = Some(if ready {
        ApprovalNotice::DeviceAvailable
    } else {
        ApprovalNotice::DeviceUnavailable
    });
}

#[fission_reducer(AndroidBiometricsUnavailable)]
pub fn on_android_biometrics_unavailable(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.checking_device = false;
    state.availability = None;
    state.message = None;
    let Some(error) = ctx.input.capability_error(GET_BIOMETRIC_AVAILABILITY) else {
        state.error = Some(ApprovalNotice::AvailabilityFailed);
        return;
    };

    state.error = Some(match error.code.as_str() {
        "unsupported" | "unavailable" => ApprovalNotice::DeviceUnavailable,
        _ => ApprovalNotice::AvailabilityFailed,
    });
}

#[fission_reducer(VerifyWarehouseLead)]
pub fn on_verify_warehouse_lead(
    state: &mut StockApprovalState,
    reason: String,
    title: String,
    subtitle: String,
    fallback_title: String,
    cancel_title: String,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    if state.authenticating || state.verified_with.is_some() {
        return;
    }
    let Some(availability) = state.availability.as_ref() else {
        state.error = Some(ApprovalNotice::CheckDeviceFirst);
        state.message = None;
        return;
    };
    if !device_can_verify(availability) {
        state.error = Some(ApprovalNotice::NoCredential);
        state.message = None;
        return;
    }
    if state.adjustment.is_none() {
        state.error = Some(ApprovalNotice::AdjustmentMissing);
        state.message = None;
        return;
    }

    state.authenticating = true;
    state.error = None;
    state.message = Some(ApprovalNotice::WaitingForPrompt);

    let on_ok = ctx.effects.bind(
        WarehouseLeadVerified,
        reduce_with!(on_warehouse_lead_verified),
    );
    let on_err = ctx.effects.bind(
        WarehouseLeadVerificationFailed,
        reduce_with!(on_warehouse_lead_verification_failed),
    );

    ctx.effects
        .biometrics()
        .authenticate(BiometricAuthenticateRequest {
            reason,
            title: Some(title),
            subtitle: Some(subtitle),
            fallback_title: Some(fallback_title),
            cancel_title: Some(cancel_title),
            allow_device_credential: true,
            required_strength: BiometricStrength::Any,
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(WarehouseLeadVerified)]
pub fn on_warehouse_lead_verified(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.authenticating = false;
    let Some(result) = ctx.input.capability_ok(AUTHENTICATE_BIOMETRIC) else {
        state.verified_with = None;
        state.message = None;
        state.error = Some(ApprovalNotice::ResultMissing);
        return;
    };
    if !result.verified {
        state.verified_with = None;
        state.message = None;
        state.error = Some(ApprovalNotice::NotVerified);
        return;
    }

    let method = if result.used_device_credential {
        BiometricMethod::DeviceCredential
    } else {
        match result.kind {
            Some(BiometricKind::Fingerprint) => BiometricMethod::Fingerprint,
            Some(BiometricKind::Face) => BiometricMethod::Face,
            Some(BiometricKind::Iris) => BiometricMethod::Iris,
            Some(BiometricKind::DeviceCredential) => BiometricMethod::DeviceCredential,
            Some(BiometricKind::Unknown) | None => BiometricMethod::Other,
        }
    };
    state.verified_with = Some(method.clone());
    state.error = None;
    state.message = Some(ApprovalNotice::Verified(method));
}

#[fission_reducer(WarehouseLeadVerificationFailed)]
pub fn on_warehouse_lead_verification_failed(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.authenticating = false;
    state.verified_with = None;
    state.message = None;
    let Some(error) = ctx.input.capability_error(AUTHENTICATE_BIOMETRIC) else {
        state.error = Some(ApprovalNotice::AuthenticationFailed);
        return;
    };

    state.error = Some(match error.code.as_str() {
        "cancelled" | "canceled" | "user_cancel" | "system_cancelled" => ApprovalNotice::PromptCancelled,
        "locked_out" | "lockout" => ApprovalNotice::TemporarilyLocked,
        "not_enrolled" | "unavailable" | "unsupported" | "permission_denied" => {
            ApprovalNotice::AuthenticationUnavailable
        }
        _ => ApprovalNotice::AuthenticationFailed,
    });
}

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

const SOURCES: [(&str, &str); 2] = [
    ("en-US", include_str!("../../i18n/en-US.yaml")),
    ("es-ES", include_str!("../../i18n/es-ES.yaml")),
];

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in SOURCES {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid biometric tutorial translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

## Test the Android prompt and recovery paths

The browser preview exercises the unavailable-host recovery path. It cannot show Android’s real biometric prompt or prove that a device has enrolled a fingerprint. Test the installed app on an Android emulator or handheld after declaring the capability.

On a supported device, check availability and approve the discrepancy with a fingerprint. Then cancel the prompt and verify that the adjustment remains a proposal. Try a device with no enrolled biometric or an older Android API; the screen should keep the count, explain why local verification is unavailable, and direct the lead to warehouse account sign-in. Android 10 (API level 29) or later is required by this Fission host’s availability check.
