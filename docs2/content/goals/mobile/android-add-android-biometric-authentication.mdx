At Cedar Ridge Outfitters, the closing count finds **17 Trail tarps** in bin **C-12**, while the inventory system still says **18**. A stock adjustment needs a warehouse lead’s review before it is sent to the inventory service. On the shared Android handheld, the app can ask the device to verify that the current user is present before preparing that review.

This screen keeps those decisions separate. A fingerprint or device-credential response confirms the local user; it does not grant that person an inventory role. After a successful check, the adjustment is only marked **ready for server review**. The backend must still check the signed-in account and its permissions before changing the saved quantity. If the prompt is cancelled or the device cannot verify anyone, the proposed count remains intact and the lead can use account sign-in instead.

The browser cannot open Android’s biometric prompt, so this preview uses Fission’s real web behavior: standalone biometric authentication is unavailable. You can inspect the recovery message and confirm that the discrepancy stays unchanged. A successful prompt, cancellation, and enrollment check must be exercised in the Android app on an emulator or device.

## Check the device and verify the warehouse lead

The first button asks the host what authentication methods are available. Only after a usable method is reported does the screen enable **Verify warehouse lead**. This makes an unavailable device a clear recovery path instead of a surprise after the manager has started the approval.

Open the tabs from left to right. The app module separates adjustment state and capability reducers from the screen component. The final tab starts the browser preview with one review waiting. It leaves the web host in place, so its unavailable result is the browser’s actual behavior rather than a pretend Android prompt.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct StockAdjustment {
    pub reference: String,
    pub sku: String,
    pub product_name: String,
    pub bin: String,
    pub system_quantity: u32,
    pub physical_count: u32,
}

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct StockApprovalState {
    pub adjustment: Option<StockAdjustment>,
    pub availability: Option<BiometricAvailability>,
    pub checking_device: bool,
    pub authenticating: bool,
    pub verified_with: Option<String>,
    pub message: Option<String>,
    pub error: Option<String>,
}

impl GlobalState for StockApprovalState {}

fn device_can_verify(availability: &BiometricAvailability) -> bool {
    availability.supported && (availability.enrolled || availability.device_credential)
}

#[fission_reducer(CheckAndroidBiometrics)]
pub fn on_check_android_biometrics(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    if state.checking_device || state.authenticating {
        return;
    }

    state.checking_device = true;
    state.error = None;
    state.message = Some("Checking this Android device’s authentication options…".to_string());

    let on_ok = ctx.effects.bind(
        AndroidBiometricsAvailable,
        reduce_with!(on_android_biometrics_available),
    );
    let on_err = ctx.effects.bind(
        AndroidBiometricsUnavailable,
        reduce_with!(on_android_biometrics_unavailable),
    );

    ctx.effects
        .biometrics()
        .availability()
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(AndroidBiometricsAvailable)]
pub fn on_android_biometrics_available(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.checking_device = false;
    let Some(availability) = ctx.input.capability_ok(GET_BIOMETRIC_AVAILABILITY) else {
        state.availability = None;
        state.message = None;
        state.error = Some("The device returned no availability result. Use warehouse account sign-in before continuing.".to_string());
        return;
    };

    let ready = device_can_verify(&availability);
    let reason = availability.reason.clone();
    state.availability = Some(availability);
    state.error = None;
    state.message = Some(if ready {
        "An enrolled local method is available. The lead can continue with this adjustment.".to_string()
    } else if let Some(reason) = reason {
        format!("This device cannot verify a local user: {reason}. Use warehouse account sign-in instead.")
    } else {
        "No enrolled biometric or allowed device credential is available. Use warehouse account sign-in instead.".to_string()
    });
}

#[fission_reducer(AndroidBiometricsUnavailable)]
pub fn on_android_biometrics_unavailable(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.checking_device = false;
    state.availability = None;
    state.message = None;
    let Some(error) = ctx.input.capability_error(GET_BIOMETRIC_AVAILABILITY) else {
        state.error = Some("The device could not check its authentication options. Use warehouse account sign-in instead.".to_string());
        return;
    };

    state.error = Some(match error.code.as_str() {
        "unsupported" | "unavailable" => {
            "This Android device does not support the requested local check. Use warehouse account sign-in instead.".to_string()
        }
        _ => "The device could not check its authentication options. Use warehouse account sign-in instead.".to_string(),
    });
}

#[fission_reducer(VerifyWarehouseLead)]
pub fn on_verify_warehouse_lead(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    if state.authenticating || state.verified_with.is_some() {
        return;
    }
    let Some(availability) = state.availability.as_ref() else {
        state.error = Some("Check the device before asking it to verify the warehouse lead.".to_string());
        state.message = None;
        return;
    };
    if !device_can_verify(availability) {
        state.error = Some("No usable local credential is available. Use warehouse account sign-in instead.".to_string());
        state.message = None;
        return;
    }
    let Some(adjustment) = state.adjustment.as_ref() else {
        state.error = Some("Open a stock adjustment before asking the lead to verify.".to_string());
        state.message = None;
        return;
    };

    let reference = adjustment.reference.clone();
    let sku = adjustment.sku.clone();
    let physical_count = adjustment.physical_count;
    let system_quantity = adjustment.system_quantity;
    state.authenticating = true;
    state.error = None;
    state.message = Some("Waiting for the Android authentication prompt…".to_string());

    let on_ok = ctx.effects.bind(
        WarehouseLeadVerified,
        reduce_with!(on_warehouse_lead_verified),
    );
    let on_err = ctx.effects.bind(
        WarehouseLeadVerificationFailed,
        reduce_with!(on_warehouse_lead_verification_failed),
    );

    ctx.effects
        .biometrics()
        .authenticate(BiometricAuthenticateRequest {
            reason: format!(
                "Review stock adjustment {reference} for {sku}: {physical_count} counted, {system_quantity} in the system"
            ),
            title: Some("Review stock adjustment".into()),
            subtitle: Some(format!("{sku} · {reference}")),
            fallback_title: Some("Use device credential".into()),
            cancel_title: Some("Cancel".into()),
            allow_device_credential: true,
            required_strength: BiometricStrength::Any,
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(WarehouseLeadVerified)]
pub fn on_warehouse_lead_verified(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.authenticating = false;
    let Some(result) = ctx.input.capability_ok(AUTHENTICATE_BIOMETRIC) else {
        state.verified_with = None;
        state.message = None;
        state.error = Some("The device returned no verification result. The stock adjustment remains a proposal.".to_string());
        return;
    };
    if !result.verified {
        state.verified_with = None;
        state.message = None;
        state.error = Some("The device did not verify the lead. Inventory remains unchanged; try again or use account sign-in.".to_string());
        return;
    }

    let method = if result.used_device_credential {
        "device credential"
    } else {
        match result.kind {
            Some(BiometricKind::Fingerprint) => "fingerprint",
            Some(BiometricKind::Face) => "face recognition",
            Some(BiometricKind::Iris) => "iris recognition",
            Some(BiometricKind::DeviceCredential) => "device credential",
            Some(BiometricKind::Unknown) | None => "local authentication",
        }
    };
    state.verified_with = Some(method.to_string());
    state.error = None;
    state.message = Some(format!(
        "Local verification passed with {method}. The adjustment is ready for inventory-service review; saved stock is unchanged."
    ));
}

#[fission_reducer(WarehouseLeadVerificationFailed)]
pub fn on_warehouse_lead_verification_failed(
    state: &mut StockApprovalState,
    ctx: &mut ReducerContext<StockApprovalState>,
) {
    state.authenticating = false;
    state.verified_with = None;
    state.message = None;
    let Some(error) = ctx.input.capability_error(AUTHENTICATE_BIOMETRIC) else {
        state.error = Some("No verification result came back. The adjustment is unchanged; try again or use warehouse account sign-in.".to_string());
        return;
    };

    state.error = Some(match error.code.as_str() {
        "cancelled" | "canceled" | "user_cancel" => {
            "The prompt was cancelled. The adjustment is unchanged; try again or use warehouse account sign-in.".to_string()
        }
        "not_enrolled" | "unavailable" | "unsupported" | "permission_denied" => {
            "This device cannot complete local verification right now. Use warehouse account sign-in instead.".to_string()
        }
        _ => "The device did not verify the lead. The adjustment is unchanged; try again or use warehouse account sign-in.".to_string(),
    });
}

## Test the Android prompt and recovery paths

The browser preview exercises the unavailable-host recovery path. It cannot show Android’s real biometric prompt or prove that a device has enrolled a fingerprint. Test the installed app on an Android emulator or handheld after declaring the capability.

On a supported device, check availability and approve the discrepancy with a fingerprint. Then cancel the prompt and verify that the adjustment remains a proposal. Try a device with no enrolled biometric or an older Android API; the screen should keep the count, explain why local verification is unavailable, and direct the lead to warehouse account sign-in. Android 10 (API level 29) or later is required by this Fission host’s availability check.

Run the target checks from the generated project root:
