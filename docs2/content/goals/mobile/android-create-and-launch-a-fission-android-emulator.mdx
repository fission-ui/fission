An Android Virtual Device (AVD) is a saved emulator configuration, not the emulator process itself. Creating one establishes its system image and device profile; booting it starts the Android system that will run the app. A successful Rust build proves neither.

We will use Fission's generated launcher to create or reuse an arm64 AVD, wait for Android to boot, and install the app. Start with the [Android setup guide](/blog/set-up-rust-android-gui-development-with-fission/) and [SDK packages](/blog/install-android-sdk-packages-for-a-fission-app/) if the tools or system image are missing.

## Create the project and add the target

Start with a fresh project and add Android as a target. If you have not installed the SDK and NDK yet, do that before continuing.

```sh
cargo install cargo-fission
fission init android-create-and-launch-a-fission-android-emulator
cd android-create-and-launch-a-fission-android-emulator
cargo add serde_yaml
fission add-target android --project-dir .
```

## Files created by Fission

This is the tree Fission creates. The app and its behaviour live under `src/`; `platforms/android/` is the generated host used to launch and package the Android app. Keep the shared Rust code in one place rather than creating a separate Android version of the screen.

```text
android-create-and-launch-a-fission-android-emulator/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # Compose checklist
└── platforms/
    └── android/              # generated Android host
```

The generated platform directory owns launch and packaging. The shared Rust library owns this screen and its translations.

## Keep an observable launch checklist

Use the same screen in the browser and the native app, but do not confuse those results. A browser click checks the interface; changing a checkbox on the selected native device checks that this build actually launched there. The marks record your observations, not detected toolchain status, and can be cleared if you need to repeat a check.

Replace both `src/app.rs` and `src/lib.rs` so the generated native entrypoint launches this component. Keep the language bundles in `i18n/` and the setup in `src/translations.rs`. The separate preview entrypoint is only for this documentation page.

        .with_title("Android emulator checklist");

fn android_main(app_handle: AndroidApp) {

use std::collections::HashMap;
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in setup translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Create and launch the generated Android AVD

The generated host includes `platforms/android/run-emulator.sh`. Keep only the intended emulator running for this script: it can reuse an already running emulator rather than booting the configured AVD. From the project root, it finds an installed arm64 Google APIs image, creates the default `FissionApi<level>Arm64` AVD when needed, then boots the emulator, builds and installs the APK, and launches the app. First follow the [Android SDK setup tutorial](/blog/set-up-rust-android-gui-development-with-fission/) if those tools are not installed yet.

```sh
fission doctor android --project-dir .
sdkmanager --list_installed
./platforms/android/run-emulator.sh
```

The first command reports missing Android or Rust prerequisites. The second shows which SDK packages are installed. The launcher prints each build and boot stage; let the first AVD finish booting before you start another emulator.

Set `ANDROID_AVD_NAME` if you want to use a different AVD. The launcher can only use an image already installed in the SDK. If it cannot find an arm64 Google APIs image, check the API level in `platforms/android/README.md`, install it with `sdkmanager`, and try again.

### Diagnose a boot or connection failure

```sh
emulator -accel-check
adb devices -l
fission devices --project-dir .
```

Check acceleration separately from the ADB connection. In the ADB output, `device` means ADB can communicate with Android; it does not prove that the system has finished booting. An `offline` entry means the connection is not yet usable. Use `adb -s <emulator-serial> shell getprop sys.boot_completed` to check for `1` before relying on the app launcher. Then check `fission devices` to make sure Fission sees the AVD too. If the emulator has a graphics problem, cold-boot it from Android Studio's Device Manager before changing the generated script.
