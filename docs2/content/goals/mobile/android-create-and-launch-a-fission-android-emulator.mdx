Before an Android app can run, Rust, the Android SDK, the NDK and an emulator all need to agree about the target. This guide checks them in the order Fission uses them, so when a step fails you know which part to fix instead of guessing at the whole toolchain.

The setup is ready when an AVD boots and Fission can detect it. The browser
preview only shows the sample screen; it cannot install SDK packages, create
an emulator, or connect to a phone. Use the terminal output to verify Android
setup.

### The Fission pieces in this example

The app's behaviour stays in shared Rust; the generated Android host handles launch and packaging. The small browser preview gives the page something to render, but it does not test Android. Use the commands below to check the SDK, emulator and generated host.

## Create the project and add the target

Start with a fresh project and add Android as a target. If you have not installed the SDK and NDK yet, do that before continuing.

```sh
cargo install cargo-fission
fission init android-create-and-launch-a-fission-android-emulator
cd android-create-and-launch-a-fission-android-emulator
fission add-target android --project-dir .
```

## Files created by Fission

This is the tree Fission creates. The app and its behaviour live under `src/`; `platforms/android/` is the generated host used to launch and package the Android app. Keep the shared Rust code in one place rather than creating a separate Android version of the screen.

```text
android-create-and-launch-a-fission-android-emulator/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, state, reducers and reusable `fission_component!` components in the shared Rust project. Add a separate state, service or effect module when the feature gives it a real job; do not create one just to fill out the folder tree. The generated host owns Android launch and packaging, so shared components do not need to import Android APIs.

mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn load_bundle(locale: &str, source: &str) -> TranslationBundle {
    TranslationBundle {
        locale: Locale::from(locale),
        messages: serde_yaml::from_str(source).expect("valid tutorial translations"),
    }
}

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    env.i18n
        .add_bundle(load_bundle("en-US", include_str!("i18n/en-US.yaml")));
    env.i18n
        .add_bundle(load_bundle("es-ES", include_str!("i18n/es-ES.yaml")));
    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::AndroidEmulatorReadiness)
        .with_env(preview_env())
        .with_title("Fission Android Emulator Setup")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Create and launch the generated Android AVD

The generated host includes `platforms/android/run-emulator.sh`. From the project root, it finds an installed arm64 Google APIs image, creates the default `FissionApi<level>Arm64` AVD when needed, then boots the emulator, builds and installs the APK, and launches the app. First follow the [Android SDK setup tutorial](/blog/set-up-rust-android-gui-development-with-fission/) if those tools are not installed yet.

```sh
fission doctor android --project-dir .
sdkmanager --list_installed
./platforms/android/run-emulator.sh
```

The first command reports missing Android or Rust prerequisites. The second shows which SDK packages are installed. The launcher prints each build and boot stage; let the first AVD finish booting before you start another emulator.

Set `ANDROID_AVD_NAME` if you want to use a different AVD. The launcher can only use an image already installed in the SDK. If it cannot find an arm64 Google APIs image, check the API level in `platforms/android/README.md`, install it with `sdkmanager`, and try again.

### Diagnose a boot or connection failure

```sh
emulator -accel-check
adb devices -l
fission devices --project-dir .
```

The emulator needs hardware acceleration. In the ADB output, `device` means it is ready; `offline` usually means it is still booting. Then check `fission devices` to make sure Fission sees the AVD too. If the emulator has a graphics problem, cold-boot it from Android Studio's Device Manager before changing the generated script.
