    env

## Handle mobile lifecycle changes while effects are in flight

When the app pauses, keep product state in GlobalState for the current app session or persist it in Fission Store if it must survive process termination. Do not expect a component conversion or a background thread to preserve an unfinished operation. On resume, re-check the request ID, refresh transient permission status and ignore results from an obsolete screen. Test pausing during a request, process termination, restart with a pending record, and a late response after the user navigates away. Do not promise background execution unless the operating system service has been configured for it.

This browser-safe preview keeps its work-order data in `GlobalState` and uses a local effect to exercise request IDs and completion reducers. It does not call a server, persist data, or test an operating-system lifecycle callback.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct WorkOrderState {
    pub note: String,
    pub ready_for_sync: bool,
    pub sync_request_id: u64,
    pub sync_pending: bool,
    pub sync_failed: bool,
    pub synced_note: Option<String>,
}

impl Default for WorkOrderState {
    fn default() -> Self {
        Self {
            note: String::new(),
            ready_for_sync: false,
            sync_request_id: 0,
            sync_pending: false,
            sync_failed: false,
            synced_note: None,
        }
    }
}

impl GlobalState for WorkOrderState {}

#[fission_effect]
async fn sync_work_order_note(
    request_id: u64,
    note: String,
) -> Result<(u64, String), (u64, String)> {
    if note.trim().is_empty() {
        Err((request_id, "empty-note".to_string()))
    } else {
        Ok((request_id, note))
    }
}

fission_component! {
    pub MobileLifecycleChangesEffectsAre<WorkOrderState>
    view(_screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let note_is_synced = state.synced_note.as_ref() == Some(&state.note);
    } =>
    SemanticsRegion(
        identifier: Some("work-order.note".to_string()),
        label: Some(cx.tr("work_order.a11y")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text(cx.tr("work_order.heading"))
                            .size(tokens.typography.heading2_size),
                        Text(cx.tr("work_order.location"))
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: cx.tr(if state.sync_pending {
                        "work_order.status.syncing"
                    } else if state.sync_failed {
                        "work_order.status.failed"
                    } else if state.ready_for_sync {
                        "work_order.status.ready"
                    } else {
                        "work_order.status.draft"
                    })),
                ]),
                Divider(),
                Text(cx.tr("work_order.note.heading"))
                    .weight(tokens.typography.font_weight_semibold),
                TextInput(
                    label: Some(cx.tr("work_order.note.label").into()),
                    bind: state.note,
                    placeholder: Some(cx.tr("work_order.note.placeholder").into()),
                    multiline: true,
                    semantics_identifier: "work-order.note.input".to_string(),
                ),
                Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                    Button(
                        child: Text(cx.tr(if state.ready_for_sync {
                            "work_order.note.return_to_draft"
                        } else {
                            "work_order.note.ready"
                        })),
                        key: "mark-note-ready",
                        disabled: state.note.trim().is_empty() && !state.ready_for_sync,
                        on_press: reduce {
                            state.ready_for_sync = !state.ready_for_sync;
                            state.sync_failed = false;
                        },
                    ).semantics_identifier("work-order.note.ready"),
                    Button(
                        child: Text(cx.tr(if state.sync_pending {
                            "work_order.sync.latest"
                        } else if state.sync_failed {
                            "work_order.sync.retry"
                        } else {
                            "work_order.sync.start"
                        })),
                        key: "sync-work-order-note",
                        disabled: state.note.trim().is_empty() || !state.ready_for_sync,
                        on_press: effect sync_work_order_note(
                            state.sync_request_id + 1,
                            state.note.clone(),
                        ) {
                            on_start {
                                state.sync_request_id += 1;
                                state.sync_pending = true;
                                state.sync_failed = false;
                            }
                            on_ok(result) {
                                let (request_id, synced_note) = result;
                                if state.sync_request_id == request_id {
                                    state.sync_pending = false;
                                    state.synced_note = Some(synced_note);
                                }
                            }
                            on_err(error) {
                                let (request_id, _message) = error;
                                if state.sync_request_id == request_id {
                                    state.sync_pending = false;
                                    state.sync_failed = true;
                                }
                            }
                        },
                    ).semantics_identifier("work-order.note.sync"),
                ]),
                if state.sync_pending {
                    Row(gap: tokens.spacing.s, align_items: ir_op::AlignItems::Center, children: [
                        Spinner(),
                        Text(cx.tr("work_order.sync.pending"))
                            .color(tokens.colors.text_secondary),
                    ])
                } else if state.sync_failed {
                    Text(cx.tr("work_order.sync.failed"))
                        .color(tokens.colors.text_secondary)
                } else if note_is_synced {
                    Text(cx.tr("work_order.sync.done"))
                        .color(tokens.colors.text_secondary)
                } else if state.ready_for_sync {
                    Text(cx.tr("work_order.note.ready_detail"))
                        .color(tokens.colors.text_secondary)
                } else {
                    Text(cx.tr("work_order.note.draft_detail"))
                        .color(tokens.colors.text_secondary)
                },
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Check delayed and interrupted work on Android and iOS

In a Rust test, a fake service returns the result you choose instead of making a network request. Start two requests, return the newer result first, and then return the older one. Because the app stores the newest request ID, the reducer should ignore that stale response and keep the newer result on screen.

Also background the app while work is pending, then return to it. The loading state should finish or recover, errors should remain visible, and a retry should not require the user to repeat work that was already saved.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add for reducer or stale-completion rules; the generated scaffold does not create those feature tests. `fission doctor` checks each target’s toolchain, `fission run` launches its emulator or Simulator, and `fission test` checks that the generated host can start. A release build validates packaging, not real hardware behavior.
