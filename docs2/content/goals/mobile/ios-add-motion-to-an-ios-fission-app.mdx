## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-add-motion-to-an-ios-fission-app
cd ios-add-motion-to-an-ios-fission-app
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-add-motion-to-an-ios-fission-app/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

```rust
use fission::motion::{
    scalar, Motion, MotionEasing, MotionPhase, MotionPropertyId, MotionStartValue, MotionTrack,
    MotionTransition,
};
use fission::prelude::*;

fission_component! {
    pub IosMotion<()> {
        state {
            saved: bool = false,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("motion-preview".to_string()),
        label: Some(cx.tr("motion.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("motion.title"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("motion.description")),
                Button(
                    child: Text(if screen.saved {
                        cx.tr("motion.reset")
                    } else {
                        cx.tr("motion.save")
                    }),
                    key: "save",
                    on_press: reduce { screen.saved = !screen.saved; },
                ),
                if screen.saved {
                    Motion {
                        id: WidgetId::explicit("northbank.inspection-saved-banner"),
                        tracks: vec![MotionTrack {
                            property: MotionPropertyId::Opacity,
                            phase: MotionPhase::Composite,
                            from: MotionStartValue::Explicit(scalar(0.0)),
                            to: scalar(1.0),
                            transition: MotionTransition::tween(220, MotionEasing::EaseOut),
                        }],
                        child: Text::new(cx.tr("motion.saved")).into(),
                        ..Default::default()
                    }
                } else {
                    Spacer()
                },
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Add motion to an iOS Fission app

Use motion to explain a state change, such as an item entering the list or a panel opening. Keep the final state correct when animations are disabled or finish immediately; never use motion as the only signal for success, failure or selection. Use the same component state and reducer for both animated and reduced-motion paths, and avoid starting timers during component conversion. Check the screen with reduced motion enabled, after rapid repeated taps, and while the view resizes or returns from the background.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

## Check the layout and system settings on iOS

Run the same screen at a narrow phone width and a wider window. Resize or rotate while it is open, then change the system text size and appearance where this tutorial covers them. Content should reflow without clipping essential controls or status messages.

Use real platform insets for safe-area checks and let Fission’s responsive layout choose the arrangement. Avoid fixing a problem with device-specific padding that breaks the other sizes.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
