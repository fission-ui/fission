## The morning inspection round

We’re building the morning inspection board for a city tree-care crew. It needs to show which trees need attention, where they are, what the inspector found, and whether a crew has been assigned. Dispatch can assign an unowned inspection to the Green Crew, and the card and summary should update together.

Each inspection needs the same information and action, so it belongs in one reusable card. The dashboard arranges the cards and calculates its counts from shared records. The card owns presentation; app state remains the source of truth.

The browser preview starts with three sample records, so you can try the workflow before opening an emulator. They belong to the tutorial, not to production data. A real app would load inspections from a service or local database through an effect.

## Create the Android project

Install the Fission CLI, create the project, and add Android as a target. If this is your first Android build, follow the [Android development setup guide](/blog/set-up-rust-android-gui-development-with-fission/) first; it covers the SDK, NDK, and emulator setup.

```sh
cargo install cargo-fission
fission init urban-tree-rounds
cd urban-tree-rounds
fission add-target android --project-dir .
```

Fission generates the Android host and Rust application shell. Keep the records, reducers, and screen in shared Rust code. The host launches and packages that app; it shouldn’t have a second copy of the inspection rules.

## Give each inspection a clear card

Before a crew walks to a tree, it needs the inspection number, species, location, priority, and a short report. `TreeInspectionCard` keeps that information in a consistent shape. Its props describe one inspection, so the parent can reuse it without the card reaching into unrelated app state.

The first version is read-only. Check that the records are easy to scan; we’ll add the assignment action next.

## Compose the dispatch board from reusable components

Now connect each card to app state. The board derives its counts from the records, so assigning a crew can’t leave a separate summary number stale. Each `TreeInspectionCard` receives one record and binds its button to a reducer that updates `TreeRoundsState`. All cards use the same component, and each button carries the ID of its own inspection.

Each card’s `key` is its durable inspection ID. When the list changes, Fission can keep retained widget state with the right inspection instead of reusing it for whatever row moves into the same position.

The tutorial keeps the source together so you can run it without creating a set of files first. In an app you plan to grow, put the model, reducer, card, and screen in focused modules. Those boundaries are already visible here; splitting them out doesn’t change how the components fit together.

use fission::prelude::*;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum InspectionStatus {
    NeedsCrew,
    Scheduled,
    Completed,
}

impl InspectionStatus {
    fn label(self) -> &'static str {
        match self {
            Self::NeedsCrew => "Needs a crew",
            Self::Scheduled => "Scheduled",
            Self::Completed => "Completed",
        }
    }
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct TreeInspection {
    pub id: u32,
    pub species: &'static str,
    pub location: &'static str,
    pub priority: &'static str,
    pub finding: &'static str,
    pub reported_by: &'static str,
    pub status: InspectionStatus,
    pub assigned_crew: Option<&'static str>,
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct TreeRoundsState {
    pub inspections: Vec<TreeInspection>,
    pub notice: String,
}

impl Default for TreeRoundsState {
    fn default() -> Self {
        Self {
            inspections: vec![
                TreeInspection {
                    id: 184,
                    species: "London plane",
                    location: "Alder Street · bus shelter",
                    priority: "Urgent",
                    finding: "A large limb split above the shelter after last night’s wind.",
                    reported_by: "Maya Jones",
                    status: InspectionStatus::NeedsCrew,
                    assigned_crew: None,
                },
                TreeInspection {
                    id: 207,
                    species: "Silver birch",
                    location: "Oak Lane · north playground gate",
                    priority: "Routine",
                    finding: "Inspect the raised root near the gate and mark the path safe.",
                    reported_by: "Pavel Singh",
                    status: InspectionStatus::Scheduled,
                    assigned_crew: Some("Green Crew"),
                },
                TreeInspection {
                    id: 213,
                    species: "Common lime",
                    location: "Mason Square · east entrance",
                    priority: "Routine",
                    finding: "Seasonal inspection found no work required.",
                    reported_by: "Tree team",
                    status: InspectionStatus::Completed,
                    assigned_crew: Some("Tree Team"),
                },
            ],
            notice: "One urgent tree needs a crew before the afternoon route.".to_string(),
        }
    }
}

impl GlobalState for TreeRoundsState {}

#[cfg(test)]
#[path = "app_tests.rs"]
mod app_tests;

fn assign_tree_to_green_crew(state: &mut TreeRoundsState, inspection_id: u32) {
    let Some(inspection) = state
        .inspections
        .iter_mut()
        .find(|inspection| inspection.id == inspection_id)
    else {
        return;
    };

    if inspection.status != InspectionStatus::NeedsCrew {
        return;
    }

    inspection.status = InspectionStatus::Scheduled;
    inspection.assigned_crew = Some("Green Crew");
    state.notice = format!(
        "TREE-{} is on the Green Crew’s afternoon route.",
        inspection.id,
    );
}

#[fission_reducer(AssignTreeToGreenCrew)]
pub fn on_assign_tree_to_green_crew(state: &mut TreeRoundsState, inspection_id: u32) {
    assign_tree_to_green_crew(state, inspection_id);
}

fission_component! {
    pub TreeInspectionCard<TreeRoundsState> { inspection: TreeInspection }
    view(card, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let assign = with_reducer!(
            cx.build,
            AssignTreeToGreenCrew(card.inspection.id),
            on_assign_tree_to_green_crew,
        );
    } =>
    SemanticsRegion(
        identifier: Some(format!("tree-inspection-{}", card.inspection.id)),
        label: Some(format!(
            "Tree inspection {}: {}, {}",
            card.inspection.id,
            card.inspection.species,
            card.inspection.location,
        )),
        child: Container(
            Column(gap: tokens.spacing.s, align_items: ir_op::AlignItems::Start, children: [
                Row(gap: tokens.spacing.s, children: [
                    Text(format!("TREE-{}", card.inspection.id))
                        .weight(tokens.typography.font_weight_semibold),
                    Text(card.inspection.priority)
                        .color(tokens.colors.text_secondary),
                    Text(card.inspection.status.label())
                        .color(tokens.colors.text_secondary),
                ]),
                Text(card.inspection.species)
                    .weight(tokens.typography.font_weight_bold),
                Text(card.inspection.location)
                    .color(tokens.colors.text_secondary),
                Text(card.inspection.finding),
                Text(format!("Reported by {}", card.inspection.reported_by))
                    .color(tokens.colors.text_secondary),
                if let Some(crew) = card.inspection.assigned_crew {
                    Text(format!("Assigned to {crew}"))
                        .color(tokens.colors.text_secondary)
                } else {
                    Button(
                        child: Text("Assign to Green Crew"),
                        key: "assign-to-green-crew",
                        variant: ButtonVariant::Primary,
                        on_press: assign,
                    )
                    .semantics_identifier(format!(
                        "tree-inspection.assign.{}",
                        card.inspection.id,
                    ))
                },
            ]),
        )
        .padding_all(tokens.spacing.m)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.medium)
        .width_length(Length::percent(100.0)),
    )
}

fission_component! {
    pub TreeRoundsDashboard<TreeRoundsState> {}
    view(_dashboard, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let needs_crew = state.inspections.iter()
            .filter(|inspection| inspection.status == InspectionStatus::NeedsCrew)
            .count();
        let scheduled = state.inspections.iter()
            .filter(|inspection| inspection.status == InspectionStatus::Scheduled)
            .count();
        let completed = state.inspections.iter()
            .filter(|inspection| inspection.status == InspectionStatus::Completed)
            .count();
    } =>
    SemanticsRegion(
        identifier: Some("cedar-county-tree-rounds".to_string()),
        label: Some("Cedar County tree inspection round".to_string()),
        child: Scroll(
            flex_grow: 1.0,
            height: cx.view.viewport_size().height,
            child: Container(
                Column(align_items: ir_op::AlignItems::Center, children: [
                    Container(
                        Column(gap: tokens.spacing.m, children: [
                            Column(gap: tokens.spacing.xs, children: [
                                Text("Cedar County Urban Forestry")
                                    .weight(tokens.typography.font_weight_bold),
                                Text("Morning inspection round · Wednesday, 8 May")
                                    .color(tokens.colors.text_secondary),
                            ]),
                            Text(format!(
                                "Needs a crew · {}     Scheduled · {}     Completed · {}",
                                needs_crew,
                                scheduled,
                                completed,
                            )),
                            Text(state.notice.clone())
                                .color(tokens.colors.text_secondary),
                            Column(gap: tokens.spacing.s, children: [
                                for inspection in state.inspections.iter().cloned() {
                                    TreeInspectionCard(
                                        inspection.clone(),
                                        key: inspection.id,
                                    )
                                },
                            ]),
                        ])
                    )
                    .padding_all(tokens.spacing.m)
                    .width_length(Length::clamp(
                        Length::points(0.0),
                        Length::percent(100.0),
                        Length::points(760.0),
                    ))
                    .bg(tokens.colors.background),
                ]),
            )
            .width_length(Length::percent(100.0))
            .bg(tokens.colors.background),
        ),
    )
}

## Run the same shared app on Android

Replace the generated `CounterApp` wiring in `src/lib.rs` with the Android shell below. Browser and Android then use the same `TreeRoundsState`, reducer, and dashboard. The browser shell is handy for inspecting the interaction; Android adds the device window and generated host. Tree assignment stays in shared Rust code.

As you expand the app, move `TreeInspection` and `TreeRoundsState` into a model module, keep `on_assign_tree_to_green_crew` with the transition it implements, and give `TreeInspectionCard` its own component file. Android should still run the same shared app library.
