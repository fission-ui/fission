An unsupported scan and an empty scan are not the same result. An empty result means a host performed the operation and returned no matching networks. Unsupported means it cannot perform that operation at all. Calling either one "no Wi-Fi" would send the user towards the wrong recovery step.

Fission's default iOS host does not implement Wi-Fi scanning or connection. This tutorial is deliberately about handling that boundary, as its goal states, not adding native Wi-Fi support. We will issue the real capability request, show its typed result and leave a working note intact whilst the user configures a network manually.

## Create the app

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) if needed.

```sh
cargo install cargo-fission
fission init ios-use-fissions-constrained-ios-wi-fi-capability
cd ios-use-fissions-constrained-ios-wi-fi-capability
fission add-target ios --project-dir .
fission add-capability wifi --project-dir .
cargo add serde_yaml
```

The capability command records the feature and synchronizes its platform metadata. It does not install a native Wi-Fi implementation. Keep the generated `src/main.rs`; the shared library below runs the same error-handling screen on native and Web targets without a memory provider.

## Decode the host's result rather than creating one

The scan reducer binds unit completion actions, requests the typed operation and returns immediately. Its completion reads `cx.input`. A real unsupported error receives its own status instead of being disguised as denial, a successful empty list or a prepared upload.

Only one scan is admitted at a time. The working note remains editable and is not replaced by either completion path. The last successful scan, if a different host supplies one, is labelled as historical rather than displayed as proof of the current network.

```rust
use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NetworkNoteState {
    pub locale: Locale,
    pub note: String,
    pub pending: bool,
    pub status_key: String,
    pub result: Option<WifiScanResult>,
    pub error: Option<String>,
}

impl Default for NetworkNoteState {
    fn default() -> Self {
        Self {
            locale: Locale::from("en-US"),
            note: String::new(),
            pending: false,
            status_key: "network.ready".into(),
            result: None,
            error: None,
        }
    }
}
impl GlobalState for NetworkNoteState {}

pub fn try_scan(state: &mut NetworkNoteState, cx: &mut ReducerContext<NetworkNoteState>) {
    if state.pending {
        return;
    }
    state.pending = true;
    state.status_key = "network.pending".into();
    state.error = None;
    let ok = cx.effects.bind(ScanReturned, reduce_with!(scan_returned));
    let err = cx.effects.bind(ScanFailed, reduce_with!(scan_failed));
    cx.effects
        .wifi()
        .scan_networks(WifiScanRequest {
            ssid_prefix: None,
            include_hidden: false,
            timeout_ms: Some(5_000),
        })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(ScanReturned)]
fn scan_returned(state: &mut NetworkNoteState, cx: &mut ReducerContext<NetworkNoteState>) {
    state.pending = false;
    match cx.input.capability_ok(SCAN_WIFI_NETWORKS) {
        Some(result) => {
            state.result = Some(result);
            state.status_key = "network.returned".into();
        }
        None => state.status_key = "network.unexpected".into(),
    }
}

#[fission_reducer(ScanFailed)]
fn scan_failed(state: &mut NetworkNoteState, cx: &mut ReducerContext<NetworkNoteState>) {
    state.pending = false;
    let error = cx.input.capability_error(SCAN_WIFI_NETWORKS);
    state.status_key = if error
        .as_ref()
        .is_some_and(|error| error.code == "unsupported")
    {
        "network.unsupported"
    } else {
        "network.failed"
    }
    .into();
    state.error = error
        .map(|error| format!("{}: {}", error.code, error.message))
        .or_else(|| {
            cx.input
                .capability_error_message(SCAN_WIFI_NETWORKS)
                .map(str::to_owned)
        });
}
```

```rust
                Text(cx.tr("network.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("network.explanation")),
                Row(gap: tokens.spacing.s, children: [

                        child: Text(cx.tr("language.english")), key: "english",
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                TextInput(
                    value: state.note.clone(), bind(on_input): to(state.note),
                    label: Some(TextContent::Key("network.note".into())),
                    multiline: true, keyboard_type: TextInputType::Multiline,

                Button(
                    child: Text(cx.tr("network.try")), key: "try-wifi-scan",

            ]))
            .padding_all(tokens.spacing.l),

    )
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid network note translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::NetworkNoteState, env: &mut Env) {
    env.locale = state.locale.clone();
}
```

## Provide a manual path without inventing connection success

The screen explains how to use iOS Settings. It does not use an undocumented URL to jump directly into the Wi-Fi pane, and it does not ask the user for a network password that this app cannot use.

Returning from Settings leaves the running app's note available. It does not prove a connection succeeded, that a captive portal has been completed or that your server is reachable. In a real upload workflow, the upload's actual response would establish that operation's success; a Wi-Fi scan is not its authority.

The default unsupported provider's availability object reports disabled/denied/no network. Do not interpret that placeholder as an observed iPhone radio state. The typed unsupported scan error is the relevant capability boundary here.

## Check the native fallback and the capability contract separately

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Select a simulator with [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/), then repeat on an iPhone using [the installation guide](/blog/install-a-fission-app-on-a-physical-iphone/). Listen to the unsupported message with VoiceOver and check both languages at narrow widths.

A test provider belongs in test infrastructure when checking success, timeout or malformed completion handling. It must not silently replace the normal provider in the published preview or native launcher. A test with invented networks proves result handling, not iOS scanning.

Adding a native Wi-Fi provider would be a separate upstream implementation, with its own OS restrictions, permissions and qualification. This page does not claim that work is complete.
