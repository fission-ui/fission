## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-build-an-offline-first-ios-workflow
cd ios-build-an-offline-first-ios-workflow
fission add-target ios --project-dir .
fission add-capability storage --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-build-an-offline-first-ios-workflow/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

## Save locally first and reject stale sync results

Treat the local record as the source the screen renders. When a user edits a note, increment its revision, persist that revision locally, and show the edit immediately. Queue a sync effect only after the local write succeeds. Include the revision in the request and apply a network response only when it still matches the latest local revision; a slow response must not overwrite a newer edit.

Render four distinct states: **Saved on this device**, **Syncing**, **Synced**, and **Could not sync**. Keep the offline edit after a failed request and offer **Retry sync** without requiring the user to re-enter it. On restart, hydrate the local queue before starting network work, then retry only records that remain pending.

For deterministic tests, use a fake service that completes requests out of order: make revision 1 finish after revision 2, and assert that revision 2 stays visible. Also test no network, a successful retry and an app restart with an unsent edit.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

fission_component! {
    pub IosOfflineFirstWorkflow<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
        state {
            draft_revision: u32 = 0,
            sync_pending: bool = false,
            sync_error: bool = false,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("offline-workflow".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(screen.title.clone())

                    .weight(tokens.typography.font_weight_bold),
                Text(screen.goal.clone()),
                Text(format!("Local draft revision {}", screen.draft_revision)),
                Button(
                    child: Text("Save a local edit"),
                    key: "edit-draft",
                    on_press: reduce {
                        screen.draft_revision += 1;
                        screen.sync_pending = true;
                        screen.sync_error = false;
                    },
                ),
                Button(
                    child: Text("Simulate sync response"),
                    key: "sync-response",
                    on_press: reduce {
                        screen.sync_pending = false;
                        screen.sync_error = true;
                    },
                ),
                Text(if screen.sync_pending {
                    "Saved locally; waiting for sync."
                } else if screen.sync_error {
                    "Sync failed; the local draft is still available to retry."
                } else {
                    "All local changes are saved."
                }),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Verify saved data on iOS

Save one change, close the app completely, and launch it again. The screen should load the saved value before presenting it as current. Test the empty database and an unreadable or incompatible database separately so loading, default and error states are not confused.

For SQL migrations, open both a fresh database and one created by the previous schema version. For offline workflows, disconnect the network, edit locally, reconnect, and confirm a failed or stale response does not erase the newer local change.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
