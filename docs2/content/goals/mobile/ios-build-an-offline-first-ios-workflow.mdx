Start with the [shared offline-first field-notes app](/blog/build-an-offline-first-notes-app-for-android-and-ios/). It contains the note model, SQLite migration, save reducers, and startup hydration used by both mobile targets. This page focuses on running that app on iOS and checking device behavior; it does not duplicate the app logic or pretend a browser button wrote to SQLite.

The browser preview below is an interactive work-order selector so you can inspect the screen at this stage. Its sample records live only in the preview. They are not read from SQLite and do not survive a reload.

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");

    for (locale, source) in [
        ("en-US", include_str!("i18n/en-US.yaml")),
        ("es-ES", include_str!("i18n/es-ES.yaml")),
    ] {
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages: serde_yaml::from_str(source).expect("valid tutorial translations"),
        });
    }

    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::IosFieldNotesPreview)
        .with_env(preview_env())
        .with_title("Harbour Field Notes · iOS")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Run the shared app on iOS

The shared tutorial already adds Android and iOS targets and enables Store. If you are applying this to another project, add only the missing target or capability:

```sh
fission add-target ios --project-dir .
fission add-capability storage --project-dir .
```

Use the shared `MobileApp` startup path. Hydration runs after reducer registration, and the screen stays in its loading state until SQLite responds:

```rust
MobileApp::<FieldNotesState, _>::new(FieldNotesWorkspace::new())
    .with_env(create_env())
    .with_title("Harbour Field Notes")
    .with_state_init(|state| {
        state.notes.clear();
        state.selected_note_id = None;
        state.is_loading = true;
        state.notice = "notes.notice.opening".into();
    })
    .with_startup_action(PrepareFieldNotes)
```

Do not seed production state with the browser preview records. On iOS, the notes in the app come from the native SQLite provider. The linked tutorial implements local writes and a reducer that rejects stale sync-completion actions; it does not include an HTTP service or claim that a server has accepted a note.

### Verify offline persistence in Simulator

`fission run --target ios` launches an iOS Simulator. Run these commands from the shared `field-notes` project:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
```

Create or edit a field note and wait for **Saved on this device**. Turn off network access in Simulator, stop and relaunch the app, and confirm the note is still present. Restore networking; without a real service configured, the note should remain **Waiting to sync**.

For the sync boundary, test the shared reducer with two completions delivered out of order: a completion for revision 5 must not mark revision 6 as synced. The tutorial’s `SyncNoteSucceeded` action is the seam a real network effect should dispatch after the server confirms that exact revision.

```sh
cargo test
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs tests you add for the reducer and storage behavior. `fission test` checks the generated iOS host; it does not replace the offline restart check above. `fission run --target ios` is Simulator-only. Installing on a physical iPhone also requires signing and an Xcode device-install workflow.
