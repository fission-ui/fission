## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-support-ios-dynamic-type-dark-appearance-and-contrast
cd ios-support-ios-dynamic-type-dark-appearance-and-contrast
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-support-ios-dynamic-type-dark-appearance-and-contrast/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

```rust
use fission::prelude::*;
fission_component! {
    pub AccessibleReadingPreview<()> {
        state {
            large_text: bool = false,
        }
    }
    view(reader, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let sample_size = if reader.large_text {
            tokens.typography.heading2_size
        } else {
            tokens.typography.body_medium_size
        };
        let scale_action = if reader.large_text {
            cx.tr("appearance.action.standard")
        } else {
            cx.tr("appearance.action.large")
        };
    } =>
    SemanticsRegion(
        identifier: Some("ios-accessible-reading-preview".to_string()),
        label: Some(cx.tr("appearance.screen.label")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Column(gap: tokens.spacing.xs, children: [
                    Text(cx.tr("appearance.app.name"))
                        .weight(tokens.typography.font_weight_bold),
                    Text(cx.tr("appearance.route"))
                        .color(tokens.colors.text_secondary),
                ]),
                Badge(text: cx.tr("appearance.preview.badge")),
                Divider(),
                Text(cx.tr("appearance.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("appearance.summary"))
                    .color(tokens.colors.text_secondary),
                Container(
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("appearance.article.title"))
                            .weight(tokens.typography.font_weight_semibold),
                        Text(cx.tr("appearance.article.body"))
                            .size(sample_size),
                        Text(cx.tr("appearance.article.caption"))
                            .color(tokens.colors.text_secondary),
                    ])
                )
                .padding_all(tokens.spacing.m)
                .bg(tokens.colors.background)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.medium),
                Button(
                    child: Text(scale_action),
                    key: "toggle-dynamic-type-sample",
                    on_press: reduce { reader.large_text = !reader.large_text; },
                    semantics: Some(Semantics {
                        role: Role::Button,
                        label: Some(scale_action.clone()),
                        identifier: Some("appearance.toggle-text-size".to_string()),
                        ..Default::default()
                    }),
                ),
                Text(cx.tr("appearance.preview.note"))
                    .color(tokens.colors.text_secondary),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn load_bundle(locale: &str, source: &str) -> TranslationBundle {
    TranslationBundle {
        locale: Locale::from(locale),
        messages: serde_yaml::from_str(source).expect("valid tutorial translations"),
    }
}

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    env.i18n
        .add_bundle(load_bundle("en-US", include_str!("i18n/en-US.yaml")));
    env.i18n
        .add_bundle(load_bundle("es-ES", include_str!("i18n/es-ES.yaml")));
    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::AccessibleReadingPreview)
        .with_env(preview_env())
        .with_title("Northstar Reader")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Use design-system tokens and verify enlarged text and system appearance changes

Read colours, type sizes, spacing and component properties from the active design-system tokens rather than maintaining parallel light/dark constants in each component. Store a user theme override in GlobalState and mirror it into Env; let system appearance apply when the preference is Automatic. Keep layouts flexible when text grows, and do not truncate essential labels to fit a fixed card. Test light, dark, high contrast and the largest supported font scale on a real target.

## Check the layout and system settings on iOS

Run the same screen at a narrow phone width and a wider window. Resize or rotate while it is open, then change the system text size and appearance where this tutorial covers them. Content should reflow without clipping essential controls or status messages.

Use real platform insets for safe-area checks and let Fission’s responsive layout choose the arrangement. Avoid fixing a problem with device-specific padding that breaks the other sizes.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
