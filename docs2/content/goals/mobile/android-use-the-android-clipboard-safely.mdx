## Create the project and add the target

Create the project and add Android as a target. Clipboard access comes from the built-in shell, so this example does not need a project capability declaration.

```sh
cargo install cargo-fission
fission init android-use-the-android-clipboard-safely
cd android-use-the-android-clipboard-safely
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-use-the-android-clipboard-safely/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

## Run the Clipboard operation through Fission

Keep host work out of component conversion. The button dispatches a typed action, its reducer queues the capability request, and separate completion reducers update the screen. The Web preview installs `MemoryClipboardHost` and sends the same operation through Fission’s typed capability path. Its deterministic response is not a claim about device hardware, OS permission or native platform support.

The Web preview installs MemoryClipboardHost, so the write reaches Fission's typed clipboard effect without changing the browser or OS clipboard.

use fission::prelude::*;

#[derive(Debug, Default)]
pub struct WorkOrderState {
    pub pending: bool,
    pub result: Option<String>,
    pub error: Option<String>,
}

impl GlobalState for WorkOrderState {}

#[fission_reducer(RunCapability)]
pub fn run_capability(state: &mut WorkOrderState, ctx: &mut ReducerContext<WorkOrderState>) {
    state.pending = true;
    state.result = None;
    state.error = None;

    let ok: ActionEnvelope = CapabilitySucceeded.into();
    let err: ActionEnvelope = CapabilityFailed.into();

    ctx.effects
        .clipboard().write_text(ClipboardWriteTextRequest {
            text: "WO-1048 · CMP-7A-2219".into(),
        })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(CapabilitySucceeded)]
pub fn capability_succeeded(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.error = None;
    state.result = ctx
        .input
        .capability_ok(WRITE_CLIPBOARD_TEXT)
        .map(|_value| "Work-order reference copied to the host clipboard.".to_string());
    if state.result.is_none() {
        state.error = Some("The host completed without the expected typed result.".into());
    }
}

#[fission_reducer(CapabilityFailed)]
pub fn capability_failed(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.result = None;
    state.error = Some(ctx
        .input
        .capability_error(WRITE_CLIPBOARD_TEXT)
        .map(|error| format!("{}: {}", error.code, error.message))
        .or_else(|| {
            ctx.input
                .capability_error_message(WRITE_CLIPBOARD_TEXT)
                .map(str::to_owned)
        })
        .unwrap_or_else(|| "The host returned an error without details.".into()));
}

pub fn callback_registry() -> ActionRegistry<WorkOrderState> {
    let mut registry = ActionRegistry::new();
    registry.register(reduce_with!(capability_succeeded));
    registry.register(reduce_with!(capability_failed));
    registry
}

fission_component! {
    pub WorkOrderScreen<WorkOrderState> {
        state {
            note_draft: String = String::new(),
        }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let action = with_reducer!(cx.build, RunCapability, run_capability);
        let status = if state.pending {
            cx.tr("work.waiting")
        } else if let Some(error) = &state.error {
            format!("{}: {error}", cx.tr("work.error"))
        } else if let Some(result) = &state.result {
            format!("{}: {result}", cx.tr("work.result"))
        } else {
            cx.tr("work.ready")
        };
    } =>
    SemanticsRegion(
        identifier: Some("work-order-clipboard".to_string()),
        label: Some(cx.tr("work.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("work.site"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("work.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("work.asset"))
                    .color(tokens.colors.text_secondary),
                Text(cx.tr("work.context")),
                TextInput(
                    label: Some(cx.tr("work.note.label").into()),
                    placeholder: Some(cx.tr("work.note.placeholder").into()),
                    helper_text: Some(cx.tr("work.note.help").into()),
                    bind: screen.note_draft,
                    multiline: true,
                    semantics_identifier: "work-order.private-note".to_string(),
                ),
                Button(
                    child: Text(cx.tr("work.action")),
                    key: "run-capability",
                    variant: ButtonVariant::Primary,
                    disabled: state.pending,
                    loading: state.pending,
                    on_press: action,
                ),
                Container(Text(status))
                    .padding_all(tokens.spacing.m)
                    .bg(tokens.colors.background)
                    .border(tokens.colors.border, 1.0)
                    .border_radius(tokens.radii.medium),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}

## Verify the native request on Android

The website preview cannot exercise the native provider. Build and launch this target on a supported emulator or device, then use the feature action from the component above. Check the result the host actually returns, including denial, cancellation or unsupported hardware where those outcomes apply.

Repeat with the feature unavailable, denied or cancelled, as applicable. Confirm the screen preserves the user’s existing data and offers the right recovery step. Use a physical device when the behavior depends on real hardware or an operating-system prompt.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. A release build checks packaging, but none of these commands proves a physical permission or hardware flow works.
