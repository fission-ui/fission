## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-integrate-an-android-sdk-through-a-fission-native-module
cd android-integrate-an-android-sdk-through-a-fission-native-module
cargo add serde_yaml
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-integrate-an-android-sdk-through-a-fission-native-module/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");

    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid Northbank translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }

    env
}

        .run()

## Integrate an Android SDK through a Fission native module

Use a native module when an Android SDK needs a Gradle dependency, repository, manifest entry or Java/Kotlin source directory. Fission includes those inputs in the generated Android build, but it does not make SDK methods callable from Rust automatically. First check the vendor's Android install guide and the generated `platforms/android/README.md`; then add the SDK to `fission.toml`:

```toml
[[native.modules]]
name = "scanner-sdk"

[native.modules.android]
repositories = ["https://maven.vendor.example/releases"]
gradle_dependencies = ["com.vendor:scanner-sdk:1.2.3"]
source_dirs = ["native/android/scanner/src/main/java"]
```

The repository, package coordinate and source path above are examples. Replace them with values published by the SDK vendor; `source_dirs` is relative to the project root and is added as a Java source directory. Keep that source outside `platforms/android/`, which is generated. The native-module config does not enable a Kotlin plugin or create a Java/Kotlin-to-Rust bridge. It only adds build inputs to the generated host. Keep product state and UI in Rust; if Rust must consume SDK results, implement and test the platform bridge as separate work. The [native module guide](/docs/build-and-package/native-modules/) explains the build boundary, and the [Android package guide](/docs/build-and-package/android-packages/) lists Android-specific configuration.

## Confirm the dependency reaches the generated Android host

Replace the example repository and dependency coordinate with an SDK that exists, then build the Android target. Fission syncs the configured repository, dependency and Java source directories into its generated host. Inspect `platforms/android/native-modules.gradle` and the Android settings file to see those inputs. This confirms build wiring only; it does not show that Rust can call the SDK.

```sh
fission doctor android --project-dir .
fission build --target android --project-dir .
sed -n '1,160p' platforms/android/native-modules.gradle
sed -n '1,160p' platforms/android/settings.gradle.kts
```

The vendor SDK's documentation is still authoritative for its Android version, permissions, Java/Kotlin requirements and runtime behavior. This configuration example does not exercise an SDK call or claim that the example vendor coordinate resolves.
