The Android SDK is a collection of packages, not one tool whose presence establishes that a build can run. A working `adb` tells you that platform tools are available; it does not establish that a platform API, the native compiler or an accepted licence is present.

Here, we will locate one SDK installation, inspect its packages and install the missing pieces used by the generated Fission host. Keeping the installation and the selected versions explicit avoids a common failure: Android Studio and the terminal finding different toolchains.

At the end, `fission doctor` should be able to find the packages needed by the generated Android host. The browser preview cannot install them or inspect your machine; the command output is the check that matters here.

## Create the project and add the target

Create a small Fission project and add Android as a target. This gives the checks below a real project configuration to validate.

```sh
cargo install cargo-fission
fission init android-install-android-sdk-packages-for-a-fission-app
cd android-install-android-sdk-packages-for-a-fission-app
cargo add serde_yaml
fission add-target android --project-dir .
```

## Files created by Fission

This is the tree Fission generates. Shared Rust code stays under `src/`; the Android host under `platforms/android/` owns launch and packaging.

```text
android-install-android-sdk-packages-for-a-fission-app/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   ├── app.rs                 # manual Compose checklist
│   └── translations.rs        # embedded language bundles
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, state, reducers and reusable `fission_component!` components in the shared Rust project. Add a separate service or effect module only when the feature needs one. The generated host handles Android launch and packaging; shared components do not need to import Android APIs.

## Keep a manual record of the package checks

The small app below records which checks you have reviewed. It gives the native build a real interactive screen to launch, but does not pretend that a checkbox can inspect the host's SDK.

Replace the normal `src/lib.rs` as well as the screen, keeping the generated `src/main.rs`. The marked state belongs to the checklist and resets when the app restarts; the package manager remains the authority for what is installed.

use std::collections::HashMap;
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in setup translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Install the Android SDK packages the generated host needs

The [full Android setup guide](/blog/set-up-rust-android-gui-development-with-fission/) also covers the compatible Java and Gradle installation. SDK packages alone do not supply those tools.

Work from the Fission project root so the generated README and doctor output describe this app's target requirements. `sdkmanager --list_installed` shows what is already present; the package names below cover the Android platform, build tools, NDK, emulator and an arm64 Google APIs image used by the generated launcher.

### Check the SDK manager and installed packages

```sh
sdkmanager --version
sdkmanager --list_installed
```

Install **Android SDK Command-line Tools (latest)** in Android Studio's SDK Manager and add the SDK's `cmdline-tools/latest/bin` directory to `PATH`. Fission currently checks for `sdkmanager` and `avdmanager` at that path; the newer `android sdk` command alone does not satisfy those checks yet. Android Studio shows the SDK root in **Settings → Languages & Frameworks → Android SDK** (on macOS, **Android Studio → Settings → Languages & Frameworks → Android SDK**). Set `ANDROID_HOME` to that root if Fission cannot find it.

### Install the packages

The commands below choose API 35 and Build Tools 35.0.0 as a concrete setup, not a framework-wide version pin. The generated script selects the highest installed platform unless `ANDROID_TARGET_API_LEVEL` overrides it. Inspect `platforms/android/README.md` and the generated build configuration before choosing a different API.

```sh
sdkmanager --install \
  "platform-tools" "emulator" \
  "platforms;android-35" "build-tools;35.0.0" \
  "system-images;android-35;google_apis;arm64-v8a"
sdkmanager --licenses
```

Install one NDK version through Android Studio's SDK Manager or choose an exact `ndk;...` package shown by `sdkmanager --list`. Fission selects the latest NDK installed under `$ANDROID_HOME/ndk`, unless `ANDROID_NDK` names a specific installation. The project does not pin a universal NDK version. Read each licence prompt and accept only after reviewing it. `platform-tools` provide `adb`; the Android platform and build tools compile the host; the NDK supplies the native linker; and the system image gives the emulator an Android system to boot.

### Verify discovery before building

```sh
fission doctor android --project-dir .
fission devices --project-dir .
```

`fission doctor` reports which tool or SDK path is missing. Fix that first, then run it again. `fission devices` lists the emulators or phones Fission can currently launch; an empty list means the SDK may be ready while no AVD or device is running yet. See the [Android setup tutorial](/blog/set-up-rust-android-gui-development-with-fission/) for the next emulator and phone checks.
