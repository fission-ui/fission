An Android build can fail before Rust gets to your app if the SDK packages or licences are missing. This guide checks the SDK location, installs the platform and build tools Fission expects, and confirms that the NDK and emulator packages are visible. You can stop after each command and fix the exact missing piece it reports.

At the end, `fission doctor` should be able to find the packages needed by the generated Android host. The browser preview cannot install them or inspect your machine; the command output is the check that matters here.

## Create the project and add the target

Create a small Fission project and add Android as a target. This gives the checks below a real project configuration to validate.

```sh
cargo install cargo-fission
fission init android-install-android-sdk-packages-for-a-fission-app
cd android-install-android-sdk-packages-for-a-fission-app
fission add-target android --project-dir .
```

## Files created by Fission

This is the tree Fission generates. Shared Rust code stays under `src/`; the Android host under `platforms/android/` owns launch and packaging.

```text
android-install-android-sdk-packages-for-a-fission-app/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, state, reducers and reusable `fission_component!` components in the shared Rust project. Add a separate service or effect module only when the feature needs one. The generated host handles Android launch and packaging; shared components do not need to import Android APIs.

## Install the Android SDK packages the generated host needs

Work from the Fission project root so the generated README and doctor output describe this app's target requirements. `sdkmanager --list_installed` shows what is already present; the package names below cover the Android platform, build tools, NDK, emulator and an arm64 Google APIs image used by the generated launcher.

### Check the SDK manager and installed packages

```sh
sdkmanager --version
sdkmanager --list_installed
```

If the shell cannot find `sdkmanager`, add the SDK's `cmdline-tools/latest/bin` directory to `PATH`. Android Studio shows the SDK root in **Settings → Languages & Frameworks → Android SDK** (on macOS, **Android Studio → Settings → Languages & Frameworks → Android SDK**).

### Install the packages

The generated Android host currently uses API 35 and Build Tools 35.0.0 by default. Read `platforms/android/README.md` after scaffolding; if that file specifies different versions, use its values in place of the versions below.

```sh
sdkmanager --install \
  "platform-tools" "cmdline-tools;latest" "emulator" \
  "platforms;android-35" "build-tools;35.0.0" "ndk;27.2.12479018" \
  "system-images;android-35;google_apis;arm64-v8a"
sdkmanager --licenses
```

Read each licence prompt and accept only after reviewing it. The command-line tools install the package manager; platform-tools provide `adb`; the platform and build-tools compile the Android host; the NDK supplies the native linker; and the system image gives the emulator an Android system to boot.

### Verify discovery before building

```sh
fission doctor android --project-dir .
fission devices --project-dir .
```

`fission doctor` reports which tool or SDK path is missing. Fix that first, then run it again. `fission devices` lists the emulators or phones Fission can currently launch; an empty list means the SDK may be ready while no AVD or device is running yet. See the [Android setup tutorial](/blog/set-up-rust-android-gui-development-with-fission/) for the next emulator and phone checks.
