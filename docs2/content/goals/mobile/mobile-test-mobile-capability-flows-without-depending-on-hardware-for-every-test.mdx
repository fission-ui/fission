A permission failure should not cost someone the note they were writing. That is an application rule which we can test without a phone. Whether iOS displays the right permission prompt is a different question and still needs the native host.

We will use the real caption-and-permission screen from [the privacy tutorial](/blog/configure-ios-permissions-and-privacy-descriptions-for-fission-capabilities/). A dedicated test launcher injects a controlled camera provider, then the normal button queues the normal effect and its actual completion updates the normal reducers. There are no “pretend success” buttons inside the product screen.

## Create the shared project

Complete the [Android setup](/blog/set-up-rust-android-gui-development-with-fission/) and [iOS setup](/blog/set-up-rust-ios-development-with-fission/) guides before checking their native paths.

```sh
cargo install cargo-fission
fission init mobile-test-mobile-capability-flows-without-depending-on-hardware-for-every-test
cd mobile-test-mobile-capability-flows-without-depending-on-hardware-for-every-test
fission add-target android ios --project-dir .
fission add-capability camera --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs`. Its shared library installs the real platform provider by default. The separate `examples/camera_test_host.rs` is test infrastructure, not an alternate production entrypoint. Its crate import matches the project name above; change that import if you choose a different package name.

## Keep production and controlled-provider launches distinct

The caption belongs to the screen's retained draft state. Permission state belongs to the app because another part of a larger workflow may observe it. Only an explicit button action requests access. Pending state disables a duplicate request but does not lock the draft.

The test host supplies either a memory permission result or an unsupported error. Its memory provider has no image data because this screen never calls capture; a permission grant must not be presented as an attached photograph.

```rust
use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct PhotoAccessState {
    pub locale: Locale,
    pub pending: bool,
    pub permission: Option<CameraPermission>,
    pub status_key: String,
    pub error: Option<String>,
}

impl Default for PhotoAccessState {
    fn default() -> Self {
        Self {
            locale: Locale::from("en-US"),
            pending: false,
            permission: None,
            status_key: "photo.ready".into(),
            error: None,
        }
    }
}
impl GlobalState for PhotoAccessState {}

pub fn request_access(state: &mut PhotoAccessState, cx: &mut ReducerContext<PhotoAccessState>) {
    if state.pending {
        return;
    }
    state.pending = true;
    state.error = None;
    state.status_key = "photo.pending".into();
    let ok = cx
        .effects
        .bind(PermissionReturned, reduce_with!(permission_returned));
    let err = cx
        .effects
        .bind(PermissionFailed, reduce_with!(permission_failed));
    cx.effects
        .camera()
        .request_permission(CameraPermissionRequest { reason: None })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(PermissionReturned)]
fn permission_returned(state: &mut PhotoAccessState, cx: &mut ReducerContext<PhotoAccessState>) {
    state.pending = false;
    state.permission = cx.input.capability_ok(REQUEST_CAMERA_PERMISSION);
    state.status_key = match state.permission {
        Some(CameraPermission::Granted) => "photo.granted",
        Some(CameraPermission::Denied) => "photo.denied",
        Some(CameraPermission::Restricted) => "photo.restricted",
        Some(CameraPermission::Unknown) => "photo.unknown",
        None => "photo.unexpected",
    }
    .into();
}

#[fission_reducer(PermissionFailed)]
fn permission_failed(state: &mut PhotoAccessState, cx: &mut ReducerContext<PhotoAccessState>) {
    state.pending = false;
    let error = cx.input.capability_error(REQUEST_CAMERA_PERMISSION);
    state.status_key = if error
        .as_ref()
        .is_some_and(|error| error.code == "unsupported")
    {
        "photo.unsupported"
    } else {
        "photo.failed"
    }
    .into();
    state.error = error
        .map(|error| format!("{}: {}", error.code, error.message))
        .or_else(|| {
            cx.input
                .capability_error_message(REQUEST_CAMERA_PERMISSION)
                .map(str::to_owned)
        });
}
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid photo access translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::PhotoAccessState, env: &mut Env) {
    env.locale = state.locale.clone();
}
```

```rust
use fission::prelude::*;
use mobile_test_mobile_capability_flows_without_depending_on_hardware_for_every_test::{
    app::{PhotoAccessScreen, PhotoAccessState},
    i18n,
};

fn memory_camera(permission: CameraPermission) -> MemoryCameraHost {
    // This test requests permission only; it never captures these empty bytes.
    MemoryCameraHost::new(
        CameraAvailability {
            permission,
            devices: Vec::new(),
        },
        Vec::new(),
        "image/png",
        0,
        0,
        None,
    )
}

fn main() -> anyhow::Result<()> {
    let outcome = std::env::args()
        .nth(1)
        .ok_or_else(|| anyhow::anyhow!("expected granted, denied or unsupported"))?;
    let app = DesktopApp::<PhotoAccessState, _>::new(PhotoAccessScreen)
        .with_env(i18n::create_env())
        .with_sync_env(i18n::sync_env);
    match outcome.as_str() {
        "granted" => app
            .with_camera_host(memory_camera(CameraPermission::Granted))
            .run(),
        "denied" => app
            .with_camera_host(memory_camera(CameraPermission::Denied))
            .run(),
        "unsupported" => app.with_camera_host(UnsupportedCameraHost).run(),
        _ => Err(anyhow::anyhow!("unknown test outcome")),
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn controlled_providers_return_distinct_permission_results() {
        for permission in [CameraPermission::Granted, CameraPermission::Denied] {
            let actual = memory_camera(permission)
                .request_permission(CameraPermissionRequest { reason: None });
            assert_eq!(actual, Ok(permission));
        }
        let error = UnsupportedCameraHost
            .request_permission(CameraPermissionRequest { reason: None })
            .expect_err("unsupported must not become a grant");
        assert_eq!(error.code, "unsupported");
    }
}
```

## Exercise the same effect path with controlled outcomes

Run these on a desktop with a graphical session. The example launcher opens the same Compose screen and installs a controlled host only for that process. Run each scenario separately, close its window, then launch the next.

```sh
cargo test --example camera_test_host
FISSION_TEST_CONTROL_PORT=48763 cargo run --example camera_test_host -- granted
FISSION_TEST_CONTROL_PORT=48763 cargo run --example camera_test_host -- denied
FISSION_TEST_CONTROL_PORT=48763 cargo run --example camera_test_host -- unsupported
```

The first command asserts the providers' distinct contract results. The launched app tests a broader path: a UI action requests a capability, the registry dispatches it to the injected host, and bound unit completion actions decode the result from `cx.input`. Use these requests whilst one scenario is open:

```sh
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"FillText","query":{"selector":{"kind":"semantic_identifier","identifier":"photo.caption"}},"text":"The parcel seal is damaged"}' \
  http://127.0.0.1:48763/cmd
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"ActivateSelector","query":{"selector":{"kind":"semantic_identifier","identifier":"photo.request"}}}' \
  http://127.0.0.1:48763/cmd
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"WaitForIdle","timeout_ms":5000,"ignore_repeating_motion":false}' \
  http://127.0.0.1:48763/cmd
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"GetTree"}' http://127.0.0.1:48763/cmd
```

Check the JSON application status, not only HTTP success. An `Error` or `SelectorError` is a failed command. With the English bundle selected, the screen must show the corresponding granted, denied or unsupported message from the checked-in translations. The caption's semantic value must still equal the text you entered, the request button must be enabled again, and the pending spinner must be gone.

Repeat the request and switch language. Inspect a screenshot as well as the semantic tree; both tell us something which a provider unit test cannot. The [simulator-testing tutorial](/blog/test-an-ios-app-in-the-simulator-and-on-a-device/) shows screenshot retrieval and the exact response format.

A granted memory response does not mean an actual camera was opened. A denied result here does not mean that iOS displayed a permission sheet. These runs establish the application's recovery behaviour, not the operating system's implementation.

## Check the remaining native boundary

Run the normal app, without the example launcher:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

The Android path requires the SDK, NDK and configured emulator from the setup guide. The iOS path runs on macOS with Xcode and an installed simulator runtime. Neither smoke test proves camera hardware, native purpose text or recovery after a real Settings change.

Use [a physical Android phone](/blog/run-a-fission-app-on-a-physical-android-phone/) and [a physical iPhone](/blog/install-a-fission-app-on-a-physical-iphone/) for those checks. Verify the purpose description, grant, denial, restriction where applicable, returning from Settings and editing the caption whilst the response is pending. Do not repeatedly reset someone's permissions as a production recovery strategy.

Keep controlled-provider, simulator and phone results separate in the test record. A failing shared-state assertion should be reproducible without hardware; a native prompt defect needs evidence from the corresponding native host.
