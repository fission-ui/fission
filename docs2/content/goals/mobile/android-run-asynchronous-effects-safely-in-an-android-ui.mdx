## Create the project and add the target

Create a project and add Android as a target. The screen and effect logic stay in shared Rust; the generated Android host is what builds and launches them on the device.

```sh
cargo install cargo-fission
fission init android-run-asynchronous-effects-safely-in-an-android-ui
cd android-run-asynchronous-effects-safely-in-an-android-ui
fission add-target android --project-dir .
```

## Files created by Fission

This is the tree Fission creates. Shared app code belongs under `src/`, while `platforms/android/` holds the generated host for launch and packaging. We will add feature-specific pieces only when the example needs them.

```text
android-run-asynchronous-effects-safely-in-an-android-ui/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, state, reducers and reusable `fission_component!` components in the shared Rust project. Add a separate state, service or effect module when it gives the feature a useful boundary, and name it for that feature. The Android host handles platform launch and packaging; shared components do not need Android APIs.

## Add the screen used by the example

```rust
use fission::prelude::*;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
enum TemperatureValidationIssue {
    InvalidNumber,
    OutOfRange,
}

impl TemperatureValidationIssue {
    fn translation_key(self) -> &'static str {
        match self {
            Self::InvalidNumber => "async.error.number",
            Self::OutOfRange => "async.error.range",
        }
    }
}

#[fission_effect]
async fn validate_temperature(
    request_id: u64,
    raw_temperature: String,
) -> Result<(u64, String), (u64, u8)> {
    let normalized = raw_temperature.trim().replace(',', ".");
    let temperature = normalized
        .parse::<f32>()
        .map_err(|_| (request_id, 1))?;

    if !(-40.0..=80.0).contains(&temperature) {
        return Err((request_id, 2));
    }

    Ok((request_id, format!("{temperature:.1} °C")))
}

fission_component! {
    pub CompressorTemperatureCheck<()> {
        state {
            temperature: String = "4.2".to_string(),
            latest_request: u64 = 0,
            loading: bool = false,
            checked_temperature: Option<String> = None,
            error: Option<TemperatureValidationIssue> = None,
        }
    }
    view(check, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("northbank.temperature-check".to_string()),
        label: Some(cx.tr("async.screen.label")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("async.title"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("async.description"))
                    .color(tokens.colors.text_secondary),
                Divider(),
                Column(gap: tokens.spacing.s, children: [
                    Text(cx.tr("async.work_order"))
                        .weight(tokens.typography.font_weight_semibold),
                    Text(cx.tr("async.asset"))
                        .size(tokens.typography.heading2_size),
                    Text(cx.tr("async.location"))
                        .color(tokens.colors.text_secondary),
                ]),
                TextInput(
                    label: Some(cx.tr("async.input.label").into()),
                    bind: check.temperature,
                    placeholder: Some(cx.tr("async.input.placeholder").into()),
                    required: true,
                    keyboard_type: TextInputType::Number,
                    autocorrect: false,
                    semantics_identifier: "northbank.temperature.value".to_string(),
                ),
                Button(
                    child: Text(if check.loading {
                        cx.tr("async.action.running")
                    } else {
                        cx.tr("async.action.check")
                    }),
                    key: "check-temperature",
                    variant: ButtonVariant::Primary,
                    disabled: check.loading,
                    on_press: effect validate_temperature(
                        check.latest_request + 1,
                        check.temperature.clone(),
                    ) {
                        on_start {
                            check.latest_request += 1;
                            check.loading = true;
                            check.error = None;
                        }
                        on_ok(result) {
                            if result.0 == check.latest_request {
                                check.checked_temperature = Some(result.1);
                                check.loading = false;
                            }
                        }
                        on_err(error) {
                            if error.0 == check.latest_request {
                                check.error = Some(if error.1 == 1 {
                                    TemperatureValidationIssue::InvalidNumber
                                } else {
                                    TemperatureValidationIssue::OutOfRange
                                });
                                check.loading = false;
                            }
                        }
                    },
                ),
                if check.loading {
                    Text(cx.tr("async.status.running"))
                        .color(tokens.colors.text_secondary)
                } else if let Some(error) = check.error {
                    Alert(
                        kind: AlertKind::Error,
                        title: cx.tr(error.translation_key()),
                    )
                } else if let Some(temperature) = &check.checked_temperature {
                    Alert(
                        kind: AlertKind::Success,
                        title: format!("{} {temperature}", cx.tr("async.status.saved")),
                    )
                } else {
                    Text(cx.tr("async.status.ready"))
                        .color(tokens.colors.text_secondary)
                },
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

```rust
mod app;

use std::collections::HashMap;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("i18n/en-US.yaml")),
        ("es-ES", include_str!("i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid embedded tutorial translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::CompressorTemperatureCheck)
        .with_env(preview_env())
        .with_title("Northbank temperature check")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Run asynchronous effects safely in an Android UI

The tricky case is not starting the request; it is getting an old response after a newer one. Give each request an ID and keep the current ID in app state. When a response arrives, the reducer can ignore it if the user has already started another request or left the screen. While work is running, show a pending state and keep useful existing data visible. Handle both success and failure with typed actions, and offer a retry after an error. Only offer cancel if the underlying service can actually cancel the work.

You can test the ordering without a network connection: start two requests in a Rust test, return the newer result first, then return the older result. The old response must not replace the newer state. Effects run outside reducers, so keep sleep, file access, SQL and network work out of the UI thread.

## Check delayed and interrupted work on Android

In a Rust test, use a fake service so you choose when each request completes. Start two requests, return the newer result first, then return the older one. Because state records the latest request ID, the reducer should ignore that late response and leave the newer result on screen.

Also background the app while a request is pending, then return to it. Check that the UI reaches a clear success or error state, and that retrying does not make the user repeat work that has already been saved.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs the Rust tests you write; the generated project does not create tests for this feature. `fission doctor` checks the Android tools, `fission run` launches an emulator or connected phone, and `fission test` checks that the generated host starts. A release build checks packaging. It does not prove a device-specific permission or hardware flow works.
