Completing a task and feeling a vibration are two different outcomes. The first changes the app's record; the second helps the person notice the change. If feedback is unavailable or suppressed by the device, the task should remain complete.

Here, the user enters a task they have finished and marks it complete. That gives the example an actual input rather than a pre-filled work order whose only purpose is to trigger a device API. The shared state records the completion before requesting optional feedback. It is session-local task data, not a claim of server persistence.

## Create the project and add the target

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) and [simulator setup](/blog/install-and-select-xcodes-ios-simulator-tools/) first. Use [a physical iPhone](/blog/install-a-fission-app-on-a-physical-iphone/) to judge how the feedback feels.

```sh
cargo install cargo-fission
fission init ios-add-haptic-feedback-to-an-ios-app
cd ios-add-haptic-feedback-to-an-ios-app
fission add-target ios --project-dir .
fission add-capability haptics --project-dir .
cargo add serde_yaml
```

Keep Fission's generated `src/main.rs`. Replace `src/lib.rs` as well as the screen below, otherwise the normal iOS launch would still use the generated counter. The shared app, state transitions and translations belong under `src/`; native and Web entrypoints only install that app.

## Complete a task and request optional feedback

The screen starts empty. A whitespace-only task cannot be completed, and another completion is disabled whilst the current feedback request is pending. Editing the next task remains possible. Because there is at most one request in flight, these callbacks do not need a second operation-ID mechanism.

The two completion actions are unit actions. They decode the host result from `cx.input`; no success value is invented in the button handler. Each request binds its own callbacks through `cx.effects.bind`, so neither shell needs a manually assembled callback registry.

```rust
use fission::prelude::*;

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub enum Feedback {
    #[default]
    Idle,
    Pending,
    Accepted,
    Unavailable,
    InvalidResult,
}

impl Feedback {
    pub fn message_key(&self) -> &'static str {
        match self {
            Self::Idle => "feedback.optional",
            Self::Pending => "feedback.pending",
            Self::Accepted => "feedback.accepted",
            Self::Unavailable => "feedback.unavailable",
            Self::InvalidResult => "feedback.invalid",
        }
    }
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct TaskState {
    pub draft: String,
    pub completed: Option<String>,
    pub feedback: Feedback,
    pub locale: Locale,
}

impl Default for TaskState {
    fn default() -> Self {
        Self {
            draft: String::new(),
            completed: None,
            feedback: Feedback::Idle,
            locale: Locale::from("en-US"),
        }
    }
}

impl GlobalState for TaskState {}

pub fn complete_task(state: &mut TaskState, cx: &mut ReducerContext<TaskState>) {
    if state.feedback == Feedback::Pending {
        return;
    }
    let task = state.draft.trim();
    if task.is_empty() {
        return;
    }
    state.completed = Some(task.to_owned());
    state.draft.clear();
    state.feedback = Feedback::Pending;

    let ok = cx
        .effects
        .bind(HapticAccepted, reduce_with!(on_haptic_accepted));
    let err = cx
        .effects
        .bind(HapticUnavailable, reduce_with!(on_haptic_unavailable));
    cx.effects
        .haptics()
        .notification(HapticNotificationRequest {
            kind: HapticNotificationKind::Success,
        })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(HapticAccepted)]
fn on_haptic_accepted(state: &mut TaskState, cx: &mut ReducerContext<TaskState>) {
    state.feedback = if cx.input.capability_ok(HAPTIC_NOTIFICATION).is_some() {
        Feedback::Accepted
    } else {
        Feedback::InvalidResult
    };
}

#[fission_reducer(HapticUnavailable)]
fn on_haptic_unavailable(state: &mut TaskState, cx: &mut ReducerContext<TaskState>) {
    state.feedback = if cx.input.capability_error(HAPTIC_NOTIFICATION).is_some() {
        Feedback::Unavailable
    } else {
        Feedback::InvalidResult
    };
}
```

```rust
use super::state::{complete_task, Feedback, TaskState};
use fission::prelude::*;

fission_component! {
    pub TaskCompletionScreen<TaskState> {}
    view(_screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let pending = state.feedback == Feedback::Pending;
    } => SafeArea(
        child: Scroll(
            child: Container(
                Column(gap: tokens.spacing.m, children: [
                    Text(cx.tr("task.title"))
                        .size(tokens.typography.heading2_size),
                    Text(cx.tr("task.explanation"))
                        .color(tokens.colors.text_secondary),
                    Row(gap: tokens.spacing.s, children: [
                        Button(
                            child: Text(cx.tr("language.english")),
                            key: "english",
                            on_press: reduce { state.locale = Locale::from("en-US"); },
                        ),
                        Button(
                            child: Text(cx.tr("language.spanish")),
                            key: "spanish",
                            on_press: reduce { state.locale = Locale::from("es-ES"); },
                        ),
                    ]),
                    FormControl(
                        label: Some(cx.tr("task.label")),
                        required: true,
                        child: TextInput(
                            value: state.draft.clone(),
                            bind(on_input): to(state.draft),
                            placeholder: Some(TextContent::Key("task.placeholder".into())),
                            semantics_identifier: Some("task.draft".into()),
                        ),
                    ),
                    Button(
                        child: Text(cx.tr("task.complete")),
                        key: "complete-task",
                        disabled: pending || state.draft.trim().is_empty(),
                        on_press: reduce { complete_task(state, cx); },
                    )
                    .semantics_identifier("task.complete"),
                    if let Some(task) = &state.completed {
                        Text(cx.tr("task.completed").replace("{task}", task))
                    },
                    if pending {
                        Spinner(
                            motion: Some(SpinnerMotion::Default),
                            label: Some(cx.tr("feedback.pending")),
                        )
                    },
                    Text(cx.tr(state.feedback.message_key())),
                    Text(cx.tr("task.persistence"))
                        .color(tokens.colors.text_secondary),
                ]),
            )
            .padding_all(tokens.spacing.l)
            .bg(tokens.colors.surface),
        ),
    )
}
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid task translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::TaskState, env: &mut Env) {
    env.locale = state.locale.clone();
}
```

## Understand the result rather than assuming vibration happened

The reducer records the task synchronously, clears the draft and queues `HAPTIC_NOTIFICATION`. It returns whilst the host performs the operation. The real `Spinner` and status message describe pending feedback without blocking the app.

On iOS, Fission's native haptic provider uses `UINotificationFeedbackGenerator` for this operation. On Web, the normal provider calls the browser's vibration API and reports an unsupported/rejected operation when that API is unavailable. This preview does not install `MemoryHapticHost` or a simulated success provider.

An accepted request establishes that the host accepted the operation, not that a person felt it. Hardware, settings and the environment still affect perception. Haptics are not an authentication prompt, and notification-style haptics do not require asking for notification permission.

If the typed result is absent, the callback reports an unexpected result instead of treating it as success. A host error leaves the task complete with a translated unavailable message. In a persisted task app, request this optional cue after the actual save succeeds; do not use vibration to imply a save that has not happened.

## Verify the native experience separately

Run from the generated project root on macOS:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

The run/test paths launch the simulator. They check launch and UI behavior, not the presence or quality of a physical haptic. For an iPhone, follow the [signing and installation tutorial](/blog/install-a-fission-app-on-a-physical-iphone/); packaging a signed IPA is a separate workflow.

Test a blank task, a normal completion, fast repeated presses, editing whilst feedback is pending, unavailable feedback and a language change. Inspect the narrow layout and VoiceOver labels. On a physical phone, confirm that the cue is brief and does not replace the visible completion.

No native build or hardware interaction is established merely by compiling the Web preview. The simulator, iPhone and browser checks provide different evidence.
