The app icon, launch screen and first usable screen are three different parts of a launch. iOS displays the icon before your code runs and the launch storyboard whilst the host starts. Fission then renders the interactive app. A browser card saying "launch ready" cannot demonstrate either native asset.

We will use a small journey-plan editor as the first usable screen, then configure the native assets around it. The editor is the same shared Compose app used in [the reusable-component tutorial](/blog/compose-an-ios-app-from-reusable-fission-widgets/); it is included here so the project can actually run rather than launching the generated counter behind a static website preview.

## Create the project

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) if needed.

```sh
cargo install cargo-fission
fission init ios-add-an-ios-app-icon-and-launch-screen
cd ios-add-an-ios-app-icon-and-launch-screen
fission add-target ios --project-dir .
cargo add serde_yaml
```

Fission creates `assets/app-icon.png` as a starter asset. We will use that existing file first so there is no missing image to prevent the native build. Replace it with your own artwork before shipping; the Fission starter icon is not your product identity.

## Start an actual app after the launch screen

Keep the generated `src/main.rs` and add the files below. The normal shared library and browser launcher run the same editor. Entering a journey and preparing its snapshot checks that the first frame is usable, not merely that the native launch image appeared.

The editor does not calculate a route or book transport. It provides a real input/review task whose success can be distinguished from packaging success.

```rust
use super::{
    state::{Journey, JourneyState},
    summary::JourneySummary,
};
use fission::prelude::*;

fission_component! {
    pub JourneyScreen<JourneyState> {
        state {
            origin: String = String::new(),
            destination: String = String::new(),
        }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => SafeArea(
        child: Scroll(
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("journey.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("journey.explanation")),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("language.english")), key: "english",
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                FormControl(
                    label: Some(cx.tr("journey.origin")),
                    required: true,
                    child: TextInput(
                        value: screen.origin.clone(),
                        bind(on_input): to(screen.origin),
                    ),
                ),
                FormControl(
                    label: Some(cx.tr("journey.destination")),
                    required: true,
                    child: TextInput(
                        value: screen.destination.clone(),
                        bind(on_input): to(screen.destination),
                    ),
                ),
                if !screen.origin.trim().is_empty() && !screen.destination.trim().is_empty() {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.draft")),
                        JourneySummary(
                            Journey {
                                origin: screen.origin.trim().to_owned(),
                                destination: screen.destination.trim().to_owned(),
                            },
                            key: "draft-summary",
                        ),
                    ])
                },
                Button(
                    child: Text(cx.tr("journey.prepare")), key: "prepare-journey",
                    disabled: screen.origin.trim().is_empty() || screen.destination.trim().is_empty(),
                    on_press: reduce {
                        state.prepared = Some(Journey {
                            origin: screen.origin.trim().to_owned(),
                            destination: screen.destination.trim().to_owned(),
                        });
                    },
                ),
                if let Some(journey) = &state.prepared {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.prepared")),
                        JourneySummary(journey.clone(), key: "prepared-summary"),
                    ])
                },
            ]))
            .padding_all(tokens.spacing.l),
        ),
    )
}
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid journey translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::JourneyState, env: &mut Env) {
    env.locale = state.locale.clone();
}
```

## Configure assets through the project's authority

Merge these tables into the existing `fission.toml`; do not replace the rest of the generated configuration.

```toml
[package.icons.ios]
source = "assets/app-icon.png"

[app.splash]
image = "assets/app-icon.png"
background_color = "#F4F7F7"
resize_mode = "contain"
```

Both image paths are relative to the project root and initially point to the file Fission created. They are separate settings even when they share a file: replacing the launcher icon need not change the launch artwork, and a launch mark does not need the icon's full background.

The current iOS generator accepts PNG or JPEG images, not Android adaptive-icon XML or an SVG. It copies the configured icon to `platforms/ios/AppIcon.<extension>` and generates `platforms/ios/LaunchScreen.storyboard` plus the launch image. Keep your original artwork and configuration as the authority instead of editing generated copies and assuming the next generation will preserve them.

The background colour is an explicit native launch setting, not a live lookup into Fission's theme. Here it matches the default light background token. If your first route uses another design system or appearance, choose its intended launch background deliberately and inspect the transition. This table does not implement appearance-specific storyboard assets.

## Cold-launch the generated iOS app

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission build --target ios --project-dir . --release
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Follow [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) for selection. End the running app and launch it again rather than checking only a warm foreground return. Inspect the installed Home Screen icon, the brief launch frame and the transition into the working journey editor.

Repeat with your own artwork, both orientations and the device appearances you support. Use a clearly distinguishable local revision when checking whether an asset change reached the installed bundle. A generated filename or successful Rust build does not prove iOS used the intended image.

The current generator's image-copy path is not evidence of a complete App Store icon catalogue or a successful App Store submission. Before a release, inspect the actual package and run the distribution checks in [the TestFlight guide](/blog/package-and-prepare-a-fission-ios-app-for-testflight/). Follow [the iPhone installation guide](/blog/install-a-fission-app-on-a-physical-iphone/) for signing and physical-device checks.

Keep onboarding, account loading and progress in Fission after launch. Extending a static storyboard to hide unfinished asynchronous app setup would make the startup look longer without giving the user a truthful task state.
