## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-add-an-ios-app-icon-and-launch-screen
cd ios-add-an-ios-app-icon-and-launch-screen
cargo add serde_yaml
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-add-an-ios-app-icon-and-launch-screen/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

## Configure generated assets and splash settings

Treat the iOS app icon and launch screen as separate assets. Set a target-specific icon source in `fission.toml`; the splash image is used only for the short, static launch screen shown before the first Fission frame. iOS does not use Android adaptive-icon layers or the Android animated splash drawable. Keep onboarding and loading progress in a Fission route after startup. After packaging, cold-launch an iOS Simulator to check icon cropping, launch-screen contrast and the transition into the first screen.

```toml
[package.icons.ios]
source = "assets/ios/app-icon.png"

[app.splash]
image = "assets/ios/launch-mark.png"
background_color = "#F8FAFC"
resize_mode = "contain"
```

Create the PNG files before packaging; the paths are relative to the project root.

## Check the launch experience on iOS

Build and install the target package, then cold-launch it. Confirm the launcher icon uses the intended foreground and background, the native splash stays legible, and it hands off to the first Fission frame without showing a blank screen.

Repeat after changing the asset paths so you know the generated package picked up the new files. Keep onboarding and loading progress in the app’s first route; the operating-system splash is only a short launch frame.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
