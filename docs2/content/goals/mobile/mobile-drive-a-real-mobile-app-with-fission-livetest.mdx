A coordinate identifies a place on the screen, not the control which happens to occupy it. If a longer translation moves the record button, a test which still taps the old coordinates may do the wrong thing without explaining why.

We will build an inspection form and drive it through stable semantic identifiers. The person supplies the actual asset and observation; there is no preloaded work order or button which pretends a pressure measurement occurred. The final record is an in-memory snapshot, not a durable save. That gives the test a precise outcome to assert.

## Create the shared app

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/) and [iOS setup](/blog/set-up-rust-ios-development-with-fission/) before testing their native hosts.

```sh
cargo install cargo-fission
fission init mobile-drive-a-real-mobile-app-with-fission-livetest
cd mobile-drive-a-real-mobile-app-with-fission-livetest
fission add-target android ios web --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs`. Shared state, validation, components and translations belong in `src/`; the platform directories supply launch and packaging.

## Make the result testable without inventing success

The draft is retained local state. A valid submission creates a shared record; an invalid submission changes only validation feedback and leaves any previous record intact. The small pure `prepare_record` function is used by the actual reducer and narrow unit tests.

`FormControl` owns the label, required state and validation relationship. A nearby red string alone would not give the native accessibility tree the same validation information. The semantic identifiers name a control's meaning, not its current English label.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct InspectionRecord {
    pub asset: String,
    pub note: String,
}

pub fn prepare_record(asset: &str, note: &str) -> Option<InspectionRecord> {
    let (asset, note) = (asset.trim(), note.trim());
    if asset.is_empty() || note.is_empty() {
        return None;
    }
    Some(InspectionRecord {
        asset: asset.to_owned(),
        note: note.to_owned(),
    })
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct InspectionState {
    pub recorded: Option<InspectionRecord>,
    pub locale: Locale,
}
impl Default for InspectionState {
    fn default() -> Self {
        Self {
            recorded: None,
            locale: Locale::from("en-US"),
        }
    }
}
impl GlobalState for InspectionState {}

#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn incomplete_input_never_becomes_a_record() {
        assert_eq!(prepare_record("Pump 4", " "), None);
        assert_eq!(prepare_record(" ", "Seal is intact"), None);
    }
    #[test]
    fn accepted_record_contains_trimmed_user_input() {
        assert_eq!(
            prepare_record(" Pump 4 ", " Seal is intact "),
            Some(InspectionRecord {
                asset: "Pump 4".into(),
                note: "Seal is intact".into(),
            })
        );
    }
}

use super::state::{prepare_record, InspectionState};
use fission::prelude::*;

fission_component! {
    pub InspectionScreen<InspectionState> {
        state {
            asset: String = String::new(),
            note: String = String::new(),
            attempted: bool = false,
        }
    }
    view(form, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let asset_error = (form.attempted && form.asset.trim().is_empty())
            .then(|| cx.tr("inspection.asset_required"));
        let note_error = (form.attempted && form.note.trim().is_empty())
            .then(|| cx.tr("inspection.note_required"));
    } => SafeArea(child: Scroll(child: Container(
        Column(gap: tokens.spacing.m, children: [
            Text(cx.tr("inspection.title")).size(tokens.typography.heading2_size),
            Text(cx.tr("inspection.explanation")),
            Row(gap: tokens.spacing.s, children: [
                Button(child: Text(cx.tr("language.english")), key: "english",
                    on_press: reduce { state.locale = Locale::from("en-US"); }),
                Button(child: Text(cx.tr("language.spanish")), key: "spanish",
                    on_press: reduce { state.locale = Locale::from("es-ES"); }),
            ]),
            FormControl(
                label: Some(cx.tr("inspection.asset")), required: true, error: asset_error,
                child: TextInput(
                    value: form.asset.clone(), bind(on_input): to(form.asset),
                    semantics_identifier: Some("inspection.asset".into()),
                ),
            ),
            FormControl(
                label: Some(cx.tr("inspection.note")), required: true, error: note_error,
                child: TextInput(
                    value: form.note.clone(), bind(on_input): to(form.note),
                    multiline: true, keyboard_type: TextInputType::Multiline,
                    semantics_identifier: Some("inspection.note".into()),
                ),
            ),
            Button(
                child: Text(cx.tr("inspection.record")), key: "record-inspection",
                on_press: reduce {
                    form.attempted = true;
                    if let Some(record) = prepare_record(&form.asset, &form.note) {
                        state.recorded = Some(record);
                        form.asset.clear();
                        form.note.clear();
                        form.attempted = false;
                    }
                },
            ).semantics_identifier("inspection.record"),
            if let Some(record) = &state.recorded {
                SemanticsRegion(
                    identifier: Some("inspection.result".into()), role: Role::Status,
                    child: Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("inspection.recorded")),
                        Text(record.asset.clone()).weight(tokens.typography.font_weight_semibold),
                        Text(record.note.clone()),
                    ]),
                )
            } else {
                Text(cx.tr("inspection.empty"))
            },
            Text(cx.tr("inspection.persistence")).color(tokens.colors.text_secondary),
        ])
    ).padding_all(tokens.spacing.l)))
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid task translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::InspectionState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Drive validation and record creation through the real shell

First run the shared rule tests:

```sh
cargo test --lib
```

On Android, the debug-only entrypoint above enables the generated launch script's forwarded port. Do not ship that development control interface as a production feature. Launch one test target at a time:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
export TEST_PORT=48761
```

For iOS, use macOS and pass a different port into the simulator process:

```sh
fission doctor ios --project-dir .
FISSION_TEST_CONTROL_PORT=48762 fission run --target ios --project-dir .
export TEST_PORT=48762
```

In a second terminal on the launching machine, set the matching `TEST_PORT` and issue these requests:

```sh
curl --fail-with-body "http://127.0.0.1:${TEST_PORT}/health"
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"ActivateSelector","query":{"selector":{"kind":"semantic_identifier","identifier":"inspection.record"}}}' \
  "http://127.0.0.1:${TEST_PORT}/cmd"
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"WaitForText","text":"Add an inspection note.","timeout_ms":5000}' \
  "http://127.0.0.1:${TEST_PORT}/cmd"
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"FillText","query":{"selector":{"kind":"semantic_identifier","identifier":"inspection.asset"}},"text":"Loading bay door 2"}' \
  "http://127.0.0.1:${TEST_PORT}/cmd"
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"FillText","query":{"selector":{"kind":"semantic_identifier","identifier":"inspection.note"}},"text":"Seal intact; latch closes without force."}' \
  "http://127.0.0.1:${TEST_PORT}/cmd"
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"ActivateSelector","query":{"selector":{"kind":"semantic_identifier","identifier":"inspection.record"}}}' \
  "http://127.0.0.1:${TEST_PORT}/cmd"
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"WaitForText","text":"Inspection recorded for this session.","timeout_ms":5000}' \
  "http://127.0.0.1:${TEST_PORT}/cmd"
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"cmd":"GetTree"}' "http://127.0.0.1:${TEST_PORT}/cmd"
```

Inspect every JSON response. HTTP success is not a passed LiveTest assertion: `Error` and `SelectorError` are failures. The text waits must return `status: Ok`, and the final semantic tree must contain the actual asset and observation under `inspection.result`. A success label alone would not establish that the right input was recorded.

These text assertions deliberately use the default English bundle. Repeat the journey in Spanish using its corresponding messages; control selection still uses the same identifiers. For a repeatable suite, use the [LiveTest client](/docs/test-and-debug/live-test-api/) to assert returned values and stop the run on a command failure.

## Inspect the rendered screen as well as its semantics

Use `CaptureScreenshot` through the same `/cmd` endpoint and decode its `png_base64` result on the test client. The [iOS testing tutorial](/blog/test-an-ios-app-in-the-simulator-and-on-a-device/) shows that command. Inspect small-screen scrolling, the open keyboard, longer translations and error placement. A semantic tree cannot establish that the visible layout is usable.

Run the generated-host smoke checks separately:

```sh
fission test --target android --project-dir .
fission test --target ios --project-dir .
```

Then follow the same journey on [an Android phone](/blog/run-a-fission-app-on-a-physical-android-phone/) and [an iPhone](/blog/install-a-fission-app-on-a-physical-iphone/). Check native text entry and accessibility. This workflow does not require a sensor, but simulator results still do not establish physical keyboard and device behaviour.

When durable storage is added, the button must request a Store or service effect and report durable success only after its bound completion confirms the write. Do not preserve the session-only success label and imply that persistence came for free.
