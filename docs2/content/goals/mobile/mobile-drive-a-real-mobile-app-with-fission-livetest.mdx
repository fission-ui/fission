## Create the project and add the target

```sh
cargo install cargo-fission
fission init mobile-drive-a-real-mobile-app-with-fission-livetest
cd mobile-drive-a-real-mobile-app-with-fission-livetest
fission add-target android ios --project-dir .
```

## Files created by Fission

Fission generates Android and iOS hosts alongside the shared Rust project:

```text
mobile-drive-a-real-mobile-app-with-fission-livetest/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    ├── android/              # generated Android host
    └── ios/                  # generated iOS host
```

Keep the tested journey in shared Rust. LiveTest drives the generated Android and iOS hosts, so both targets use the same reducers and widgets.

use fission::prelude::*;

fission_component! {
    pub MobileLiveTest<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("task-workspace".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text(screen.title.clone())
                            .weight(tokens.typography.font_weight_bold),
                        Text(screen.step.clone())
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: "In progress".to_string()),
                ]),
                Divider(),
                Column(gap: tokens.spacing.s, children: [
                    Text("Current task")
                        .weight(tokens.typography.font_weight_semibold),
                    Text(screen.goal.clone()),
                ]),
                Row(gap: tokens.spacing.s, align_items: ir_op::AlignItems::Center, children: [
                    Badge(text: "Next".to_string()),
                    Text("Connect this screen to the workflow in the next step.".to_string())
                        .color(tokens.colors.text_secondary),
                ]),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}

mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(inline_js = "export function tutorial_title() { const parts = document.title.split(' — '); return parts.slice(1).join(' — ') || 'Fission tutorial'; } export function tutorial_step() { return document.title.split(' — ')[0] || 'Tutorial step'; } export function tutorial_goal() { return document.querySelector('meta[name=\"tutorial-goal\"]')?.content || 'Complete the task and verify it on the target.'; }")]
extern "C" {
    fn tutorial_title() -> String;
    fn tutorial_step() -> String;
    fn tutorial_goal() -> String;
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::MobileLiveTest::new(tutorial_title(), tutorial_step(), tutorial_goal());
    WebApp::<(), _>::new(preview)
        .with_title("Fission tutorial preview")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Drive a real mobile app with Fission LiveTest

Start the app with test control enabled, then use LiveTest to select controls by their stable semantic identifiers instead of screen coordinates. Drive one critical journey from its initial empty state through the primary action and verify the user-visible result and error path. Keep reducer tests for business rules and use the native LiveTest shell for widget composition, focus and target integration. Run the journey on Android Emulator and iOS Simulator; note that a successful simulator test cannot establish sensor or physical permission behaviour.

## Run the test layers for this task

Use a different check for each risk: `cargo test` for Rust rules you have written, `fission test` for the generated host smoke path, and LiveTest for the composed screen and user journey. A passing test at one layer does not replace the checks at the next layer.

Run the same critical journey on Android Emulator and iOS Simulator. Add a real-device check only for behavior the simulator cannot prove, such as a permission sheet, radio, camera, sensor or signed installation.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add for reducer or stale-completion rules; the generated scaffold does not create those feature tests. `fission doctor` checks each target’s toolchain, `fission run` launches its emulator or Simulator, and `fission test` checks that the generated host can start. A release build validates packaging, not real hardware behavior.


### Run the shared project on both mobile targets

Run both target checks from the generated project root:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target android --project-dir .
fission test --target ios --project-dir .
```
