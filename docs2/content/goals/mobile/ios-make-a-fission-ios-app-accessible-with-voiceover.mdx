A control can look obvious and still be unusable without sight. A nearby caption is not necessarily its accessible name, a coloured error is not necessarily announced, and a test identifier is not a substitute for either.

We will build a contact-preferences form with a required name, an on/off choice and an explicit result. The task is small enough to navigate completely with VoiceOver, but it exercises real form relationships and state rather than a button whose label merely says that accessibility exists.

## Create the app

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) if needed.

```sh
cargo install cargo-fission
fission init ios-make-a-fission-ios-app-accessible-with-voiceover
cd ios-make-a-fission-ios-app-accessible-with-voiceover
fission add-target ios --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs`. The shared library below starts the same form on native and Web targets; neither shell injects a fake successful preference change.

## Use controls which already own the interaction

`TextInput`, `Switch` and `Button` expose their respective control roles and actions. `FormControl` adds the visible label, help text and validation relationship to its descendant control. We therefore do not have to duplicate a field's caption into an unrelated semantic wrapper and hope the screen reader associates them.

The switch's checked value is real state, not a colour convention. Applying copies a valid snapshot into application state, whilst the draft remains local to the form. No message is sent and no notification permission is requested by changing a contact preference.

pub struct ContactPreferences {
    pub name: String,
    pub text_messages: bool,
}

#[derive(Clone, Debug, PartialEq, Eq)]

    pub preferences: Option<ContactPreferences>,
    pub locale: Locale,

impl Default for ContactState {
    fn default() -> Self {
        Self {
            preferences: None,
            locale: Locale::from("en-US"),
        }
    }
}
impl GlobalState for ContactState {}

use super::state::{ContactPreferences, ContactState};
use fission::prelude::*;

fission_component! {
    pub ContactScreen<ContactState> {
        state {
            name: String = String::new(),
            text_messages: bool = false,
            attempted: bool = false,
        }
    }
    view(form, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let name_error = (form.attempted && form.name.trim().is_empty())
            .then(|| cx.tr("contact.name_required"));
    } => SafeArea(
        child: Scroll(
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("contact.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("contact.explanation")),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("language.english")), key: "english",
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                FormControl(
                    label: Some(cx.tr("contact.name")),
                    helper: Some(cx.tr("contact.name_help")),
                    required: true,
                    error: name_error,
                    child: TextInput(
                        value: form.name.clone(), bind(on_input): to(form.name),
                        keyboard_type: TextInputType::Name,
                        semantics_identifier: Some("contact.name".into()),
                    ),
                ),
                FormControl(
                    label: Some(cx.tr("contact.messages")),
                    helper: Some(cx.tr("contact.messages_help")),
                    child: Switch(
                        checked: form.text_messages,
                        bind(on_toggle): to(form.text_messages),
                        semantics_identifier: Some("contact.messages".into()),
                    ),
                ),
                Button(
                    child: Text(cx.tr("contact.apply")), key: "apply-preferences",
                    on_press: reduce {
                        form.attempted = true;
                        if !form.name.trim().is_empty() {
                            state.preferences = Some(ContactPreferences {
                                name: form.name.trim().to_owned(),
                                text_messages: form.text_messages,
                            });
                        }
                    },
                )
                .semantics_identifier("contact.apply"),
                if let Some(preferences) = &state.preferences {
                    SemanticsRegion(
                        identifier: Some("contact.result".into()),
                        role: Role::Status,
                        child: Column(gap: tokens.spacing.s, children: [
                            Text(cx.tr("contact.applied")),
                            Text(preferences.name.clone()),
                            Text(if preferences.text_messages {
                                cx.tr("contact.messages_enabled")
                            } else {
                                cx.tr("contact.messages_disabled")
                            }),
                        ]),
                    )
                },
                Text(cx.tr("contact.session")).color(tokens.colors.text_secondary),
            ]))
            .padding_all(tokens.spacing.l),
        ),
    )
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid contact translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::ContactState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Distinguish a semantic contract from native evidence

Stable identifiers such as `contact.name` let LiveTest select the intended control without depending on its translated label or generated tree position. Labels serve a different audience: the person using the control. Keep both meaningful, but do not assume that a passing identifier lookup proves a useful spoken name.

The source order follows the task: explanation, language, name, contact choice, Apply and result. There is no arbitrary focus-index scheme to keep synchronized with a second visual order. The built-in controls retain their normal keyboard and accessibility actions.

The result uses a status semantic region, and validation is attached through `FormControl`. Those declarations express what the application means; the actual announcement timing still needs checking. Fission's iOS shell sends its semantic tree through AccessKit's iOS adapter. A browser's accessibility tree exercises a different adapter and cannot qualify that native path.

## Complete the task with VoiceOver rather than inspecting its pixels

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Use [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) for selection and [the iPhone installation guide](/blog/install-a-fission-app-on-a-physical-iphone/) for a signed physical-device run.

Enable VoiceOver and navigate without relying on the screen. The name field should have a useful name and required/error information. The switch should expose its name and current on/off state, and activation should change that state once. Apply should remain understandable when its longer translated label wraps. Check that the result can be found and that changes are announced usefully; if the platform behavior differs from the declaration, treat that as a defect to investigate, not evidence that the task is complete.

Repeat with the software keyboard open, larger text and both languages. Check that focus does not disappear after applying or get stuck on a decorative container. The generated launch smoke test does not perform these checks, and even a correct semantic tree does not replace listening to the actual VoiceOver result.
