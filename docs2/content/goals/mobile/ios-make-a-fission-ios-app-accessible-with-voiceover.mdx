## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-make-a-fission-ios-app-accessible-with-voiceover
cd ios-make-a-fission-ios-app-accessible-with-voiceover
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-make-a-fission-ios-app-accessible-with-voiceover/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

<Tabs>
<TabItem label="src/app.rs">

```rust
use fission::prelude::*;

fission_component! {
    pub IosAccessibilityVoiceOver<()> {
        state {
            saved: bool = false,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("accessible-settings".to_string()),
        label: Some(cx.tr("accessibility.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("accessibility.title"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("accessibility.description")),
                Button(
                    child: Text(if screen.saved {
                        cx.tr("accessibility.saved")
                    } else {
                        cx.tr("accessibility.save")
                    }),
                    key: "save-settings",
                    on_press: reduce { screen.saved = !screen.saved; },
                )
                .semantics_identifier("settings.save"),
                Text(if screen.saved {
                    cx.tr("accessibility.status.saved")
                } else {
                    cx.tr("accessibility.status.ready")
                })
                    .color(tokens.colors.text_secondary),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn load_bundle(locale: &str, source: &str) -> TranslationBundle {
    TranslationBundle {
        locale: Locale::from(locale),
        messages: serde_yaml::from_str(source).expect("valid tutorial translations"),
    }
}

fn preview_env() -> Env {
    let mut env = Env::default();
    env.i18n.add_bundle(load_bundle("en-US", include_str!("i18n/en-US.yaml")));
    env.i18n.add_bundle(load_bundle("es-ES", include_str!("i18n/es-ES.yaml")));
    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::IosAccessibilityVoiceOver)
        .with_env(preview_env())
        .with_title("ios make a fission ios app accessible with voiceover")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Add useful semantic roles, labels, values, focus order and control actions

Give each icon-only control a useful semantic label and expose selected, disabled, checked and value state through the Fission widget or `SemanticsRegion` metadata. Keep focus order aligned with reading order and never use colour alone to explain an error. Check labels and state with LiveTest, then navigate the task with VoiceOver in the iOS Simulator and on a device. A browser preview can show the component's semantics, but only VoiceOver on an iOS target confirms the native accessibility experience. See the [accessibility reference](/reference/platform/accessibility/) for the platform contract.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

## Check screen-reader behavior on iOS

The browser preview can show the labels in the component, but it cannot prove the native VoiceOver bridge. On a target with VoiceOver enabled, move through the task without looking at the screen and listen for each control’s purpose, value and state.

Check that focus follows the visual reading order, errors are announced when they appear, and disabled or selected controls are described correctly. If an icon-only action has no useful spoken name, fix its semantic label before release.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
