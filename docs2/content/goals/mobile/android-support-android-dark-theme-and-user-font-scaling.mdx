## Let presentation change without changing the user's work

Dark appearance and larger text are presentation inputs, not separate versions of a screen. If each component maintains its own colours or multiplies font sizes independently, those choices soon disagree. The result is a dark surface with a light input, or text scaled twice in one region and not at all in another.

Here, a handover-note screen uses the generated Fission design system and lets the shell supply text scaling. The app owns only an optional theme override. Without an override, the system appearance applies; choosing Light or Dark replaces that presentation choice without recreating the note.

## Create the Android project

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/), then start [an emulator](/blog/create-and-launch-a-fission-android-emulator/) or connect [a phone](/blog/run-a-fission-app-on-a-physical-android-phone/).

```sh
cargo install cargo-fission
fission init android-support-android-dark-theme-and-user-font-scaling
cd android-support-android-dark-theme-and-user-font-scaling
cargo add serde_yaml
fission add-target android --project-dir .
```

Keep the generated `src/main.rs`. The native and Web entrypoints below run the same note screen. We use `FissionDefaultDesignSystem`, which is generated from Fission's default DSP; an application-specific DSP can replace it without teaching each widget another palette.

## Use the host's scale and the active design tokens

The Android shell reads `Configuration.fontScale` and supplies `Env.text_scaler` before building a frame. Leave that value alone in `with_sync_env`. Normal text and controls use the shared scaler; multiplying token font sizes again is not how to support the system preference.

The note has no fixed reading height or line limit. `Scroll` keeps the form reachable when the keyboard or large text reduces the available space, and `SafeArea` accounts for device insets rather than guessing padding for a particular phone.

use fission::prelude::*;

#[derive(Debug, Default)]
pub struct ReadingState {
    pub theme_override: Option<DesignMode>,
}
impl GlobalState for ReadingState {}

pub fn sync_env(state: &ReadingState, env: &mut Env) {
    let mode = state.theme_override.unwrap_or(env.system_theme_mode);
    env.theme = FissionDefaultDesignSystem::theme(mode);
    // Keep the host's text_scaler. Do not multiply token font sizes again.
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn automatic_follows_the_host_and_override_does_not_reset_text_scaling() {
        let mut state = ReadingState::default();
        let mut env = Env::default();
        env.system_theme_mode = DesignMode::Dark;
        env.text_scaler = TextScaler::accessibility(1.8);
        let host_scaler = env.text_scaler.clone();
        sync_env(&state, &mut env);
        assert_eq!(env.theme.design_system.mode, DesignMode::Dark);
        state.theme_override = Some(DesignMode::Light);
        sync_env(&state, &mut env);
        assert_eq!(env.theme.design_system.mode, DesignMode::Light);
        assert_eq!(env.text_scaler, host_scaler);
    }
}

use fission::prelude::*;
use crate::presentation::ReadingState;

fission_component! {
    pub HandoverNotes<ReadingState> {
        state { note: String = String::new() }
    }
    view(notes, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SafeArea(
        child: Scroll(
            child: Container(
                child: Column(gap: tokens.spacing.l, children: [
                    Text(cx.tr("reading.title")).size(tokens.typography.heading2_size),
                    Text(cx.tr("reading.context")),

                    TextInput(
                        label: Some(cx.tr("reading.note").into()),
                        helper_text: Some(cx.tr("reading.note_help").into()),
                        multiline: true,
                        bind: notes.note,
                        semantics_identifier: "reading.note".to_string(),
                    ),
                    if notes.note.trim().is_empty() {
                        EmptyState(
                            title: cx.tr("reading.empty"),
                            description: cx.tr("reading.empty_help"),
                        )
                    } else {
                        Card(child: Column(gap: tokens.spacing.s, children: [
                            Text(cx.tr("reading.preview")).weight(tokens.typography.font_weight_semibold),
                            Text(notes.note.clone()),
                        ]))
                    },
                ]),
            ).padding_all(tokens.spacing.l).bg(tokens.colors.background),
        ),
    )
}

use std::collections::HashMap;
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid checked-in translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Add a theme override without replacing system scaling

`None` means use the host's appearance; `Some(Light)` or `Some(Dark)` is the user's app-specific override. That makes precedence explicit. Switching the device theme must not defeat a deliberate override, and choosing the device appearance again must remove that override.

The picker changes state through reducers. The existing shell callback selects one complete generated theme, including component recipes, instead of replacing just the page background.

use fission::prelude::*;
use crate::presentation::ReadingState;

fission_component! {
    pub AppearancePicker<ReadingState> {}
    view(_picker, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Column(gap: tokens.spacing.s, children: [
        Text(cx.tr("appearance.title")).weight(tokens.typography.font_weight_semibold),
        Wrap(spacing: tokens.spacing.s, children: [
            Button(
                child: Text(cx.tr("appearance.system")),
                key: "appearance-system",
                disabled: state.theme_override.is_none(),
                on_press: reduce { state.theme_override = None; },
            ).semantics_identifier("appearance.system"),
            Button(
                child: Text(cx.tr("appearance.light")),
                key: "appearance-light",
                disabled: state.theme_override == Some(DesignMode::Light),
                on_press: reduce { state.theme_override = Some(DesignMode::Light); },
            ).semantics_identifier("appearance.light"),
            Button(
                child: Text(cx.tr("appearance.dark")),
                key: "appearance-dark",
                disabled: state.theme_override == Some(DesignMode::Dark),
                on_press: reduce { state.theme_override = Some(DesignMode::Dark); },
            ).semantics_identifier("appearance.dark"),
        ]),
    ])
}

## Check the combinations users actually choose

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

Check light and dark appearance at standard and large system font sizes on an emulator and a phone. Include a long translated label, multiple paragraphs, a visible keyboard, rotation and a narrow split-screen window. Essential content must remain readable and actions must remain reachable.

Do not force a linear multiplier to imitate every Android font-size rule. Fission maps the host factor through its accessibility text scaler, where larger display text grows more gradually than body text. The result still needs rendered review: reading a scale factor is not proof that every widget handles it well.

This example does not implement a separate high-contrast palette or persist the app override. Treat those as explicit requirements if the product needs them, not as capabilities supplied merely by a Light/Dark selector.
