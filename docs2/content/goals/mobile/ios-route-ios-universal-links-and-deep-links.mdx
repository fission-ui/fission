## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-route-ios-universal-links-and-deep-links
cd ios-route-ios-universal-links-and-deep-links
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-route-ios-universal-links-and-deep-links/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

use fission::prelude::*;
fission_component! {
    pub DeepLinkDocumentLibrary<()> {
        state {
            document_open: bool = false,
            missing_document: bool = false,
        }
    }
    view(library, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let route_title = if library.missing_document {
            cx.tr("links.state.missing")
        } else if library.document_open {
            cx.tr("links.state.open")
        } else {
            cx.tr("links.state.library")
        };
        let route_path = if library.missing_document {
            cx.tr("links.path.unknown")
        } else if library.document_open {
            cx.tr("links.path.guide")
        } else {
            cx.tr("links.path.library")
        };
        let detail = if library.missing_document {
            cx.tr("links.detail.missing")
        } else if library.document_open {
            cx.tr("links.detail.open")
        } else {
            cx.tr("links.detail.library")
        };
    } =>
    SemanticsRegion(
        identifier: Some("ios-universal-links-document-library".to_string()),
        label: Some(cx.tr("links.screen.label")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Column(gap: tokens.spacing.xs, children: [
                    Text(cx.tr("links.app.name"))
                        .weight(tokens.typography.font_weight_bold),
                    Text(cx.tr("links.route"))
                        .color(tokens.colors.text_secondary),
                ]),
                Badge(text: cx.tr("links.preview.badge")),
                Divider(),
                Text(cx.tr("links.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("links.summary"))
                    .color(tokens.colors.text_secondary),
                Container(
                    Column(gap: tokens.spacing.s, children: [
                        Text(route_title)
                            .weight(tokens.typography.font_weight_semibold),
                        Text(route_path),
                        Text(detail)
                            .color(tokens.colors.text_secondary),
                    ])
                )
                .padding_all(tokens.spacing.m)
                .bg(tokens.colors.background)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.medium),
                Button(
                    child: Text(cx.tr("links.action.open")),
                    key: "open-guide-link",
                    variant: ButtonVariant::Primary,
                    on_press: reduce {
                        library.document_open = true;
                        library.missing_document = false;
                    },
                    semantics: Some(Semantics {
                        role: Role::Button,
                        label: Some(cx.tr("links.action.open")),
                        identifier: Some("links.open-guide".to_string()),
                        ..Default::default()
                    }),
                ),
                Button(
                    child: Text(cx.tr("links.action.unknown")),
                    key: "open-unknown-link",
                    on_press: reduce {
                        library.document_open = false;
                        library.missing_document = true;
                    },
                    semantics: Some(Semantics {
                        role: Role::Button,
                        label: Some(cx.tr("links.action.unknown")),
                        identifier: Some("links.open-unknown".to_string()),

                    child: Text(cx.tr("links.action.back")),

## Accept a product URL and reduce it to route state

Deep links are inbound shell events, so there is no button that should parse a URL. Configure the schemes and domain at app startup, then turn the accepted link into a normal route in one reducer. Android still needs the matching intent filter or App Links verification, and iOS needs its URL scheme or Associated Domains configuration; check the generated platform README and domain association file before testing.

```rust
fn on_deep_link(state: &mut AppState, action: DeepLinkReceived) {
    let url = action.link.url;
    if let Some(id) = url.strip_prefix("fission://document/") {
        if !id.is_empty() {
            state.path = Some(format!("/documents/{id}"));
            state.route_error = None;
            return;
        }
    }
    state.route_error = Some("This document link is not recognised.".to_string());
}

let app = MobileApp::<AppState, _>::new(App)
    .with_deep_link_config(
        DeepLinkConfig::new()
            .scheme("fission")
            .domain("example.com")
            .path_prefix("/document"),
    )
    .on_deep_link(on_deep_link as fn(&mut AppState, DeepLinkReceived));
```

Use Fission `Router` and `RouterParams` to resolve the stored route. Test a cold launch and a link received while the app is open, then test an unrecognised document ID. The route component should render a useful missing-document state rather than constructing private content before access checks succeed.

## Test in-app and inbound routes on iOS

Open the destination from inside the app, return to the previous screen, then open the same destination from its external URL. The external route should use the same typed route state as an in-app link rather than creating a second copy of the screen logic.

Try an unknown record ID and a malformed link as well as a valid one. The app should show a useful not-found or recovery screen, preserve unsaved work when required, and never render a blank route.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```


To verify a hardware-dependent path on an iPhone, configure development signing and Developer Mode, create a signed release IPA, then install it through Xcode Devices and Simulators:

```sh
fission package --project-dir . --target ios --format ipa --release
```

`fission run --target ios` remains simulator-only; it does not launch directly on a physical iPhone. A simulator preview cannot prove NFC, camera, biometrics or other physical capability behaviour.
