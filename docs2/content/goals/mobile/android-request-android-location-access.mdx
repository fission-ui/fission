At Harbor Street depot, Nightjar Couriers records who received a package and which loading bay they used. The handoff should remain saveable indoors or after a driver declines location; coordinates are optional evidence, not a prerequisite.

We’ll request foreground location only when the driver chooses to add the optional pin. Android may grant approximate access even when the app asks for precise access, so the screen shows the returned accuracy and lets the driver decide whether the point is useful. There is no background tracking in this flow.

## Add an optional, one-time location pin

The driver’s choice and the platform request are separate. Buttons dispatch reducers; a reducer queues the geolocation effect, and another reducer stores the permission or position when the host replies. The view never opens a permission prompt or waits for a location lookup.

Android and the browser report permission differently, so the screen keeps requests, status checks, and position lookups separate. **Request location access** opens Android’s permission UI. The request is asynchronous, and the host may first return the state from before the driver answered. Once the prompt closes, **Refresh access status** reads the current state. On Android, the pin button stays unavailable until that check confirms access; a pending prompt is not approval.

The browser host reports its current state without opening a prompt. When it reports **Prompt**, the preview enables **Add handoff pin**; the browser asks for permission when the position lookup starts. The component works with both hosts while making their different permission steps clear.

Android 12 and later let people grant approximate access. When <code>precise</code> is true, Fission requests both foreground coarse and fine permissions, but Android decides what to grant. The returned <code>accuracy_meters</code> value tells the app how much confidence to place in the pin. If the location is too broad, the handoff can still keep its depot and loading-bay name.

use fission::prelude::*;

#[derive(Debug, Default)]
pub struct DeliveryHandoffState {
    pub permission: Option<GeolocationPermission>,
    pub permission_busy: bool,
    pub permission_message: Option<String>,
    pub locating: bool,
    pub position: Option<GeolocationPosition>,
    pub location_message: Option<String>,
}

impl GlobalState for DeliveryHandoffState {}

#[fission_reducer(LocationPermissionUpdated)]
fn on_location_permission_updated(
    state: &mut DeliveryHandoffState,
    permission: GeolocationPermission,
) {
    state.permission_busy = false;
    state.permission = Some(permission);
    state.permission_message = Some(match permission {
        GeolocationPermission::Granted => {
            "Location access is granted. Add a pin only if this handoff needs one.".to_string()
        }
        GeolocationPermission::Denied => {
            "Location is not currently granted. If the Android prompt just closed, refresh this status. Otherwise, change access in system settings or continue without a pin.".to_string()
        }
        GeolocationPermission::Prompt => {
            "No location choice has been made. Answer the Android prompt if it is open, then refresh. In this browser preview, Add handoff pin opens the browser prompt.".to_string()
        }
        GeolocationPermission::Unsupported => {
            "This host cannot provide location. The stop name and handoff notes are still enough to save the record.".to_string()
        }
        GeolocationPermission::Unknown => {
            "The host could not determine location access. Refresh the status or continue without a pin.".to_string()
        }
    });
}

#[fission_reducer(LocationPermissionFailed)]
fn on_location_permission_failed(
    state: &mut DeliveryHandoffState,
    error: GeolocationError,
) {
    state.permission_busy = false;
    state.permission_message = Some(if error.message.trim().is_empty() {
        "The host could not check location access. You can still save the handoff without a pin."
            .to_string()
    } else {
        format!(
            "Location access could not be checked: {}. You can still save the handoff without a pin.",
            error.message
        )
    });
}

#[fission_reducer(RequestDeliveryLocationAccess)]
fn on_request_delivery_location_access(
    state: &mut DeliveryHandoffState,
    ctx: &mut ReducerContext<DeliveryHandoffState>,
) {
    if state.permission_busy {
        return;
    }

    state.permission_busy = true;
    state.permission_message = Some("Requesting foreground location access…".to_string());

    let on_ok = ctx.effects.bind(
        LocationPermissionUpdated(GeolocationPermission::Unknown),
        reduce_with!(on_location_permission_updated),
    );
    let on_err = ctx.effects.bind(
        LocationPermissionFailed(GeolocationError::default()),
        reduce_with!(on_location_permission_failed),
    );

    ctx.effects
        .geolocation()
        .request_permission(GeolocationPermissionRequest {
            precise: true,
            background: false,
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(RefreshDeliveryLocationAccess)]
fn on_refresh_delivery_location_access(
    state: &mut DeliveryHandoffState,
    ctx: &mut ReducerContext<DeliveryHandoffState>,
) {
    if state.permission_busy {
        return;
    }

    state.permission_busy = true;
    state.permission_message = Some("Checking the current location access…".to_string());

    let on_ok = ctx.effects.bind(
        LocationPermissionUpdated(GeolocationPermission::Unknown),
        reduce_with!(on_location_permission_updated),
    );
    let on_err = ctx.effects.bind(
        LocationPermissionFailed(GeolocationError::default()),
        reduce_with!(on_location_permission_failed),
    );

    ctx.effects
        .geolocation()
        .permission()
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(HandoffPinCaptured, no_eq)]
fn on_handoff_pin_captured(
    state: &mut DeliveryHandoffState,
    position: GeolocationPosition,
) {
    state.locating = false;
    state.position = Some(position.clone());
    state.location_message = Some(format!(
        "Pin ready at {:.5}, {:.5}; reported accuracy is about {:.0} m.",
        position.latitude,
        position.longitude,
        position.accuracy_meters,
    ));
}

#[fission_reducer(HandoffPinFailed)]
fn on_handoff_pin_failed(
    state: &mut DeliveryHandoffState,
    error: GeolocationError,
) {
    state.locating = false;
    if error.code == "permission_denied" {
        state.permission = Some(GeolocationPermission::Denied);
        state.permission_message = Some(
            "Location access was denied. Refresh the status after changing Android settings, or continue without a pin."
                .to_string(),
        );
    }
    state.location_message = Some(match error.code.as_str() {
        "permission_denied" => {
            "Location was not granted. Refresh access after the Android prompt, or keep the named stop and save without a pin.".to_string()
        }
        "unsupported" => {
            "This device cannot provide a location pin. Keep the named stop and save the handoff.".to_string()
        }
        "timeout" => {
            "The phone did not find a position in time. Try once more or save the handoff without a pin.".to_string()
        }
        "position_unavailable" | "unavailable" => {
            "The location provider has no position right now. Check location services or save without a pin.".to_string()
        }
        _ if error.message.trim().is_empty() => {
            "The location provider returned no position. Try again or save without a pin."
                .to_string()
        }
        _ => format!(
            "The handoff pin could not be added: {}. The stop name and notes are unchanged.",
            error.message
        ),
    });
}

#[fission_reducer(AddHandoffPin)]
fn on_add_handoff_pin(
    state: &mut DeliveryHandoffState,
    ctx: &mut ReducerContext<DeliveryHandoffState>,
) {
    if state.locating {
        return;
    }

    let may_request_position = state.permission == Some(GeolocationPermission::Granted)
        || state.permission == Some(GeolocationPermission::Prompt);
    if !may_request_position {
        state.location_message = Some(
            "Request location access and refresh the status before adding a pin. The handoff form remains available without it."
                .to_string(),
        );
        return;
    }

    state.locating = true;
    state.location_message = Some("Finding a position for this handoff…".to_string());

    let on_ok = ctx.effects.bind(
        HandoffPinCaptured(GeolocationPosition {
            latitude: 0.0,
            longitude: 0.0,
            altitude_meters: None,
            accuracy_meters: 0.0,
            altitude_accuracy_meters: None,
            heading_degrees: None,
            speed_mps: None,
            timestamp_unix_ms: 0,
        }),
        reduce_with!(on_handoff_pin_captured),
    );
    let on_err = ctx.effects.bind(
        HandoffPinFailed(GeolocationError::default()),
        reduce_with!(on_handoff_pin_failed),
    );

    ctx.effects
        .geolocation()
        .current_position(GeolocationPositionRequest {
            high_accuracy: true,
            timeout_ms: Some(10_000),
            maximum_age_ms: Some(30_000),
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

The position request asks for a fresh, high-accuracy reading, with a ten-second timeout and a short cache age. Those are preferences, not guarantees: the device may return an older or less precise result. That is why the screen shows the reported accuracy and leaves the depot name and notes alone if lookup fails.

## Verify the Android permission choices

Run the generated app on an emulator and test each choice from a known permission state. Reset the app’s location permission in Android Settings between runs to see the first-use prompt again.

<Tabs>
<TabItem label="Run on Android">
```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
```
</TabItem>
<TabItem label="Check permission behavior">
```text
1. On first use, request location access from the handoff form.
2. Choose precise access. Refresh the status, add a pin, and check the reported accuracy.
3. Reset the permission, choose approximate access, refresh, and add a pin.
4. Reset once more and deny access. Confirm the stop and notes still save.
5. Turn Android location services off and confirm the app offers the no-pin path.
```

Approximate access is still permission granted. Don’t report it as a failure or silently ask for more. If the pin is not useful at that accuracy, the driver can keep the named stop and complete the handoff. This guide only requests foreground access; it does not add <code>ACCESS_BACKGROUND_LOCATION</code>.

For platform behavior, see Android’s [runtime location permission guide](https://developer.android.com/develop/sensors-and-location/location/permissions/runtime) and [approximate location guidance](https://developer.android.com/develop/sensors-and-location/location/permissions#approximate-request). For Fission’s portable provider contract, see the [Geolocation capability guide](/docs/capabilities/geolocation/) and the [Geolocation reference](/reference/capabilities/geolocation/).
