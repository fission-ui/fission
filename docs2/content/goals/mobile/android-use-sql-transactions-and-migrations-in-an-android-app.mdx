## Name what has to commit together

Closing an inspection changes two related facts: the visit becomes complete, and its closure note explains what was done. The invariant is that neither change becomes visible without the other. Two independent SQL effects cannot provide that guarantee; one bounded transaction can.

This app starts from the device's actual SQLite database. The user creates an inspection and later closes it with a note. The interface refreshes from committed rows rather than marking the card complete before the database acknowledges the write. There is no fixture provider, server or synchronisation layer.

## Migrate first, then allow writes

Migration 1 creates the visits table. Migration 2 adds closure notes without replacing existing visits. Their versions are stable schema history, not a reason to edit migration 1 every time the application grows.

The shell queues one startup action. The view registers that action unconditionally, before any error branch exists; merely generating its reducer function would not register it. Migration success then triggers a bounded query. A loading or failed database cannot masquerade as an empty ready database.

The closure transaction updates an open visit and inserts its note only when that update changed one row. Both run on the transaction's connection, so SQLite's `changes()` refers to that update. A second note is not silently substituted for an earlier one. The completion reducer checks both step results, then reads the actual committed records.

use fission::prelude::*;
use crate::state::{valid_text, Inspection, InspectionsState, Phase};

pub fn migrations() -> SqlMigrations {
    let mut migrations = SqlMigrations::new();
    migrations.add(SqlMigration::new(1, "inspection records",
        "CREATE TABLE inspection_visits(
            id INTEGER PRIMARY KEY,
            title TEXT NOT NULL CHECK(length(trim(title)) BETWEEN 1 AND 160),
            completed INTEGER NOT NULL DEFAULT 0 CHECK(completed IN (0,1))
        );"
    )).expect("unique version one");
    migrations.add(SqlMigration::new(2, "inspection closure notes",
        "CREATE TABLE inspection_closures(
            visit_id INTEGER PRIMARY KEY REFERENCES inspection_visits(id),
            note TEXT NOT NULL CHECK(length(trim(note)) BETWEEN 1 AND 160)
        );"
    )).expect("unique version two");
    migrations
}

pub fn close_transaction(id: i64, note: &str) -> SqlTransaction {
    let mut transaction = SqlTransaction::new();
    transaction.execute(SqlStatement::new(
        "UPDATE inspection_visits SET completed=1 WHERE id=?1 AND completed=0"
    ).bind(id));
    transaction.execute(SqlStatement::new(
        "INSERT INTO inspection_closures(visit_id,note)
         SELECT ?1,?2 WHERE changes()=1"
    ).bind(id).bind(note.trim().to_owned()));
    transaction
}

pub fn query_inspections(ctx: &mut ReducerContext<InspectionsState>) {
    let ok = ctx.effects.bind(InspectionsLoaded, reduce_with!(inspections_loaded));
    let err = ctx.effects.bind(DatabaseFailed, reduce_with!(database_failed));
    ctx.effects.sql().query(SqlStatement::new(
        "SELECT v.id,v.title,v.completed,c.note
         FROM inspection_visits v LEFT JOIN inspection_closures c ON c.visit_id=v.id
         ORDER BY v.id DESC LIMIT 251"
    )).on_ok(ok).on_err(err);
}

pub fn decode_inspections(rows: SqlRows) -> Result<Vec<Inspection>, &'static str> {
    if rows.rows.len() > 250 { return Err("sql.limit"); }
    rows.rows.into_iter().map(|row| {
        let id: i64 = row.get("id").map_err(|_| "sql.records")?;
        let title: String = row.get("title").map_err(|_| "sql.records")?;
        let completed: i64 = row.get("completed").map_err(|_| "sql.records")?;
        let note: Option<String> = row.get("note").map_err(|_| "sql.records")?;
        if id <= 0 || !valid_text(&title) || !matches!(completed, 0 | 1)
            || (completed == 1) != note.is_some()
            || note.as_deref().is_some_and(|value| !valid_text(value)) {
            return Err("sql.records");
        }
        Ok(Inspection { id, title, closure_note: note })
    }).collect()
}

#[fission_reducer(PrepareInspections)]
pub fn prepare_inspections(state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>) {
    if state.phase == Phase::Writing { return; }
    state.phase = Phase::Loading;
    state.issue = None;
    let ok = ctx.effects.bind(SchemaPrepared, reduce_with!(schema_prepared));
    let err = ctx.effects.bind(DatabaseFailed, reduce_with!(database_failed));
    ctx.effects.sql().migrate(migrations()).on_ok(ok).on_err(err);
}
#[fission_reducer(SchemaPrepared)]
pub fn schema_prepared(state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>) {
    if !ctx.input.sql_migration_result().is_some_and(|value| value.current_version == 2) {
        state.phase = Phase::Failed;
        state.issue = Some("sql.schema");
        return;
    }
    query_inspections(ctx);
}
#[fission_reducer(InspectionsLoaded)]
pub fn inspections_loaded(state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>) {
    match ctx.input.sql_rows().ok_or("sql.records").and_then(decode_inspections) {
        Ok(records) => {
            state.records = records;
            state.phase = Phase::Ready;
            state.issue = None;
        }
        Err(key) => {
            state.phase = Phase::Failed;
            state.issue = Some(key);
        }
    }
}
#[fission_reducer(DatabaseFailed)]
pub fn database_failed(state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>) {
    let _ = ctx.input.sql_error();
    state.phase = Phase::Failed;
    state.issue = Some("sql.failed");
}

use fission::prelude::*;
use crate::state::{valid_text, InspectionsState, Phase};
use crate::storage::{close_transaction, query_inspections, DatabaseFailed, database_failed};

pub fn add_inspection(state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>) {
    if state.phase != Phase::Ready { return; }
    if state.records.len() >= 250 { state.issue = Some("sql.limit"); return; }
    if !valid_text(&state.title_draft) { state.issue = Some("sql.invalid"); return; }
    state.phase = Phase::Writing;
    state.issue = None;
    let ok = ctx.effects.bind(InspectionAdded, reduce_with!(inspection_added));
    let err = ctx.effects.bind(DatabaseFailed, reduce_with!(database_failed));
    ctx.effects.sql().execute(SqlStatement::new(
        "INSERT INTO inspection_visits(title) VALUES (?1)"
    ).bind(state.title_draft.trim().to_owned())).on_ok(ok).on_err(err);
}
#[fission_reducer(InspectionAdded)]
pub fn inspection_added(state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>) {
    if !ctx.input.sql_execute_result().is_some_and(|value| value.affected_rows == 1) {
        state.phase = Phase::Failed;
        state.issue = Some("sql.failed");
        return;
    }
    // Inputs are read-only while writing, so this is the submitted draft.
    state.title_draft.clear();
    state.phase = Phase::Loading;
    query_inspections(ctx);
}

pub fn close_inspection(
    state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>, id: i64, note: &str,
) {
    if state.phase != Phase::Ready { return; }
    if !valid_text(note) { state.issue = Some("sql.invalid"); return; }
    if !state.records.iter().any(|record| record.id == id && record.closure_note.is_none()) { return; }
    state.phase = Phase::Writing;
    state.issue = None;
    let ok = ctx.effects.bind(InspectionClosed, reduce_with!(inspection_closed));
    let err = ctx.effects.bind(DatabaseFailed, reduce_with!(database_failed));
    ctx.effects.sql().transaction(close_transaction(id, note)).on_ok(ok).on_err(err);
}
#[fission_reducer(InspectionClosed)]
pub fn inspection_closed(state: &mut InspectionsState, ctx: &mut ReducerContext<InspectionsState>) {
    let confirmed = ctx.input.sql_transaction_result().is_some_and(|value| {
        matches!(value.steps.as_slice(), [
            SqlStepResult::Execute(first), SqlStepResult::Execute(second),
        ] if first.affected_rows == 1 && second.affected_rows == 1)
    });
    if !confirmed {
        state.phase = Phase::Failed;
        state.issue = Some("sql.failed");
        return;
    }
    state.phase = Phase::Loading;
    query_inspections(ctx);
}

            Text(cx.tr("sql.title")).size(tokens.typography.heading2_size),

                semantics_identifier: "inspection.new".to_owned(),

            Button(
                child: Text(cx.tr("sql.add")), key: "inspection.add",
                disabled: state.phase != Phase::Ready || !valid_text(&state.title_draft),
                on_press: reduce { add_inspection(state, cx); },
            ),
            if matches!(state.phase, Phase::Loading | Phase::Writing) {
                Spinner(motion: Some(SpinnerMotion::Default), label: cx.tr("sql.pending"))
            },

                    child: Text(cx.tr("sql.reload")), key: "inspection.reload",
                    on_press: prepare,
                )

            if state.phase == Phase::Ready && state.records.is_empty() {
                Text(cx.tr("sql.empty"))

use super::*;
use fission::sqlite::SqliteStore;
use fission::store::SqlStoreProvider;

#[test]
fn migration_upgrade_and_second_statement_failure_use_the_real_sqlite_provider() {
    pollster::block_on(async {
        let store = SqliteStore::open_in_memory().unwrap();
        let mut version_one = SqlMigrations::new();
        version_one.add(migrations().iter().next().unwrap().clone()).unwrap();
        assert_eq!(store.migrate(version_one).await.unwrap().current_version, 1);
        let created = store.execute(SqlStatement::new(
            "INSERT INTO inspection_visits(title) VALUES (?1)"
        ).bind("Check the caretaker's gate")).await.unwrap();
        let id = created.last_insert_rowid.unwrap();

        let upgraded = store.migrate(migrations()).await.unwrap();
        assert_eq!(upgraded.previous_version, 1);
        assert_eq!(upgraded.current_version, 2);
        assert_eq!(upgraded.applied, 1);
        assert_eq!(store.migrate(migrations()).await.unwrap().applied, 0);

        // Bypass UI validation only in this test. The second statement fails
        // its CHECK constraint after the first statement has changed the visit.
        assert!(store.transaction(close_transaction(id, "")).await.is_err());
        let row = store.query(SqlStatement::new(
            "SELECT completed FROM inspection_visits WHERE id=?1"
        ).bind(id).into()).await.unwrap().rows.remove(0);
        assert_eq!(row.get::<i64>("completed").unwrap(), 0);
        let row = store.query(SqlStatement::new(
            "SELECT COUNT(*) AS count FROM inspection_closures"
        ).into()).await.unwrap().rows.remove(0);
        assert_eq!(row.get::<i64>("count").unwrap(), 0);

        let committed = store.transaction(
            close_transaction(id, "Latch replaced and tested"),
        ).await.unwrap();
        assert!(matches!(committed.steps.as_slice(), [
            SqlStepResult::Execute(first), SqlStepResult::Execute(second),
        ] if first.affected_rows == 1 && second.affected_rows == 1));
        // A repeated request cannot overwrite the first closure note.
        let repeated = store.transaction(close_transaction(id, "Another note")).await.unwrap();
        assert!(matches!(repeated.steps.as_slice(), [
            SqlStepResult::Execute(first), SqlStepResult::Execute(second),
        ] if first.affected_rows == 0 && second.affected_rows == 0));
    });
}

## Exercise rollback through the actual provider

The native test uses a temporary in-memory SQLite database provided by `SqliteStore`, not a fake implementation of SQL. It creates version 1, writes a record, upgrades to version 2 and checks migrations are not reapplied. It then deliberately supplies an invalid closure note, bypassing UI validation only inside the test.

That second statement fails after the first has updated the visit. The test checks that the visit remains open and no closure row was inserted. This is the failure that establishes the need for the transaction; a test which merely counts the statements would not establish rollback.

```sh
cargo test
fission doctor android --project-dir .
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

On Android, create a record, close the process without uninstalling it, and reopen the same application ID. Verify the title and closure note reload from that installation's database. Test an actual version-1 database as well as a fresh installation. Do not delete the user's database to make a migration test pass.

Writes and refreshes are serialised in this example, and inputs remain read-only until their result is known. A failed or missing acknowledgment is not permission to repeat an insert: reload committed data first, since a write may have reached the database before its result was lost. The screen retains its last confirmed rows and disables editing rather than treating an error as success.

This lesson supports 250 records and fails explicitly if a query discovers more. Larger datasets need intentional pagination, not a hidden `LIMIT` that silently makes records disappear. A local closure note is also not a tamper-proof audit log or a server authorisation mechanism.
