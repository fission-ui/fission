A responsive layout changes how a task is presented, not what the user has entered. For an announcement editor, a wide window can show the draft and its preview side by side, whilst a narrow window needs those sections stacked. Neither arrangement should own a separate copy of the announcement.

We will build that editor with real user input. The draft belongs to application state because two independently constructed layout branches read it. Resizing can therefore change the arrangement without replacing the user's work with another branch's empty local state.

## Create the project

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) first, then generate the shared app.

```sh
cargo install cargo-fission
fission init ios-make-an-ios-layout-adapt-across-iphone-and-ipad-sizes
cd ios-make-an-ios-layout-adapt-across-iphone-and-ipad-sizes
fission add-target ios --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs` and replace `src/lib.rs` with the shared shell wiring below. Native and Web targets then run the same editor rather than a browser-only layout demonstration.

## Share the task, not one retained widget instance

The editor and preview are named components. Each responsive branch constructs its own instances, whilst both read the same `AnnouncementState`. Do not construct one `Widget` and clone it into both branches: retained widget identity and shared application data are not interchangeable.

The breakpoint is a layout choice, not a claim that every iPad is wide. A narrow split-screen window on an iPad should receive the compact arrangement too. The example uses a container query because it must also respond correctly when embedded in the documentation's preview panel.

            multiline: true,

```rust
use super::{editor::AnnouncementEditor, preview::AnnouncementPreview, state::AnnouncementState};
use fission::prelude::*;

const TWO_PANE_MIN_WIDTH: f32 = 760.0;

fission_component! {
    pub WideAnnouncement<AnnouncementState> {}
    view(_layout, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => Row(gap: tokens.spacing.l, children: [
        Container(AnnouncementEditor).flex_grow(1.0),
        Container(AnnouncementPreview).flex_grow(1.0),
    ])
}

fission_component! {
    pub CompactAnnouncement<AnnouncementState> {}
    view(_layout, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => Column(gap: tokens.spacing.l, children: [
        AnnouncementEditor,
        AnnouncementPreview,
    ])
}

fission_component! {
    pub AnnouncementScreen<AnnouncementState> {}
    view(_screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => SafeArea(
        child: Scroll(
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("announcement.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("announcement.explanation")),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("language.english")), key: "english",
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                Responsive::new_with_id(
                    WidgetId::explicit("announcement.layout"),
                    || WideAnnouncement,
                )
                .case_max_width_with(TWO_PANE_MIN_WIDTH, || CompactAnnouncement)
                .container_query(),
            ]))
            .padding_all(tokens.spacing.l),
        ),
    )
}
```

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid announcement translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::AnnouncementState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Choose constraints that describe the component's actual space

`Responsive` checks its cases in order and uses the fallback when none match. Here the compact case matches below 760 logical units and the fallback takes over at 760. The value is explicit so you can adjust it after checking the two sections' real content; it is not a device-model lookup.

Without `.container_query()`, the query uses the full viewport. That can be appropriate for an app shell, but it is wrong for an editor inside a smaller panel: a wide browser window does not imply the embedded editor has enough room for two columns.

The identity-aware constructors give each branch its own retained scope. They do not transfer local state from one branch into another, and hidden responsive branches are not an authorization boundary. Keeping the announcement in shared state follows from its ownership; it is not an incidental workaround for resizing.

## Verify windows rather than device names

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Follow [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) for selection. Check an iPhone in both orientations and an iPad at full width and a narrow supported multitasking width. Keep a draft open during every transition; that tests ownership as well as layout.

Repeat with larger system text and the keyboard visible. Those settings can expose insufficient space even when the width rule is correct. The generated host smoke test checks launch, not text clipping, focus, keyboard avoidance or draft continuity, so exercise those paths explicitly before calling the screen qualified.

This is an in-memory editor. It intentionally has no Send action or persistence claim; [the Store tutorial](/blog/persist-ios-app-state-with-fission-store-and-sqlite/) covers retaining a draft across process restarts.
