Riverside Property Services handles repairs across several apartment buildings. A coordinator starts the day with a queue of open jobs, opens one work order to see its location and reported problem, and returns to the same queue when the repair is complete. On Android, the system Back action should return from that detail screen just like the app’s own navigation.

We will build that flow around three work orders. Fission’s `Router` will select the queue or a detail screen from the current path. The detail route will read its work-order ID from `RouteParams`, and a reducer will mark the repair complete. A route handler keeps app state in sync when Android changes the path through system Back.

## Build the maintenance queue

Start with the information a coordinator needs before opening a job: its short ID, location, priority, current status, and reported problem. We will use sample records in memory so the first screen is ready to inspect as soon as the app opens. Later, a service or database can replace this sample source without changing the way the queue lays out each row.

`WorkOrderCard` presents one repair request. `WorkOrderList` counts the open and urgent jobs, then gives each record a stable key so Fission can keep rows associated with the same work order when the list changes.

## Open a work order and return with Android Back

Now give each row an action. The queue and detail screen are two destinations in one app, so their current path belongs in `WorkOrderState`. `Router` compares that path with the route table and builds only the matching screen. A route such as `/work-orders/4201` contains the record ID; the detail route reads that value from `RouteParams` and checks it against the records before displaying anything.

When a coordinator marks a repair resolved, a reducer changes the shared work-order record. The queue count and detail screen then read the same updated state. Opening a record pushes a route through `ctx.effects.navigate`. Android’s system Back changes the shell route, and `with_route_handler` copies that change into `current_path`, so the Router returns to the queue.

Replace `src/app.rs` with this version. The queue looks familiar, but its cards can now open typed detail routes, and the detail screen can update the repair status.

```rust
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct WorkOrderState {
    pub current_path: String,
    pub work_orders: Vec<WorkOrder>,
    pub notice: String,

impl Default for WorkOrderState {
    fn default() -> Self {
        Self {

impl GlobalState for WorkOrderState {}

#[fission_reducer(OpenWorkOrder)]
pub fn on_open_work_order(
    state: &mut WorkOrderState,
    work_order_id: u32,
    cx: &mut ReducerContext<WorkOrderState>,
) {
    if state.work_orders.iter().any(|order| order.id == work_order_id) {
        let path = format!("/work-orders/{work_order_id}");
        state.current_path = path.clone();
        cx.effects.navigate(path);
    }
}

#[fission_reducer(MarkWorkOrderResolved)]
pub fn on_mark_work_order_resolved(state: &mut WorkOrderState, work_order_id: u32) {
    let Some(order) = state.work_orders.iter_mut().find(|order| order.id == work_order_id) else {
        return;
    };
    if order.status == WorkOrderStatus::Resolved {
        return;
    }
    order.status = WorkOrderStatus::Resolved;
    state.notice = format!("Work order WO-{} is resolved.", order.id);
}

#[fission_reducer(BackToWorkOrders)]
pub fn on_back_to_work_orders(
    _state: &mut WorkOrderState,
    _work_order_id: u32,
    cx: &mut ReducerContext<WorkOrderState>,
) {
    cx.effects.navigation_back();
}

pub fn on_shell_route_changed(
    state: &mut WorkOrderState,
    action: fission::core::action::ShellRouteChanged,
    _cx: &mut ReducerContext<WorkOrderState>,
) {
    state.current_path = action.location.pathname;
}

fission_component! {
    pub WorkOrderDetailRoute<WorkOrderState> {}
    view(_route, state, _cx) {
        let params = fission::build::read::<RouteParams>();
        let requested_id = params.get("id").cloned().unwrap_or_default();
        let work_order = requested_id
            .parse::<u32>()
            .ok()
            .and_then(|id| state.work_orders.iter().find(|order| order.id == id))
            .cloned();
    } =>
    WorkOrderDetail(work_order, requested_id)
}
```

## Connect the route handler to the Android shell

The component code now knows how to render each route. The shell still needs a handler for route changes that originate outside a button, such as pressing Android Back. Register `on_shell_route_changed` when you create the app. It receives the new path from the shell and updates `WorkOrderState`; the next render then gives that path to `Router`.

Keep this setup in `src/lib.rs`. The generated `src/main.rs` and `platforms/android/` files can stay as Fission created them.

```rust
pub mod app;

use app::{on_shell_route_changed, WorkOrderState, WorkOrdersApp};
use fission::prelude::*;

#[cfg(target_os = "android")]
const ANDROID_TEST_CONTROL_PORT: u16 = 48762;

#[cfg(any(target_os = "android", target_os = "ios"))]
fn mobile_app() -> MobileApp<WorkOrderState, WorkOrdersApp> {
    let app = MobileApp::<WorkOrderState, _>::new(WorkOrdersApp::new())
        .with_title("Riverside maintenance work orders")
        .with_route_handler(on_shell_route_changed);
    #[cfg(target_os = "android")]
    let app = app.with_test_control_port(ANDROID_TEST_CONTROL_PORT);
    app
}

#[cfg(target_arch = "wasm32")]
fn web_app() -> WebApp<WorkOrderState, WorkOrdersApp> {
    WebApp::<WorkOrderState, _>::new(WorkOrdersApp::new())
        .with_title("Riverside maintenance work orders")
        .with_route_handler(on_shell_route_changed)
}

#[cfg(not(any(target_arch = "wasm32", target_os = "android", target_os = "ios")))]
pub fn run_desktop() -> anyhow::Result<()> {
    DesktopApp::<WorkOrderState, _>::new(WorkOrdersApp::new())
        .with_title("Riverside maintenance work orders")
        .with_route_handler(on_shell_route_changed)
        .run()
}

#[cfg(any(target_os = "android", target_os = "ios"))]
pub fn run_mobile() -> anyhow::Result<()> {
    mobile_app().run()
}

#[cfg(target_os = "android")]
#[no_mangle]
fn android_main(app_handle: AndroidApp) {
    let _ = mobile_app().run_with_android_app(app_handle);
}

#[cfg(target_arch = "wasm32")]
#[wasm_bindgen::prelude::wasm_bindgen(start)]
pub fn run_web() -> Result<(), wasm_bindgen::JsValue> {
    console_error_panic_hook::set_once();
    web_app()
        .run()
        .map_err(|error| wasm_bindgen::JsValue::from_str(&error.to_string()))
}
```
