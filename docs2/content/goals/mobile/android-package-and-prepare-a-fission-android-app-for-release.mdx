## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-package-and-prepare-a-fission-android-app-for-release
cd android-package-and-prepare-a-fission-android-app-for-release
cargo add serde_yaml
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-package-and-prepare-a-fission-android-app-for-release/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

## Preview a real field-work screen

Use the same kind of task a technician would open on a phone: a named work order, location, due time, one clear inspection step and a status the user can change. The preview keeps that status in memory and lets you switch languages. It does not read a device sensor, call the SDK or prove that a native build, signature or package is valid; the target-specific steps below do that.

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");

    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid Northbank translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }

    env
}

## Package and prepare a Fission Android app for release

Set a stable application ID and increment the version code for every Play upload. The package fields belong in `fission.toml`:

```toml
[app]
name = "Northbank Work Orders"
app_id = "com.example.northbank.workorders"
version = "1.0.0"
build = 1

[package.android]
package_name = "com.example.northbank.workorders"
version_code = 1
version_name = "1.0.0"
keystore_alias = "upload"
keystore_env = "ANDROID_KEYSTORE"
keystore_password_env = "ANDROID_KEYSTORE_PASSWORD"
key_password_env = "ANDROID_KEY_PASSWORD"
```

Keep the keystore file and passwords outside the repository. Supply `ANDROID_KEYSTORE` and `ANDROID_KEYSTORE_PASSWORD` from a secure local or CI secret source; `ANDROID_KEYSTORE_ALIAS` defaults to `upload`, and `ANDROID_KEY_PASSWORD` defaults to the store password if it is not set. Run package readiness before building. Make an APK for device testing, then an AAB for Play; an APK install does not prove the Play upload will be accepted.

## Check readiness, package, then install the APK

Check both formats before producing either artifact. Readiness can find missing package inputs, but it cannot guarantee that Google Play will accept an upload. Keep the generated artifact manifest with the package and test the signed APK on a physical Android device before uploading the AAB.

```sh
fission readiness package --project-dir . --target android --format apk
fission package --project-dir . --target android --format apk --release
fission readiness package --project-dir . --target android --format aab
fission package --project-dir . --target android --format aab --release
fission devices --project-dir .
fission run --target android --device <adb-serial> --release --project-dir .
```

`fission run --release` builds and installs a release APK on the selected device, so release signing must be configured first. Use the artifact manifest emitted by `fission package` to locate and identify the APK/AAB; do not assume an output path from another Fission version.
