## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-compose-an-ios-app-from-reusable-fission-widgets
cd ios-compose-an-ios-app-from-reusable-fission-widgets
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-compose-an-ios-app-from-reusable-fission-widgets/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

use fission::prelude::*;

fission_component! {
    pub IosWidgetComposition<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("task-workspace".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text(screen.title.clone())
                            .weight(tokens.typography.font_weight_bold),
                        Text(screen.step.clone())
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: "In progress".to_string()),
                ]),
                Divider(),
                Column(gap: tokens.spacing.s, children: [
                    Text("Current task")
                        .weight(tokens.typography.font_weight_semibold),
                    Text(screen.goal.clone()),
                ]),
                Row(gap: tokens.spacing.s, align_items: ir_op::AlignItems::Center, children: [
                    Badge(text: "Next".to_string()),
                    Text("Connect this screen to the workflow in the next step.".to_string())
                        .color(tokens.colors.text_secondary),
                ]),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}

## Compose an iOS app from reusable Fission widgets

Split the screen at a meaningful reusable boundary, such as a labelled form field, summary card or row. Give that component typed props for the values supplied by its parent; keep only its own retained interaction state inside its fission_component! declaration. The parent screen owns the workflow and reducer bindings. Avoid a component that reads unrelated global data just to render its props, and avoid returning a large anonymous Widget tree from a helper function. Verify the component once on the target and then reuse it in two different parent layouts.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

fission_component! {
    #[derive(Default)]
    pub MetricTile<()> {
        props {
            label: String,
            value: String,
        }
    }
    view(tile, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(gap: tokens.spacing.xs, children: [
            Text(tile.label.clone()).color(tokens.colors.text_secondary),
            Text(tile.value.clone())

                .weight(tokens.typography.font_weight_bold),
        ])
    )
    .padding_all(tokens.spacing.m)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.medium)
}

fission_component! {
    pub IosWidgets<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("reusable-components".to_string()),
        label: Some(preview.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(preview.title.clone())

                    .weight(tokens.typography.font_weight_bold),
                Text(preview.goal.clone()),
                Row(gap: tokens.spacing.m, children: [
                    MetricTile(label: "Open tasks".to_string(), value: "4".to_string()),
                    MetricTile(label: "Completed".to_string(), value: "12".to_string()),
                ]),
                Text("MetricTile owns the repeated presentation; the screen supplies each label and value."),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Verify the user task on iOS

On an iOS simulator, repeat the feature path described above and check the expected result. If this task has an unavailable, denied or failure path, run that path too and confirm the screen offers a way to continue. The browser preview demonstrates component state only; the commands below verify the native host.

Use LiveTest with the semantic identifiers shown in the component to confirm focus and action behavior. If this screen adapts to window size, repeat the flow at a narrow phone width and a wider display.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
