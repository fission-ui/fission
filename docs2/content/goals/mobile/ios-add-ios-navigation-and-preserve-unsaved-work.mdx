## Create the project and add the target

Install the Fission command line, create the app, and add its native target.

```sh
cargo install cargo-fission
fission init ios-add-ios-navigation-and-preserve-unsaved-work
cd ios-add-ios-navigation-and-preserve-unsaved-work
fission add-target ios --project-dir .
```

## Files created by Fission

This is the starter tree after `fission init` and `fission add-target`; the component and state used for this task are additions in the steps below. Keep shared Rust behavior under `src/` and leave target launch and packaging in `platforms/ios/`.

```text
ios-add-ios-navigation-and-preserve-unsaved-work/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep `src/app.rs`, shared state, reducers and reusable `fission_component!` components in the common Rust project. Add a state, service or effect module only when this feature needs that boundary, and use a name tied to the feature. The generated iOS host owns launch and packaging details; shared components describe the user task without importing iOS APIs.

## Compose routes and implement a predictable back and cancel path for an edited form

Represent the active destination with the Fission Router and RouterParams so a detail screen can receive a typed route parameter. Keep the edit draft with the form component and store a durable saved record in GlobalState. On Android, handle system Back consistently with the visible Back control; on iOS, preserve the navigation stack and confirm before discarding a dirty draft. Test opening a detail route, returning, cancelling the discard prompt, confirming the discard, and opening a deep link directly into the detail route. An unknown record ID should render a not-found state rather than an empty or crashing screen.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

fission_component! {
    pub ItemList<()> {
    }
    view(_screen, _state, _cx) =>
        Column(children: [
            Text("Items"),
            Text("Draft record · tap Back to return"),
        ])
}

fission_component! {
    pub ItemDetail<()> {
    }
    view(_screen, _state, _cx) =>
        Column(children: [
            Text("Item details"),
            Text("Record 42"),
        ])
}

fission_component! {
    pub IosNavigationPreserveUnsavedWork<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
        state {
            detail_open: bool = false,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let path = if screen.detail_open { "/items/42" } else { "/items" };
        let router: Widget = Router::<()>::new()
            .with_path(path.to_string())
            .route_component("/items", ItemList)
            .route_component("/items/:id", ItemDetail)
            .into();
    } =>
    SemanticsRegion(
        identifier: Some("route-preview".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(screen.title.clone())

                    .weight(tokens.typography.font_weight_bold),
                Text(screen.goal.clone()),
                Button(
                    child: Text(if screen.detail_open { "Back to items" } else { "Open record 42" }),
                    key: "toggle-route",
                    on_press: reduce { screen.detail_open = !screen.detail_open; },
                ),
                router,
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Test in-app and inbound routes on iOS

Open the destination from inside the app, return to the previous screen, then open the same destination from its external URL. The external route should use the same typed route state as an in-app link rather than creating a second copy of the screen logic.

Try an unknown record ID and a malformed link as well as a valid one. The app should show a useful not-found or recovery screen, preserve unsaved work when required, and never render a blank route.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
