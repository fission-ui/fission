A simulator build and a signed device package answer different questions. The first shows that the shared app can run in Simulator; the second must match the iPhone, bundle identifier, signing identity and provisioning profile. A working simulator is therefore a useful earlier check, not a substitute for installing on the phone.

This guide packages a device IPA and installs it through Xcode. Fission's iOS run command targets simulators, so we will not present it as a physical-device installer. Complete the [iOS setup guide](/blog/set-up-rust-ios-development-with-fission/) before preparing the signing inputs.

## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-install-a-fission-app-on-a-physical-iphone
cd ios-install-a-fission-app-on-a-physical-iphone
cargo add serde_yaml
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-install-a-fission-app-on-a-physical-iphone/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # Compose checklist
└── platforms/
    └── ios/                  # generated iOS host
```

The generated platform directory owns launch and packaging. The shared Rust library owns this screen and its translations.

## Keep an observable launch checklist

Use the same screen in the browser and the native app, but do not confuse those results. A browser click checks the interface; changing a checkbox on the selected native device checks that this build actually launched there. The marks record your observations, not detected toolchain status, and can be cleared if you need to repeat a check.

Replace both `src/app.rs` and `src/lib.rs` so the generated native entrypoint launches this component. Keep the language bundles in `i18n/` and the setup in `src/translations.rs`. The separate preview entrypoint is only for this documentation page.

use std::collections::HashMap;
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in setup translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Install a Fission app on a physical iPhone

Connect a registered iPhone to the Mac, enable Developer Mode when prompted, and configure an Apple signing identity and provisioning profile for the app's bundle identifier. From the project root, check the package prerequisites and create a device IPA:

```sh
fission readiness package --project-dir . --target ios --format ipa --release
fission package --project-dir . --target ios --format ipa --release
```

The packaging script requires `IOS_SIGNING_IDENTITY` and, by default, `IOS_PROVISIONING_PROFILE`. Keep both outside source control; provide them through a local secret store or CI secrets. Use the IPA path printed by the command, then open Xcode **Window → Devices and Simulators**, select the connected iPhone, install the IPA, and launch it from the device. Fission's iOS `run` command launches simulators only. A Simulator cannot verify a physical camera, NFC antenna, biometric sensor or radio.

## Check packaging prerequisites and install the IPA

```sh
fission doctor ios --project-dir .
fission readiness package --project-dir . --target ios --format ipa --release
fission package --project-dir . --target ios --format ipa --release
```

`fission doctor ios` checks the iOS toolchain; readiness checks the IPA packaging inputs. The package script requires `IOS_SIGNING_IDENTITY` and, by default, `IOS_PROVISIONING_PROFILE`. Keep those in a local secret store or CI secrets, not in `fission.toml` or source control. After packaging, install the reported IPA through Xcode Devices and Simulators. `fission devices` lists simulators, not physical iPhones; `fission run --target ios` also targets the Simulator.

```sh
fission devices --project-dir .
fission run --target ios --project-dir .
```

These last two commands are an optional Simulator check, not part of installing the IPA on the phone. A Simulator cannot prove NFC, camera, biometrics or other physical capability behaviour.
