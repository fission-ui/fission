## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init ios-understand-fissions-generated-ios-host
cd ios-understand-fissions-generated-ios-host
fission add-target ios --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
ios-understand-fissions-generated-ios-host/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app state, reducers and components in shared Rust. Put direct iOS API calls in the generated host or a typed provider, and split a feature into modules when that boundary helps.

use fission::prelude::*;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
enum ProjectLayer {
    Configuration,
    RustApp,
    IosHost,
}

fission_component! {
    pub GeneratedIosHostMap<()> {
        state {
            selected_layer: ProjectLayer = ProjectLayer::Configuration,
        }
    }
    view(project, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let (layer_title, layer_path, layer_detail) = match project.selected_layer {
            ProjectLayer::Configuration => (
                cx.tr("host.layer.configuration"),
                "fission.toml",
                cx.tr("host.detail.configuration"),
            ),
            ProjectLayer::RustApp => (
                cx.tr("host.layer.rust"),
                "src/",
                cx.tr("host.detail.rust"),
            ),
            ProjectLayer::IosHost => (
                cx.tr("host.layer.native"),
                "platforms/ios/",
                cx.tr("host.detail.native"),
            ),
        };
    } =>
    SemanticsRegion(
        identifier: Some("generated-ios-host-map".to_string()),
        label: Some(cx.tr("host.screen.label")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Column(gap: tokens.spacing.xs, children: [
                    Text(cx.tr("host.app.name"))
                        .weight(tokens.typography.font_weight_bold),
                    Text(cx.tr("host.route"))
                        .color(tokens.colors.text_secondary),
                ]),
                Badge(text: cx.tr("host.preview.badge")),
                Divider(),
                Text(cx.tr("host.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("host.summary"))
                    .color(tokens.colors.text_secondary),
                Button(
                    child: Text(cx.tr("host.layer.configuration")),
                    key: "select-project-configuration",
                    variant: if project.selected_layer == ProjectLayer::Configuration { ButtonVariant::Primary } else { ButtonVariant::Outline },
                    on_press: reduce { project.selected_layer = ProjectLayer::Configuration; },
                    semantics: Some(Semantics {
                        role: Role::Button,
                        label: Some(cx.tr("host.layer.configuration")),
                        identifier: Some("host-map.configuration".to_string()),
                        ..Default::default()
                    }),
                ),
                Button(
                    child: Text(cx.tr("host.layer.rust")),
                    key: "select-rust-app",
                    variant: if project.selected_layer == ProjectLayer::RustApp { ButtonVariant::Primary } else { ButtonVariant::Outline },

mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn load_bundle(locale: &str, source: &str) -> TranslationBundle {
    TranslationBundle {
        locale: Locale::from(locale),
        messages: serde_yaml::from_str(source).expect("valid tutorial translations"),
    }
}

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    env.i18n
        .add_bundle(load_bundle("en-US", include_str!("i18n/en-US.yaml")));
    env.i18n
        .add_bundle(load_bundle("es-ES", include_str!("i18n/es-ES.yaml")));
    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::GeneratedIosHostMap)
        .with_env(preview_env())
        .with_title("Fission iOS Project Map")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Understand Fission’s generated iOS host

Start at `fission.toml`: it selects targets and capabilities. Cargo then builds the shared Rust app, while `platforms/ios/` contains the generated Xcode host and launch scripts. Read `platforms/ios/README.md` before opening the project in Xcode. Change `fission.toml` or the documented source templates, not a generated project file that the next Fission command can replace. After changing a target setting, run `fission build --target ios --project-dir .` and inspect the app bundle or generated plist to confirm the permission or resource reached the app.

## Verify the iOS development setup

The browser preview cannot inspect your computer. Run the target-specific `fission doctor` command below from the generated project root, then fix the first missing SDK, runtime, compiler target or device prerequisite it reports before trying the build again.

When the checks pass, run the generated app and keep the complete command output if it fails. A host smoke test confirms the scaffold can start; it does not prove release signing, device permissions or hardware behavior.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
