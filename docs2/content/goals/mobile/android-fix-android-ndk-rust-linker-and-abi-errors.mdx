A linker error is not necessarily a missing library. It can mean the build selected the wrong target, found a library for another CPU, or tried to use a host compiler where an Android compiler was required. Adding search paths before identifying which case applies usually obscures the original failure.

Here, we trace the target and toolchain selected by Fission's generated Android package script. There are three separate identities to keep straight: the development machine that runs Clang, the Android ABI of the output, and the minimum Android API level used to compile it.

## Work in the project that failed

Start in your existing app and preserve its configuration and logs. Do not run `fission init` over it. Complete the [Android setup guide](/blog/set-up-rust-android-gui-development-with-fission/) if the SDK and NDK have not been installed.

The embedded example is a small diagnostic-note app, not a simulated device inspector. If you want to run that separate reproduction, create a new scratch project:

```sh
fission init android-fix-android-ndk-rust-linker-and-abi-errors
cd android-fix-android-ndk-rust-linker-and-abi-errors
fission add-target android --project-dir .
cargo add serde_yaml
```

use fission::prelude::*;

fission_component! {
    pub DiagnosticNote<()> {
        state {
            command: String = String::new(),
            device: String = String::new(),
            first_error: String = String::new(),
            reviewed: bool = false,
        }
    }
    view(note, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let complete = !note.command.trim().is_empty() && !note.first_error.trim().is_empty();
        let summary = cx.tr("diagnostic.summary")
            .replace("{command}", &note.command)
            .replace("{device}", &note.device)
            .replace("{error}", &note.first_error);
    } =>
    Container(SafeArea(child: Scroll(child:
        Container(Column(gap: tokens.spacing.m, children: [
            Text(cx.tr("diagnostic.title")).size(tokens.typography.heading1_size),
            Text(cx.tr("diagnostic.scope")).color(tokens.colors.text_secondary),
            TextInput(
                label: Some(cx.tr("diagnostic.command").into()),
                bind: note.command,
                required: true,
                semantics_identifier: "diagnostic.command".to_string(),
            ),
            TextInput(
                label: Some(cx.tr("diagnostic.device").into()),
                bind: note.device,
                semantics_identifier: "diagnostic.device".to_string(),
            ),
            TextInput(
                label: Some(cx.tr("diagnostic.error").into()),
                bind: note.first_error,
                required: true,
                multiline: true,
                semantics_identifier: "diagnostic.error".to_string(),
            ),
            Button(
                child: Text(cx.tr("diagnostic.review")),
                key: "review-diagnostic-note",
                on_press: reduce { note.reviewed = true; },
            ).semantics_identifier("diagnostic.review"),
            if note.reviewed {
                if complete { Code(text: summary) }
                else { Text(cx.tr("diagnostic.invalid")).color(tokens.colors.error) }
            },
        ]))
        .padding_all(tokens.spacing.l)
        .width_length(Length::percent(100.0))
        .max_width(760.0),
    )))
    .height_length(Length::vh(100.0))
}

## Trace the Rust target, NDK and native library

The generated package script defaults to `aarch64-linux-android`, packaged as Android `arm64-v8a`. Its minimum API level defaults to 24. The target SDK is selected separately from installed Android platforms; changing an emulator image does not change the ABI of a vendor library.

| Item | Example | What it determines |
| --- | --- | --- |
| Rust target | `aarch64-linux-android` | Target architecture and Android ABI |
| Android ABI directory | `arm64-v8a` | Where the APK carries its native library |
| NDK compiler wrapper | `aarch64-linux-android24-clang` | Target architecture and minimum API |
| NDK host directory | The installed prebuilt directory | Which development machine can execute the compiler |

Start with the generated project, not an unrelated Cargo command that bypasses its environment:

```sh
fission doctor android --project-dir .
rustup target list --installed
fission build --target android --project-dir .
```

If the Android Rust target is missing, install that exact target:

```sh
rustup target add aarch64-linux-android
```

Fission selects `ANDROID_NDK` when explicitly set, otherwise the newest installed NDK under the configured SDK's `ndk/` directory. Inspect `platforms/android/package-apk.sh` to see the generated paths and any overrides in this project:

```sh
rg -n 'ANDROID_NDK|ANDROID_TOOLCHAIN|ANDROID_MIN_API_LEVEL|ANDROID_TARGET_API_LEVEL|TARGET=|LINKER|CC_' platforms/android/package-apk.sh
file path/to/vendor/lib/arm64-v8a/libvendor.so
```

A matching ARM64 CPU is necessary, not sufficient. A GNU/Linux ARM64 library is not automatically an Android library: it may depend on glibc rather than Android's Bionic interfaces. Inspect the ELF header and dependencies with the selected NDK's `llvm-readelf` as well. Replace both placeholders before running:

```sh
"<ndk-directory>/toolchains/llvm/prebuilt/<host-tag>/bin/llvm-readelf" -h -d path/to/vendor/lib/arm64-v8a/libvendor.so
```

If the NDK compiler itself fails with an executable-format error, inspect the host executable, not just the output target. Its host architecture must run on the development machine. If the library lacks the needed Android ABI, obtain or build a compatible library rather than renaming it or copying another architecture into `arm64-v8a`.

The script exposes overrides, but setting `ANDROID_TARGET_TRIPLE` alone is not a supported way to manufacture another complete package architecture: the compiler, native dependencies and Gradle ABI configuration must agree. Keep this guide's generated ARM64 path unless you are deliberately implementing and validating another target.

## Verify the fix at the stage that failed

Once the target and native dependency agree, rerun the same Fission build. Do not change several variables at once: otherwise a successful retry does not tell you which mismatch caused the failure.

```sh
fission doctor android --project-dir .
fission build --target android --project-dir .
fission test --target android --project-dir .
```

If the APK builds but does not install, the linker problem has moved out of the current path; inspect the installation error separately. If it installs but exits, use the selected device and collect runtime logs:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
fission logs --target android --device <adb-serial> --project-dir . --follow
```

A successful build establishes that this target linked and packaged. The generated smoke test checks host startup. Neither result verifies a physical-device permission or hardware feature.
