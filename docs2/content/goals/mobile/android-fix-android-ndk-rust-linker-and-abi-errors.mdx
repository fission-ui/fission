## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-fix-android-ndk-rust-linker-and-abi-errors
cd android-fix-android-ndk-rust-linker-and-abi-errors
cargo add serde_yaml
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-fix-android-ndk-rust-linker-and-abi-errors/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

use fission::i18n::{Locale, TranslationBundle};

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");

    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid Northbank translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }

    env
}

## Fix Android NDK, Rust linker and ABI errors

The generated Android build currently targets `aarch64-linux-android` (`arm64-v8a`). Fission's package script uses the NDK LLVM Clang executable for that target, with API level 24 by default. It does not automatically build x86 or x86_64 variants for an emulator. Check that a third-party `.so` contains `arm64-v8a`; do not copy a library for another ABI into the linker search path.

```sh
fission doctor android --project-dir .
rustup target list --installed | rg '^aarch64-linux-android$'
printf 'ANDROID_NDK=%s\n' "${ANDROID_NDK:-latest installed under ANDROID_HOME/ndk}"
file path/to/vendor/lib/arm64-v8a/libvendor.so
```

If the NDK selection is wrong, set `ANDROID_NDK` to the installed NDK directory and rerun `fission doctor`. If the failing dependency does not ship an `arm64-v8a` library, install or build a compatible version. Do not change the Rust target to match a binary unless the Fission target and the full package actually support that ABI.

## Rebuild and capture the first native failure

Run the checks from the project root. `fission build` exercises Rust and the generated Android package build; the output should identify which stage failed. `fission test` starts the generated emulator smoke test, but it is not a substitute for a physical-device or hardware check.

```sh
fission doctor android --project-dir .
fission build --target android --project-dir .
fission test --target android --project-dir .
```

If the APK builds but does not install, confirm ADB sees the intended device and check the install error before changing build configuration. If it installs but exits, rerun it while following the device logs:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
fission logs --target android --device <adb-serial> --project-dir . --follow
```
