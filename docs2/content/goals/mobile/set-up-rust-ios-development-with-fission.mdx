This guide installs and verifies the tools needed to build a Rust iOS app with Fission. We will select the full Xcode installation, check the Simulator SDK and runtime, and distinguish a simulator launch from a signed iPhone package. You need a terminal and basic Rust familiarity; each command explains what it checks before you move on.

By the end, you will have a verified iOS development setup for Fission. The WebAssembly preview is a compiled example of the component syntax used in the guide; it cannot install Xcode, select a simulator runtime, sign an app or launch an iPhone. The terminal checks below are what prove the toolchain is ready.

### The Fission pieces in this example

`fission_component!` describes a reusable part of the screen. It receives values through typed props and can retain small UI memory such as an open panel or an unsaved field draft. The component reads the current state and builds widgets; it does not write files or call an operating-system API while it is being rendered.

Put product data that survives a screen change in `GlobalState`. A typed action names what the user did, and its reducer makes the short, synchronous state transition. If the task needs a permission, file, network request or database, the reducer queues an effect or capability request and returns. The later success or error action updates the state, so the screen can explain what happened.

## Create the project and add the target

Install the Fission command line, create the app, and add its native target. This is the canonical iOS setup path for the generated Fission host.

```sh
cargo install cargo-fission
fission init set-up-rust-ios-development-with-fission
cd set-up-rust-ios-development-with-fission
fission add-target ios --project-dir .
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
```

### Select Xcode and verify the simulator SDK

Install Xcode from Apple, open it once to finish component setup, and select the Xcode installation that owns the simulator runtime.

```sh
xcode-select -p
xcodebuild -version
xcrun --sdk iphonesimulator --show-sdk-path
xcrun simctl list devices available
fission doctor ios --project-dir .
```

If `xcode-select -p` points at Command Line Tools instead of Xcode, select the installed Xcode application with `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer`, then repeat the checks. Install an iOS Simulator runtime from Xcode’s Platforms settings if `simctl list devices available` has no bootable iPhone.

### Run in the simulator and package for a phone

```sh
fission devices --project-dir .
fission run --target ios --project-dir .
fission package --project-dir . --target ios --format ipa --release
```

`fission run --target ios` discovers and launches simulators only. To install on a physical iPhone, configure Apple development signing, enable Developer Mode on the phone, create the signed IPA above, and install it from Xcode’s Devices and Simulators window. The `fission doctor` result confirms local tooling; a successful simulator run confirms the app launches in the simulator, not that physical-device signing is ready.


## Files created by Fission

This is the starter tree after `fission init` and `fission add-target`; the component and state used for this task are additions in the steps below. Keep shared Rust behavior under `src/` and leave target launch and packaging in `platforms/ios/`.

```text
set-up-rust-ios-development-with-fission/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep `src/app.rs`, shared state, reducers and reusable `fission_component!` components in the common Rust project. Add a state, service or effect module only when this feature needs that boundary, and use a name tied to the feature. The generated iOS host owns launch and packaging details; shared components describe the user task without importing iOS APIs.

## Verify the iOS toolchain

The browser preview does not inspect your Mac. First run `fission doctor` to confirm Xcode, the Simulator SDK and both Rust targets are discoverable. Then list the available simulators and launch the app:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
```

A successful `fission run` confirms the app builds and opens in the iOS Simulator. It does not verify signing or physical iPhone behaviour. `fission test` runs the generated host smoke test; `cargo test` only runs tests you have added to the project.


To verify a signed physical-device build, choose an Apple development team in Xcode, use a unique bundle identifier, connect and trust the iPhone, enable Developer Mode when iOS asks, then install the signed IPA through Xcode Devices and Simulators. Keep signing keys and profiles outside source control. The simulator workflow remains the ordinary `fission run --target ios` path.
