A simulator build and an iPhone build share application code but do not establish the same result. The simulator needs its own SDK and Rust target; a physical-device build also needs signing and a device installation path. Combining those into a single “iOS works” check makes failures harder to locate.

We will first select the Xcode installation, verify the simulator SDK and install the matching Rust targets. Only after the app launches in the simulator will we consider the additional requirements for an iPhone.

At the end, you should be able to launch the app in an iOS Simulator. Installing on a physical iPhone also needs Apple signing and Developer Mode. The browser preview cannot verify either path; use the terminal and Xcode checks in this guide.

## Create the project and add the target

Create a project and add iOS as a target. Fission generates the host; you do not need to create a second Xcode app by hand.

```sh
cargo install cargo-fission
fission init set-up-rust-ios-development-with-fission
cd set-up-rust-ios-development-with-fission
fission add-target ios --project-dir .
cargo add serde_yaml
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
```

### Select Xcode and verify the simulator SDK

Install Xcode from Apple, open it once to finish component setup, and select the Xcode installation that owns the simulator runtime.

```sh
xcode-select -p
xcodebuild -version
xcrun --sdk iphonesimulator --show-sdk-path
xcrun simctl list devices available
fission doctor ios --project-dir .
```

If `xcode-select -p` points at Command Line Tools instead of Xcode, select the installed Xcode app with `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer`, then repeat the checks. If `simctl list devices available` shows no bootable iPhone, install a simulator runtime from Xcode's Platforms settings.

### Run in the simulator and package for a phone

```sh
fission devices --project-dir .
fission run --target ios --project-dir .
fission package --project-dir . --target ios --format ipa --release
```

`fission run --target ios` launches a simulator; it does not install the app on a physical iPhone. For a phone, configure Apple development signing, enable Developer Mode, build the signed IPA above, then install it from Xcode's Devices and Simulators window. Passing `fission doctor` proves the local tools are present; a simulator launch does not prove phone signing works.


## Files created by Fission

This is the tree Fission creates. Shared app code lives in `src/`; the generated host in `platforms/ios/` handles launch and packaging.

```text
set-up-rust-ios-development-with-fission/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   ├── app.rs                 # Compose checklist
│   └── translations.rs        # embedded language bundles
└── platforms/
    └── ios/                  # generated iOS host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a separate service or effect module only when the feature needs one, and name it for the job it does. The generated host handles iOS launch and packaging; shared components do not need to import iOS APIs.

## Create the app screen

The screen gives the native build something concrete to launch. Its checkboxes record your review of terminal output; they cannot inspect Xcode or establish that signing worked. Replace both the component and normal `src/lib.rs` entrypoint below, keeping the generated `src/main.rs`.

The three flags are retained interface memory, not application configuration. Reloading or restarting clears them. The app installs English and Spanish messages and starts explicitly in English.

use fission::prelude::*;

fission_component! {
    pub ToolchainChecklist<()> {
        state {
            tools_checked: bool = false,
            runtime_checked: bool = false,
            targets_checked: bool = false,
        }
    }
    view(setup, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let reviewed = [setup.tools_checked, setup.runtime_checked, setup.targets_checked]
            .iter().filter(|checked| **checked).count();
    } =>
    Container(SafeArea(child: Scroll(child: Container(
        Column(gap: tokens.spacing.m, children: [
            Text(cx.tr("setup.title")).size(tokens.typography.heading2_size),
            Text(cx.tr("setup.summary")).color(tokens.colors.text_secondary),
            Text(cx.tr("setup.manual")).weight(tokens.typography.font_weight_semibold),
            Divider(),
            Checkbox(
                checked: setup.tools_checked,
                label: Some(cx.tr("setup.tools.check")),
                semantics_identifier: Some("setup.tools".into()),
                bind(on_toggle): to(setup.tools_checked),
            ),
            Text(cx.tr("setup.tools.detail")),
            Checkbox(
                checked: setup.runtime_checked,
                label: Some(cx.tr("setup.runtime.check")),
                semantics_identifier: Some("setup.runtime".into()),
                bind(on_toggle): to(setup.runtime_checked),
            ),
            Text(cx.tr("setup.runtime.detail")),
            Checkbox(
                checked: setup.targets_checked,
                label: Some(cx.tr("setup.targets.check")),
                semantics_identifier: Some("setup.targets".into()),
                bind(on_toggle): to(setup.targets_checked),
            ),
            Text(cx.tr("setup.targets.detail")),
            Divider(),
            Text(cx.tr("setup.reviewed").replace("{count}", &reviewed.to_string())),
            Text(cx.tr("setup.scope")).color(tokens.colors.text_secondary),
        ])
    ).padding_all(tokens.spacing.l)
     .width_length(Length::percent(100.0))
     .max_width(680.0))))
    .height_length(Length::vh(100.0))
}

#[cfg(not(any(target_arch = "wasm32", target_os = "android", target_os = "ios")))]

    DesktopApp::<(), _>::new(app::ToolchainChecklist)

        .run()

#[cfg(any(target_os = "android", target_os = "ios"))]
fn mobile_app() -> MobileApp<(), app::ToolchainChecklist> {
    let app = MobileApp::<(), _>::new(app::ToolchainChecklist)
        .with_env(translations::create_env())
        .with_title("Toolchain checklist");
    #[cfg(target_os = "android")]
    let app = app.with_test_control_port(48761);
    app
}

#[cfg(any(target_os = "android", target_os = "ios"))]
pub fn run_mobile() -> anyhow::Result<()> { mobile_app().run() }

#[cfg(target_os = "android")]
#[no_mangle]
fn android_main(app_handle: AndroidApp) {
    let _ = mobile_app().run_with_android_app(app_handle);
}

use std::collections::HashMap;
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in setup translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Verify the iOS toolchain

The browser preview does not inspect your Mac. First run `fission doctor` to confirm Xcode, the Simulator SDK and both Rust targets are discoverable. Then list the available simulators and launch the app:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
```

A successful `fission run` confirms the app builds and opens in the iOS Simulator. It does not verify signing or physical iPhone behaviour. `fission test` runs the generated host smoke test; `cargo test` only runs tests you have added to the project.


To verify a signed physical-device build, choose an Apple development team in Xcode, use a unique bundle identifier, connect and trust the iPhone, enable Developer Mode when iOS asks, then install the signed IPA through Xcode Devices and Simulators. Keep signing keys and profiles outside source control. The simulator workflow remains the ordinary `fission run --target ios` path.
