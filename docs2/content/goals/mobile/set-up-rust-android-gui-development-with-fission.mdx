Building an Android app involves two toolchains, not two implementations of the app. Rust compiles the shared code; the Android SDK and NDK provide the host tools, native libraries and packaging needed to run it on a device. An installed Rust target alone does not supply the second half.

We will check those pieces in dependency order, then launch the same app on an emulator or an authorised phone. The distinction is useful when something fails: a missing compiler, an unavailable device and an app error require different corrections.

At the end, `fission doctor` should find the Android tools and you should be able to launch the app on an emulator or connected phone. The browser preview only shows the example screen. It cannot install SDK packages or connect to a device; the terminal checks are what verify the setup.

## Create the project and add the target

Create the project and add Android as a target. This uses Fission's generated host, so you do not need to create a separate Android project by hand.

```sh
cargo install cargo-fission
fission init set-up-rust-android-gui-development-with-fission
cd set-up-rust-android-gui-development-with-fission
cargo add serde_yaml
fission add-target android --project-dir .
rustup target add aarch64-linux-android
```

### Install Android SDK, NDK and emulator packages

Install Android Studio's **Android SDK Command-line Tools (latest)** package first. Fission currently checks for `sdkmanager` and `avdmanager` at `cmdline-tools/latest/bin`; the newer `android sdk` command alone does not satisfy those checks yet. Add that directory to `PATH`, and set `ANDROID_HOME` to the SDK root if it is not already set.

The generated shell also runs Gradle. Its current Android Gradle Plugin is 8.13.2; Google's [compatibility table](https://developer.android.com/build/releases/agp-8-13-0-release-notes#compatibility) lists Gradle 8.13 and JDK 17. Use a compatible installation, then check `java -version` and `gradle --version`. The script prefers `platforms/android/gradlew` when you have installed a wrapper there; otherwise `gradle` must be available on `PATH`.

The package commands below install API 35 as one explicit example; they are not a Fission-wide version pin. The current generated build script selects the highest installed platform API unless `ANDROID_TARGET_API_LEVEL` is set, and defaults the minimum API to 24. Inspect `platforms/android/README.md` and the generated host before changing those choices.

```sh
sdkmanager --list | rg 'platform-tools|cmdline-tools|emulator|platforms;android-|build-tools;|ndk;|system-images;android-'
sdkmanager "platform-tools" "emulator" \
  "platforms;android-35" "build-tools;35.0.0" \
  "system-images;android-35;google_apis;arm64-v8a"
sdkmanager --licenses
rustup target add aarch64-linux-android
fission doctor android --project-dir .
```

Install an NDK side by side through Android Studio's SDK Manager, or choose an exact `ndk;...` package shown by `sdkmanager --list`. Fission uses the latest installed NDK under `$ANDROID_HOME/ndk` unless `ANDROID_NDK` points to a specific installation. There is no Fission-wide pinned NDK version, so use the version required by your native dependencies rather than copying a version number from another project. Run `fission doctor android --project-dir .` again after changing the SDK or NDK selection.

### Run in an emulator or on a phone

```sh
fission devices --project-dir .
fission run --target android --project-dir .
./platforms/android/run-emulator.sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

The generated `run-emulator.sh` creates or starts the configured arm64 AVD, then builds, installs and launches the app. A phone listed as `unauthorized` has not accepted this computer's debugging key yet: unlock it, accept the prompt and run `adb devices -l` again. For Wi-Fi debugging, pair the phone in Developer Options and use the serial that ADB reports.


## Files created by Fission

This is the tree created by `fission init` and `fission add-target`. Shared Rust code lives in `src/`; the Android host in `platforms/android/` handles launch and packaging.

```text
set-up-rust-android-gui-development-with-fission/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   ├── app.rs                 # Compose checklist
│   └── translations.rs        # embedded language bundles
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a separate service or effect module when this app needs that boundary, and give it a name that says what it does. The generated host owns Android launch and packaging, so shared components do not need to import Android APIs.

## Launch a small app with a manual setup checklist

The app gives the build something observable to launch: three labelled checks whose state changes when you select them. Marking a box records your own review of command output; it does not inspect the SDK or convert an unsuccessful diagnostic into success.

Replace the generated `src/lib.rs` as well as `src/app.rs`, so the native launcher runs this screen rather than the starter counter. The translations stay separate from the component, and the checklist state belongs to this one interface.

use fission::prelude::*;

fission_component! {
    pub ToolchainChecklist<()> {
        state {
            tools_checked: bool = false,
            runtime_checked: bool = false,
            targets_checked: bool = false,
        }
    }
    view(setup, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let reviewed = [setup.tools_checked, setup.runtime_checked, setup.targets_checked]
            .iter().filter(|checked| **checked).count();
    } =>
    Container(SafeArea(child: Scroll(child: Container(
        Column(gap: tokens.spacing.m, children: [
            Text(cx.tr("setup.title")).size(tokens.typography.heading2_size),
            Text(cx.tr("setup.summary")).color(tokens.colors.text_secondary),
            Text(cx.tr("setup.manual")).weight(tokens.typography.font_weight_semibold),
            Divider(),
            Checkbox(
                checked: setup.tools_checked,
                label: Some(cx.tr("setup.tools.check")),
                semantics_identifier: Some("setup.tools".into()),
                bind(on_toggle): to(setup.tools_checked),
            ),
            Text(cx.tr("setup.tools.detail")),
            Checkbox(
                checked: setup.runtime_checked,

                semantics_identifier: Some("setup.runtime".into()),

use std::collections::HashMap;
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in setup translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Verify the Android toolchain

The browser preview does not inspect your machine. In the project root, run `fission doctor` first; it names missing SDK, NDK or Rust prerequisites. Then list the launchable targets and run the generated AVD script:

```sh
fission doctor android --project-dir .
fission devices --project-dir .
./platforms/android/run-emulator.sh
```

The launcher creates or starts the configured arm64 AVD, then builds, installs and launches the app. If you are using a phone instead, connect it and follow the device-specific commands in the setup section above. `fission test` is a generated host smoke test; `cargo test` only runs tests you have added to the project.


For a connected Android phone, enable USB debugging or pair Wireless debugging, unlock it and accept the host-key prompt. Then verify and run the selected serial:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

A serial shown as `unauthorized` means the phone has not accepted the host key. A serial shown as `offline` usually means ADB must reconnect or the device must finish starting. Revoke USB debugging authorisations in Developer Options only if the prompt does not reappear after reconnecting.
