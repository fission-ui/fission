Before building, check that Rust, the Android SDK and NDK, and the emulator
are installed. This guide checks them in the order Fission needs them. Run each
command, fix what it reports, and then continue.

At the end, `fission doctor` should find the Android tools and you should be able to launch the app on an emulator or connected phone. The browser preview only shows the example screen. It cannot install SDK packages or connect to a device; the terminal checks are what verify the setup.

### The Fission pieces in this example

`fission_component!` is how we describe a reusable part of the screen. A component can receive typed props and keep small pieces of UI state, such as whether a panel is open. Building the screen reads state and creates widgets; it is not where we write files or call the operating system.

Put product data that needs to survive a screen change in `GlobalState`. An action names what the user did, and its reducer makes the synchronous state change. If the work needs a permission, file, network request or database, the reducer asks Fission to run it as an effect and returns. A later success or error action updates the state. The screen can then show what happened without blocking while the work runs.

## Create the project and add the target

Create the project and add Android as a target. This uses Fission's generated host, so you do not need to create a separate Android project by hand.

```sh
cargo install cargo-fission
fission init set-up-rust-android-gui-development-with-fission
cd set-up-rust-android-gui-development-with-fission
fission add-target android --project-dir .
rustup target add aarch64-linux-android
```

### Install Android SDK, NDK and emulator packages

Install the SDK packages required by the generated project. The current host defaults to API 35 and supports back to API 24; check `platforms/android/README.md` before choosing a different platform or build-tools version. Keeping those versions aligned avoids fixing errors caused by a mismatched SDK.

```sh
sdkmanager --list | rg 'platform-tools|cmdline-tools|emulator|platforms;android-|build-tools;|ndk;|system-images;android-'
sdkmanager "platform-tools" "cmdline-tools;latest" "emulator" \
  "platforms;android-35" "build-tools;35.0.0" "ndk;27.2.12479018" \
  "system-images;android-35;google_apis;arm64-v8a"
sdkmanager --licenses
rustup target add aarch64-linux-android
fission doctor android --project-dir .
```

If Fission cannot find the SDK, set `ANDROID_HOME` to its directory. If more than one NDK is installed, set `ANDROID_NDK` to the version this project uses. Run `fission doctor android --project-dir .` again and clear every reported prerequisite before you build.

### Run in an emulator or on a phone

```sh
fission devices --project-dir .
fission run --target android --project-dir .
./platforms/android/run-emulator.sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

The generated `run-emulator.sh` creates or starts the configured arm64 AVD, then builds, installs and launches the app. A phone listed as `unauthorized` has not accepted this computer's debugging key yet: unlock it, accept the prompt and run `adb devices -l` again. For Wi-Fi debugging, pair the phone in Developer Options and use the serial that ADB reports.


## Files created by Fission

This is the tree created by `fission init` and `fission add-target`. Shared Rust code lives in `src/`; the Android host in `platforms/android/` handles launch and packaging.

```text
set-up-rust-android-gui-development-with-fission/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a separate service or effect module when this app needs that boundary, and give it a name that says what it does. The generated host owns Android launch and packaging, so shared components do not need to import Android APIs.

fission_component! {
    pub AndroidDevelopmentSetup<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("task-workspace".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text(screen.title.clone())
                            .weight(tokens.typography.font_weight_bold),
                        Text(screen.step.clone())
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: "In progress".to_string()),
                ]),
                Divider(),
                Column(gap: tokens.spacing.s, children: [
                    Text("Current task")
                        .weight(tokens.typography.font_weight_semibold),
                    Text(screen.goal.clone()),

                    Badge(text: "Next".to_string()),
                    Text("Connect this screen to the workflow in the next step.".to_string())

                ]),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)

    )
}

## Verify the Android toolchain

The browser preview does not inspect your machine. In the project root, run `fission doctor` first; it names missing SDK, NDK or Rust prerequisites. Then list the launchable targets and run the generated AVD script:

```sh
fission doctor android --project-dir .
fission devices --project-dir .
./platforms/android/run-emulator.sh
```

The launcher creates or starts the configured arm64 AVD, then builds, installs and launches the app. If you are using a phone instead, connect it and follow the device-specific commands in the setup section above. `fission test` is a generated host smoke test; `cargo test` only runs tests you have added to the project.


For a connected Android phone, enable USB debugging or pair Wireless debugging, unlock it and accept the host-key prompt. Then verify and run the selected serial:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

A serial shown as `unauthorized` means the phone has not accepted the host key. A serial shown as `offline` usually means ADB must reconnect or the device must finish starting. Revoke USB debugging authorisations in Developer Options only if the prompt does not reappear after reconnecting.
