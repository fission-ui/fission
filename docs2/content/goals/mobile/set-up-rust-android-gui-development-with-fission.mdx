This guide installs and verifies the tools needed to build a Rust Android app with Fission. We will check the command-line tools, SDK, NDK, emulator and phone connection in the order the build uses them. You need a terminal and basic Rust familiarity; each command explains what it checks before you move on.

By the end, you will have a verified Android development setup for Fission. The WebAssembly preview is a compiled example of the component syntax used in the guide; it cannot install SDK packages, create an emulator or connect to a phone. The terminal checks below are what prove the toolchain is ready.

### The Fission pieces in this example

`fission_component!` describes a reusable part of the screen. It receives values through typed props and can retain small UI memory such as an open panel or an unsaved field draft. The component reads the current state and builds widgets; it does not write files or call an operating-system API while it is being rendered.

Put product data that survives a screen change in `GlobalState`. A typed action names what the user did, and its reducer makes the short, synchronous state transition. If the task needs a permission, file, network request or database, the reducer queues an effect or capability request and returns. The later success or error action updates the state, so the screen can explain what happened.

## Create the project and add the target

Install the Fission command line, create the app, and add its native target. This is the canonical Android setup path for the generated Fission host.

```sh
cargo install cargo-fission
fission init set-up-rust-android-gui-development-with-fission
cd set-up-rust-android-gui-development-with-fission
fission add-target android --project-dir .
rustup target add aarch64-linux-android
```

### Install Android SDK, NDK and emulator packages

Use the Android versions required by the generated project and `fission doctor`, then choose matching SDK platform and build-tools packages. The current generated host defaults to API 35 and a minimum API 24; check the generated `platforms/android/README.md` before selecting a different level.

```sh
sdkmanager --list | rg 'platform-tools|cmdline-tools|emulator|platforms;android-|build-tools;|ndk;|system-images;android-'
sdkmanager "platform-tools" "cmdline-tools;latest" "emulator" \
  "platforms;android-35" "build-tools;35.0.0" "ndk;27.2.12479018" \
  "system-images;android-35;google_apis;arm64-v8a"
sdkmanager --licenses
rustup target add aarch64-linux-android
fission doctor android --project-dir .
```

Set `ANDROID_HOME` to the SDK directory if discovery fails. Set `ANDROID_NDK` to the installed NDK directory when multiple versions are present. Run `fission doctor android --project-dir .` again and resolve each reported prerequisite before building.

### Run in an emulator or on a phone

```sh
fission devices --project-dir .
fission run --target android --project-dir .
./platforms/android/run-emulator.sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

The generated `run-emulator.sh` creates or starts the configured arm64 AVD, builds the APK, installs it and launches the app. An ADB row marked `unauthorized` means unlock the phone and accept its debugging-key prompt, then run `adb devices -l` again. For Wi-Fi debugging, pair the phone in Developer Options first and use the serial shown by `adb devices -l`.


## Files created by Fission

This is the starter tree after `fission init` and `fission add-target`; the component and state used for this task are additions in the steps below. Keep shared Rust behavior under `src/` and leave target launch and packaging in `platforms/android/`.

```text
set-up-rust-android-gui-development-with-fission/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep `src/app.rs`, shared state, reducers and reusable `fission_component!` components in the common Rust project. Add a state, service or effect module only when this feature needs that boundary, and use a name tied to the feature. The generated Android host owns launch and packaging details; shared components describe the user task without importing Android APIs.

use fission::prelude::*;

fission_component! {
    pub AndroidDevelopmentSetup<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("task-workspace".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text(screen.title.clone())
                            .weight(tokens.typography.font_weight_bold),
                        Text(screen.step.clone())
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: "In progress".to_string()),
                ]),
                Divider(),
                Column(gap: tokens.spacing.s, children: [
                    Text("Current task")
                        .weight(tokens.typography.font_weight_semibold),
                    Text(screen.goal.clone()),

                    Badge(text: "Next".to_string()),

        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)

## Verify the Android toolchain

The browser preview does not inspect your machine. In the project root, run `fission doctor` first; it names missing SDK, NDK or Rust prerequisites. Then list the launchable targets and run the generated AVD script:

```sh
fission doctor android --project-dir .
fission devices --project-dir .
./platforms/android/run-emulator.sh
```

The launcher creates or starts the configured arm64 AVD, then builds, installs and launches the app. If you are using a phone instead, connect it and follow the device-specific commands in the setup section above. `fission test` is a generated host smoke test; `cargo test` only runs tests you have added to the project.


For a connected Android phone, enable USB debugging or pair Wireless debugging, unlock it and accept the host-key prompt. Then verify and run the selected serial:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

A serial shown as `unauthorized` means the phone has not accepted the host key. A serial shown as `offline` usually means ADB must reconnect or the device must finish starting. Revoke USB debugging authorisations in Developer Options only if the prompt does not reappear after reconnecting.
