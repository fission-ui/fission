## Build a trail report that still works without GPS

Juniper County's trail crew records hazards during its afternoon inspections. A report needs a trail segment and a clear description even when a phone has no signal or the crew member declines location access. A map pin is helpful for a washout or fallen tree, but it is not a reason to block the report.

We will start with that useful fallback, then connect an optional location lookup to Fission's geolocation capability. The app will ask for coordinates only after someone chooses **Add map pin**. If Android returns a denial or the device cannot provide a position, the report and its manually assigned trail segment remain available.

The preview loads without asking for location. On Android, choose **Request location access**, answer the system prompt, refresh the access status, and then add a pin if access was granted. In the browser preview, refresh first; if the state is **Prompt**, **Add map pin** opens the browser’s location prompt. The report can always be saved with its assigned trail segment and no coordinates.

## Let the crew save a report before asking for location

Begin with the information the crew can provide without GPS: the assigned trail segment and what they found. A saved draft gives them a safe fallback when the phone is offline, location services are disabled, or they would rather not share coordinates.

The form below keeps its edits in the component while the crew member is writing. **Save report draft** shows the result the screen can provide locally. In a deployed app, the report itself belongs in app state and should be persisted through a job or service; the preview deliberately makes no claim that it reached the county's reporting system.

## Request a map pin only when the crew asks for one

Now add the permission and position flow. Juniper County needs a phone position only when the crew member decides a map pin will help. The app must not request access at startup or track the crew in the background. First ask for foreground access, then refresh Android’s state after the prompt, and only read a position after access is confirmed.

First declare the capability so Fission can configure the generated Android project:

```sh
fission add-capability geolocation --project-dir .
```

Keep the in-flight flag, returned position, and failure reason in `GlobalState`. They describe the report workflow and must remain visible to the screen after the asynchronous host request completes.

use fission::prelude::*;

#[derive(Debug, Default)]
pub struct TrailReportState {
    pub locating: bool,
    pub position: Option<GeolocationPosition>,
    pub location_error: Option<String>,
    pub permission: Option<GeolocationPermission>,
    pub checking_permission: bool,
    pub permission_error: Option<String>,
}

impl GlobalState for TrailReportState {}

#[fission_reducer(TrailCoordinatesLoaded, no_eq)]
fn on_trail_coordinates_loaded(
    state: &mut TrailReportState,
    position: GeolocationPosition,
) {
    state.locating = false;
    state.position = Some(position);
    state.location_error = None;
    state.permission = Some(GeolocationPermission::Granted);
}

#[fission_reducer(TrailCoordinatesFailed)]
fn on_trail_coordinates_failed(state: &mut TrailReportState, error: GeolocationError) {
    state.locating = false;
    if error.code == "permission_denied" {
        state.permission = Some(GeolocationPermission::Denied);
    }
    state.location_error = Some(match error.code.as_str() {
        "permission_denied" => {
            "Location access is off. Keep the trail segment or enable access in system settings."
                .to_string()
        }
        "unsupported" => {
            "Location is unavailable on this device. Use the assigned segment.".to_string()
        }
        "timeout" => {
            "Location took too long. Try again or keep the assigned trail segment.".to_string()
        }
        "position_unavailable" => {
            "No position was returned. Check location services or use the assigned segment."
                .to_string()
        }
        "host_error" => {
            "The location provider failed. Retry or use the assigned segment.".to_string()
        }
        _ if error.message.trim().is_empty() => {
            "No position was returned. Try again or keep the assigned segment.".to_string()
        }
        _ => format!("Location could not be added: {}", error.message),
    });
}

#[fission_reducer(TrailPermissionChecked)]
fn on_trail_permission_checked(
    state: &mut TrailReportState,
    permission: GeolocationPermission,
) {
    state.checking_permission = false;
    state.permission = Some(permission);
    state.permission_error = None;
}

#[fission_reducer(TrailPermissionCheckFailed)]
fn on_trail_permission_check_failed(state: &mut TrailReportState, error: GeolocationError) {
    state.checking_permission = false;
    state.permission_error = Some(if error.message.trim().is_empty() {
        "The host could not report the current permission status.".to_string()
    } else {
        format!("Permission status could not be refreshed: {}", error.message)
    });
}

#[fission_reducer(RequestTrailPermission)]
fn on_request_trail_permission(
    state: &mut TrailReportState,
    ctx: &mut ReducerContext<TrailReportState>,
) {
    if state.checking_permission {
        return;
    }

    state.checking_permission = true;
    state.permission_error = None;
    let on_ok = ctx.effects.bind(
        TrailPermissionChecked(GeolocationPermission::Unknown),
        reduce_with!(on_trail_permission_checked),
    );
    let on_err = ctx.effects.bind(
        TrailPermissionCheckFailed(GeolocationError::default()),
        reduce_with!(on_trail_permission_check_failed),
    );
    ctx.effects
        .geolocation()
        .request_permission(GeolocationPermissionRequest {
            precise: true,
            background: false,
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(RefreshTrailPermission)]
fn on_refresh_trail_permission(
    state: &mut TrailReportState,
    ctx: &mut ReducerContext<TrailReportState>,
) {
    if state.checking_permission {
        return;
    }

    state.checking_permission = true;
    state.permission_error = None;
    let on_ok = ctx.effects.bind(
        TrailPermissionChecked(GeolocationPermission::Unknown),
        reduce_with!(on_trail_permission_checked),
    );
    let on_err = ctx.effects.bind(
        TrailPermissionCheckFailed(GeolocationError::default()),
        reduce_with!(on_trail_permission_check_failed),
    );
    ctx.effects
        .geolocation()
        .permission()
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(AddTrailMapPin)]
fn on_add_trail_map_pin(
    state: &mut TrailReportState,
    ctx: &mut ReducerContext<TrailReportState>,
) {
    if state.locating {
        return;
    }
    if state.permission != Some(GeolocationPermission::Granted)
        && state.permission != Some(GeolocationPermission::Prompt)
    {
        state.location_error = Some(
            "Request and refresh location access before adding a map pin. The assigned trail segment remains available."
                .to_string(),
        );
        return;
    }

    state.locating = true;
    state.location_error = None;
    let on_ok = ctx.effects.bind(
        TrailCoordinatesLoaded(GeolocationPosition {
            latitude: 0.0,
            longitude: 0.0,
            altitude_meters: None,
            accuracy_meters: 0.0,
            altitude_accuracy_meters: None,
            heading_degrees: None,
            speed_mps: None,
            timestamp_unix_ms: 0,
        }),
        reduce_with!(on_trail_coordinates_loaded),
    );
    let on_err = ctx.effects.bind(
        TrailCoordinatesFailed(GeolocationError::default()),
        reduce_with!(on_trail_coordinates_failed),
    );
    ctx.effects
        .geolocation()
        .current_position(GeolocationPositionRequest {
            high_accuracy: true,
            timeout_ms: Some(10_000),
            maximum_age_ms: Some(30_000),
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

            on_refresh_trail_permission

    } =>
    SemanticsRegion(

        child: Scroll(
            flex_grow: 1.0,
            height: cx.view.viewport_size().height,
            child: Container(
                Column(align_items: ir_op::AlignItems::Center, children: [
                    Container(
                        Column(gap: tokens.spacing.m, children: [
                            Column(gap: tokens.spacing.xs, children: [
                                Text("Juniper County Trail Service")
                                    .weight(tokens.typography.font_weight_bold),
                                Text("Afternoon inspection · Crew 4")
                                    .color(tokens.colors.text_secondary),
                            ]),
                            Text("Location access")
                                .weight(tokens.typography.font_weight_bold),
                            Text(location_message)
                                .color(if state.location_error.is_some() {
                                    tokens.colors.error
                                } else {
                                    tokens.colors.text_secondary
                                }),
                            Text(permission_message)
                                .color(if permission_has_error {
                                    tokens.colors.error
                                } else {
                                    tokens.colors.text_secondary
                                }),
                            Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                                Button(
                                    child: Text(
                                        if state.checking_permission {
                                            "Working…"
                                        } else {
                                            "Request location access"
                                        }
                                    ),
                                    key: "request-location-permission",
                                    variant: ButtonVariant::Outline,
                                    disabled: state.checking_permission,
                                    on_press: request_permission,

                                .semantics_identifier(

                                ),
                                Button(
                                    child: Text("Refresh access status"),
                                    key: "refresh-location-permission",
                                    variant: ButtonVariant::Outline,

                                    on_press: refresh_permission,

                                required: true,
                                semantics_identifier: "trail-report.segment".to_string(),

The request and position are separate effects. On Android, the permission request opens the operating-system prompt, but its result can reflect the state from before the crew member finished answering. Refresh after the prompt closes. Once access is granted, the pin action asks the Android provider for coordinates; in the browser preview, that position request opens the browser prompt. The example position passed to the result action is only its payload shape—the host supplies the real coordinates. A denial is a normal outcome, so clear the loading flag and keep the saved report intact.

The **Request location access** button calls the geolocation effect’s permission request with foreground access enabled and background access disabled. The **Refresh access status** button reads the current permission without opening another prompt. After a crew member changes access in system settings and returns to the app, refresh the label before enabling the pin action. The [Geolocation guide](/docs/capabilities/geolocation/) explains the provider contract and memory-host tests in more depth.

## Verify grant, denial, and a later settings change

Run the app on an Android emulator. Start from a fresh install or reset this app’s location permission in Android Settings. Tap **Request location access**, choose **Don’t allow**, and then tap **Refresh access status**. Confirm the report still saves with its assigned segment. Reset the permission again, request access, choose precise or approximate, refresh, and add a pin only after the refreshed state is granted.

Next, open the app’s location permission in Android settings, change it, and return to the report. Tap **Refresh access status**: the screen should show the new answer without opening another prompt. This example makes refresh explicit so you can see the state transition; a larger app can dispatch the same action when its screen resumes. The [mobile lifecycle tutorial](/blog/handle-mobile-lifecycle-changes-while-effects-are-in-flight/) covers that resume boundary. Check the disabled-location and timeout paths too; they should offer a retry or the manual segment, never erase the report.
