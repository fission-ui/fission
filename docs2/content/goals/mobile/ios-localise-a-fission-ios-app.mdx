A translated interface and translated user data are different things. If someone writes a reminder in Spanish, selecting English should change the controls around it, not replace the reminder or pretend to translate it.

We will build a small session-notes app which makes that boundary visible. Its captions, help text, empty state and count messages come from checked-in English and Spanish bundles. Notes remain the user's own text, and changing language leaves both the unfinished draft and existing notes intact.

## Create the shared app

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) if needed.

```sh
cargo install cargo-fission
fission init ios-localise-a-fission-ios-app
cd ios-localise-a-fission-ios-app
fission add-target ios --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs` and replace the shared library with the files below. Both the native shell and Web preview install the same bundles and locale synchronization; localization must not exist only in the preview launcher.

## Keep the selected locale in application state

The locale is app-wide presentation state. Reducers change `NotesState.locale`, then `.with_sync_env(...)` copies it into the environment used to resolve labels. A component does not need to know which file supplied its translation.

`TextContent::Key` keeps field labels tied to meaning rather than to the current English text. Ordinary captions use `cx.tr(...)` because they need a resolved string. The note body is supplied as literal user data; treating it as a key would mix application content with interface messages.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Note {
    pub id: u64,
    pub body: String,
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NotesState {
    pub notes: Vec<Note>,
    pub next_id: u64,
    pub locale: Locale,
}

impl Default for NotesState {
    fn default() -> Self {
        Self {
            notes: Vec::new(),
            next_id: 1,
            locale: Locale::from("en-US"),
        }
    }
}
impl GlobalState for NotesState {}

pub fn add_note(state: &mut NotesState, body: &str) -> bool {
    let body = body.trim();
    if body.is_empty() {
        return false;
    }
    let Some(next_id) = state.next_id.checked_add(1) else {
        return false;
    };
    state.notes.push(Note {
        id: state.next_id,
        body: body.to_owned(),
    });
    state.next_id = next_id;
    true
}

fission_component! {
    pub NoteRow<NotesState> {
        props { note_id: u64 }
    }
    view(row, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let note = state.notes.iter().find(|note| note.id == row.note_id);
    } => if let Some(note) = note {
        Container(
            Column(gap: tokens.spacing.s, children: [
                Text(note.body.clone()),
                Button(
                    child: Text(cx.tr("notes.remove")), key: "remove-note",
                    on_press: reduce { state.notes.retain(|note| note.id != row.note_id); },
                ),
            ]),
        )
        .padding_all(tokens.spacing.m)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.medium)
    } else {
        Spacer()
    }
}

use super::{
    note::NoteRow,
    state::{add_note, NotesState},
};
use fission::prelude::*;

fission_component! {
    pub NotesScreen<NotesState> {
        state { draft: String = String::new() }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let count = state.notes.len();
        let count_key = match count {
            0 => "notes.count.zero",
            1 => "notes.count.one",
            _ => "notes.count.other",
        };
    } => SafeArea(
        child: Scroll(
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("notes.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("notes.explanation")),
                Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                    Button(
                        child: Text(cx.tr("language.english")), key: "english",
                        disabled: state.locale == Locale::from("en-US"),
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        disabled: state.locale == Locale::from("es-ES"),
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                TextInput(
                    value: screen.draft.clone(), bind(on_input): to(screen.draft),
                    label: Some(TextContent::Key("notes.draft".into())),
                    helper_text: Some(TextContent::Key("notes.draft_help".into())),
                    multiline: true, keyboard_type: TextInputType::Multiline,
                ),
                Button(
                    child: Text(cx.tr("notes.add")), key: "add-note",
                    disabled: screen.draft.trim().is_empty() || state.next_id == u64::MAX,
                    on_press: reduce {
                        if add_note(state, &screen.draft) { screen.draft.clear(); }
                    },
                ),
                Text(cx.tr(count_key).replace("{count}", &count.to_string())),
                if state.notes.is_empty() {
                    Text(cx.tr("notes.empty"))
                },
                for note in &state.notes {
                    NoteRow(note.id, key: note.id)
                },
                Text(cx.tr("notes.session")).color(tokens.colors.text_secondary),
            ]))
            .padding_all(tokens.spacing.l),
        ),
    )
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid notes translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::NotesState, env: &mut Env) {
    env.locale = state.locale.clone();
}

#[cfg(test)]
mod tests {
    use super::*;
    use std::collections::BTreeSet;

    #[test]
    fn both_languages_define_the_same_nonempty_messages() {
        let english: HashMap<String, String> =
            serde_yaml::from_str(include_str!("../i18n/en-US.yaml")).unwrap();
        let spanish: HashMap<String, String> =
            serde_yaml::from_str(include_str!("../i18n/es-ES.yaml")).unwrap();
        assert_eq!(
            english.keys().collect::<BTreeSet<_>>(),
            spanish.keys().collect::<BTreeSet<_>>(),
        );
        assert!(english
            .values()
            .chain(spanish.values())
            .all(|value| !value.trim().is_empty()));
    }
}

## Make missing messages and grammatical choices explicit

Fission's translation registry resolves an exact locale/key pair. A missing translation is shown as its key, not automatically borrowed from another language. That makes a gap visible, but it does not make the gap acceptable. The included test checks matching key sets and non-empty values before a missing Spanish caption reaches a user.

The count message deliberately selects zero, one or other in Rust. This is sufficient for these two bundles; it is not an implementation of all languages' plural rules. Keep the complete message in the bundle rather than joining translated fragments whose order may not make sense in another language.

The app starts in English by an explicit choice and changes locale only through its two controls. It does not claim to negotiate the device's preferred-language list or restore a previously saved choice. If you add those policies, resolve to a supported bundle in the shell or app setup rather than making each widget guess.

## Verify the labels in the real iOS app

```sh
cargo test
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Use [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) for selection. Repeat the draft, add, remove and language-switch flow on iOS. Check the software keyboard, multiline input and VoiceOver's labels in each language; a translated visual label is not by itself evidence about the platform's spoken result.

The two languages here are left-to-right. They do not qualify right-to-left layout, locale-specific date/currency formatting or every writing system. Those are separate requirements and need their own data, layout direction and target checks.

Notes and the selected language last only for this run. When persistence is required, retain the locale as an application preference and keep the synchronization function limited to copying that presentation choice into `Env`.
