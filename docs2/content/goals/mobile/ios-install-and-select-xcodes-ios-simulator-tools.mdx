If Fission cannot find the iOS SDK, the problem is often that macOS is pointing at Command Line Tools instead of the full Xcode installation, or that no simulator runtime is installed. This guide checks both and fixes the selection before you try to build.

At the end, `xcodebuild` and `simctl` should be using the Xcode installation and runtime you expect. The browser preview does not inspect Xcode or launch a simulator; the command output is what verifies this setup.

### The Fission pieces in this example

Fission keeps app behaviour in shared Rust and generates the platform host. This page's browser preview is just a visual example; it cannot inspect installed tools or boot a simulator. Use the commands here to check the actual setup.

## Create the project and add the target

Create a project and add iOS as a target. That gives `fission doctor` and the generated host a project to check.

```sh
cargo install cargo-fission
fission init ios-install-and-select-xcodes-ios-simulator-tools
cd ios-install-and-select-xcodes-ios-simulator-tools
cargo add serde_yaml
fission add-target ios --project-dir .
```

## Files created by Fission

This is the tree Fission creates. Shared Rust code stays under `src/`; the generated iOS host under `platforms/ios/` handles launch and packaging.

```text
ios-install-and-select-xcodes-ios-simulator-tools/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app state, reducers and components in shared Rust. Put direct iOS API calls in the generated host or a typed provider, and split a feature into modules when that boundary helps.

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");

    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid Northbank translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }

    env
}

## Select the full Xcode installation and add a simulator runtime

`xcode-select` chooses which developer directory command-line tools use. iOS builds need the full Xcode installation because it supplies the Simulator SDK and `simctl`; the standalone Command Line Tools package is not enough. Install Xcode, open it once to finish first-launch setup, then inspect the active selection:

```sh
xcode-select -p
xcodebuild -version
xcodebuild -showsdks
```

If the selected path ends in `CommandLineTools`, switch to the installed Xcode app. The path below is the standard Applications location; adjust it if Xcode was installed elsewhere.

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
xcode-select -p
```

Now check the simulator SDK and installed runtimes:

```sh
xcrun --sdk iphonesimulator --show-sdk-path
xcrun simctl list runtimes
xcrun simctl list devices available
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
fission doctor ios --project-dir .
```

If no iOS Simulator runtime appears, open Xcode's **Settings → Platforms** and install one. `fission doctor` should then report the selected Xcode, simulator SDK and Rust targets. The [iOS setup tutorial](/blog/set-up-rust-ios-development-with-fission/) explains the full device and signing workflow.
