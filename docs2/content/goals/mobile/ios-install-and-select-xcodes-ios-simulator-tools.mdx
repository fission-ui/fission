This guide installs and verifies the tools needed to build a Rust iOS app with Fission. We will select the full Xcode installation, check the Simulator SDK and runtime, and distinguish a simulator launch from a signed iPhone package. You need a terminal and basic Rust familiarity; each command explains what it checks before you move on.

By the end, you will have a verified iOS development setup for Fission. The WebAssembly preview is a compiled example of the component syntax used in the guide; it cannot install Xcode, select a simulator runtime, sign an app or launch an iPhone. The terminal checks below are what prove the toolchain is ready.

### The Fission pieces in this example

Fission keeps app behaviour in shared Rust code while the generated platform host owns launch and packaging. The compiled browser example cannot inspect installed tools or start a simulator. The commands in this guide check the actual platform setup.

## Create the project and add the target

Install the Fission command line, create the app, and add its native target.

```sh
cargo install cargo-fission
fission init ios-install-and-select-xcodes-ios-simulator-tools
cd ios-install-and-select-xcodes-ios-simulator-tools
fission add-target ios --project-dir .
```

## Files created by Fission

This is the starter tree after `fission init` and `fission add-target`; the component and state used for this task are additions in the steps below. Keep shared Rust behavior under `src/` and leave target launch and packaging in `platforms/ios/`.

```text
ios-install-and-select-xcodes-ios-simulator-tools/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep `src/app.rs`, shared state, reducers and reusable `fission_component!` components in the common Rust project. Add a state, service or effect module only when this feature needs that boundary, and use a name tied to the feature. The generated iOS host owns launch and packaging details; shared components describe the user task without importing iOS APIs.

```rust
use fission::prelude::*;

fission_component! {
    pub IosSimulatorSetup<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
        state {
            simulated_success: bool = false,
            simulated_unavailable: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("tutorial-preview".to_string()),
        label: Some(preview.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(preview.title.clone())

                    .weight(tokens.typography.font_weight_bold),
                Text(preview.step.clone())
                    .color(tokens.colors.text_secondary),
                Text(preview.goal.clone()),
                Button(
                    child: Text(if preview.simulated_success {
                        "Reset success simulation".to_string()
                    } else {
                        "Simulate success".to_string()
                    }),
                    key: "tutorial-complete",
                    on_press: reduce {
                        preview.simulated_success = !preview.simulated_success;
                        if preview.simulated_success { preview.simulated_unavailable = false; }
                    },
                ),
                Text(if preview.simulated_success {
                    format!("Simulated success for {}. Only browser-local state changed. Use the target steps below to verify the real behaviour.", preview.goal)
                } else {
                    "Ready: no native request has run. Choose a simulation to see how the screen state changes.".to_string()
                }),
                Button(
                    child: Text(if preview.simulated_unavailable {
                        "Clear unavailable simulation".to_string()
                    } else {
                        "Simulate unavailable".to_string()
                    }),
                    key: "tutorial-unavailable",
                    on_press: reduce {
                        preview.simulated_unavailable = !preview.simulated_unavailable;
                        if preview.simulated_unavailable { preview.simulated_success = false; }
                    },
                ),
                if preview.simulated_unavailable {
                    Text(format!("Simulated unavailable result for {}. No native request ran; the target app should explain the real reason and recovery action.", preview.title))
                } else {
                    Text("No unavailable response is being simulated.".to_string())
                },
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Select the full Xcode installation and add a simulator runtime

`xcode-select` chooses which developer directory command-line tools use. `xcrun` and `simctl` are included with the full Xcode installation, not with the standalone Command Line Tools package. Install Xcode, open it once to finish first-launch setup, then inspect the active selection:

```sh
xcode-select -p
xcodebuild -version
xcodebuild -showsdks
```

If the selected path ends in `CommandLineTools`, switch to the installed Xcode app. The path below is the standard Applications location; adjust it if Xcode was installed elsewhere.

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
xcode-select -p
```

Now check the simulator SDK and installed runtimes:

```sh
xcrun --sdk iphonesimulator --show-sdk-path
xcrun simctl list runtimes
xcrun simctl list devices available
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
fission doctor ios --project-dir .
```

If no iOS Simulator runtime appears, open Xcode's **Settings → Platforms** and install one. `fission doctor` should then report the selected Xcode, simulator SDK and Rust targets. The [iOS setup tutorial](/blog/set-up-rust-ios-development-with-fission/) explains the full device and signing workflow.
