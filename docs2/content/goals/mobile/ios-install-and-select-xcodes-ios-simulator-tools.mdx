Installing Xcode and selecting it are different steps. A Mac can have the full app installed whilst command-line tools still resolve through the standalone Command Line Tools directory. In that case, reinstalling a Rust target will not make the missing simulator SDK appear.

There is another distinction: the SDK supplies build inputs, whilst a simulator runtime supplies an OS environment in which to run the result. We will check both before using a real shared Compose app as the final launch candidate.

## Check the Mac's selected developer directory

Run these checks on the Mac that will build iOS, not in an unrelated Linux or Windows shell:

```sh
xcode-select -p
xcodebuild -version
xcodebuild -showsdks
```

iOS builds need the full Xcode installation. Open that installation and finish its first-launch setup. If the active path is the standalone `CommandLineTools` directory, select the installed Xcode app deliberately. The path below is the conventional location; use the actual path if yours differs.

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
xcode-select -p
```

This changes the machine's selected developer directory, so consider other builds using it. It is not an app-local setting or a step to repeat whenever compilation fails.

## Verify the SDK, runtime and Rust targets

```sh
xcrun --sdk iphonesimulator --show-sdk-path
xcrun simctl list runtimes
xcrun simctl list devices available
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
```

If no usable iOS runtime appears, install one through Xcode's simulator/platform settings and repeat the listing. Do not treat an SDK directory as evidence that a bootable runtime exists. See [simulator selection](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) for creating or choosing the destination once these prerequisites are present.

## Give Fission a complete app to check

Use an existing app or create this separate practice project. Do not initialize over an existing checkout:

```sh
cargo install cargo-fission
fission init ios-install-and-select-xcodes-ios-simulator-tools
cd ios-install-and-select-xcodes-ios-simulator-tools
fission add-target ios --project-dir .
cargo add serde_yaml
fission doctor ios --project-dir .
```

The following journey editor is the same working app used in [the component tutorial](/blog/compose-an-ios-app-from-reusable-fission-widgets/). Keep the generated `src/main.rs`. use super::{
    state::{Journey, JourneyState},
    summary::JourneySummary,
};
use fission::prelude::*;

fission_component! {
    pub JourneyScreen<JourneyState> {
        state {
            origin: String = String::new(),
            destination: String = String::new(),
        }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => SafeArea(
        child: Scroll(
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("journey.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("journey.explanation")),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("language.english")), key: "english",
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                FormControl(
                    label: Some(cx.tr("journey.origin")),
                    required: true,
                    child: TextInput(
                        value: screen.origin.clone(),
                        bind(on_input): to(screen.origin),
                    ),
                ),
                FormControl(
                    label: Some(cx.tr("journey.destination")),
                    required: true,
                    child: TextInput(
                        value: screen.destination.clone(),
                        bind(on_input): to(screen.destination),
                    ),
                ),
                if !screen.origin.trim().is_empty() && !screen.destination.trim().is_empty() {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.draft")),
                        JourneySummary(
                            Journey {
                                origin: screen.origin.trim().to_owned(),
                                destination: screen.destination.trim().to_owned(),
                            },
                            key: "draft-summary",
                        ),
                    ])
                },
                Button(
                    child: Text(cx.tr("journey.prepare")), key: "prepare-journey",
                    disabled: screen.origin.trim().is_empty() || screen.destination.trim().is_empty(),
                    on_press: reduce {
                        state.prepared = Some(Journey {
                            origin: screen.origin.trim().to_owned(),
                            destination: screen.destination.trim().to_owned(),
                        });
                    },
                ),
                if let Some(journey) = &state.prepared {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.prepared")),
                        JourneySummary(journey.clone(), key: "prepared-summary"),
                    ])
                },
            ]))
            .padding_all(tokens.spacing.l),
        ),
    )
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid journey translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::JourneyState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Use the tool output to choose the next check

If `xcrun` cannot resolve the simulator SDK, return to Xcode selection and installation. If `simctl` lists runtimes but no suitable available device, follow the simulator guide. If Rust reports a missing standard library, confirm the requested target is the simulator or device target you intended before installing or changing anything.

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

The run command uses an iOS Simulator. Check the actual launch and repeat the journey task in its window, with the keyboard and both languages. A green setup check means the named prerequisites were found; it does not qualify every interaction, signing path or hardware capability.

Keep the command and first useful diagnostic when a later stage fails. [The diagnosis guide](/blog/diagnose-ios-build-signing-and-launch-failures/) separates compilation, bundle assembly, installation and process failures. For a physical iPhone, follow [the device guide](/blog/install-a-fission-app-on-a-physical-iphone/) instead of treating simulator setup as device-signing evidence.
