A technician checking a temperature probe needs to distinguish three facts: whether the device supports Bluetooth LE, whether access is currently allowed, and whether the sensor is advertising the expected service. Discovering a name does not establish a connection, authenticate the probe or provide a temperature.

This page implements discovery using the current Android provider. Connection, disconnection and characteristic reads/writes remain unsupported by that provider. Those are upstream blockers to a connected-sensor workflow; a memory provider would hide the gap rather than resolve it.

## Create the Android project

Complete [Set up Rust Android GUI development with Fission](/blog/set-up-rust-android-gui-development-with-fission/), then prepare [an emulator](/blog/create-and-launch-a-fission-android-emulator/) or [a phone](/blog/run-a-fission-app-on-a-physical-android-phone/). Use a phone and an advertising BLE sensor for the actual discovery check.

```sh
cargo install cargo-fission
fission init northbank-probe-finder
cd northbank-probe-finder
cargo add serde_yaml
fission add-target android --project-dir .
fission add-capability bluetooth --project-dir .
```

Keep the generated `src/main.rs`. The shared library below replaces the starter app from the first step, not only after the browser example is complete. Neither shell installs sample devices or a `MemoryBluetoothHost`.

## Check the prerequisites before offering a scan

The availability request supplies hardware, enabled and permission state. Keep each result unknown until the host reports it. A manifest declaration does not mean permission has been granted, and an enabled adapter does not mean it supports BLE.

The request, pending state and callback handling belong to the shared state module. The shell only selects a target and installs the checked-in translations.

use fission::prelude::*;

const ENVIRONMENTAL_SENSING_SERVICE: &str = "0000181a-0000-1000-8000-00805f9b34fb";

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Pending { Check, Permission, Scan }

#[derive(Debug, Default)]
pub struct ProbeState {
    pub permission: BluetoothPermission,
    pub enabled: Option<bool>,
    pub low_energy: Option<bool>,
    pub pending: Option<Pending>,
    pub scan_complete: bool,
    pub devices: Vec<BluetoothDevice>,
    pub issue_key: Option<&'static str>,
}
impl GlobalState for ProbeState {}

impl ProbeState {
    pub fn can_scan(&self) -> bool {
        self.pending.is_none()
            && self.permission == BluetoothPermission::Granted
            && self.enabled == Some(true)
            && self.low_energy == Some(true)
    }
}

pub fn check(state: &mut ProbeState, ctx: &mut ReducerContext<ProbeState>) {
    if state.pending.is_some() { return; }
    state.pending = Some(Pending::Check);
    state.issue_key = None;
    let ok = ctx.effects.bind(ProbeChecked, reduce_with!(probe_checked));
    let err = ctx.effects.bind(ProbeFailed, reduce_with!(probe_failed));
    ctx.effects.bluetooth().availability().on_ok(ok).on_err(err);
}

#[fission_reducer(RequestProbePermission)]
pub fn request_permission(
    state: &mut ProbeState,
    reason: String,
    ctx: &mut ReducerContext<ProbeState>,
) {
    if state.pending.is_some() { return; }
    state.pending = Some(Pending::Permission);
    state.issue_key = None;
    let ok = ctx.effects.bind(ProbePermissionReported, reduce_with!(probe_permission_reported));
    let err = ctx.effects.bind(ProbeFailed, reduce_with!(probe_failed));
    ctx.effects.bluetooth()
        .request_permission(BluetoothPermissionRequest { reason: Some(reason) })
        .on_ok(ok).on_err(err);
}

pub fn scan(state: &mut ProbeState, ctx: &mut ReducerContext<ProbeState>) {
    if !state.can_scan() { return; }
    state.pending = Some(Pending::Scan);
    state.scan_complete = false;
    state.devices.clear();
    state.issue_key = None;
    let ok = ctx.effects.bind(ProbesReported, reduce_with!(probes_reported));
    let err = ctx.effects.bind(ProbeFailed, reduce_with!(probe_failed));
    ctx.effects.bluetooth().scan_devices(BluetoothScanRequest {
        service_uuids: vec![ENVIRONMENTAL_SENSING_SERVICE.into()],
        timeout_ms: Some(5_000),
        include_paired: false,
        allow_duplicates: false,
    }).on_ok(ok).on_err(err);
}

#[fission_reducer(ProbeChecked)]
fn probe_checked(state: &mut ProbeState, ctx: &mut ReducerContext<ProbeState>) {
    if state.pending != Some(Pending::Check) { return; }
    state.pending = None;
    match ctx.input.capability_ok(GET_BLUETOOTH_AVAILABILITY) {
        Some(value) => {
            state.permission = value.permission;
            state.enabled = Some(value.enabled);
            state.low_energy = Some(value.supports_low_energy);
        }
        None => state.issue_key = Some("probe.failed"),
    }
}

#[fission_reducer(ProbePermissionReported)]
fn probe_permission_reported(state: &mut ProbeState, ctx: &mut ReducerContext<ProbeState>) {
    if state.pending != Some(Pending::Permission) { return; }
    state.pending = None;
    match ctx.input.capability_ok(REQUEST_BLUETOOTH_PERMISSION) {
        Some(permission) => state.permission = permission,
        None => state.issue_key = Some("probe.failed"),
    }
}

#[fission_reducer(ProbesReported)]
fn probes_reported(state: &mut ProbeState, ctx: &mut ReducerContext<ProbeState>) {
    if state.pending != Some(Pending::Scan) { return; }
    state.pending = None;
    match ctx.input.capability_ok(SCAN_BLUETOOTH_DEVICES) {
        Some(result) => {
            state.devices = result.devices;
            state.scan_complete = true;
        }
        None => state.issue_key = Some("probe.failed"),
    }
}

#[fission_reducer(ProbeFailed)]
fn probe_failed(state: &mut ProbeState, ctx: &mut ReducerContext<ProbeState>) {
    let code = match state.pending.take() {
        Some(Pending::Check) => ctx.input.capability_error(GET_BLUETOOTH_AVAILABILITY).map(|error| error.code),
        Some(Pending::Permission) => ctx.input.capability_error(REQUEST_BLUETOOTH_PERMISSION).map(|error| error.code),
        Some(Pending::Scan) => ctx.input.capability_error(SCAN_BLUETOOTH_DEVICES).map(|error| error.code),
        None => return,
    };
    state.issue_key = Some(match code.as_deref() {
        Some("unsupported") => "probe.unsupported",
        Some("permission_denied") => "probe.denied",
        _ => "probe.failed",
    });
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn scan_requires_current_known_prerequisites() {
        let mut state = ProbeState::default();
        assert!(!state.can_scan());
        state.permission = BluetoothPermission::Granted;
        state.enabled = Some(true);
        assert!(!state.can_scan());
        state.low_energy = Some(true);
        assert!(state.can_scan());
        state.pending = Some(Pending::Scan);

    }
}

## Request access, check again, then discover sensors

The Android permission provider currently initiates a prompt and immediately reads the current permission. It does not wait for the user's answer. For that reason, the UI separates Request access, Check and Scan. Finish the prompt, then check again; do not run a prompt loop or treat an early denied snapshot as the user's final answer.

The scan uses the Bluetooth SIG Environmental Sensing UUID. `include_paired` is deliberately false: the current Android helper includes all bonded devices when that flag is true, before applying the advertising-service filter. A paired device is not necessarily a nearby advertising sensor.

<!-- fission:checkpoint -->
On Android, request access if needed, answer the system prompt, check again and scan. Compare the returned name with your sensor's own identification. Do not infer distance, a healthy connection or a temperature from RSSI; it is only reported signal strength.

A successful empty response means no devices were reported. The current Android helper can also return an empty list when Bluetooth becomes disabled, and it does not turn every scanner callback failure into a typed error. Recheck settings and the sensor before treating an empty response as evidence of absence.

## Qualify discovery without claiming connection

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

Check permission granted, not granted and restricted where the device policy allows it. Test Bluetooth off, a sensor advertising the matching UUID, a sensor advertising another service, and a scan after the matching sensor is switched off. Starting a scan clears the previous results so they cannot be mistaken for the new scan.

Device IDs supply stable row keys, but the screen does not display or log addresses. Advertised names remain untrusted text. Do not use a name alone to select a customer record or authorise an inspection.

Connection and characteristic operations need an implemented provider and separate physical qualification before this becomes a connected-sensor app. This tutorial does not manufacture a connected state or a sensor reading in their absence.
