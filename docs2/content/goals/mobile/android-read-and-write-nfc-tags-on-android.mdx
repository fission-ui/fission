## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-read-and-write-nfc-tags-on-android
cd android-read-and-write-nfc-tags-on-android
fission add-target android --project-dir .
fission add-capability nfc --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-read-and-write-nfc-tags-on-android/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

            cx.tr("nfc.hide_details")
        } else {
            cx.tr("nfc.show_details")

    SemanticsRegion(
        identifier: Some("incoming-inspection".to_string()),
        label: Some(cx.tr("nfc.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("nfc.site"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("nfc.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("nfc.tag"))
                    .color(tokens.colors.text_secondary),
                Container(
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("nfc.context")),
                        Text(details),
                    ])
                )
                .padding_all(tokens.spacing.m)
                .bg(tokens.colors.background)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.medium),
                Button(
                    child: Text(button_label),
                    key: "toggle-tag-details",
                    variant: ButtonVariant::Primary,
                    on_press: reduce {
                        state.tag_details_open = !state.tag_details_open;
                    },
                ),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)

    )

## Run the Nfc operation through Fission

Keep host work out of component conversion. The button dispatches a typed action, its reducer queues the capability request, and separate completion reducers update the screen. The Web preview installs `MemoryNfcHost` and sends the same operation through Fission’s typed capability path. Its deterministic response is not a claim about device hardware, OS permission or native platform support.

The Web preview uses `MemoryNfcHost` to exercise the typed scan flow with a deterministic response. It does not access an NFC reader or Android hardware.

use fission::prelude::*;

#[derive(Debug, Default)]
pub struct NfcTagState {
    pub pending: bool,
    pub records_read: Option<usize>,
    pub failed: bool,
}

impl GlobalState for NfcTagState {}

#[fission_reducer(RunCapability)]
pub fn run_capability(
    state: &mut NfcTagState,
    request: NfcScanRequest,
    ctx: &mut ReducerContext<NfcTagState>,
) {
    state.pending = true;
    state.records_read = None;
    state.failed = false;

    let ok: ActionEnvelope = CapabilitySucceeded.into();
    let err: ActionEnvelope = CapabilityFailed.into();

    ctx.effects
        .nfc().scan_tag(request)
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(CapabilitySucceeded)]
pub fn capability_succeeded(
    state: &mut NfcTagState,
    ctx: &mut ReducerContext<NfcTagState>,
) {
    state.pending = false;
    state.records_read = ctx
        .input
        .capability_ok(SCAN_NFC_TAG)
        .map(|value| value.records.len());
    state.failed = state.records_read.is_none();
}

#[fission_reducer(CapabilityFailed)]
pub fn capability_failed(
    state: &mut NfcTagState,
) {
    state.pending = false;
    state.records_read = None;
    state.failed = true;
}

pub fn callback_registry() -> ActionRegistry<NfcTagState> {
    let mut registry = ActionRegistry::new();
    registry.register(reduce_with!(capability_succeeded));
    registry.register(reduce_with!(capability_failed));
    registry
}

fission_component! {
    pub NfcTagInspectionScreen<NfcTagState> {}
    view(_screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let request = NfcScanRequest {
            technologies: vec![NfcTechnology::Ndef],
            message: Some(cx.tr("nfc.scan_prompt")),
            timeout_ms: Some(10_000),
            read_multiple_records: false,
        };
        let action = with_reducer!(cx.build, RunCapability(request), run_capability);
        let status = if state.pending {
            cx.tr("nfc.waiting")
        } else if state.failed {
            cx.tr("nfc.error")
        } else if let Some(records_read) = state.records_read {
            format!("{} {records_read}", cx.tr("nfc.result"))
        } else {
            cx.tr("nfc.ready")
        };
    } =>
    SemanticsRegion(
        identifier: Some("incoming-inspection-nfc".to_string()),
        label: Some(cx.tr("nfc.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("nfc.site"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("nfc.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("nfc.tag"))
                    .color(tokens.colors.text_secondary),
                Text(cx.tr("nfc.context")),
                Button(
                    child: Text(cx.tr("nfc.action")),
                    key: "run-capability",
                    variant: ButtonVariant::Primary,
                    disabled: state.pending,
                    loading: state.pending,
                    on_press: action,
                ),
                Container(Text(status))
                    .padding_all(tokens.spacing.m)
                    .bg(tokens.colors.background)
                    .border(tokens.colors.border, 1.0)
                    .border_radius(tokens.radii.medium),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}

## Verify the native request on Android

The website preview cannot exercise the native provider. Build and launch this target on a supported emulator or device, then use the feature action from the component above. Check the result the host actually returns, including denial, cancellation or unsupported hardware where those outcomes apply.

Repeat with the feature unavailable, denied or cancelled, as applicable. Confirm the screen preserves the user’s existing data and offers the right recovery step. Use a physical device when the behavior depends on real hardware or an operating-system prompt.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. A release build checks packaging, but none of these commands proves a physical permission or hardware flow works.


### Emulator and connected-device commands

Run these emulator checks from the generated project root:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
```


For a real capability check, use an Android phone that has the required hardware and permission. Connect it with USB or Wi-Fi debugging, confirm its serial, then run the app on that device:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

An emulator can exercise the UI and memory-provider outcomes; it is not evidence that physical hardware or an OS permission flow works.
