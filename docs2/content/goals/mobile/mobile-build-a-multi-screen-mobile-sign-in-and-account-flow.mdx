**Status: blocked — the original shared native sign-in goal is not fulfilled.** Fission's current iOS shell installs `UnsupportedPasskeyHost`, and this tutorial has no relying-party server challenge or verification service. An associated domain, typed request or synthetic assertion cannot replace those missing pieces.

The distinction matters because a credential response is not an authenticated session. A server must verify it before the application may construct protected account content. We will keep that boundary visible whilst providing a real host-support diagnostic and actual Router-based denied account route. There is no memory-provider sign-in, hard-coded challenge or “continue anyway” action.

## Create the shared diagnostic app

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/) and [iOS setup](/blog/set-up-rust-ios-development-with-fission/) first.

```sh
cargo install cargo-fission
fission init mobile-build-a-multi-screen-mobile-sign-in-and-account-flow
cd mobile-build-a-multi-screen-mobile-sign-in-and-account-flow
fission add-target android ios --project-dir .
fission add-capability passkeys --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs`. The library installs the same app, route handler, translations and actual target provider on normal native and Web launches. Web uses hash routing so the embedded preview does not take over the documentation path.

## Start with what the app can establish

The person may enter an account label and query passkey availability. The label is explicitly unverified user input. A supported secure host may help satisfy a prerequisite, but the account selector still returns `Deny` because no server has verified a session.

`ProtectedRoute` constructs the denied branch without constructing account content. This is a real presentation boundary, not a button which toggles a fake signed-in flag. The incomplete integration deliberately has no path which grants account access.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct AccountState {
    pub locale: Locale,
    pub current_path: String,
    pub account_label: String,
    pub pending: bool,
    pub message_key: String,
    pub diagnostic: Option<String>,
}
impl Default for AccountState {
    fn default() -> Self {
        Self {
            locale: Locale::from("en-US"),
            current_path: "/".into(),
            account_label: String::new(),
            pending: false,
            message_key: "check.ready".into(),
            diagnostic: None,
        }
    }
}
impl GlobalState for AccountState {}

pub fn check_host(state: &mut AccountState, cx: &mut ReducerContext<AccountState>) {
    if state.pending {
        return;
    }
    state.pending = true;
    state.message_key = "check.pending".into();
    state.diagnostic = None;
    let ok = cx.effects.bind(HostChecked, reduce_with!(host_checked));
    let err = cx
        .effects
        .bind(HostCheckFailed, reduce_with!(host_check_failed));
    cx.effects.passkeys().availability().on_ok(ok).on_err(err);
}

#[fission_reducer(HostChecked)]
fn host_checked(state: &mut AccountState, cx: &mut ReducerContext<AccountState>) {
    state.pending = false;
    match cx.input.capability_ok(GET_PASSKEY_AVAILABILITY) {
        Some(value) => {
            state.message_key = if value.supported && value.secure_context {
                "check.available"
            } else {
                "check.unavailable"
            }
            .into();
            state.diagnostic = Some(format!("{value:?}"));
        }
        None => state.message_key = "check.invalid".into(),
    }
}

#[fission_reducer(HostCheckFailed)]
fn host_check_failed(state: &mut AccountState, cx: &mut ReducerContext<AccountState>) {
    state.pending = false;
    match cx.input.capability_error(GET_PASSKEY_AVAILABILITY) {
        Some(error) => {
            state.message_key = if error.code == "unsupported" {
                "check.unavailable"
            } else {
                "check.failed"
            }
            .into();
            state.diagnostic = Some(format!("{}: {}", error.code, error.message));
        }
        None => state.message_key = "check.invalid".into(),
    }
}

pub fn route_changed(
    state: &mut AccountState,
    action: fission::core::action::ShellRouteChanged,
    _cx: &mut ReducerContext<AccountState>,
) {
    state.current_path = action.location.pathname;
}

// There is no session-verification service in this example. Host support is
// never an authorization input. The unfinished integration must fail closed.
pub fn account_route_decision(_state: &AccountState) -> RouteDecision {
    RouteDecision::Deny
}

#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn support_or_an_entered_account_cannot_authorize_access() {
        let mut state = AccountState::default();
        state.account_label = "person@example.com".into();
        state.message_key = "check.available".into();
        assert!(matches!(
            account_route_decision(&state),
            RouteDecision::Deny
        ));
    }
}

use super::screen::{AccountBlocked, AccountContent, SignInScreen};
use super::state::{account_route_decision, AccountState};
use fission::prelude::*;

fission_component! {
    pub UnknownRoute<AccountState> {}
    view(_unknown, _state, cx) => Column(children: [
        Text(cx.tr("account.unknown")),
        Button(child: Text(cx.tr("account.return")), key: "recover",
            on_press: reduce { cx.effects.replace_route("/"); }),
    ])
}

fission_component! {
    pub AccountApp<AccountState> {}
    view(_app, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let router = Router::<AccountState>::new()
            .with_path(state.current_path.clone())
            .route_component("/", SignInScreen)
            .route_component("/account",
                ProtectedRoute::new(account_route_decision(state), AccountContent)
                    .denied(AccountBlocked))
            .not_found(|| UnknownRoute);
    } => SafeArea(child: Scroll(child: Container(Column(gap: tokens.spacing.m, children: [
        Row(gap: tokens.spacing.s, children: [
            Button(child: Text(cx.tr("language.english")), key: "english",
                on_press: reduce { state.locale = Locale::from("en-US"); }),
            Button(child: Text(cx.tr("language.spanish")), key: "spanish",
                on_press: reduce { state.locale = Locale::from("es-ES"); }),
        ]),
        router,
    ])).padding_all(tokens.spacing.l)))
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid navigation translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::AccountState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Complete authentication before enabling the account route

The intended flow is: ask the service for a fresh challenge, request a real credential for its relying-party identity, send the assertion back to that service, then accept only its verified session result. Cancellation, no credential, expired challenge and verification failure leave the user signed out. A retry requires another fresh challenge.

The challenge belongs to the server's authentication attempt, not a string generated in a view. The server verifies the expected challenge, relying party, origin/application association, credential and account policy using a maintained WebAuthn implementation. Keep assertions short-lived in memory and do not log or persist them as debugging fixtures.

For iOS, configure the signed app's `webcredentials` association and the domain's `apple-app-site-association` document as well as installing a genuine AuthenticationServices provider. Android has its own app/domain association and credential-provider requirements. The portable capability declaration does not implement either platform integration by itself.

Once those dependencies exist, replace the deliberately denied selector with one pure selector over resolved session state: pending whilst session hydration runs, signed-out redirect, authenticated-and-authorized allow, otherwise deny. Register startup hydration unconditionally before queuing its action. Do not scatter redirect side effects through protected screens.

The included test checks only the current fail-closed rule. It does not verify any credential or server session. This goal remains blocked until the real authentication path is implemented and qualified.

Until then, report the missing integration rather than claiming that launching the diagnostic qualified sign-in.

Route protection does not authorize server requests. The protected API must independently authenticate the session and enforce account access. Do not send secret account data to this client merely because its Router would hide a component.
