## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-build-ios-forms-that-work-with-the-keyboard
cd ios-build-ios-forms-that-work-with-the-keyboard
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-build-ios-forms-that-work-with-the-keyboard/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

```rust
use fission::prelude::*;

fission_component! {
    pub VisitCheckInForm<()> {
        state {
            contact_name: String = String::new(),
            access_code: String = String::new(),
            submitted: bool = false,
        }
    }
    view(form, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("northbank.visit-check-in".to_string()),
        label: Some(cx.tr("form.screen.label")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("form.title"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("form.description"))
                    .color(tokens.colors.text_secondary),
                TextInput(
                    label: Some(cx.tr("form.contact.label").into()),
                    bind: form.contact_name,
                    placeholder: Some(cx.tr("form.contact.placeholder").into()),
                    required: true,
                    semantics_identifier: "northbank.check-in.contact".to_string(),
                ),
                TextInput(
                    label: Some(cx.tr("form.code.label").into()),
                    bind: form.access_code,
                    placeholder: Some(cx.tr("form.code.placeholder").into()),
                    required: true,
                    keyboard_type: TextInputType::Number,
                    autocorrect: false,
                    semantics_identifier: "northbank.check-in.access-code".to_string(),
                ),
                Button(
                    child: Text(cx.tr("form.submit")),
                    key: "submit-check-in",
                    on_press: reduce { form.submitted = true; },
                ),
                if form.submitted && form.contact_name.trim().is_empty() {
                    Text(cx.tr("form.contact.error"))
                        .color(tokens.colors.error)
                } else if form.submitted && form.access_code.chars().count() != 6 {
                    Text(cx.tr("form.code.error"))
                        .color(tokens.colors.error)
                } else if form.submitted {
                    Text(cx.tr("form.success"))
                        .color(tokens.colors.success)
                } else {
                    Text(cx.tr("form.pending"))
                        .color(tokens.colors.text_secondary)
                },
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

mod app;

use std::collections::HashMap;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("i18n/en-US.yaml")),
        ("es-ES", include_str!("i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid embedded tutorial translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::VisitCheckInForm)
        .with_env(preview_env())
        .with_title("ios build ios forms that work with the keyboard")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Build iOS forms that work with the keyboard

Keep each field's draft in the form component and put only a validated submission in shared app state. Give every field a visible label, an input type that matches its data, and a specific validation message. On a phone, verify that focusing the last field scrolls it above the software keyboard, the submit action remains reachable, and the keyboard can be dismissed without losing text. Test empty, malformed, valid and long input, then rotate or resize the device while the keyboard is open. Do not treat keyboard dismissal as successful validation.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

## Verify the user task on iOS

On an iOS simulator, repeat the feature path described above and check the expected result. If this task has an unavailable, denied or failure path, run that path too and confirm the screen offers a way to continue. The browser preview demonstrates component state only; the commands below verify the native host.

Use LiveTest with the semantic identifiers shown in the component to confirm focus and action behavior. If this screen adapts to window size, repeat the flow at a narrow phone width and a wider display.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
