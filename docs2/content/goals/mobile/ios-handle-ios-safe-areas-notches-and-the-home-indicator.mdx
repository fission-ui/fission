A screen can fit within its window and still place a button beneath the home indicator. The window's bounds describe the available surface; its safe-area insets describe the part of that surface the host asks ordinary content to avoid. These are different inputs, so a fixed bottom padding is not a substitute for the inset.

We will build a delivery handover form with a long note and a final review action. This gives us something useful to inspect: the heading must clear the status area, the note must remain editable and the last action must remain reachable as the available space changes.

## Create the shared app

Follow [iOS setup](/blog/set-up-rust-ios-development-with-fission/) if Xcode and the Rust targets are not installed.

```sh
cargo install cargo-fission
fission init ios-handle-ios-safe-areas-notches-and-the-home-indicator
cd ios-handle-ios-safe-areas-notches-and-the-home-indicator
fission add-target ios --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs`. Replace the shared library with the files below so that the native app runs the same form as the Web preview.

## Put the safe boundary outside the scrollable content

The nesting is deliberate. The background belongs to the outer container, whilst `SafeArea` insets the scrollable content. Ordinary spacing comes from theme tokens inside that boundary. It therefore remains useful spacing on every device rather than being an accidental correction for one iPhone.

The form's draft is local UI memory. Preparing a handover copies a snapshot into application state; it does not claim to send a delivery request or persist it. Keeping those meanings separate makes the visible result match what the code actually does.

use super::state::{Handover, HandoverState};
use fission::prelude::*;

fission_component! {
    pub HandoverScreen<HandoverState> {
        state {
            recipient: String = String::new(),
            instructions: String = String::new(),
        }
    }
    view(form, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => Container(
        SafeArea(
            child: Scroll(
                child: Container(Column(gap: tokens.spacing.m, children: [
                    Text(cx.tr("handover.title")).size(tokens.typography.heading2_size),
                    Text(cx.tr("handover.explanation")).color(tokens.colors.text_secondary),
                    Row(gap: tokens.spacing.s, children: [
                        Button(
                            child: Text(cx.tr("language.english")), key: "english",
                            on_press: reduce { state.locale = Locale::from("en-US"); },
                        ),
                        Button(
                            child: Text(cx.tr("language.spanish")), key: "spanish",
                            on_press: reduce { state.locale = Locale::from("es-ES"); },
                        ),
                    ]),
                    FormControl(
                        label: Some(cx.tr("handover.recipient")),
                        required: true,
                        child: TextInput(
                            value: form.recipient.clone(),
                            bind(on_input): to(form.recipient),
                            keyboard_type: TextInputType::Name,
                            semantics_identifier: Some("handover.recipient".into()),
                        ),
                    ),
                    Text(cx.tr("handover.guidance")),
                    TextInput(
                        value: form.instructions.clone(),
                        bind(on_input): to(form.instructions),
                        label: Some(TextContent::Key("handover.instructions".into())),
                        multiline: true,
                        keyboard_type: TextInputType::Multiline,
                        text_input_action: TextInputAction::Newline,
                        semantics_identifier: Some("handover.instructions".into()),
                    ),
                    Text(cx.tr("handover.review_hint")).color(tokens.colors.text_secondary),
                    Button(
                        child: Text(cx.tr("handover.prepare")), key: "prepare-handover",
                        disabled: form.recipient.trim().is_empty() || form.instructions.trim().is_empty(),
                        on_press: reduce {
                            state.prepared = Some(Handover {
                                recipient: form.recipient.trim().to_owned(),
                                instructions: form.instructions.trim().to_owned(),
                            });
                        },
                    ),
                    if let Some(handover) = &state.prepared {
                        Column(gap: tokens.spacing.s, children: [
                            Text(cx.tr("handover.prepared")).weight(tokens.typography.font_weight_semibold),
                            Text(handover.recipient.clone()),
                            Text(handover.instructions.clone()),
                            Text(cx.tr("handover.session_only")).color(tokens.colors.text_secondary),
                        ])
                    },
                ]))
                .padding_all(tokens.spacing.l),
            ),
        ),
    )
    .bg(tokens.colors.surface)
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid handover translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::HandoverState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Understand what SafeArea can and cannot infer

Fission's `SafeArea` reads `Env.window_insets` and lowers a padded layout box. It does not identify an iPhone model, guess the notch's height or add a second copy of the inset to every child. Wrapping this form once is sufficient; repeatedly wrapping descendants can apply the same host input more than once.

There are two consequences worth making explicit. Firstly, a browser preview whose host reports zero insets cannot demonstrate clearance around an iPhone's physical cutout. Secondly, the keyboard is not merely another name for a notch. `SafeArea` alone does not establish keyboard avoidance or that a focused field will be scrolled into view. The scrollable form provides a way to reach content, but the actual keyboard behavior still needs target testing.

Do not add a hard-coded "keyboard height" when a check fails. Establish which window metrics the host reports and whether the control is obscured, unreachable or merely outside the current scroll position. Those failures have different causes. See [keyboard-aware forms](/blog/build-ios-forms-that-work-with-the-keyboard/) for focus and text-editing behavior.

## Check the device boundary rather than a screenshot of it

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Use [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) to select a notched iPhone, then repeat on an iPad and in landscape. Check both languages with the keyboard open and closed. Scroll to the final action and make sure it can be pressed without a system gesture taking precedence.

The generated launch test establishes that the host starts, not that these controls clear every inset. A physical-device pass remains useful because the status region, home indicator and system gestures are part of the behavior being checked. Record the device, orientation and text-size setting alongside the result.

The example keeps handovers in memory. Reloading clears them; that is independent of safe-area layout and should not be mistaken for a persistence failure.
