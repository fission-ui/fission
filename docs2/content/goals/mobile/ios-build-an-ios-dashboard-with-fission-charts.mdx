## Create the iOS project

Create the shared Rust app and add its iOS host:

```sh
cargo install cargo-fission
fission init ios-build-an-ios-dashboard-with-fission-charts
cd ios-build-an-ios-dashboard-with-fission-charts
fission add-target ios --project-dir .
```

The generated host handles launch and packaging. The dashboard and its state stay in shared Rust code, so the same components can render in the browser preview and in the iOS app.

## Give the dispatcher a clear view of the shift

At 8:42 on a weekday morning, the Central depot is preparing its next wave of departures. The dispatcher needs a quick answer to three questions: how many trips are scheduled, are vehicles leaving on time, and which routes need help now? We will build that screen for Northstar Transit. The values are sample records stored in memory; there is no service call hidden behind the preview.

Keep the first screen focused on decisions. Three metrics summarise today’s operation, while the route review section explains what the dispatcher can do about the two most urgent items. `TransitMetric` and `RouteReviewRow` are named components because they express reusable parts of this screen and keep the main dashboard readable.

## Compare on-time departures across a date range

The shift metrics tell the dispatcher what is happening now, but they do not show whether this morning is unusual. A chart can answer that question, provided its data matches the question. We will plot the percentage of scheduled departures that left within five minutes. Percentages are more useful here than raw trip counts because the number of scheduled services changes from day to day.

The **7 days** and **30 days** buttons use sample values for their selected window. The average badge and sentence are calculated from the same values that draw the bars, so changing the range cannot leave the chart and its summary out of sync. The selected range belongs to this component alone, so Fission’s retained local state is the smallest suitable state bucket. If several routes later share a date filter, move that shared choice into app state and load its data through an effect.

use fission::prelude::*;
use fission::charts::{Axis, BarSeries, Chart, Legend, Tooltip};

fission_component! {
    pub RoutePunctualityTrend<()> {
        state { thirty_days: bool = false }
    }
    view(trend, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let labels = if trend.thirty_days {
            vec!["Week 1", "Week 2", "Week 3", "Week 4"]
        } else {
            vec!["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
        };
        let rates = if trend.thirty_days {
            vec![84.0, 88.0, 90.0, 92.0]
        } else {
            vec![90.0, 86.0, 92.0, 95.0, 91.0, 88.0, 94.0]
        };
        let average = (rates.iter().sum::<f32>() / rates.len() as f32).round() as u32;
        let chart_width = (cx.view.env().viewport_size.width - tokens.spacing.l * 2.0).max(260.0);
        let chart: Widget = Chart::new()
            .width(chart_width)
            .height(320.0)
            .x_axis(Axis::category(labels))
            .y_axis(Axis::value().min(0.0).max(100.0))
            .legend(Legend::top_right())
            .tooltip(Tooltip::axis_trigger())
            .series(vec![BarSeries::new("On-time departures")
                .data(rates)
                .into()])
            .into();
    } =>
    SemanticsRegion(
        identifier: Some("northstar-on-time-departures".to_string()),
        label: Some("Northstar Transit on-time departure rate".to_string()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text("On-time departures").weight(tokens.typography.font_weight_semibold),
                        Text("Scheduled services leaving within five minutes.")
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: format!("{average}% average")),
                ]),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text("7 days"),
                        key: "range-seven-days",
                        variant: if trend.thirty_days { ButtonVariant::Outline } else { ButtonVariant::Primary },
                        on_press: reduce { trend.thirty_days = false; },
                    ),
                    Button(
                        child: Text("30 days"),
                        key: "range-thirty-days",
                        variant: if trend.thirty_days { ButtonVariant::Primary } else { ButtonVariant::Outline },
                        on_press: reduce { trend.thirty_days = true; },
                    ),
                ]),
                Row(gap: tokens.spacing.s, children: [chart]),
                Text(format!(
                    "{}% of scheduled departures left on time on average in this period.",
                    average,
                )).color(tokens.colors.text_secondary),
            ]),
        )
            .padding_all(tokens.spacing.l)
            .bg(tokens.colors.surface)
            .border(tokens.colors.border, 1.0)
            .border_radius(tokens.radii.large),
    )
}

## Check the dashboard on an iPhone

Run the app in an iOS Simulator and check it first at a phone width, then at a wider iPad size. The metric cards should wrap into readable rows, route notes should keep their status, and the chart should retain its labels without squeezing the plot into a narrow strip. Use VoiceOver to confirm that the chart’s surrounding label and average explain the same information as the bars.

The preview uses a fixed sample set, so it does not pretend to load live transit data. When a service supplies the real rates, keep its loading, no-service and error results visible in this same chart section. Build those states from actual request outcomes, and keep the last valid summary on screen while a new date range loads.

Run the native target from the generated project root:

```sh
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`fission doctor` reports missing Xcode tools or Rust targets, `fission run` launches a simulator, and `fission test` checks that the generated host starts. A simulator build does not verify device signing or physical-device behavior.

For chart options and shared state decisions, continue with the [Fission Charts reference](/reference/charts/overview/) and the [state, handles and providers guide](/docs/guides/state-handles-and-providers/).
