A row's position and the record it represents are different things. If a technician opens the details for one check, reversing the list must not transfer that open panel to the item now occupying the same position.

We will build a checklist the user can actually add to, filter and reorder. Completion is application data; the details panel's open/closed state is local UI memory. Using completion itself as local state would teach the wrong ownership rule, because hiding a widget should not change whether the inspection was done.

## Create the project and add the target

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) first. This behavior belongs to shared Fission state and identity; it does not require a native device capability.

```sh
cargo install cargo-fission
fission init ios-give-repeated-ios-list-rows-stable-identity
cd ios-give-repeated-ios-list-rows-stable-identity
fission add-target ios --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs` and replace `src/lib.rs` below. Both the native app and browser preview use the same checklist, rather than compiling a second screen only for the website.

## Separate record data from a row's presentation memory

The state allocates an ID when an item is created. Reversing or filtering never recalculates that ID. The counter is session-scoped and never reused within the session; a persisted app should retain its record IDs alongside the records rather than derive them from current list positions.

The row receives all its required props through the source-supported positional constructor, then gives Compose the item's ID as its key. There is no empty `Default` standing in for required input. The title is user data; only interface captions are translated.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ChecklistItem {
    pub id: u64,
    pub title: String,
    pub complete: bool,
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ChecklistState {
    pub items: Vec<ChecklistItem>,
    pub next_id: u64,
    pub locale: Locale,
}

impl Default for ChecklistState {
    fn default() -> Self {
        Self {
            items: Vec::new(),
            next_id: 1,
            locale: Locale::from("en-US"),
        }
    }
}

impl GlobalState for ChecklistState {}

pub fn add_item(state: &mut ChecklistState, title: &str) {
    let title = title.trim();
    if title.is_empty() {
        return;
    }
    let Some(next) = state.next_id.checked_add(1) else {
        return;
    };
    state.items.push(ChecklistItem {
        id: state.next_id,
        title: title.to_owned(),
        complete: false,
    });
    state.next_id = next;
}

use super::state::ChecklistState;
use fission::prelude::*;

fission_component! {
    pub ChecklistRow<ChecklistState> {
        props {
            item_id: u64,
            title: String,
            complete: bool,
        }
        state {
            expanded: bool = false,
        }
    }
    view(row, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let status = if row.complete {
            cx.tr("item.complete")
        } else {
            cx.tr("item.pending")
        };
    } => SemanticsRegion(
        identifier: Some(format!("checklist.item.{}", row.item_id)),
        child: Container(
        Column(gap: tokens.spacing.s, children: [
            Text(row.title.clone()).weight(tokens.typography.font_weight_semibold),
            Text(status),
            Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                Button(
                    child: Text(if row.complete { cx.tr("item.reopen") } else { cx.tr("item.finish") }),
                    key: "toggle-completion",
                    on_press: reduce {
                        if let Some(item) = state.items.iter_mut().find(|item| item.id == row.item_id) {
                            item.complete = !item.complete;
                        }
                    },
                ),
                Button(
                    child: Text(if row.expanded { cx.tr("item.hide") } else { cx.tr("item.details") }),
                    key: "toggle-details",
                    on_press: reduce { row.expanded = !row.expanded; },
                ),
            ]),
            if row.expanded {
                Text(cx.tr("item.detail_summary").replace("{title}", &row.title))
            },
        ]),
    )
    .padding_all(tokens.spacing.m)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.medium),
    )
}

use super::row::ChecklistRow;
use super::state::{add_item, ChecklistState};
use fission::prelude::*;

fission_component! {
    pub ChecklistScreen<ChecklistState> {
        state {
            draft: String = String::new(),
            filter: String = String::new(),
            reversed: bool = false,
        }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let query = screen.filter.to_lowercase();
        let mut visible: Vec<_> = state.items.iter()
            .filter(|item| item.title.to_lowercase().contains(&query))
            .collect();
        if screen.reversed {
            visible.reverse();
        }
    } => SafeArea(
        child: Scroll(
            child: Container(
                Column(gap: tokens.spacing.m, children: [
                    Text(cx.tr("list.title")).size(tokens.typography.heading2_size),
                    Text(cx.tr("list.explanation")),
                    Row(gap: tokens.spacing.s, children: [
                        Button(
                            child: Text(cx.tr("language.english")),
                            key: "english",
                            on_press: reduce { state.locale = Locale::from("en-US"); },
                        ),
                        Button(
                            child: Text(cx.tr("language.spanish")),
                            key: "spanish",
                            on_press: reduce { state.locale = Locale::from("es-ES"); },
                        ),
                    ]),
                    FormControl(
                        label: Some(cx.tr("list.new_item")),
                        required: true,
                        child: TextInput(
                            value: screen.draft.clone(),
                            bind(on_input): to(screen.draft),
                        ),
                    ),
                    Button(
                        child: Text(cx.tr("list.add")),
                        key: "add-item",
                        disabled: screen.draft.trim().is_empty() || state.next_id == u64::MAX,
                        on_press: reduce {
                            add_item(state, &screen.draft);
                            screen.draft.clear();
                        },
                    ),
                    TextInput(
                        value: screen.filter.clone(),
                        bind(on_input): to(screen.filter),
                        label: Some(TextContent::Key("list.filter".into())),
                    ),
                    Button(
                        child: Text(cx.tr("list.reverse")),
                        key: "reverse-order",
                        on_press: reduce { screen.reversed = !screen.reversed; },
                    ),
                    if visible.is_empty() {
                        Text(cx.tr("list.empty"))
                    },
                    for item in visible {
                        ChecklistRow(
                            item.id,
                            item.title.clone(),
                            item.complete,
                            key: item.id,
                        )
                    },
                ]),
            )
            .padding_all(tokens.spacing.l)
            .bg(tokens.colors.surface),
        ),
    )
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid checklist translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::ChecklistState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Filter without treating absence as a new record

Filtering changes only the displayed projection. Completion remains on `ChecklistItem` in `GlobalState`, so removing a row from the visible tree cannot undo its work. Clearing the filter reveals the same record and completion value.

The optional details panel has a different lifetime. It belongs to the retained row instance. Stable keys prevent that memory from moving to another item during reordering; they are not a persistence mechanism for widgets removed from the tree. Do not promise that a panel stays open across unmounting unless the relevant retention policy has been established. Put that choice in application state if the product requires it to survive removal.

For the same reason, an index is not a useful key. Inserting a check before the selected row changes the index without changing the record. A durable record identifier avoids that dependency. Its visible title can also change without creating a new identity.

## Verify the same identity behavior on iOS

```sh
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Follow [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) for selecting the target. Repeat the browser sequence on iOS, with narrow layouts, long titles, duplicate titles and both languages. The row exposes `checklist.item.<id>` as a semantic identifier for LiveTest checks.

The generated launch smoke test does not test row identity for you. Drive the controls, inspect the resulting state and verify that actions still refer to the intended IDs after reordering. Check a real rendering before calling the layout qualified.

This app deliberately keeps records in memory; reloading resets them. See [persistent iOS state](/blog/persist-ios-app-state-with-fission-store-and-sqlite/) when the checklist must survive process restarts. Do not turn a widget key into a substitute for storage.
