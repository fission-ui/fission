## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-add-an-android-app-icon-and-native-splash-screen
cd android-add-an-android-app-icon-and-native-splash-screen
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-add-an-android-app-icon-and-native-splash-screen/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

## Create the app screen

The first Fission frame is where onboarding and longer loading states belong; Android’s native splash is only a brief launch screen. Start with the app screen, then configure the launcher icon and splash assets separately.

```rust
use fission::prelude::*;

fission_component! {
    pub AndroidLaunchBranding<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("task-workspace".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text(screen.title.clone())
                            .weight(tokens.typography.font_weight_bold),
                        Text(screen.step.clone())
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: "In progress".to_string()),
                ]),
                Divider(),
                Column(gap: tokens.spacing.s, children: [
                    Text("Current task")
                        .weight(tokens.typography.font_weight_semibold),
                    Text(screen.goal.clone()),
                ]),
                Row(gap: tokens.spacing.s, align_items: ir_op::AlignItems::Center, children: [
                    Badge(text: "Next".to_string()),
                    Text("Connect this screen to the workflow in the next step.".to_string())
                        .color(tokens.colors.text_secondary),
                ]),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Configure generated launcher assets and splash settings

Treat the Android launcher icon and native splash as separate assets. The icon may use adaptive foreground and background art; the splash is the short operating-system-owned frame shown before Fission starts. Configure the actual files in `fission.toml`, then run the Android package command and inspect the generated resources. Keep onboarding and loading progress in a Fission route after startup rather than stretching the native splash into an app screen. Force-stop and cold-launch an emulator to check icon cropping, splash contrast and the transition into the first frame.

```toml
[package.icons.android]
foreground = "assets/android/icon-foreground.png"
background = "assets/android/icon-background.png"

[app.splash]
image = "assets/android/splash-mark.png"
background_color = "#F8FAFC"
android_animated_icon = "assets/android/splash-animated.xml"
android_animation_duration_ms = 800
```

Create those asset files before packaging; the paths are project-relative. The animated icon field is Android-only.

## Check the launch experience on Android

Build and install the target package, then cold-launch it. Confirm the launcher icon uses the intended foreground and background, the native splash stays legible, and it hands off to the first Fission frame without showing a blank screen.

Repeat after changing the asset paths so you know the generated package picked up the new files. Keep onboarding and loading progress in the app’s first route; the operating-system splash is only a short launch frame.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. A release build checks packaging, but none of these commands proves a physical permission or hardware flow works.


### Emulator and connected-device commands
