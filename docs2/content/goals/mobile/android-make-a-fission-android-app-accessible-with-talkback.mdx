A visible label is useful, but accessibility also depends on the relationship between that label and the control, the control's current state and what happens after an action. A red border alone does not tell someone which input needs attention. A button called “Save” is also misleading if it only toggles a Boolean and saves nothing.

Here, we prepare pickup details for a local review. The form has a required name, an explicit validation message and, in the second step, optional instructions and an assistance choice. It uses the built-in controls which already own those roles and interactions instead of building lookalike controls from generic boxes.

The Android shell uses AccessKit's Android adapter, but Fission's native TalkBack support is currently incomplete. This page improves authored semantics and supplies a concrete check sequence; it cannot promise a complete TalkBack experience until the native bridge supports and passes that flow.

## Create the Android project

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/), then start [an emulator](/blog/create-and-launch-a-fission-android-emulator/) or connect [a phone](/blog/run-a-fission-app-on-a-physical-android-phone/).

```sh
cargo install cargo-fission
fission init android-make-a-fission-android-app-accessible-with-talkback
cd android-make-a-fission-android-app-accessible-with-talkback
fission add-target android --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs`. Both native and Web entrypoints below launch this form rather than leaving the starter counter installed on Android.

## Give the control a label and the error a relationship

`FormControl` supplies the name, helper, required flag and error context to its descendant input. That is different from placing an unrelated text label above a bare field. Keep one authority for those messages: the input does not declare a second label or a conflicting error.

The visible and semantic error comes from the same validation result. Preparing an empty name leaves the form editable; preparing a valid name makes it read-only for review. Nothing is persisted or submitted, so the result says exactly that.

```rust
use fission::prelude::*;

fission_component! {
    pub PickupDetails<()> {
        state {
            name: String = String::new(),
            attempted: bool = false,
            reviewing: bool = false,
        }
    }
    view(draft, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let invalid_name = draft.attempted && draft.name.trim().chars().count() < 2;
    } =>
    SafeArea(
        child: Scroll(
            child: Container(
                child: SemanticsRegion(
                    identifier: Some("pickup-details".to_string()),
                    label: Some(cx.tr("pickup.title")),
                    child: Column(gap: tokens.spacing.m, children: [
                        Text(cx.tr("pickup.title")).size(tokens.typography.heading2_size),
                        Text(cx.tr("pickup.context")),
                        FormControl(
                            label: Some(cx.tr("pickup.name")),
                            helper: Some(cx.tr("pickup.name_help")),
                            error: if invalid_name {
                                Some(cx.tr("pickup.invalid_name"))
                            } else { None },
                            required: true,
                            child: TextInput(
                                read_only: draft.reviewing,
                                bind: draft.name,
                                semantics_identifier: "pickup.name".to_string(),
                            ),
                        ),
                        Button(
                            child: Text(cx.tr("pickup.prepare")),
                            key: "prepare-pickup",
                            disabled: draft.reviewing,
                            on_press: reduce {
                                draft.attempted = true;
                                if draft.name.trim().chars().count() >= 2 {
                                    draft.reviewing = true;
                                }
                            },
                        ).semantics_identifier("pickup.prepare"),
                        if draft.reviewing {
                            Column(gap: tokens.spacing.s, children: [
                                SemanticsRegion(
                                    identifier: Some("pickup.review-status".to_string()),
                                    label: Some(cx.tr("pickup.status_label")),
                                    value: Some(cx.tr("pickup.prepared")),
                                    child: Text(cx.tr("pickup.prepared")),
                                ),
                                Button(
                                    child: Text(cx.tr("pickup.edit")),
                                    key: "edit-pickup",
                                    on_press: reduce { draft.reviewing = false; },
                                ).semantics_identifier("pickup.edit"),
                            ])
                        },
                    ]),
                ),
            ).padding_all(tokens.spacing.l),
        ),
    )
}
```

```rust
use std::collections::HashMap;
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid checked-in translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}
```

## Expose choice, disabled state and review status

The assistance choice is a real `Checkbox`, not a coloured circle with a click handler. It supplies checked and disabled state through Fission's normal semantics. The optional instructions remain a labelled multiline input.

The declared order is also the task order: name, instructions, assistance, prepare and review. Do not visually move controls into a different order and then expect an accessibility adapter to infer the intended sequence.

```rust
                            label: Some(cx.tr("pickup.instructions").into()),
```

## Inspect semantics, then test the actual TalkBack path

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

Use LiveTest to inspect the named region, input, checkbox and actions. Check that roles, labels, checked state, read-only state and validation messages agree with the visible screen. That catches authored errors; it does not qualify the Android bridge.

On a phone with TalkBack enabled, navigate without looking at the screen. Find the name field, submit the invalid form, correct it, enter instructions, select assistance, prepare and return to editing. Listen for each purpose, value and state, and record any control that cannot be reached or activated. Include the largest usable text size and long Spanish labels; the scroll view must keep the next action reachable.

Native touch and focus also need direct checks. Keep the standard button and checkbox target policies and test the actual hit areas rather than shrinking them to fit a screenshot.

The [accessibility reference](/reference/platform/accessibility/) records the current Android bridge gap. A Web canvas preview does not expose a complete browser document accessibility tree either, so it cannot substitute for the TalkBack check. If a required native action fails, the accessibility goal remains blocked even when the authored semantics are correct.
