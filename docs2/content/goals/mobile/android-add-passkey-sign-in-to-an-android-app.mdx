A passkey prompt returns an assertion: a signed response to a relying party's challenge. It does not, by itself, establish an application session. The server must check that response before returning a pickup token or any other protected data.

Here, the intended flow is a member collecting an order at Cedar Ridge Outfitters. The public order summary can be displayed before sign-in, but the collection code must remain server-side until the member is authenticated and authorised for that order.

**This is an integration outline, not a completed Android sign-in app.** This checkout registers `UnsupportedPasskeyHost` by default, including on Android; declaring the capability does not install Credential Manager. The runnable screen checks that real host and reports its unsupported result. It does not inject fixture credentials, invent a challenge or unlock an order. Completing the advertised sign-in flow requires both a product-owned native provider and a relying-party server. Those implementations are not supplied here.

The order summary and sign-in attempt belong in app state because several parts of the screen need them. Start with no order loaded; do not put a sample order in the production default. Both entrypoints start without an order. A real app loads an authorised public summary from its service; this outline does not manufacture one. The loading flag and response status also belong in app state because Android’s credential request finishes after the first reducer has returned. The component below renders that state and binds its buttons to reducer actions. It does not start a host request while building the view.

## Model passkey sign-in and protect the pickup order

First model the boundary. The signed-out state has no pickup token and no sign-in options. A completed integration loads the public summary and fresh options from its server through effects. Until then the screen can honestly check host availability, but it cannot request a meaningful assertion.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct PickupOrder {
    pub reference: String,
    pub pickup_location: String,
    pub item_summary: String,
    pub pickup_window: String,
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ServerPasskeyOptions {
    pub relying_party_id: String,
    pub challenge: Vec<u8>,
    pub allowed_credentials: Vec<PasskeyCredentialDescriptor>,
}

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct MemberPasskeySignInState {
    pub order: Option<PickupOrder>,
    /// Loaded from the relying-party server, never generated by this screen.
    pub options: Option<ServerPasskeyOptions>,
    pub availability: Option<PasskeyAvailability>,
    pub checking_support: bool,
    pub requesting_passkey: bool,
    /// Retained only until the assertion is sent to the server for verification.
    pub pending_assertion: Option<PasskeyAuthenticationResult>,
    pub message_key: Option<String>,
    pub error_key: Option<String>,
}

impl GlobalState for MemberPasskeySignInState {}

fn host_can_request_passkey(availability: &PasskeyAvailability) -> bool {
    availability.supported && availability.secure_context
}

#[fission_reducer(CheckPasskeySupport)]
pub fn on_check_passkey_support(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    if state.checking_support || state.requesting_passkey {
        return;
    }

    state.checking_support = true;
    state.error_key = None;
    state.message_key = Some("passkey.support.checking".into());

    let on_ok = ctx.effects.bind(
        PasskeySupportReceived,
        reduce_with!(on_passkey_support_received),
    );
    let on_err = ctx.effects.bind(
        PasskeySupportCheckFailed,
        reduce_with!(on_passkey_support_check_failed),
    );

    ctx.effects.passkeys().availability().on_ok(on_ok).on_err(on_err);
}

#[fission_reducer(PasskeySupportReceived)]
pub fn on_passkey_support_received(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.checking_support = false;
    let Some(availability) = ctx.input.capability_ok(GET_PASSKEY_AVAILABILITY) else {
        state.availability = None;
        state.message_key = None;
        state.error_key = Some("passkey.support.no_result".into());
        return;
    };

    let ready = host_can_request_passkey(&availability);
    state.availability = Some(availability);
    state.error_key = None;
    state.message_key = Some(if ready {
        "passkey.support.ready".into()
    } else {
        "passkey.support.unavailable".into()
    });
}

#[fission_reducer(PasskeySupportCheckFailed)]
pub fn on_passkey_support_check_failed(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.checking_support = false;
    state.availability = None;
    state.message_key = None;
    let Some(error) = ctx.input.capability_error(GET_PASSKEY_AVAILABILITY) else {
        state.error_key = Some("passkey.support.failed".into());
        return;
    };

    state.error_key = Some(if error.code == "unsupported" {
        "passkey.host.unsupported".into()
    } else {
        "passkey.support.failed".into()
    });
}

#[fission_reducer(SignInWithPasskey)]
pub fn on_sign_in_with_passkey(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    if state.checking_support || state.requesting_passkey || state.pending_assertion.is_some() {
        return;
    }

    let Some(availability) = state.availability.as_ref() else {
        state.error_key = Some("passkey.error.check_first".into());
        state.message_key = None;
        return;
    };
    if !host_can_request_passkey(availability) {
        state.error_key = Some("passkey.error.unavailable".into());
        state.message_key = None;
        return;
    }
    let Some(options) = state.options.take() else {
        state.error_key = Some("passkey.error.challenge_missing".into());
        state.message_key = None;
        return;
    };
    if options.challenge.is_empty() || options.relying_party_id.trim().is_empty() {
        state.error_key = Some("passkey.error.challenge_missing".into());
        state.message_key = None;
        return;
    }

    state.requesting_passkey = true;
    state.error_key = None;
    state.message_key = Some("passkey.request.waiting".into());

    let on_ok = ctx.effects.bind(
        PasskeyAssertionReceived,
        reduce_with!(on_passkey_assertion_received),
    );
    let on_err = ctx.effects.bind(
        PasskeyRequestFailed,
        reduce_with!(on_passkey_request_failed),
    );

    ctx.effects
        .passkeys()
        .authenticate(PasskeyAuthenticationRequest {
            relying_party_id: options.relying_party_id,
            challenge: options.challenge,
            // An empty list asks for a discoverable credential. The server may
            // instead return credential ids for an account-first sign-in flow.
            allow_credentials: options.allowed_credentials,
            user_verification: PasskeyUserVerification::Required,
            mediation: PasskeyMediation::Required,
            timeout_ms: Some(60_000),
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(PasskeyAssertionReceived)]
pub fn on_passkey_assertion_received(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.requesting_passkey = false;
    let Some(assertion) = ctx.input.capability_ok(AUTHENTICATE_PASSKEY) else {
        state.pending_assertion = None;
        state.message_key = None;
        state.error_key = Some("passkey.assertion.no_result".into());
        return;
    };

    state.pending_assertion = Some(assertion);
    state.error_key = None;
    state.message_key = Some("passkey.assertion.ready".into());
}

#[fission_reducer(PasskeyRequestFailed)]
pub fn on_passkey_request_failed(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.requesting_passkey = false;
    state.pending_assertion = None;
    state.message_key = None;
    let Some(error) = ctx.input.capability_error(AUTHENTICATE_PASSKEY) else {
        state.error_key = Some("passkey.request.failed".into());
        return;
    };

    state.error_key = Some(match error.code.as_str() {
        "cancelled" | "canceled" | "user_cancel" | "not_allowed" => "passkey.error.cancelled".into(),
        "unsupported" | "unavailable" => "passkey.error.unavailable".into(),
        "security_error" => "passkey.error.domain_association".into(),
        _ => "passkey.request.failed".into(),
    });
}

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

fn parse_properties(source: &str) -> HashMap<String, String> {
    source
        .lines()
        .filter(|line| !line.trim().is_empty() && !line.trim_start().starts_with('#'))
        .filter_map(|line| {
            let (key, value) = line.split_once('=')?;
            Some((key.trim().to_string(), value.trim().to_string()))
        })
        .collect()
}

fn load_bundle(locale: &str, source: &str) -> TranslationBundle {
    TranslationBundle {
        locale: Locale::from(locale),
        messages: parse_properties(source),
    }
}

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    env.i18n.add_bundle(load_bundle(
        "en-US",
        include_str!("../../i18n/en-US.properties"),
    ));
    env.i18n.add_bundle(load_bundle(
        "es-ES",
        include_str!("../../i18n/es-ES.properties"),
    ));
    env
}

`CheckPasskeySupport` and `SignInWithPasskey` are user actions. Their effect callbacks use unit actions to route completion to a reducer, and each reducer reads the typed result from `ctx.input`. The result is not smuggled through a pretend action payload, so the screen reports what the provider actually returned.

The server supplies the relying-party ID, challenge and any allowed credential IDs as one `ServerPasskeyOptions` value. Its challenge must be fresh, unpredictable and tied to the attempt. The reducer consumes those options when requesting an assertion, including when the request later fails. A retry must load new options; it must not silently replay an old challenge. The server remains the authority for challenge lifetime, replay prevention and verification.

The screen’s messages live in checked-in English and Spanish property files. `create_env` loads both bundles, and the component resolves stable translation keys through the active locale. That keeps translated copy out of the reusable component; the order and item names stay app data.

### Build the reusable pickup sign-in screen

Now put the screen in a named Fission component. The order summary lets Mara check what she is unlocking, and the locked-state message explains why the QR code is still hidden. Both actions are disabled while the host is busy. Even after a real provider returns an assertion, the component must not show a signed-in state. Loading options and submitting the assertion are server integration work, not something a local success flag can replace.

## Prepare Android Credential Manager

Android uses Credential Manager for passkeys. The app gets sign-in options from its relying-party server, passes them to Credential Manager, then sends the returned assertion back. The server checks the challenge, relying-party identity, credential, authenticator data, and signature before creating a session. Android’s [passkey sign-in guide](https://developer.android.com/identity/passkeys/sign-in-with-passkeys) explains the full exchange.

For a native Android app to share credentials with its website, the production website must also publish a Digital Asset Links file. Replace the placeholders below with the real application id and signing certificate fingerprint; do not copy these example values into a release app.

```json
[
  {
    "relation": [
      "delegate_permission/common.get_login_creds"
    ],
    "target": {
      "namespace": "android_app",
      "package_name": "com.example.cedarridge",
      "sha256_cert_fingerprints": [
        "REPLACE_WITH_THE_RELEASE_SIGNING_CERTIFICATE_SHA256"
      ]
    }
  }
]
```

Replace `members.example.com` with the real HTTPS domain used by your relying party, then host this file at `https://<your-domain>/.well-known/assetlinks.json`. The package name and SHA-256 fingerprint must match the Android app you sign. Android requires the association URL to return HTTP 200 with `Content-Type: application/json`; redirects or a mismatched signing certificate prevent verification. See Android’s [Credential Manager prerequisites](https://developer.android.com/identity/credential-manager/prerequisites) for the complete Digital Asset Links requirements.

The project command declares `passkeys`, but this checkout’s generated Android shell does not include a Credential Manager implementation of Fission’s `PasskeyHost`. Register an adapter with `MobileApp::with_passkey_host(...)`. Until you provide one, the native shell reports passkeys as unsupported. The Web preview deliberately retains that same real unsupported boundary instead of installing a fixture provider.

If native adapters are new to you, start with [Integrate an Android SDK through a Fission native module](/blog/integrate-an-android-sdk-through-a-fission-native-module/), then come back to the [PasskeyHost reference](/reference/capabilities/passkeys/).

## Verify the app and the sign-in boundary

Compiling this outline checks Rust types and the availability/error path. It does not verify Digital Asset Links, Android Credential Manager, or the server’s signature checks. Keep those checks separate; otherwise a passing browser build can look like stronger proof than it is.

Replace `members.your-company.com` in the shell command with a domain you control and deploy the file before running the check. The Android build validates the project and generated configuration; it cannot supply the missing `PasskeyHost`. Once your adapter is installed, test the successful and recovery paths: accept the prompt, cancel it, try a device with no available credential, and try an incorrect domain association. Unless the server returns a verified session, order CR-7712 and its pickup code must stay locked.
