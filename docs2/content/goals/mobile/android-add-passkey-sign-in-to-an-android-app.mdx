Mara Chen has arrived at the Cedar Ridge Outfitters pickup desk for order **CR-7712**. The order includes a weatherproof daypack and two trail maps. Its pickup QR code contains a short-lived collection token, so the app must keep it hidden until Mara has signed in.

We’ll build the client side of that sign-in. The app asks the passkey provider for an assertion using a fresh challenge, then keeps the order locked while the server verifies the response. The prompt may use a fingerprint, face check, device PIN, password manager, another phone, or a security key. The app never receives a fingerprint, and closing the prompt is not proof that Mara has an account. Only a server-verified assertion can establish the session.

The browser preview uses Fission’s `MemoryPasskeyHost`, so you can exercise the same request and reducer path without an Android device. It returns fixture bytes, not a cryptographic assertion. The preview stops at **Ready for server verification** and never unlocks the order. There’s one important gap on Android: declaring the passkeys capability does not install a Credential Manager provider. The native shell still needs an Android `PasskeyHost` adapter.

The order and sign-in attempt belong in app state because several parts of the screen need them. So do the loading flag and response status: Android’s credential request finishes after the first reducer has returned. The component below renders that state and binds its buttons to reducer actions. It does not start a host request while building the view.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct PickupOrder {
    pub reference: String,
    pub pickup_location: String,
    pub item_summary: String,
    pub pickup_window: String,
}

impl Default for PickupOrder {
    fn default() -> Self {
        Self {
            reference: "CR-7712".into(),
            pickup_location: "Troutdale trail counter".into(),
            item_summary: "Weatherproof daypack · 2 trail maps".into(),
            pickup_window: "Today, 14:00–18:00".into(),
        }
    }
}

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct MemberPasskeySignInState {
    pub order: PickupOrder,
    /// A fresh challenge from the relying-party server in a real sign-in flow.
    pub challenge: Vec<u8>,
    /// Optional allow-list returned by the server. Empty means discoverable credentials.
    pub allowed_credentials: Vec<PasskeyCredentialDescriptor>,
    pub availability: Option<PasskeyAvailability>,
    pub checking_support: bool,
    pub requesting_passkey: bool,
    /// Retained only until the assertion is sent to the server for verification.
    pub pending_assertion: Option<PasskeyAuthenticationResult>,
    pub message_key: Option<String>,
    pub error_key: Option<String>,
}

impl GlobalState for MemberPasskeySignInState {}

fn host_can_request_passkey(availability: &PasskeyAvailability) -> bool {
    availability.supported && availability.secure_context
}

#[fission_reducer(CheckPasskeySupport)]
pub fn on_check_passkey_support(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    if state.checking_support || state.requesting_passkey {
        return;
    }

    state.checking_support = true;
    state.error_key = None;
    state.message_key = Some("passkey.support.checking".into());

    let on_ok = ctx.effects.bind(
        PasskeySupportReceived,
        reduce_with!(on_passkey_support_received),
    );
    let on_err = ctx.effects.bind(
        PasskeySupportCheckFailed,
        reduce_with!(on_passkey_support_check_failed),
    );

    ctx.effects.passkeys().availability().on_ok(on_ok).on_err(on_err);
}

#[fission_reducer(PasskeySupportReceived)]
pub fn on_passkey_support_received(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.checking_support = false;
    let Some(availability) = ctx.input.capability_ok(GET_PASSKEY_AVAILABILITY) else {
        state.availability = None;
        state.message_key = None;
        state.error_key = Some("passkey.support.no_result".into());
        return;
    };

    let ready = host_can_request_passkey(&availability);
    state.availability = Some(availability);
    state.error_key = None;
    state.message_key = Some(if ready {
        "passkey.support.ready".into()
    } else {
        "passkey.support.unavailable".into()
    });
}

#[fission_reducer(PasskeySupportCheckFailed)]
pub fn on_passkey_support_check_failed(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.checking_support = false;
    state.availability = None;
    state.message_key = None;
    let Some(error) = ctx.input.capability_error(GET_PASSKEY_AVAILABILITY) else {
        state.error_key = Some("passkey.support.failed".into());
        return;
    };

    state.error_key = Some(if error.code == "unsupported" {
        "passkey.host.unsupported".into()
    } else {
        "passkey.support.failed".into()
    });
}

#[fission_reducer(SignInWithPasskey)]
pub fn on_sign_in_with_passkey(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    if state.checking_support || state.requesting_passkey || state.pending_assertion.is_some() {
        return;
    }

    let Some(availability) = state.availability.as_ref() else {
        state.error_key = Some("passkey.error.check_first".into());
        state.message_key = None;
        return;
    };
    if !host_can_request_passkey(availability) {
        state.error_key = Some("passkey.error.unavailable".into());
        state.message_key = None;
        return;
    }
    if state.challenge.is_empty() {
        state.error_key = Some("passkey.error.challenge_missing".into());
        state.message_key = None;
        return;
    }

    state.requesting_passkey = true;
    state.error_key = None;
    state.message_key = Some("passkey.request.waiting".into());

    let on_ok = ctx.effects.bind(
        PasskeyAssertionReceived,
        reduce_with!(on_passkey_assertion_received),
    );
    let on_err = ctx.effects.bind(
        PasskeyRequestFailed,
        reduce_with!(on_passkey_request_failed),
    );

    ctx.effects
        .passkeys()
        .authenticate(PasskeyAuthenticationRequest {
            relying_party_id: "members.cedarridge.example".into(),
            challenge: state.challenge.clone(),
            // An empty list asks for a discoverable credential. The server may
            // instead return credential ids for an account-first sign-in flow.
            allow_credentials: state.allowed_credentials.clone(),
            user_verification: PasskeyUserVerification::Required,
            mediation: PasskeyMediation::Required,
            timeout_ms: Some(60_000),
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(PasskeyAssertionReceived)]
pub fn on_passkey_assertion_received(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.requesting_passkey = false;
    let Some(assertion) = ctx.input.capability_ok(AUTHENTICATE_PASSKEY) else {
        state.pending_assertion = None;
        state.message_key = None;
        state.error_key = Some("passkey.assertion.no_result".into());
        return;
    };

    state.pending_assertion = Some(assertion);
    state.error_key = None;
    state.message_key = Some("passkey.assertion.ready".into());
}

#[fission_reducer(PasskeyRequestFailed)]
pub fn on_passkey_request_failed(
    state: &mut MemberPasskeySignInState,
    ctx: &mut ReducerContext<MemberPasskeySignInState>,
) {
    state.requesting_passkey = false;
    state.pending_assertion = None;
    state.message_key = None;
    let Some(error) = ctx.input.capability_error(AUTHENTICATE_PASSKEY) else {
        state.error_key = Some("passkey.request.failed".into());
        return;
    };

    state.error_key = Some(match error.code.as_str() {
        "cancelled" | "canceled" | "user_cancel" | "not_allowed" => "passkey.error.cancelled".into(),
        "unsupported" | "unavailable" => "passkey.error.unavailable".into(),
        "security_error" => "passkey.error.domain_association".into(),
        _ => "passkey.request.failed".into(),
    });
}

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

fn parse_properties(source: &str) -> HashMap<String, String> {
    source
        .lines()
        .filter(|line| !line.trim().is_empty() && !line.trim_start().starts_with('#'))
        .filter_map(|line| {
            let (key, value) = line.split_once('=')?;
            Some((key.trim().to_string(), value.trim().to_string()))
        })
        .collect()
}

fn load_bundle(locale: &str, source: &str) -> TranslationBundle {
    TranslationBundle {
        locale: Locale::from(locale),
        messages: parse_properties(source),
    }
}

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    env.i18n.add_bundle(load_bundle(
        "en-US",
        include_str!("../../i18n/en-US.properties"),
    ));
    env.i18n.add_bundle(load_bundle(
        "es-ES",
        include_str!("../../i18n/es-ES.properties"),
    ));
    env
}

`CheckPasskeySupport` and `SignInWithPasskey` are user actions. Their effect callbacks use unit actions to route completion to a reducer, and each reducer reads the typed result from `ctx.input`. The result is not smuggled through a pretend action payload, so the screen reports what the provider actually returned.

The server supplies `challenge` and, for an account-first flow, `allowed_credentials`. The challenge must be fresh, unpredictable, tied to this sign-in attempt, and kept server-side until the response arrives. The preview uses a fixed challenge to stay runnable. Production code must fetch a new one for every attempt.

The screen’s messages live in checked-in English and Spanish property files. `create_env` loads both bundles, and the component resolves stable translation keys through the active locale. That keeps translated copy out of the reusable component; the order and item names stay app data.

### Build the reusable pickup sign-in screen

Now put the screen in a named Fission component. The order summary lets Mara check what she is unlocking, and the locked-state message explains why the QR code is still hidden. Both actions are disabled while the host is busy. Even after the preview returns fixture assertion bytes, the component must not show a signed-in state.

use app::{MemberPasskeySignInState, PickupOrderSignInScreen};
use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();

    let preview_state = MemberPasskeySignInState {
        // A local fixture makes the preview request deterministic. Production
        // apps must fetch a fresh challenge from their sign-in server.
        challenge: vec![0x42; 32],
        ..Default::default()
    };
    let env = app::create_env();
    let app_title = env
        .i18n
        .get(&env.locale, "pickup.app.title")
        .unwrap_or("Cedar Ridge order pickup")
        .to_string();

    WebApp::<MemberPasskeySignInState, _>::new(PickupOrderSignInScreen)
        .with_env(env)
        .with_state_init(move |state: &mut MemberPasskeySignInState| {
            *state = preview_state.clone();
        })
        // MemoryPasskeyHost returns fixture bytes. The screen deliberately
        // stops before treating them as a verified account session.
        .with_passkey_host(MemoryPasskeyHost::default())
        .with_title(app_title)
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Prepare Android Credential Manager

Android uses Credential Manager for passkeys. The app gets sign-in options from its relying-party server, passes them to Credential Manager, then sends the returned assertion back. The server checks the challenge, relying-party identity, credential, authenticator data, and signature before creating a session. Android’s [passkey sign-in guide](https://developer.android.com/identity/passkeys/sign-in-with-passkeys) explains the full exchange.

For a native Android app to share credentials with its website, the production website must also publish a Digital Asset Links file. Replace the placeholders below with the real application id and signing certificate fingerprint; do not copy these example values into a release app.

```json
[
  {
    "relation": [
      "delegate_permission/common.get_login_creds"
    ],
    "target": {
      "namespace": "android_app",
      "package_name": "com.example.cedarridge",
      "sha256_cert_fingerprints": [
        "REPLACE_WITH_THE_RELEASE_SIGNING_CERTIFICATE_SHA256"
      ]
    }
  }
]
```

Host this as `https://members.cedarridge.example/.well-known/assetlinks.json`. Android requires the association to be reachable directly with HTTP 200 and an `application/json` response; a redirect or an incorrect package name or signing fingerprint prevents verification. See Android’s [Credential Manager prerequisites](https://developer.android.com/identity/credential-manager/prerequisites) for the complete Digital Asset Links requirements.

The project command declares `passkeys`, but this checkout’s generated Android shell does not include a Credential Manager implementation of Fission’s `PasskeyHost`. Register an adapter with `MobileApp::with_passkey_host(...)`. Until you provide one, the native shell reports passkeys as unsupported. `MemoryPasskeyHost` in the next tab only supports the browser preview; it is not an Android provider and cannot sign anyone in.

<Tabs>
<TabItem label="Android adapter boundary">
```rust
// In the Android app entrypoint, register a concrete host once the Credential
// Manager adapter exists. The adapter must implement all PasskeyHost methods.
use app::{create_env, MemberPasskeySignInState, PickupOrderSignInScreen};

MobileApp::<MemberPasskeySignInState, _>::new(PickupOrderSignInScreen)
    .with_env(create_env())
    .with_passkey_host(AndroidCredentialManagerPasskeyHost::new())
```
</TabItem>
</Tabs>

The final tab shows the integration boundary; it does not pretend an Android provider already exists. An `AndroidCredentialManagerPasskeyHost` would map Fission’s typed request to Android’s `GetCredentialRequest`, convert `PublicKeyCredential` into `PasskeyAuthenticationResult`, and report cancellation or unsupported cases as typed errors. If native adapters are new to you, start with [Integrate an Android SDK through a Fission native module](/blog/integrate-an-android-sdk-through-a-fission-native-module/), then come back to the [PasskeyHost reference](/reference/capabilities/passkeys/).

## Verify the app and the sign-in boundary

The browser build proves that the Rust state, component, typed effects, and preview host compile together. It does not verify Digital Asset Links, Android Credential Manager, or the server’s signature checks. Keep those checks separate; otherwise a passing browser build can look like stronger proof than it is.

<Tabs>
<TabItem label="Build the Android target">
```sh
fission doctor android --project-dir .
fission build --target android --project-dir .
```
</TabItem>
<TabItem label="Check the association file">
```sh
curl -i https://members.cedarridge.example/.well-known/assetlinks.json
```
</TabItem>
<TabItem label="Inspect the capability declaration">
```sh
rg -n "passkeys" fission.toml
```
</TabItem>
</Tabs>

The Android build validates the project and generated configuration. It cannot supply the missing `PasskeyHost`. Once your adapter is installed, test the successful and recovery paths: accept the prompt, cancel it, try a device with no available credential, and try an incorrect domain association. Unless the server returns a verified session, order CR-7712 and its pickup code must stay locked.

For the request fields and host contract, see the [Passkeys reference](/reference/capabilities/passkeys/) and the [capability support matrix](/reference/capabilities/matrix/). For a working example of how Fission keeps Android host behavior behind a shared component, continue with [the Android native module tutorial](/blog/integrate-an-android-sdk-through-a-fission-native-module/).
