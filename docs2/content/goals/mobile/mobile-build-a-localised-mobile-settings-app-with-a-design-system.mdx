A settings screen should change the application, not merely change the text describing a choice. Selecting Spanish whilst the rest of the interface stays English would demonstrate a toggle, not localization.

We will keep appearance and locale in shared app state, then mirror them into Fission's environment. Every component reads the same active tokens and translation bundles. The choices apply immediately for this session; there is no misleading Save button or claim that they survive relaunch.

## Create the shared app and design source

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/) and [iOS setup](/blog/set-up-rust-ios-development-with-fission/) first.

```sh
cargo install cargo-fission
fission init mobile-build-a-localised-mobile-settings-app-with-a-design-system
cd mobile-build-a-localised-mobile-settings-app-with-a-design-system
fission add-target android ios --project-dir .
cargo add serde_yaml
cargo add --build fission-design-system-codegen@0.16.0
```

The build dependency is Fission's design-system generator, version-aligned with this app's runtime. The JSON files are checked-in design inputs; generated Rust belongs under Cargo's `OUT_DIR`, not in handwritten source.

This small package supplies its palette and a button recipe and inherits the remaining component recipes from Fission's default design system. For a larger branded system, start from the complete [default DSP and tokens](/docs/guides/design-system/) and keep your app-local copies. Do not read files from Fission's repository at runtime.

## Install the generated system on every entrypoint

Keep the generated `src/main.rs`. The shared files below install the same root, generated design system and translation bundles for normal Android, iOS and Web launches. The preview does not bypass that setup.

The appearance switch is wrapped in `FormControl` so its accessible label is associated with the actual control. A heading beside an unlabelled switch would not provide the same relationship. The language buttons wrap on narrow widths, whilst the sample description makes longer translated content visible.

```rust
use std::path::PathBuf;

fn main() {
    let manifest_dir = PathBuf::from(std::env::var("CARGO_MANIFEST_DIR").unwrap());
    let dsp_path = manifest_dir.join("design/dsp.json");

    fission_design_system_codegen::generate(
        fission_design_system_codegen::Config::new(dsp_path)
            .out_file("mobile_settings_design_system.rs")
            .type_name("MobileSettingsDesignSystem")
            .crate_path("fission::theme"),
    )
    .expect("failed to generate the settings design system");
}
```

```rust
use super::state::SettingsState;
use fission::prelude::*;

fission_component! {
    pub SettingsScreen<SettingsState> {}
    view(_settings, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => SafeArea(child: Scroll(child: Container(Column(gap: tokens.spacing.m, children: [
        Text(cx.tr("settings.title")).size(tokens.typography.heading2_size),
        Text(cx.tr("settings.explanation")),
        FormControl(
            label: Some(cx.tr("settings.dark_mode")),
            helper: Some(cx.tr(if state.theme_mode == DesignMode::Dark {
                "settings.dark_selected"
            } else { "settings.light_selected" })),
            child: Switch(
                checked: state.theme_mode == DesignMode::Dark,
                semantics_identifier: Some("settings.dark_mode".into()),
                on_toggle: reduce {
                    state.theme_mode = if state.theme_mode == DesignMode::Dark {
                        DesignMode::Light
                    } else { DesignMode::Dark };
                },
            ),
        ),
        Text(cx.tr("settings.language")).weight(tokens.typography.font_weight_semibold),
        Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
            Button(child: Text(cx.tr("settings.english")), key: "english",
                variant: if state.locale == Locale::from("en-US") { ButtonVariant::Primary } else { ButtonVariant::Outline },
                on_press: reduce { state.locale = Locale::from("en-US"); }),
            Button(child: Text(cx.tr("settings.spanish")), key: "spanish",
                variant: if state.locale == Locale::from("es-ES") { ButtonVariant::Primary } else { ButtonVariant::Outline },
                on_press: reduce { state.locale = Locale::from("es-ES"); }),
        ]),
        Text(cx.tr("settings.example")).weight(tokens.typography.font_weight_semibold),
        Text(cx.tr("settings.long_description")),
        Button(child: Text(cx.tr("settings.reset")), key: "reset",
            on_press: reduce {
                state.locale = Locale::from("en-US");
                state.theme_mode = DesignMode::Light;
            }),
        Text(cx.tr("settings.scope")).color(tokens.colors.text_secondary),
    ])).padding_all(tokens.spacing.l).bg(tokens.colors.surface)))
}
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid task translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::SettingsState, env: &mut Env) {
    env.locale = state.locale.clone();
    env.theme = crate::design::MobileSettingsDesignSystem::theme(state.theme_mode);
}
```

```rust
use app::{SettingsScreen, SettingsState};

#[cfg(not(any(target_arch = "wasm32", target_os = "android", target_os = "ios")))]
```

## Keep presentation synchronization in one place

The reducers update only `SettingsState`. The shared `sync_env` function applies those choices to `Env`: locale selects the bundle and the generated design-system type creates the corresponding theme. Individual widgets do not reach into another widget's settings or assemble their own palettes.

Use `with_sync_env` for these application-wide presentation inputs, not for persistence or network work. If preferences later become durable, hydrate them once through a registered startup action and Store effects. A theme rebuild is not an appropriate place to read a database.

The Rust bundles localize the app's interface. They do not translate user data or automatically change native permission-purpose strings. Similarly, choosing dark appearance here changes this app, not the operating system's appearance setting.

## Check the actual mobile controls

Run on the configured Android emulator, then on macOS with an installed iOS simulator:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Check both languages at narrow and wide widths with larger text. The long Spanish reset action must remain readable, and VoiceOver/TalkBack must announce the appearance switch's label and checked state. Inspect focus, wrapping and colour contrast in both modes; a palette declaration alone does not establish accessible rendering.

Follow [Android phone installation](/blog/run-a-fission-app-on-a-physical-android-phone/) and [iPhone installation](/blog/install-a-fission-app-on-a-physical-iphone/) for physical checks. Keep browser, simulator and phone results distinct.
