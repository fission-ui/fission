Start with the [shared offline-first field-notes app](/blog/build-an-offline-first-notes-app-for-android-and-ios/). It contains the note model, SQLite migration, save reducers, and startup hydration used by both mobile targets. This page is about running that app on Android and checking device behavior; it does not add a pretend sync button or a second copy of the app logic.

The browser preview below is an interactive work-order selector so you can inspect the screen at this stage. Its sample records live only in the preview. They are not read from SQLite and do not survive a reload.

mod app;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");

    for (locale, source) in [
        ("en-US", include_str!("i18n/en-US.yaml")),
        ("es-ES", include_str!("i18n/es-ES.yaml")),
    ] {
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages: serde_yaml::from_str(source).expect("valid tutorial translations"),
        });
    }

    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<(), _>::new(app::AndroidFieldNotesPreview)
        .with_env(preview_env())
        .with_title("Harbour Field Notes · Android")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Run the shared app on Android

The shared tutorial already adds Android and iOS targets and enables Store. If you are applying this to another project, add only the missing target or capability:

```sh
fission add-target android --project-dir .
fission add-capability storage --project-dir .
```

Use the same `MobileApp` startup path as the iOS build. Hydration runs after reducer registration, and the screen stays in its loading state until SQLite responds:

```rust
MobileApp::<FieldNotesState, _>::new(FieldNotesWorkspace::new())
    .with_env(create_env())
    .with_title("Harbour Field Notes")
    .with_state_init(|state| {
        state.notes.clear();
        state.selected_note_id = None;
        state.is_loading = true;
        state.notice = "notes.notice.opening".into();
    })
    .with_startup_action(PrepareFieldNotes)
```

Do not seed production state with the browser preview records. On Android, the notes in the app come from the native SQLite provider. The linked tutorial implements local writes and a reducer that rejects stale sync-completion actions; it does not include an HTTP service or claim that a server has accepted a note.

### Verify offline persistence

Run this on an Android emulator or connected phone:

```sh
fission doctor android --project-dir .
fission devices --project-dir .
fission run --target android --project-dir .
```

Create or edit a field note and wait for **Saved on this device**. Turn on airplane mode, force-stop the app, reopen it, and confirm the note is still present. Then restore connectivity; without a real service configured, the note should remain **Waiting to sync**.

For the sync boundary, test the shared reducer with two completions delivered out of order: a completion for revision 5 must not mark revision 6 as synced. The tutorial’s `SyncNoteSucceeded` action is the seam a real network effect should dispatch after the server confirms that exact revision.

```sh
cargo test
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs tests you add for the reducer and storage behavior. `fission test` checks the generated Android host; it does not replace the offline restart check above.
