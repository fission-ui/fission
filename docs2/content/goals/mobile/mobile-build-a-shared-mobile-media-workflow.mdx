## Create the project and add the target

```sh
cargo install cargo-fission
fission init mobile-build-a-shared-mobile-media-workflow
cd mobile-build-a-shared-mobile-media-workflow
fission add-target android ios --project-dir .
fission add-capability camera --project-dir .
```

## Files created by Fission

Fission generates Android and iOS hosts alongside the shared Rust project:

```text
mobile-build-a-shared-mobile-media-workflow/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    ├── android/              # generated Android host
    └── ios/                  # generated iOS host
```

Keep the repair screen and capture state in shared Rust. Request camera access through Fission's capability; the generated hosts handle the platform-specific provider. This guide covers still photos, not microphone recording or video playback.

## Build the equipment photo screen

Start with an equipment inspection that needs a photo of a damaged part. The screen identifies the asset and lets the technician draft what they observed before adding a photo. That note remains a component-local draft in this preview; a production workflow would save it with the work order. The next step requests permission and captures through Fission.

## Run the Camera operation through Fission

Keep host work out of component conversion. The button dispatches a typed action; the reducer requests permission and only queues capture after the host grants it. Separate completion reducers update the screen. The Web preview installs `MemoryCameraHost`, whose deterministic permission and sample image exercise the same typed path without opening a browser camera.

The result includes image metadata and a one-shot stream handle. This example reports the metadata; it does not save or upload the photo. Consume the stream in a job or service before treating it as attached evidence.

use fission::prelude::*;

#[derive(Debug, Default)]
pub struct WorkOrderState {
    pub pending: bool,
    pub result: Option<String>,
    pub error: Option<String>,
}

impl GlobalState for WorkOrderState {}

#[fission_reducer(RunCapability)]
pub fn run_capability(state: &mut WorkOrderState, ctx: &mut ReducerContext<WorkOrderState>) {
    state.pending = true;
    state.result = None;
    state.error = None;

    let ok: ActionEnvelope = CameraPermissionReceived.into();
    let err: ActionEnvelope = CameraPermissionFailed.into();

    ctx.effects
        .camera()
        .request_permission(CameraPermissionRequest {
            reason: Some("Capture a photo of the damaged compressor guard.".into()),
        })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(CameraPermissionReceived)]
pub fn camera_permission_received(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    match ctx.input.capability_ok(REQUEST_CAMERA_PERMISSION) {
        Some(CameraPermission::Granted) => {
            state.pending = true;
            let ok: ActionEnvelope = CapabilitySucceeded.into();
            let err: ActionEnvelope = CapabilityFailed.into();

            ctx.effects
                .camera()
                .capture_photo(CameraCaptureRequest {
                    camera_id: None,
                    facing: CameraFacing::Back,
                    resolution: Some(CameraResolution { width: 1_600, height: 1_200 }),
                    format: CameraImageFormat::Jpeg,
                    flash: CameraFlashMode::Auto,
                    quality: Some(86),
                })
                .on_ok(ok)
                .on_err(err);
        }
        Some(CameraPermission::Denied | CameraPermission::Restricted) => {
            state.pending = false;
            state.error = Some(
                "Camera access was not granted. Allow it in device Settings to capture evidence."
                    .into(),
            );
        }
        Some(CameraPermission::Unknown) | None => {
            state.pending = false;
            state.error = Some("The host did not confirm camera permission.".into());
        }
    }
}

#[fission_reducer(CameraPermissionFailed)]
pub fn camera_permission_failed(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.result = None;
    state.error = Some(ctx
        .input
        .capability_error(REQUEST_CAMERA_PERMISSION)
        .map(|error| format!("{}: {}", error.code, error.message))
        .or_else(|| {
            ctx.input
                .capability_error_message(REQUEST_CAMERA_PERMISSION)
                .map(str::to_owned)
        })
        .unwrap_or_else(|| "The host returned no camera permission result.".into()));
}

#[fission_reducer(CapabilitySucceeded)]
pub fn capability_succeeded(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.error = None;
    state.result = ctx
        .input
        .capability_ok(CAPTURE_PHOTO)
        .map(|value| {
            format!(
                "Camera returned a {}×{} {} image in a one-shot stream.",
                value.width, value.height, value.content_type
            )
        });
    if state.result.is_none() {
        state.error = Some("The host completed without the expected typed result.".into());
    }
}

#[fission_reducer(CapabilityFailed)]
pub fn capability_failed(
    state: &mut WorkOrderState,
    ctx: &mut ReducerContext<WorkOrderState>,
) {
    state.pending = false;
    state.result = None;
    state.error = Some(ctx
        .input
        .capability_error(CAPTURE_PHOTO)
        .map(|error| format!("{}: {}", error.code, error.message))
        .or_else(|| {
            ctx.input
                .capability_error_message(CAPTURE_PHOTO)
                .map(str::to_owned)
        })
        .unwrap_or_else(|| "The host returned an error without details.".into()));
}

pub fn callback_registry() -> ActionRegistry<WorkOrderState> {
    let mut registry = ActionRegistry::new();
    registry.register(reduce_with!(camera_permission_received));
    registry.register(reduce_with!(camera_permission_failed));
    registry.register(reduce_with!(capability_succeeded));
    registry.register(reduce_with!(capability_failed));
    registry
}

fission_component! {
    pub WorkOrderScreen<WorkOrderState> {
        state {
            note_draft: String = String::new(),
        }
    }
    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let action = with_reducer!(cx.build, RunCapability, run_capability);
        let status = if state.pending {
            cx.tr("work.waiting")
        } else if let Some(error) = &state.error {
            format!("{}: {error}", cx.tr("work.error"))
        } else if let Some(result) = &state.result {
            format!("{}: {result}", cx.tr("work.result"))
        } else {
            cx.tr("work.ready")
        };
    } =>
    SemanticsRegion(
        identifier: Some("work-order-camera".to_string()),
        label: Some(cx.tr("work.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("work.site"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("work.title"))
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("work.asset"))
                    .color(tokens.colors.text_secondary),
                Text(cx.tr("work.context")),
                TextInput(
                    label: Some(cx.tr("work.note.label").into()),
                    placeholder: Some(cx.tr("work.note.placeholder").into()),
                    helper_text: Some(cx.tr("work.note.help").into()),
                    bind: screen.note_draft,
                    multiline: true,
                    semantics_identifier: "work-order.note-draft".to_string(),
                ),
                Button(
                    child: Text(cx.tr("work.action")),
                    key: "run-capability",
                    variant: ButtonVariant::Primary,
                    disabled: state.pending,
                    loading: state.pending,
                    on_press: action,
                ),
                Container(Text(status))
                    .padding_all(tokens.spacing.m)
                    .bg(tokens.colors.background)
                    .border(tokens.colors.border, 1.0)
                    .border_radius(tokens.radii.medium),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}

## Verify the native request on Android and iOS

Build and launch this target on a supported emulator or device, then use the feature action above. Check the result the host returns, including denial, cancellation or unsupported hardware where those outcomes apply.

Repeat with the feature unavailable, denied or cancelled, as applicable. Confirm the screen preserves the user’s existing data and offers the right recovery step. Use a physical device when the behavior depends on real hardware or an operating-system prompt.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add for reducer or stale-completion rules; the generated scaffold does not create those feature tests. `fission doctor` checks each target’s toolchain, `fission run` launches its emulator or Simulator, and `fission test` checks that the generated host can start. A release build validates packaging, not real hardware behavior.


### Run the shared project on both mobile targets

Run both target checks from the generated project root:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target android --project-dir .
fission test --target ios --project-dir .
```


Verify the relevant hardware on a connected Android phone and a signed iPhone build. Use `adb devices -l` and `fission run --target android --device <adb-serial> --project-dir .` for Android. For iOS, use `fission package --project-dir . --target ios --format ipa --release` and install through Xcode Devices and Simulators. The iOS `fission run` path is simulator-only.
