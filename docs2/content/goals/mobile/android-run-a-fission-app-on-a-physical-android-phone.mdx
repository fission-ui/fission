A USB connection and an authorised debugging connection are different things. ADB can see a phone while refusing to run commands because its owner has not accepted this computer's key. Check that connection before changing Rust code or rebuilding the app.

This guide takes an existing Android toolchain through authorisation, device selection and a real launch. Complete the [Android setup guide](/blog/set-up-rust-android-gui-development-with-fission/) first. The checklist below records checks you perform; it does not pair a phone or inspect its hardware.

## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-run-a-fission-app-on-a-physical-android-phone
cd android-run-a-fission-app-on-a-physical-android-phone
cargo add serde_yaml
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-run-a-fission-app-on-a-physical-android-phone/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # Compose checklist
└── platforms/
    └── android/              # generated Android host
```

The generated platform directory owns launch and packaging. The shared Rust library owns this screen and its translations.

## Keep an observable launch checklist

Use the same screen in the browser and the native app, but do not confuse those results. A browser click checks the interface; changing a checkbox on the selected native device checks that this build actually launched there. The marks record your observations, not detected toolchain status, and can be cleared if you need to repeat a check.

Replace both `src/app.rs` and `src/lib.rs` so the generated native entrypoint launches this component. Keep the language bundles in `i18n/` and the setup in `src/translations.rs`. The separate preview entrypoint is only for this documentation page.

use std::collections::HashMap;
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in setup translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Run a Fission app on a physical Android phone

On the phone, enable Developer options and USB debugging, unlock it, and accept the computer's debugging prompt. Find its serial with `adb devices -l`; an `unauthorized` entry means the phone has not accepted the key yet. Pass the authorised serial to Fission so it does not select a different connected target:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

For Wireless debugging, pair with the IP address and pairing port shown by Android's Wireless debugging screen, then connect to the device's connection address. The pairing and connection ports can differ:

```sh
adb pair <phone-ip>:<pairing-port>
adb connect <phone-ip>:<connection-port>
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

Confirm the app opens on the phone. An emulator exercises the UI, but it cannot prove that a physical camera, NFC antenna, biometric sensor or radio works.

## Check the connection and collect logs

Run `fission doctor` to check the Android toolchain, then confirm ADB lists the phone as `device`, not `unauthorized` or `offline`. Build and launch with the serial from that list. Fission attaches to app logs during `run`; you can attach again with `fission logs` if the app exits after launch.

```sh
fission doctor android --project-dir .
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
fission logs --target android --device <adb-serial> --project-dir . --follow
fission test --target android --project-dir .
```

`fission test` runs the generated emulator smoke test; it does not verify USB/Wi-Fi ADB pairing or hardware capability behavior. If the phone is listed as `offline`, reconnect it or wait for startup to finish, then run `adb devices -l` again.
