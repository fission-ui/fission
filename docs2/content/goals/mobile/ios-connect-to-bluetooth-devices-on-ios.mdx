Fission's default iOS shell does not include a Bluetooth provider. If an app requests a Bluetooth scan without installing its own `BluetoothHost`, Fission returns an `unsupported` result; it does not show a system permission prompt or discover a device.

That does not need to stop the rest of the job. This example is a Northbank receiving screen for checking a cold-room probe. It tries the Bluetooth scan, explains the unsupported result, and keeps a manual probe-label path available. The example does not pretend that entering a label reads the probe or saves an inspection to a server.

If your app supplies an iOS Bluetooth provider later, the same screen can display its real scan results. The provider is the part that must implement the platform-specific Bluetooth work.

## Create the iOS project

Keep the screen and state in shared Rust. This tutorial handles the unsupported default host; it does not add Bluetooth privacy descriptions for a provider that does not exist in this example.

```sh
cargo install cargo-fission
fission init northbank-ios-probe-check
cd northbank-ios-probe-check
cargo add serde_yaml
fission add-target ios --project-dir .
```

The generated iOS host owns launch and packaging. The screen, reducers, and manual fallback stay in the shared app.

## Build the probe-check screen

The screen makes two paths visible: try Bluetooth if a provider is installed, or enter the printed probe label. The field is app state, so the UI always shows what the technician has entered. A successful local check means only that the label is non-empty; it is not a backend write or a sensor reading.

The preview starts with an empty field and an idle scan status. The sample app will install Fission's unsupported host in the next step, so trying the scan exercises the same fallback this iOS target uses by default.

```rust
use fission::prelude::*;

#[derive(Debug, Default)]
pub struct ProbeCheckState {
    pub scan_pending: bool,
    pub scan_complete: bool,
    pub scan_unsupported: bool,
    pub scan_failed: bool,
    pub devices: Vec<BluetoothDevice>,
    pub probe_label: String,
    pub label_error: bool,
    pub confirmed_label: Option<String>,
}

impl GlobalState for ProbeCheckState {}

#[fission_reducer(UpdateProbeLabel)]
pub fn update_probe_label(state: &mut ProbeCheckState, ctx: &mut ReducerContext<ProbeCheckState>) {
    let Some(change) = ctx.input.text_change() else {
        return;
    };
    state.probe_label = change.new_text.clone();
    state.label_error = false;
    state.confirmed_label = None;
}

#[fission_reducer(ConfirmProbeLabel)]
pub fn confirm_probe_label(state: &mut ProbeCheckState) {
    let label = state.probe_label.trim();
    if label.is_empty() {
        state.label_error = true;
        state.confirmed_label = None;
        return;
    }
    state.label_error = false;
    state.confirmed_label = Some(label.to_owned());
}
```

## Show the real unsupported result

The scan is a Fission effect requested by a reducer. Its completion actions read the typed capability result and update state; component conversion never calls the host. The example installs `UnsupportedBluetoothHost` in both its Web preview and its generated iOS app. On iOS, that matches the current default. If an app later installs a working provider with `with_bluetooth_host`, the same success reducer will render the devices returned by that provider.

The unsupported response is different from a permission denial, a failed scan, and a successful scan with no matching devices. Keep those states separate so a technician gets a useful next step rather than a false success.

```rust
pub struct ProbeCheckState {
    pub scan_pending: bool,
    pub scan_complete: bool,
    pub scan_unsupported: bool,
    pub scan_failed: bool,
    pub devices: Vec<BluetoothDevice>,
    pub probe_label: String,
    pub label_error: bool,
    pub confirmed_label: Option<String>,
}

impl GlobalState for ProbeCheckState {}

#[fission_reducer(ScanForProbe)]
pub fn scan_for_probe(
    state: &mut ProbeCheckState,
    ctx: &mut ReducerContext<ProbeCheckState>,
) {
    state.scan_pending = true;
    state.scan_complete = false;
    state.scan_unsupported = false;
    state.scan_failed = false;
    state.devices.clear();

    let ok = ctx.effects.bind(ProbeScanSucceeded, reduce_with!(probe_scan_succeeded));
    let err = ctx.effects.bind(ProbeScanFailed, reduce_with!(probe_scan_failed));
    ctx.effects
        .bluetooth()
        .scan_devices(BluetoothScanRequest {
            service_uuids: vec!["0000181a-0000-1000-8000-00805f9b34fb".into()],
            timeout_ms: Some(4_000),
            include_paired: true,
            allow_duplicates: false,
        })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(ProbeScanSucceeded)]
pub fn probe_scan_succeeded(
    state: &mut ProbeCheckState,
    ctx: &mut ReducerContext<ProbeCheckState>,
) {
    state.scan_pending = false;
    state.scan_unsupported = false;
    state.scan_failed = false;
    if let Some(result) = ctx.input.capability_ok(SCAN_BLUETOOTH_DEVICES) {
        state.scan_complete = true;
        state.devices = result.devices;
    } else {
        state.scan_complete = false;
        state.scan_failed = true;
        state.devices.clear();
    }
}

#[fission_reducer(ProbeScanFailed)]
pub fn probe_scan_failed(
    state: &mut ProbeCheckState,
    ctx: &mut ReducerContext<ProbeCheckState>,
) {
    state.scan_pending = false;
    state.scan_complete = false;
    state.devices.clear();
    let error = ctx.input.capability_error(SCAN_BLUETOOTH_DEVICES);
    state.scan_unsupported = error.as_ref().is_some_and(|error| error.code == "unsupported");
    state.scan_failed = !state.scan_unsupported;
}

#[fission_reducer(UpdateProbeLabel)]

    let Some(change) = ctx.input.text_change() else {
        return;

    state.probe_label = change.new_text.clone();
    state.label_error = false;
    state.confirmed_label = None;
}

pub fn confirm_probe_label(state: &mut ProbeCheckState) {
    let label = state.probe_label.trim();
    if label.is_empty() {
        state.label_error = true;
        state.confirmed_label = None;
        return;
    }
    state.label_error = false;
    state.confirmed_label = Some(label.to_owned());
}

pub fn callback_registry() -> ActionRegistry<ProbeCheckState> {
    let mut registry = ActionRegistry::new();
    registry.register(reduce_with!(probe_scan_succeeded));
    registry.register(reduce_with!(probe_scan_failed));
    registry
}
```

## Run the fallback on iOS

The generated `src/lib.rs` still points at the starter counter. Replace it with the root setup below so the iOS command opens this screen, loads its translations and registers the asynchronous completion reducers. The app uses the default `UnsupportedBluetoothHost`, so the scan action returns `unsupported` and the same manual path remains available. You do not need a Bluetooth permission description for this example because it does not install a Bluetooth provider or request permission. If you add your own provider, follow its privacy requirements and add the matching Fission capability configuration before shipping.

```rust
pub mod app;
pub mod translations;

use fission::prelude::*;

#[cfg(target_os = "android")]
```
