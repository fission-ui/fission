## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-add-android-haptics-to-meaningful-actions
cd android-add-android-haptics-to-meaningful-actions
fission add-target android --project-dir .
fission add-capability haptics --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-add-android-haptics-to-meaningful-actions/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

    pub InspectionCompletion<()> {

        };
        let summary = if inspection.complete {
            cx.tr("inspection.complete")
        } else {
            cx.tr("inspection.ready")
        };

            cx.tr("inspection.reopen")
        } else {
            cx.tr("inspection.finish")
        };
    } =>
    Container(Column(gap: tokens.spacing.m, children: [
        Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
            Column(gap: tokens.spacing.xs, flex_grow: 1.0, children: [
                Text(cx.tr("inspection.site")).weight(tokens.typography.font_weight_bold),
                Text(cx.tr("inspection.work_order")).color(tokens.colors.text_secondary),
            ]),
            Badge(text: status),
        ]),
        Divider(),
        Text(cx.tr("inspection.asset")).weight(tokens.typography.font_weight_semibold),
        Text(cx.tr("inspection.summary")).color(tokens.colors.text_secondary),
        Text(summary),
        Button(
            child: Text(button_label),
            key: "complete-inspection",
            on_press: reduce { inspection.complete = !inspection.complete; },
        ),
    ]))
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)

## Send the haptic request through Fission

Keep work-order state in `GlobalState` because it may be read by other screens. The reducer marks the inspection complete synchronously, then requests an optional success haptic. The separate completion reducers update the message after the host responds.

<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

#[derive(Debug, Default, Clone, Copy, PartialEq, Eq)]
enum FeedbackState {
    #[default]
    Optional,
    Sending,
    Complete,
    Unavailable,
}

#[derive(Debug, Default, PartialEq)]
pub struct InspectionState {
    pub complete: bool,
    feedback: FeedbackState,
    haptic_error: Option<String>,
}

impl GlobalState for InspectionState {}

#[fission_reducer(CompleteInspection)]
fn complete_inspection(state: &mut InspectionState, ctx: &mut ReducerContext<InspectionState>) {
    state.complete = true;
    state.feedback = FeedbackState::Sending;
    state.haptic_error = None;

    let ok = ctx.effects.bind(HapticCompleted, reduce_with!(on_haptic_completed));
    let err = ctx.effects.bind(HapticUnavailable, reduce_with!(on_haptic_unavailable));
    ctx.effects
        .haptics()
        .notification(HapticNotificationRequest {
            kind: HapticNotificationKind::Success,
        })
        .on_ok(ok)
        .on_err(err);
}

#[fission_reducer(HapticCompleted)]
fn on_haptic_completed(state: &mut InspectionState, ctx: &mut ReducerContext<InspectionState>) {
    if ctx.input.capability_ok(HAPTIC_NOTIFICATION).is_some() {
        state.feedback = FeedbackState::Complete;
    } else {
        state.feedback = FeedbackState::Unavailable;
    }
}

#[fission_reducer(HapticUnavailable)]
fn on_haptic_unavailable(state: &mut InspectionState, ctx: &mut ReducerContext<InspectionState>) {
    state.haptic_error = ctx
        .input
        .capability_error_message(HAPTIC_NOTIFICATION)
        .map(str::to_owned);
    state.feedback = FeedbackState::Unavailable;
}

fission_component! {
    pub InspectionCompletion<InspectionState> {}
    view(_inspection, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let complete = with_reducer!(cx.build, CompleteInspection, complete_inspection);
        let feedback = if let Some(error) = &state.haptic_error {
            format!("{}: {error}", cx.tr("inspection.haptic_unavailable"))
        } else {
            match state.feedback {
                FeedbackState::Optional => cx.tr("inspection.optional"),
                FeedbackState::Sending => cx.tr("inspection.sending"),
                FeedbackState::Complete => cx.tr("inspection.haptic_complete"),
                FeedbackState::Unavailable => cx.tr("inspection.haptic_unavailable"),
            }
        };
        let status = if state.complete {
            cx.tr("inspection.done")
        } else {
            cx.tr("inspection.status_progress")
        };
    } =>
    SemanticsRegion(
        identifier: Some("inspection-completion".into()),
        label: Some(cx.tr("inspection.screen_title")),
        child: Container(Column(gap: tokens.spacing.m, children: [
            Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                Column(gap: tokens.spacing.xs, flex_grow: 1.0, children: [
                Text(cx.tr("inspection.site")).weight(tokens.typography.font_weight_bold),
                    Text(cx.tr("inspection.work_order")).color(tokens.colors.text_secondary),
                ]),
                Badge(text: status),
            ]),
            Divider(),
            Text(cx.tr("inspection.summary")),
            Button(
                child: Text(if state.complete { cx.tr("inspection.done") } else { cx.tr("inspection.action") }),
                key: "complete-inspection",
                disabled: state.complete,
                on_press: complete,
            ),
            Text(feedback).color(tokens.colors.text_secondary),
        ]))
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Verify the native request on Android

The browser preview uses an in-memory provider, not the Android vibrator. Build and launch on a supported emulator or device, then use the same action and compare the visible result with the feedback the Android host actually provides. Also check that an unavailable or denied haptic request does not undo the completed inspection.

Repeat with the feature unavailable, denied or cancelled, as applicable. Confirm the screen preserves the user’s existing data and offers the right recovery step. Use a physical device when the behavior depends on real hardware or an operating-system prompt.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. A release build checks packaging, but none of these commands proves a physical permission or hardware flow works.


### Emulator and connected-device commands

Run these emulator checks from the generated project root:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
```


For a real capability check, use an Android phone that has the required hardware and permission. Connect it with USB or Wi-Fi debugging, confirm its serial, then run the app on that device:

```sh
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
```

An emulator can exercise the UI and memory-provider outcomes; it is not evidence that physical hardware or an OS permission flow works.
