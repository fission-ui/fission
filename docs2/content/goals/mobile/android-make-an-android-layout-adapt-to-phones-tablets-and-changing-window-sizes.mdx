A tablet is not simply a larger phone, and a phone does not always have its full display available. Rotation, split-screen and a keyboard change the space the app can use. Choose a layout from that available space rather than from a list of device names.

Here, we build a recipe editor with a reading view. On a narrow screen, the editor comes first and the card follows below. With more room they sit side by side. Both arrangements edit the same draft, so changing the layout cannot create a second recipe or discard what the user typed.

## Create the Android project

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/), then prepare [an emulator](/blog/create-and-launch-a-fission-android-emulator/) or connect [a phone](/blog/run-a-fission-app-on-a-physical-android-phone/).

```sh
cargo install cargo-fission
fission init android-make-an-android-layout-adapt-to-phones-tablets-and-changing-window-sizes
cd android-make-an-android-layout-adapt-to-phones-tablets-and-changing-window-sizes
fission add-target android --project-dir .
cargo add serde_yaml
```

Keep the generated `src/main.rs`. Shared draft state, the editor, reading card and layout components have separate modules. Native and Web shells below launch the same app from the first step.

## Make the narrow layout useful first

The app starts with an empty recipe, not a demonstration work order. Inputs bind to the shared draft and the reading card observes those values. The screen is scrollable and respects safe-area insets, so adding a long recipe or opening the keyboard does not require a fixed-height card.

The draft is in `GlobalState` because both layout branches must observe the same content. A row-local draft in each branch would create two independent editors; matching their labels would not make their state shared.

use fission::prelude::*;
use crate::state::RecipeState;

fission_component! {
    pub RecipePreview<RecipeState> {}
    view(_preview, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Card(child: Column(gap: tokens.spacing.m, children: [
        Text(cx.tr("recipe.preview")).weight(tokens.typography.font_weight_semibold),
        if state.title.trim().is_empty()
            && state.ingredients.trim().is_empty()
            && state.instructions.trim().is_empty()
        {
            EmptyState(
                title: cx.tr("recipe.empty"),
                description: cx.tr("recipe.empty_help"),
            )
        } else {
            Column(gap: tokens.spacing.m, children: [
                Text(if state.title.trim().is_empty() {
                    cx.tr("recipe.untitled")
                } else { state.title.clone() }).size(tokens.typography.heading2_size),
                Text(cx.tr("recipe.ingredients")).weight(tokens.typography.font_weight_semibold),
                Text(state.ingredients.clone()),
                Text(cx.tr("recipe.instructions")).weight(tokens.typography.font_weight_semibold),
                Text(state.instructions.clone()),
            ])
        },
    ]))
}

use std::collections::HashMap;
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid checked-in translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Choose independent layouts around a design-system breakpoint

`Responsive` owns the width rule. The app does not scatter viewport comparisons through the editor and preview. The breakpoint comes from the active design system; test whether that threshold gives these two panes enough room rather than assuming it suits every design.

The identity-aware constructor builds each branch under a different retained scope. Supply component values which construct independent trees, not clones of a prebuilt `Widget`. The editor and preview implementations are still shared code; their mounted widget instances are separate.

use fission::prelude::*;
use crate::{editor::RecipeEditor, recipe_preview::RecipePreview, state::RecipeState};

fission_component! {
    pub WideRecipeLayout<RecipeState> {}
    view(_layout, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Start, children: [
        Container(child: RecipeEditor(), width: 0.0, min_width: 0.0, flex_grow: 1.0),
        Container(child: RecipePreview(), width: 0.0, min_width: 0.0, flex_grow: 1.0),
    ])
}

    pub RecipeWorkbench<RecipeState> {}

        let tokens = &cx.view.env().theme.tokens;

    SafeArea(
        child: Scroll(

                    Text(cx.tr("recipe.title")).size(tokens.typography.heading2_size),
                    Text(cx.tr("recipe.scope")),
                    Responsive::new_with_id(
                        WidgetId::explicit("recipe.layout"),
                        || WideRecipeLayout,
                    ).case_max_width_with(
                        tokens.breakpoints.medium_max,
                        || CompactRecipeLayout,
                    ),
                ]),
            ).padding_all(tokens.spacing.l),
        ),
    )
}

<!-- fission:checkpoint -->
Type a recipe, widen the window until the panes sit side by side, then make it narrow again. The same draft must remain visible. Below the maximum-width threshold the compact branch applies; at the threshold and above, the wide fallback applies.

The responsive widget constructs and lowers its branches even when only one is visible. Hidden content is not an authorisation or resource-startup boundary. Keep effects out of component conversion and use `ProtectedRoute` when access must prevent constructing a tree.

## Check width changes whilst the app is in use

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

On an emulator and a phone, rotate whilst a field is focused, open the keyboard, use a narrow split-screen window and increase Android's text size. The reading view and inputs should remain reachable without horizontal clipping. Focus and selection also need native checks; shared draft values alone do not prove those interactions survive every layout transition.

Test immediately below, at and above the chosen breakpoint, with a long Spanish label and a long recipe. A wide screenshot with short English text does not qualify the compact branch.

This example uses viewport width because it chooses the page layout. A reusable widget embedded in a narrower panel can use `Responsive::container_query()` instead. Do not select a phone layout merely because its parent happens to be an Android shell.
