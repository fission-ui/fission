## A URL has to cross two boundaries

An Android App Link first has to reach the application through Android's intent system. Only then can the application turn that external value into a Fission route. Registering a route does not configure Android, and accepting a domain in Rust does not prove the installed app owns that domain.

The current generated Android host does not complete that first boundary: it does not generate an App Links intent filter or forward cold-start and `onNewIntent` URL data into the running Fission application. Consequently, this is an integration outline with a working shared URL-to-route example, not a completed verified Android App Links tutorial. That native handoff remains an upstream requirement.

## Create the shared routing example

Complete [Android SDK/NDK setup](/blog/set-up-rust-android-gui-development-with-fission/), then use [an emulator](/blog/create-and-launch-a-fission-android-emulator/) or [a phone](/blog/run-a-fission-app-on-a-physical-android-phone/).

```sh
cargo install cargo-fission
fission init android-route-android-app-links-and-deep-links-into-fission
cd android-route-android-app-links-and-deep-links-into-fission
fission add-target android --project-dir .
cargo add serde_yaml
```

Keep the generated main entrypoint. The example uses `links.example.com` as a reserved illustrative host, not a domain verified for your app. Replace the host consistently with one you control before implementing a real integration.

## Use one route mapper for the external value

The mapper deliberately accepts only two canonical forms with a bounded ASCII identifier. It rejects query strings, fragments, escapes and additional path segments rather than pretending to be a general URL parser. If your product needs richer URLs, use an appropriate URL parser and retain explicit origin and identifier validation.

The manual inspector calls that same mapper as the registered deep-link handler. Its button is a contract exerciser, not a forged Android intent. Both paths request normal navigation, and one shell route handler updates the path read by Fission's native `Router`.

use fission::prelude::*;

#[derive(Debug)]
pub struct LinkState { pub current_path: String, pub invalid_link: bool }
impl Default for LinkState {
    fn default() -> Self { Self { current_path: "/".into(), invalid_link: false } }
}
impl GlobalState for LinkState {}

pub fn valid_document_id(value: &str) -> bool {
    !value.is_empty() && value.len() <= 64
        && value.bytes().all(|byte| byte.is_ascii_alphanumeric() || byte == b'-' || byte == b'_')
}

// This is intentionally a small, exact link grammar, not a general URL parser.
pub fn document_route(url: &str) -> Option<String> {
    let id = url.strip_prefix("https://links.example.com/documents/")
        .or_else(|| url.strip_prefix("fission://app/documents/"))?;
    valid_document_id(id).then(|| format!("/documents/{id}"))
}

pub fn open_link(state: &mut LinkState, url: &str, cx: &mut ReducerContext<LinkState>) {
    if let Some(route) = document_route(url) {
        state.invalid_link = false;
        cx.effects.navigate(route);
    } else {
        state.invalid_link = true;
    }
}

pub fn deep_link_received(
    state: &mut LinkState, action: DeepLinkReceived, cx: &mut ReducerContext<LinkState>,
) {
    open_link(state, &action.link.url, cx);
}

pub fn route_changed(
    state: &mut LinkState, action: fission::core::action::ShellRouteChanged,
    _cx: &mut ReducerContext<LinkState>,
) {
    state.current_path = action.location.pathname;
}

pub fn link_config() -> DeepLinkConfig {
    DeepLinkConfig::new().scheme("fission").domain("links.example.com")
        .path_prefix("/documents/")
}

#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn canonical_links_share_one_route_and_reject_ambiguous_identifiers() {
        assert_eq!(
            document_route("fission://app/documents/WO-1048"),
            document_route("https://links.example.com/documents/WO-1048"),
        );
        for url in [
            "https://links.example.com.evil.test/documents/WO-1048",
            "https://links.example.com@evil.test/documents/WO-1048",
            "https://links.example.com/documents/../private",
            "https://links.example.com/documents/%2fprivate",
            "https://links.example.com/documents/WO-1048?admin=true",
            "https://links.example.com/documents/",
        ] { assert!(document_route(url).is_none()); }
    }
}

use fission::prelude::*;
use crate::state::{valid_document_id, LinkState};

fission_component! {
    pub DocumentDestination<LinkState> {}
    view(_destination, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let params = fission::build::read::<RouteParams>();
        let id = params.get("id").filter(|value| valid_document_id(value));
    } =>
    SafeArea(child: Scroll(child: Container(
        Column(gap: tokens.spacing.m, children: [
            if let Some(id) = id {
                Column(gap: tokens.spacing.s, children: [
                    Text(cx.tr("links.destination")).size(tokens.typography.heading2_size),
                    Text(id.clone()),
                    Text(cx.tr("links.not_loaded")),
                ])
            } else {
                Text(cx.tr("links.invalid"))
            },
            Button(
                child: Text(cx.tr("links.back")), key: "links.back",
                on_press: reduce { cx.effects.navigate("/"); },
            ),
        ])
    ).padding_all(tokens.spacing.l)))
}

use fission::prelude::*;
use crate::{destination::DocumentDestination, inspector::LinkInspector, state::LinkState};

fission_component! {
    pub DocumentLinksApp<LinkState> {}
    view(_app, state, cx) {
        let missing = cx.tr("links.invalid");
        let router = Router::<LinkState>::new()
            .with_path(state.current_path.clone())
            .route_component("/", LinkInspector::new())
            .route_component("/documents/:id", DocumentDestination)
            .not_found(move || Text::new(missing.clone()));
    } =>
    router

## Complete and qualify the missing Android adapter

Android requires a browsable VIEW intent filter with the intended HTTP(S) host, plus website association for verified links. The website's `/.well-known/assetlinks.json` must name the real application ID and the certificate fingerprint of the installed distribution. A Rust `DeepLinkConfig` is only a runtime filter; it does not write either declaration. Follow [Android's App Links configuration](https://developer.android.com/training/app-links/add-applinks).

The native adapter must read launch-intent data, forward later `onNewIntent` data into the active runtime, and dispatch `DeepLinkReceived` through the registered handler without starting a second application. Passing a constant to `with_startup_deep_link` can test that handler, but cannot supply this OS handoff. Do not edit generated files and call it a durable project configuration.

The existing shell accepts startup links from process arguments or `FISSION_DEEP_LINK_URL`/`FISSION_DEEP_LINKS`. Those are useful controlled inputs for native testing; they are not Android intent delivery. The generated host gap must be resolved before the following OS-level checks can pass.

```sh
cargo test
fission doctor android --project-dir .
adb devices -l
fission run --target android --device <adb-serial> --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

Once a real adapter and owned-domain association exist, check domain verification on Android 12 or later with your actual package name:

```sh
adb shell pm verify-app-links --re-verify <application-id>
adb shell pm get-app-links <application-id>
adb shell am start -W -a android.intent.action.VIEW -c android.intent.category.BROWSABLE -d "https://<owned-domain>/documents/<document-id>"
```

Allow verification to complete before inspecting its result, as described in [Android's verification guide](https://developer.android.com/training/app-links/verify-applinks). Repeat from a stopped app and whilst it is already open, then test a malformed or unsupported link. Compare the route with the manual inspector, but record OS delivery and route parsing as separate results.

An accepted URL is not an access decision. A service-backed document screen must load the record through effects, show pending/not-found/error states, and independently enforce server authentication and authorisation. Use `ProtectedRoute` for the UI prerequisite before constructing protected content; never infer access from an external URL or its `source` classification.
