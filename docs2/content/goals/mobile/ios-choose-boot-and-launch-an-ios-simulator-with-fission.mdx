The iOS Simulator runs an app built for a simulator target, not the binary that will be installed on an iPhone. It is useful for checking layout, keyboard behaviour and application flow, but a successful launch does not establish that device signing or a physical sensor works.

Starting from the [Xcode setup guide](/blog/set-up-rust-ios-development-with-fission/), we will select one installed simulator by its unique device identifier (UDID), launch the app there and capture the result. Using the identifier avoids silently choosing another device when several are available.

## Create the project and add the target

Create a project and add iOS as a target. If you already have an app, run these commands from its project root instead.

```sh
cargo install cargo-fission
fission init ios-choose-boot-and-launch-an-ios-simulator-with-fission
cd ios-choose-boot-and-launch-an-ios-simulator-with-fission
cargo add serde_yaml
fission add-target ios --project-dir .
```

## Files created by Fission

This is the generated project tree. Shared app code lives in `src/`; the iOS host under `platforms/ios/` handles launch and packaging.

```text
ios-choose-boot-and-launch-an-ios-simulator-with-fission/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # Compose checklist
└── platforms/
    └── ios/                  # generated iOS host
```

The generated platform directory owns launch and packaging. The shared Rust library owns this screen and its translations.

## Keep an observable launch checklist

Use the same screen in the browser and the native app, but do not confuse those results. A browser click checks the interface; changing a checkbox on the selected native device checks that this build actually launched there. The marks record your observations, not detected toolchain status, and can be cleared if you need to repeat a check.

Replace both `src/app.rs` and `src/lib.rs` so the generated native entrypoint launches this component. Keep the language bundles in `i18n/` and the setup in `src/translations.rs`. The separate preview entrypoint is only for this documentation page.

use std::collections::HashMap;
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in setup translations");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}

## Choose and boot an iOS Simulator

List the simulator devices that Xcode can start. A device row includes a name and unique device identifier (UDID); use that identifier when more than one simulator is installed.

```sh
xcrun simctl list devices available
fission devices --project-dir .
```

If the list is empty, install an iOS Simulator runtime in Xcode's **Settings → Platforms**, then repeat the command. Fission runs iOS apps in the Simulator; `fission run --target ios` does not install an app directly onto a physical iPhone.

Choose the UDID from `fission devices`, then start the app on that simulator:

```sh
fission run --target ios --device <simulator-udid> --project-dir .
```

Fission builds and installs the app, boots the selected simulator if needed, launches it and attaches to its output. Open the Simulator app to inspect the visible result. For a screenshot, use the same UDID:

```sh
open -a Simulator --args -CurrentDeviceUDID <simulator-udid>
mkdir -p artifacts
xcrun simctl io <simulator-udid> screenshot artifacts/fission-simulator.png
```

If launch fails, compare the selected UDID with `fission devices` and check `xcode-select -p` before changing project code. The [Xcode tools tutorial](/blog/install-and-select-xcodes-ios-simulator-tools/) covers missing runtimes and an incorrect developer directory.
