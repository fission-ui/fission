## Create the project and add the target

Install the Fission command line, create the app, and add its native target.

```sh
cargo install cargo-fission
fission init android-localise-a-fission-android-app
cd android-localise-a-fission-android-app
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree after `fission init` and `fission add-target`; the component and state used for this task are additions in the steps below. Keep shared Rust behavior under `src/` and leave target launch and packaging in `platforms/android/`.

```text
android-localise-a-fission-android-app/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep `src/app.rs`, shared state, reducers and reusable `fission_component!` components in the common Rust project. Add a state, service or effect module only when this feature needs that boundary, and use a name tied to the feature. The generated Android host owns launch and packaging details; shared components describe the user task without importing Android APIs.

fission_component! {
    pub AndroidLocaleSettings<()> {
        props {
            title: String,

    view(screen, _state, cx) {

        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [

                            .weight(tokens.typography.font_weight_bold),
                        Text(screen.step.clone())

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(inline_js = "export function tutorial_title() { const parts = document.title.split(' — '); return parts.slice(1).join(' — ') || 'Fission tutorial'; } export function tutorial_step() { return document.title.split(' — ')[0] || 'Tutorial step'; } export function tutorial_goal() { return document.querySelector('meta[name=\"tutorial-goal\"]')?.content || 'Complete the task and verify it on the target.'; }")]

    fn tutorial_title() -> String;
    fn tutorial_step() -> String;
    fn tutorial_goal() -> String;

    console_error_panic_hook::set_once();
    let preview = app::AndroidLocaleSettings::new(tutorial_title(), tutorial_step(), tutorial_goal());
    WebApp::<(), _>::new(preview)
        .with_title("Fission tutorial preview")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}

## Localise a Fission Android app

Keep user-facing strings in checked-in translation files and use stable keys based on meaning, not screen position. Include English and Spanish from the start, parse both bundles into TranslationBundle values, and install them in Env. If the user can switch language, store Locale in GlobalState and mirror it through with_sync_env. Test a long button label, validation message and empty-state message; short English labels alone will not reveal clipping or layout problems. Native locale settings and the in-app language selector should both resolve to a supported bundle.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

fission_component! {
    pub AndroidProject<()> {
        props {
            title: String,
            step: String,
            goal: String,
        }
        state {
            spanish: bool = false,
        }
    }
    view(screen, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("localised-settings".to_string()),
        label: Some(screen.title.clone()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(screen.title.clone())

                    .weight(tokens.typography.font_weight_bold),
                Text(if screen.spanish { "Configuración" } else { "Settings" }),
                Text(screen.goal.clone()),
                Button(
                    child: Text(if screen.spanish { "Cambiar a inglés" } else { "Cambiar a español" }),
                    key: "toggle-language",
                    on_press: reduce { screen.spanish = !screen.spanish; },
                ),
                Text(if screen.spanish { "Idioma de la vista previa: español" } else { "Preview language: English" })
                    .color(tokens.colors.text_secondary),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

## Check translated text on Android

Switch between the configured languages and read every screen in the task. Long translations should wrap without hiding buttons, field errors or status messages; user-visible strings should come from translation keys rather than hard-coded component text.

Check the largest supported text size as well. Keep labels and actions understandable when they wrap to multiple lines, and verify that changing the locale updates the active Fission environment.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. A release build checks packaging, but none of these commands proves a physical permission or hardware flow works.
