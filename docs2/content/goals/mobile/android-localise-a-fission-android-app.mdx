## Create the project and add the target

Create the project and add the target used by this guide. Fission generates the native host; the app and its behaviour stay in shared Rust code.

```sh
cargo install cargo-fission
fission init android-localise-a-fission-android-app
cd android-localise-a-fission-android-app
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree Fission generates. Keep shared app code in `src/`; the generated platform files handle native launch and packaging.

```text
android-localise-a-fission-android-app/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep the screen, shared state, reducers and reusable `fission_component!` components in the Rust project. Add a feature-specific state, service or effect module only when it gives the feature a useful boundary. The generated platform files handle native launch and packaging; shared components do not need to import platform APIs.

## Create the app screen

Start with a settings screen that can show the active locale. Then move its labels into translation bundles and add a second language.

```rust
use fission::prelude::*;
use fission::i18n::Locale;

#[derive(Debug)]
pub struct PreviewState {
    pub locale: Locale,
}

impl Default for PreviewState {
    fn default() -> Self {
        Self { locale: Locale::from("en-US") }
    }
}

impl GlobalState for PreviewState {}

fission_component! {
    pub AndroidProject<PreviewState>
    view(_screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("language-settings".to_string()),
        label: Some(cx.tr("settings.title")),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("settings.title"))
                    .weight(tokens.typography.font_weight_bold)
                    .size(tokens.typography.heading2_size),
                Text(cx.tr("settings.description"))
                    .color(tokens.colors.text_secondary),
                Divider(),
                Text(cx.tr("settings.current-locale"))
                    .color(tokens.colors.text_secondary),
                Text(state.locale.0.clone())
                    .weight(tokens.typography.font_weight_semibold),
                Column(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("settings.english")),
                        key: "select-english",
                        variant: ButtonVariant::Outline,
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("settings.spanish")),
                        key: "select-spanish",
                        variant: ButtonVariant::Outline,
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                Container(
                    Text(cx.tr("settings.long-label"))
                        .color(tokens.colors.text_secondary)
                )
                .padding_all(tokens.spacing.m)
                .bg(tokens.colors.background)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.medium),
            ])
        )
        .padding_all(tokens.spacing.l)
        .bg(tokens.colors.surface)
        .border(tokens.colors.border, 1.0)
        .border_radius(tokens.radii.large),
    )
}
```

```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

fn load_bundle(locale: &str, source: &str) -> TranslationBundle {
    TranslationBundle {
        locale: Locale::from(locale),
        messages: serde_yaml::from_str(source).expect("valid tutorial translations"),
    }
}

fn preview_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    env.i18n
        .add_bundle(load_bundle("en-US", include_str!("i18n/en-US.yaml")));
    env.i18n
        .add_bundle(load_bundle("es-ES", include_str!("i18n/es-ES.yaml")));
    env
}

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    WebApp::<app::PreviewState, _>::new(app::AndroidProject)
        .with_env(preview_env())
        .with_sync_env(|state, env| { env.locale = state.locale.clone(); })
        .with_title("Northbank Service Desk · Android")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Localise a Fission Android app

Keep user-facing strings in checked-in translation files and use stable keys based on meaning, not screen position. Include English and Spanish from the start, parse both bundles into TranslationBundle values, and install them in Env. If the user can switch language, store Locale in GlobalState and mirror it through with_sync_env. Test a long button label, validation message and empty-state message; short English labels alone will not reveal clipping or layout problems. Native locale settings and the in-app language selector should both resolve to a supported bundle.

The component below is a browser-safe version of this screen. It uses Fission's retained component state and widgets to make the task visible; it does not call a native provider or operating-system API.

## Check translated text on Android

Switch between the configured languages and read every screen in the task. Long translations should wrap without hiding buttons, field errors or status messages; user-visible strings should come from translation keys rather than hard-coded component text.

Check the largest supported text size as well. Keep labels and actions understandable when they wrap to multiple lines, and verify that changing the locale updates the active Fission environment.

### Run, test and build

```sh
cargo test
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. A release build checks packaging, but none of these commands proves a physical permission or hardware flow works.
