**Status: blocked — a real NFC read on iOS is not implemented by this tutorial.** The normal iOS shell registers `UnsupportedNfcHost`; adding an entitlement does not supply a Core NFC provider.

A fabricated tag would let us demonstrate a result card, but it would hide the part this tutorial promises to teach. Instead, the small app below queries the actual host's read support. It reports unsupported capability without pretending that a label, serial number or NDEF record came from an iPhone.

## Create a diagnostic project, not a simulated feature

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) first. These commands declare the capability and generate platform inputs; they do not remove the native provider gap.

```sh
cargo install cargo-fission
fission init ios-read-nfc-tags-on-ios
cd ios-read-nfc-tags-on-ios
fission add-target ios --project-dir .
fission add-capability nfc --project-dir .
cargo add serde_yaml
```

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct NfcDiagnosticState {
    pub locale: Locale,
    pub pending: bool,
    pub message_key: String,
    pub diagnostic: Option<String>,
}
impl Default for NfcDiagnosticState {
    fn default() -> Self {
        Self {
            locale: Locale::from("en-US"),
            pending: false,
            message_key: "check.ready".into(),
            diagnostic: None,
        }
    }
}
impl GlobalState for NfcDiagnosticState {}

pub fn check_host(state: &mut NfcDiagnosticState, cx: &mut ReducerContext<NfcDiagnosticState>) {
    if state.pending {
        return;
    }
    state.pending = true;
    state.message_key = "check.pending".into();
    state.diagnostic = None;
    let ok = cx.effects.bind(HostChecked, reduce_with!(host_checked));
    let err = cx
        .effects
        .bind(HostCheckFailed, reduce_with!(host_check_failed));
    cx.effects.nfc().availability().on_ok(ok).on_err(err);
}

#[fission_reducer(HostChecked)]
fn host_checked(state: &mut NfcDiagnosticState, cx: &mut ReducerContext<NfcDiagnosticState>) {
    state.pending = false;
    match cx.input.capability_ok(GET_NFC_AVAILABILITY) {
        Some(value) => {
            state.message_key = if value.supported && value.read {
                "check.available"
            } else {
                "check.unavailable"
            }
            .into();
            state.diagnostic = Some(format!("{value:?}"));
        }
        None => state.message_key = "check.invalid".into(),
    }
}

#[fission_reducer(HostCheckFailed)]
fn host_check_failed(state: &mut NfcDiagnosticState, cx: &mut ReducerContext<NfcDiagnosticState>) {
    state.pending = false;
    match cx.input.capability_error(GET_NFC_AVAILABILITY) {
        Some(error) => {
            state.message_key = if error.code == "unsupported" {
                "check.unavailable"
            } else {
                "check.failed"
            }
            .into();
            state.diagnostic = Some(format!("{}: {}", error.code, error.message));
        }
        None => state.message_key = "check.invalid".into(),
    }
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid task translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::NfcDiagnosticState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Keep the missing integration visible

`GET_NFC_AVAILABILITY` returns the active provider's support flags. The default iOS provider returns all flags false; its scan operation returns a typed unsupported error. An availability query succeeding therefore does not mean NFC reading is available.

The generated NFC capability configuration includes `NFCReaderUsageDescription` and the NDEF reader entitlement. Those are necessary platform inputs, not evidence of a running Core NFC scan session. Keep the purpose description accurate and inspect the final signed entitlements when a real provider is added.

Finishing this goal requires the native scan-session integration, normal bound completion actions which decode the real `NfcTag`, and physical-device verification of cancellation, timeout, unsupported tags and valid NDEF data. No tag should authorize access merely because its readable identifier matches a string.

## What still has to be established

On macOS, launch the actual generated iOS host:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

These commands can check setup and launch. They cannot certify a missing provider. Follow [physical iPhone installation](/blog/install-a-fission-app-on-a-physical-iphone/) when the real native integration is available.

Use compatible physical hardware for a real scan. Confirm the native prompt, hold a known tag near the reader and inspect the bytes returned by the actual provider. A simulator, browser support flag or memory-provider result cannot establish that behaviour. The original native goal remains open until these checks are possible.
