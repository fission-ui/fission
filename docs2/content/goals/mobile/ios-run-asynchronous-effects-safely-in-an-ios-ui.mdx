## Create the project and add the target

Install the Fission command line, create the app, and add its native target.

```sh
cargo install cargo-fission
fission init ios-run-asynchronous-effects-safely-in-an-ios-ui
cd ios-run-asynchronous-effects-safely-in-an-ios-ui
fission add-target ios --project-dir .
```

## Run asynchronous effects safely in an iOS UI

Store an ID with each request so the reducer can tell whether a result still belongs to the screen. While the effect runs, show a pending state and keep existing data visible. When it finishes, dispatch a typed success or failure action; offer retry after an error, and offer cancel only if the service can actually cancel. To test the race, make two requests and have a fake service return the newer result first. The older result must not replace it, even if it arrives after navigation. Effects run outside the reducer, so never block the UI thread with sleep, file access, SQL or network work.

## Check delayed and interrupted work on iOS

In a Rust test, a fake service returns the result you choose instead of making a network request. Start two requests, return the newer result first, and then return the older one. Because the app stores the newest request ID, the reducer should ignore that stale response and keep the newer result on screen.

Also background the app while work is pending, then return to it. The loading state should finish or recover, errors should remain visible, and a retry should not require the user to repeat work that was already saved.

### Run, test and build

```sh
cargo test
fission doctor ios --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
fission build --target ios --project-dir . --release
```

`cargo test` runs Rust tests you add; the generated scaffold does not create feature-specific tests. `fission doctor` reports missing Xcode, simulator SDK or Rust targets, `fission run` launches an iOS Simulator, and `fission test` checks that the generated host can start. A release build checks the simulator package; it does not verify iPhone signing or physical-device behavior.


### Simulator and device commands

Fission’s run command discovers iOS simulators. Run these checks from the generated project root:

```sh
fission doctor ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```
