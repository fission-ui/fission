At Northbank Food Hub, Ada is inspecting **compressor bank A7** before the evening delivery window. The access panel is cracked near its lower hinge. The next technician needs a clear photo and a short note explaining why the compressor must remain isolated until the guard is replaced.

We will build that work order screen rather than a button that merely says “photo captured.” A reference schematic identifies the compressor; the evidence area stays empty until the camera returns a real image. In the Android app, Fission requests camera permission and then captures through the native provider. In a browser that supports `getUserMedia`, the same preview asks the browser for access to its actual camera. When a camera or flashlight is unavailable, the report remains available and the screen explains what can still be done.

The photo is kept as a Fission data stream while the app reads it for display. The note and photo stay in app memory for this tutorial session; this example does not persist or upload them. A production service would store the report and stream separately.

## Create the Android work-order app

Create the shared Rust project, add Android, and declare the camera capability. Fission uses that declaration when generating the Android camera permission configuration. The app code below stays in the shared crate, so the same report screen can run in the browser preview and on Android.

## Build the work order and capture real photo evidence

The browser preview starts with one example work order so there is a useful task on screen. That record is seeded only in the preview; a real Android app should open a work order from its queue or service. On startup, the app asks the host which camera features are available. It only shows a flashlight control when a camera reports a torch, so the browser preview does not offer a hardware action it cannot perform. **Capture site photo** requests camera permission and calls `capture_photo` only after the host returns `Granted`.

The app state keeps the current note, photo bytes, capability availability, and pending operations together because they all belong to this open work order. A startup action checks camera availability without blocking the first screen. The camera returns a stream id rather than a large byte vector. A registered job reads the stream asynchronously, then the evidence component renders those actual bytes with `Image::memory`.

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct EvidenceBytesRequest {
    pub stream: DataStreamId,
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct EvidenceBytes {
    pub bytes: Vec<u8>,
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct EvidenceReadError {
    pub message: String,
}

#[derive(Debug)]
pub struct ReadEvidenceBytesJob;

impl JobSpec for ReadEvidenceBytesJob {
    type Request = EvidenceBytesRequest;
    type Ok = EvidenceBytes;
    type Err = EvidenceReadError;

    const NAME: &'static str = "northbank.work-order.read-evidence";
}

pub const READ_EVIDENCE_BYTES_JOB: JobRef<ReadEvidenceBytesJob> =
    JobRef::new(ReadEvidenceBytesJob::NAME);

pub async fn read_evidence_bytes(
    request: EvidenceBytesRequest,
    ctx: JobCtx,
) -> Result<EvidenceBytes, EvidenceReadError> {
    let stream = ctx.open_data_stream(request.stream).map_err(|error| EvidenceReadError {
        message: error.to_string(),
    })?;
    let bytes = collect_data_stream(stream).await.map_err(|error| EvidenceReadError {
        message: error.to_string(),
    })?;
    Ok(EvidenceBytes { bytes: bytes.to_vec() })
}

#[fission_reducer(InspectionNoteChanged)]

#[fission_reducer(CaptureEvidencePhoto)]
pub fn on_capture_evidence_photo(
    state: &mut WorkOrderReportState,
    reason: String,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    if state.photo_pending || state.flashlight_pending {
        return;
    }
    if state.work_order.is_none() {
        state.error = Some(ReportIssue::WorkOrderMissing);
        state.notice = None;
        return;
    }
    state.photo_pending = true;
    state.error = None;
    state.notice = Some(ReportNotice::CheckingCamera);
    let on_ok = ctx.effects.bind(CameraPermissionReceived, reduce_with!(on_camera_permission_received));
    let on_err = ctx.effects.bind(CameraPermissionFailed, reduce_with!(on_camera_permission_failed));
    ctx.effects
        .camera()
        .request_permission(CameraPermissionRequest {
            reason: Some(reason),
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

fn queue_photo_capture(
    state: &mut WorkOrderReportState,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    state.notice = Some(ReportNotice::OpeningCamera);
    let on_ok = ctx.effects.bind(PhotoCaptureCompleted, reduce_with!(on_photo_capture_completed));
    let on_err = ctx.effects.bind(PhotoCaptureFailed, reduce_with!(on_photo_capture_failed));
    ctx.effects
        .camera()
        .capture_photo(CameraCaptureRequest {
            camera_id: None,
            facing: CameraFacing::Back,
            resolution: Some(CameraResolution { width: 1600, height: 1200 }),
            format: CameraImageFormat::Jpeg,
            flash: CameraFlashMode::Auto,
            quality: Some(86),
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(CameraPermissionReceived)]
pub fn on_camera_permission_received(
    state: &mut WorkOrderReportState,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    let Some(permission) = ctx.input.capability_ok(REQUEST_CAMERA_PERMISSION) else {
        state.photo_pending = false;
        state.notice = None;
        state.error = Some(ReportIssue::PermissionResultMissing);
        return;
    };
    match permission {
        CameraPermission::Granted => queue_photo_capture(state, ctx),
        CameraPermission::Denied | CameraPermission::Restricted => {
            state.photo_pending = false;
            state.notice = None;
            state.error = Some(ReportIssue::PermissionDenied);
        }
        CameraPermission::Unknown => {
            state.photo_pending = false;
            state.notice = None;
            state.error = Some(ReportIssue::PermissionUnknown);
        }
    }
}

#[fission_reducer(CameraPermissionFailed)]
pub fn on_camera_permission_failed(
    state: &mut WorkOrderReportState,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    state.photo_pending = false;
    state.notice = None;
    let Some(error) = ctx.input.capability_error(REQUEST_CAMERA_PERMISSION) else {
        state.error = Some(ReportIssue::PermissionRequestFailed);
        return;
    };
    state.error = Some(match error.code.as_str() {
        "permission_denied" | "notallowederror" => ReportIssue::PermissionDenied,
        "unsupported" | "unavailable" | "notfounderror" => ReportIssue::CameraUnavailable,
        "notreadableerror" => ReportIssue::CameraInUse,
        _ => ReportIssue::PermissionRequestFailed,
    });
}

#[fission_reducer(PhotoCaptureCompleted)]
pub fn on_photo_capture_completed(
    state: &mut WorkOrderReportState,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    state.photo_pending = false;
    let Some(capture) = ctx.input.capability_ok(CAPTURE_PHOTO) else {
        state.notice = None;
        state.error = Some(ReportIssue::CaptureResultMissing);
        return;
    };
    state.photo_details = Some(PhotoDetails {
        width: capture.width,
        height: capture.height,
        content_type: capture.content_type.clone(),
        kibibytes: capture.byte_len.map(|bytes| bytes / 1024),
    });
    state.photo_bytes = None;
    state.error = None;
    state.notice = Some(ReportNotice::PhotoCaptured);
    let on_ok = ctx.effects.bind(PhotoBytesLoaded, reduce_with!(on_photo_bytes_loaded));
    let on_err = ctx.effects.bind(PhotoBytesFailed, reduce_with!(on_photo_bytes_failed));
    ctx.effects
        .app(READ_EVIDENCE_BYTES_JOB, EvidenceBytesRequest { stream: capture.stream })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(PhotoCaptureFailed)]
pub fn on_photo_capture_failed(
    state: &mut WorkOrderReportState,
    ctx: &mut ReducerContext<WorkOrderReportState>,

    state.photo_pending = false;
    state.notice = None;

#[fission_reducer(PhotoBytesLoaded)]
pub fn on_photo_bytes_loaded(
    state: &mut WorkOrderReportState,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    if let Some(evidence) = ctx.input.job_ok(READ_EVIDENCE_BYTES_JOB) {

        state.error = None;
        state.notice = Some(ReportNotice::PhotoAttached);

#[fission_reducer(PhotoBytesFailed)]
pub fn on_photo_bytes_failed(
    state: &mut WorkOrderReportState,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    let _ = ctx.input.job_err(READ_EVIDENCE_BYTES_JOB);

#[fission_reducer(SetFlashlight)]
pub fn on_set_flashlight(
    state: &mut WorkOrderReportState,
    enabled: bool,
    reason: String,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    if state.photo_pending || state.flashlight_pending {
        return;
    }
    state.flashlight_pending = true;
    state.error = None;
    state.notice = Some(ReportNotice::CheckingFlashlight(enabled));
    let on_ok = ctx.effects.bind(FlashlightPermissionReceived(enabled), reduce_with!(on_flashlight_permission_received));
    let on_err = ctx.effects.bind(FlashlightPermissionFailed(enabled), reduce_with!(on_flashlight_permission_failed));
    ctx.effects
        .camera()
        .request_permission(CameraPermissionRequest {
            reason: Some(reason),
        })
        .on_ok(on_ok)
        .on_err(on_err);
}

#[fission_reducer(FlashlightPermissionReceived)]
pub fn on_flashlight_permission_received(
    state: &mut WorkOrderReportState,
    enabled: bool,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    let Some(permission) = ctx.input.capability_ok(REQUEST_CAMERA_PERMISSION) else {
        state.flashlight_pending = false;
        state.notice = None;
        state.error = Some(ReportIssue::FlashlightPermissionResultMissing);
        return;
    };
    match permission {
        CameraPermission::Granted => queue_flashlight_change(state, enabled, ctx),
        CameraPermission::Denied | CameraPermission::Restricted | CameraPermission::Unknown => {
            state.flashlight_pending = false;
            state.notice = None;
            state.error = Some(ReportIssue::FlashlightPermissionDenied);
        }
    }
}

fn queue_flashlight_change(
    state: &mut WorkOrderReportState,
    enabled: bool,
    ctx: &mut ReducerContext<WorkOrderReportState>,
) {
    let on_ok = ctx.effects.bind(FlashlightChanged(enabled), reduce_with!(on_flashlight_changed));
    let on_err = ctx.effects.bind(FlashlightFailed(enabled), reduce_with!(on_flashlight_failed));
    ctx.effects
        .camera()
        .set_flashlight(CameraFlashlightRequest {
            camera_id: None,
            enabled,
            intensity: Some(if enabled { 75 } else { 0 }),
        })
        .on_ok(on_ok)
        .on_err(on_err);
    state.notice = Some(ReportNotice::ChangingFlashlight(enabled));
}

## Test permission, capture, and flashlight on Android

A browser preview checks the shared Fission reducers against the browser camera provider. It cannot prove that Android has a camera, that the OS permission is configured correctly, or that a physical flashlight is available. Test the installed app on an Android emulator for layout and permission behavior, then use a physical device for the actual camera and torch.

In an app that supplies an assigned work order, wait for the availability check and capture the damaged panel. Confirm that the real photo appears before wiring persistence; this sample does not save it. Deny camera access and repeat: the report note should remain, no photo should be counted, and the screen should explain how to recover. Cancel a capture if the system UI offers cancellation. On hardware without a torch, confirm no flashlight action is shown while photo evidence remains available.

The example stores its note and current photo bytes in app state for the duration of this tutorial session. A production work-order system should persist the note and stream, associate them with the authenticated technician, and submit them to an authorized service. Keep that network request in an asynchronous effect or job; do not mark the work order submitted just because a local camera capture succeeded.
