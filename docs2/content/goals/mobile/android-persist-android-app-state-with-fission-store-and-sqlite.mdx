A default preference and a saved preference can contain the same value, but they do not mean the same thing. Before storage responds, the app does not know what was saved. After an error, it still does not know. Treating either case as a successful load risks overwriting the user's choice.

Here, an engineer chooses whether inspection fields show explanatory guidance. We load that choice once at startup, let the user change a draft, and only say **Saved** after Store acknowledges the write. The screen uses the same reducers on Android and Web; neither entrypoint installs an in-memory provider.

## Create the project and enable storage

Complete [Android SDK and NDK setup](/blog/set-up-rust-android-gui-development-with-fission/) and either [create an emulator](/blog/create-and-launch-a-fission-android-emulator/) or [connect a phone](/blog/run-a-fission-app-on-a-physical-android-phone/) first.

```sh
fission init android-persist-android-app-state-with-fission-store-and-sqlite
cd android-persist-android-app-state-with-fission-store-and-sqlite
fission add-target android --project-dir .
fission add-capability storage --project-dir .
cargo add serde --features derive
cargo add serde_yaml
```

Use the capability command rather than adding only a Cargo feature. It configures the native SQLite provider and the Web worker, bridge and SQLite WASM assets. Web also requires `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`. Without those assets and headers, the correct result is a visible storage error, not a fabricated successful load.

Keep the generated `src/main.rs`. The replacement `src/lib.rs` starts the real preferences screen and dispatches its hydration action after reducer registration.

## Load once and distinguish absence from failure

The typed `StoreKey<Preferences>` has an intentional namespace. We first ask whether it exists because absence is normal on the first run. Only a successful **not present** result selects the default. A decode failure, provider error or missing completion remains an error.

Editing stays unavailable whilst hydration is pending or failed. That prevents an apparently editable default from replacing a preference we have not successfully loaded.

use fission::prelude::*;
use serde::{Deserialize, Serialize};

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub struct Preferences { pub show_help: bool }
impl Default for Preferences {
    fn default() -> Self { Self { show_help: true } }
}

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum Phase { #[default] Idle, Loading, Ready, Saving, Failed }

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct PreferencesState {
    pub draft: Preferences,
    pub saved: Option<Preferences>,
    pub phase: Phase,
    pub error: Option<String>,
    pending: Option<Preferences>,
}
impl GlobalState for PreferencesState {}

fn preferences_key() -> StoreKey<Preferences> {
    StoreKey::new("tutorial.android.inspection", "preferences")
}

#[fission_reducer(HydratePreferences)]
pub fn hydrate_preferences(
    state: &mut PreferencesState,
    cx: &mut ReducerContext<PreferencesState>,
) {
    if !matches!(state.phase, Phase::Idle | Phase::Failed) { return; }
    state.phase = Phase::Loading;
    state.error = None;
    let ok = cx.effects.bind(PreferencesExist, reduce_with!(preferences_exist));
    let err = cx.effects.bind(PreferencesLoadFailed, reduce_with!(preferences_load_failed));
    cx.effects.store().contains(preferences_key()).on_ok(ok).on_err(err);
}

#[fission_reducer(PreferencesExist)]
fn preferences_exist(state: &mut PreferencesState, cx: &mut ReducerContext<PreferencesState>) {
    match cx.input.store_contains() {
        Some(false) => {
            state.draft = Preferences::default();
            state.saved = None;
            state.phase = Phase::Ready;
        }
        Some(true) => {
            let ok = cx.effects.bind(PreferencesLoaded, reduce_with!(preferences_loaded));
            let err = cx.effects.bind(PreferencesLoadFailed, reduce_with!(preferences_load_failed));
            cx.effects.store().get(preferences_key()).on_ok(ok).on_err(err);
        }
        None => {
            state.phase = Phase::Failed;
            state.error = Some("Store returned no contains result".into());
        }
    }
}

#[fission_reducer(PreferencesLoaded)]
fn preferences_loaded(state: &mut PreferencesState, cx: &mut ReducerContext<PreferencesState>) {
    match cx.input.store_value::<Preferences>() {
        Some(Ok(preferences)) => {
            state.draft = preferences.clone();
            state.saved = Some(preferences);
            state.phase = Phase::Ready;
        }
        Some(Err(error)) => {
            state.phase = Phase::Failed;
            state.error = Some(error.to_string());
        }
        None => {
            state.phase = Phase::Failed;
            state.error = Some("Store returned no preference value".into());
        }
    }
}

#[fission_reducer(PreferencesLoadFailed)]
fn preferences_load_failed(state: &mut PreferencesState, cx: &mut ReducerContext<PreferencesState>) {
    state.phase = Phase::Failed;
    state.error = Some(cx.input.store_error()
        .map(|error| error.to_string())
        .unwrap_or_else(|| "Store returned no failure details".into()));
}

#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn startup_does_not_claim_the_default_was_loaded_or_saved() {
        let state = PreferencesState::default();
        assert_eq!(state.phase, Phase::Idle);
        assert!(state.saved.is_none());
    }
}

## Save an owned snapshot and wait for acknowledgement

The write serialises a snapshot of the current draft. The pending snapshot is separate from the last acknowledged value, so an error cannot turn an unsaved edit into **Saved**. The switch is disabled while this small operation is pending; callbacks still record the exact snapshot that was sent.

Serialization can fail before the request is queued. The reducer handles that result as well as the asynchronous provider error. Completion actions are unit routing actions: the reducers decode the actual Store result from `cx.input`, not a placeholder action payload.

    use super::*;

pub fn save_preferences(state: &mut PreferencesState, cx: &mut ReducerContext<PreferencesState>) {
    if state.phase != Phase::Ready { return; }
    let snapshot = state.draft.clone();
    state.pending = Some(snapshot.clone());
    state.phase = Phase::Saving;
    state.error = None;
    let ok = cx.effects.bind(PreferencesSaved, reduce_with!(preferences_saved));
    let err = cx.effects.bind(PreferencesSaveFailed, reduce_with!(preferences_save_failed));
    match cx.effects.store().set(preferences_key(), &snapshot) {
        Ok(effect) => { effect.on_ok(ok).on_err(err); }
        Err(error) => {
            state.pending = None;
            state.phase = Phase::Ready;
            state.error = Some(error.to_string());
        }
    }
}

#[fission_reducer(PreferencesSaved)]
fn preferences_saved(state: &mut PreferencesState, cx: &mut ReducerContext<PreferencesState>) {
    state.phase = Phase::Ready;
    if cx.input.capability_ok(STORE_SET).is_some() {
        if let Some(saved) = state.pending.take() { state.saved = Some(saved); }
    } else {
        state.pending = None;
        state.error = Some("Store returned no save acknowledgement".into());
    }
}

#[fission_reducer(PreferencesSaveFailed)]
fn preferences_save_failed(state: &mut PreferencesState, cx: &mut ReducerContext<PreferencesState>) {
    state.phase = Phase::Ready;
    state.pending = None;
    state.error = Some(cx.input.store_error()
        .map(|error| error.to_string())
        .unwrap_or_else(|| "Store returned no failure details".into()));
}

## Verify persistence on Android

Run the app, save a change and close it completely. Reopen it without a network connection. The loading state should resolve to the acknowledged value, not briefly present the default as current.

```sh
cargo test
fission doctor android --project-dir .
fission devices --project-dir .
fission run --target android --device <device-id> --project-dir .
fission test --target android --project-dir .
fission build --target android --project-dir . --release
```

Check a fresh database and a storage failure separately. During a failed save, the last acknowledged value must stay unchanged and the draft must remain available for retry. During a failed load, editing must stay blocked until the stored value or its absence is known.

The default scope is application-wide, which is appropriate for this device preference. Use a typed user or session scope when ownership changes rather than hiding that ownership in a string prefix. A value-store preference does not need an application SQL migration; relational schemas and transactions are separate APIs.

This example serialises its own operations. An app allowing concurrent loads or edits needs an operation or generation ID so a stale completion cannot replace newer state. Adding that machinery to this single-operation screen would not make it more correct.
