A dashboard can look convincing whilst its totals describe different data. That is particularly easy when each card and chart starts with a separate sample array. Here, we take the opposite approach: one imported order report supplies the queue, metrics and completed-pick trend.

The warehouse lead can paste a real reporting snapshot, identify overdue work and compare seven or thirty days. The app does not claim to contact a warehouse service or persist that report. Both native and Web start empty and use the same import path.

## Create the project and add the target

Complete [Android SDK and NDK setup](/blog/set-up-rust-android-gui-development-with-fission/) and either [create an emulator](/blog/create-and-launch-a-fission-android-emulator/) or [connect a phone](/blog/run-a-fission-app-on-a-physical-android-phone/) first.

```sh

cd android-build-an-android-dashboard-with-fission-charts
fission add-target android --project-dir .
cargo add fission@0.16.0 --features charts

```

## Give the warehouse team an operations home

At 8:30 each morning, the warehouse lead needs three answers before opening an order: how much work is waiting, are shipments leaving on time, and which orders need a closer look? We will build that screen for Harbour Supply, a small outdoor retailer. The report is supplied by the user and held in memory. We do not seed a different dataset into the Web preview or invent unrelated metrics.

Start with the decisions the screen supports. The metric cards summarise today's workload and the review queue names the orders that need action. In the next step, a chart adds the trend behind those totals; the summary stays visible so a reader does not have to estimate the answer from bar heights.

Paste tab-separated rows with four columns: reference, customer, days ago (0–29), and one machine status: `picking`, `overdue`, `picked_on_time` or `picked_late`. For completed rows, days ago is the completion day; for outstanding rows, it is the reporting day. This is a reporting snapshot, not a continuously advancing calendar. The parser rejects duplicates and malformed rows as one import, retaining the previous good report.

use std::collections::HashSet;
use fission::prelude::*;

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum ReportStatus { Picking, Overdue, PickedOnTime, PickedLate }

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ReportOrder {
    pub reference: String,
    pub customer: String,
    pub days_ago: u8,
    pub status: ReportStatus,
}

impl ReportOrder {
    pub fn completed(&self) -> bool {
        matches!(self.status, ReportStatus::PickedOnTime | ReportStatus::PickedLate)
    }
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ImportError { pub line: usize }

pub fn parse_report(source: &str) -> Result<Vec<ReportOrder>, ImportError> {
    let mut references = HashSet::new();
    let mut records = Vec::new();
    for (index, line) in source.lines().enumerate() {
        if line.trim().is_empty() { continue; }
        let invalid = || ImportError { line: index + 1 };
        let fields: Vec<_> = line.split('\t').map(str::trim).collect();
        if fields.len() != 4 || fields[0].is_empty() || fields[1].is_empty() {
            return Err(invalid());
        }
        if !references.insert(fields[0].to_owned()) { return Err(invalid()); }
        let days_ago: u8 = fields[2].parse().map_err(|_| invalid())?;
        if days_ago >= 30 { return Err(invalid()); }
        let status = match fields[3] {
            "picking" => ReportStatus::Picking,
            "overdue" => ReportStatus::Overdue,
            "picked_on_time" => ReportStatus::PickedOnTime,
            "picked_late" => ReportStatus::PickedLate,
            _ => return Err(invalid()),
        };
        records.push(ReportOrder {
            reference: fields[0].to_owned(),
            customer: fields[1].to_owned(),
            days_ago,
            status,
        });
    }
    if records.is_empty() { return Err(ImportError { line: 1 }); }
    Ok(records)
}

#[derive(Clone, Debug, PartialEq)]
pub struct OperationsDashboardState {
    pub locale: Locale,
    pub records: Option<Vec<ReportOrder>>,
}
impl Default for OperationsDashboardState {
    fn default() -> Self {
        Self { locale: Locale::from("en-US"), records: None }
    }
}
impl GlobalState for OperationsDashboardState {}

pub struct OperationsData {
    pub orders_today: usize,
    pub need_picking: usize,
    pub on_time_dispatch_percent: Option<u32>,
    pub overdue_orders: usize,
    pub picks_7_days: Vec<f32>,
    pub picks_30_days: Vec<f32>,
    pub review_queue: Vec<ReportOrder>,
}

impl OperationsData {
    pub fn from_records(records: &[ReportOrder]) -> Self {
        let completed = records.iter().filter(|order| order.completed()).count();
        let on_time = records.iter()
            .filter(|order| order.status == ReportStatus::PickedOnTime).count();
        let mut picks_7_days = vec![0.0; 7];
        let mut picks_30_days = vec![0.0; 4];
        for order in records.iter().filter(|order| order.completed()) {
            if order.days_ago < 7 { picks_7_days[6 - usize::from(order.days_ago)] += 1.0; }
            // Oldest bucket includes days 21–29, rather than dropping two days.
            let bucket = match order.days_ago { 0..=6 => 3, 7..=13 => 2, 14..=20 => 1, _ => 0 };
            picks_30_days[bucket] += 1.0;
        }
        let mut review_queue: Vec<_> = records.iter()
            .filter(|order| !order.completed()).cloned().collect();
        review_queue.sort_by_key(|order| order.status != ReportStatus::Overdue);
        Self {
            orders_today: records.iter().filter(|order| order.days_ago == 0).count(),
            need_picking: records.iter()
                .filter(|order| order.days_ago == 0 && !order.completed()).count(),
            on_time_dispatch_percent: (completed > 0)
                .then(|| (100 * on_time / completed) as u32),
            overdue_orders: records.iter()
                .filter(|order| order.status == ReportStatus::Overdue).count(),
            picks_7_days,
            picks_30_days,
            review_queue,
        }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn rejects_duplicates_without_replacing_previous_records() {
        assert_eq!(parse_report("A\tMaya\t0\tpicking\nA\tElliot\t1\toverdue")
            .unwrap_err().line, 2);
    }

    #[test]
    fn thirty_day_summary_keeps_oldest_days_and_does_not_invent_dispatch_rate() {
        let records = parse_report("A\tMaya\t29\tpicked_on_time\nB\tElliot\t0\toverdue").unwrap();
        let summary = OperationsData::from_records(&records);
        assert_eq!(summary.picks_30_days.iter().sum::<f32>(), 1.0);
        assert_eq!(summary.picks_7_days.iter().sum::<f32>(), 0.0);
        assert_eq!(summary.on_time_dispatch_percent, Some(100));
        let pending = parse_report("A\tMaya\t0\tpicking").unwrap();
        assert_eq!(OperationsData::from_records(&pending).on_time_dispatch_percent, None);
    }
}

use std::collections::HashMap;

use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid checked-in translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

use fission::prelude::*;
use crate::state::{parse_report, OperationsDashboardState};

fission_component! {
    pub OrderReportImport<OperationsDashboardState> {
        state {
            source: String = String::new(),
            invalid_line: Option<usize> = None,
        }
    }
    view(import, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Column(gap: tokens.spacing.s, children: [
        Text(cx.tr("import.title")).size(tokens.typography.heading2_size),
        TextInput(
            label: Some(cx.tr("import.label").into()),
            helper_text: Some(cx.tr("import.help").into()),
            bind: import.source,
            multiline: true,
            semantics_identifier: "harbour.import.source".to_string(),
        ),
        Button(
            child: Text(cx.tr("import.action")),
            key: "import-report",
            on_press: reduce {
                match parse_report(&import.source) {
                    Ok(records) => {
                        state.records = Some(records);
                        import.invalid_line = None;
                    }
                    Err(error) => import.invalid_line = Some(error.line),
                }
            },
        ).semantics_identifier("harbour.import.apply"),
        if let Some(line) = import.invalid_line {
            Text(cx.tr("import.invalid").replace("{line}", &line.to_string()))
                .color(tokens.colors.error)
        },
    ])
}

## Build an Android dashboard with Fission Charts

Choose the chart from the decision it needs to support. The warehouse lead wants to compare completed picks over time, so a bar chart is a useful first view. The **7 days** and **30 days** controls change the selected window and update both the chart and its text summary from the dashboard data in `GlobalState`. The same imported records supply both ranges. Four equal seven-day buckets would only cover twenty-eight days, so the oldest thirty-day bucket explicitly includes days 21–29. Its nine-day count is not directly comparable as a per-day rate with the other seven-day buckets; the labels expose that distinction.

Keeping the filter in this chart component's retained local state is appropriate because no other screen reads it. When the app is connected to a service, load the selected range through an effect and model loading and failure separately from the empty state. This example renders the empty state when dashboard data is absent. Fission Charts supplies axis labels, a legend and tooltips, while the separate summary gives the total without asking someone to estimate bar heights. See the [Fission Charts reference](/reference/charts/overview/) for other chart types and interactions.

use crate::state::{OperationsDashboardState, OperationsData};
use crate::import::OrderReportImport;
use fission::prelude::*;
use fission::charts::axis::AxisType;
use fission::charts::{Axis, BarSeries, Chart, Legend, Tooltip};

fission_component! {
    pub FulfilmentTrend<OperationsDashboardState> {
        props { width: f32 }
        state { thirty_days: bool = false }
    }
    view(trend, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let trend_data = state.records.as_ref().map(|records| {
            let data = OperationsData::from_records(records);
            let (labels, picks) = if trend.thirty_days {
                (
                    vec![cx.tr("chart.period.week1"), cx.tr("chart.period.week2"), cx.tr("chart.period.week3"), cx.tr("chart.period.week4")],
                    data.picks_30_days.clone(),
                )
            } else {
                (
                    (0..7).rev().map(|day| cx.tr("chart.day.ago").replace("{day}", &day.to_string())).collect::<Vec<_>>(),
                    data.picks_7_days.clone(),
                )
            };
            let total = picks.iter().sum::<f32>().round() as u32;
            let period = cx.tr(if trend.thirty_days { "chart.range.30" } else { "chart.range.7" });
            let chart_title = cx.tr("chart.title");
            let picks_label = cx.tr("chart.series.picks");
            let chart: Widget = Chart::new()
                .width(trend.width)
                .height(320.0)
                .title(&chart_title)
                .x_axis(Axis {
                    axis_type: AxisType::Category,
                    data: labels,
                    name: None,
                    min: None,
                    max: None,
                    boundary_gap: true,
                    inverse: false,
                    split_line: true,
                    label_rotate: None,
                })
                .y_axis(Axis::value())
                .legend(Legend::top_right())
                .tooltip(Tooltip::axis_trigger())
                .series(vec![BarSeries::new(&picks_label).data(picks).into()])
                .into();
            (total, period, chart)
        });
    } =>
    if let Some((total, period, chart)) = trend_data {
        SemanticsRegion(
            identifier: Some("harbour-completed-picks-trend".to_string()),
            label: Some(cx.tr("chart.a11y")),
            child: Container(Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text(cx.tr("chart.heading")).weight(tokens.typography.font_weight_semibold),
                        Text(cx.tr("chart.subtitle").replace("{period}", &period))
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: cx.tr("chart.total").replace("{count}", &total.to_string())),
                ]),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("chart.range.7")),
                        key: "range-seven-days",
                        variant: if trend.thirty_days { ButtonVariant::Outline } else { ButtonVariant::Primary },
                        on_press: reduce { trend.thirty_days = false; },
                    ).semantics_identifier("harbour.range.7-days"),
                    Button(
                        child: Text(cx.tr("chart.range.30")),
                        key: "range-thirty-days",
                        variant: if trend.thirty_days { ButtonVariant::Primary } else { ButtonVariant::Outline },
                        on_press: reduce { trend.thirty_days = true; },
                    ).semantics_identifier("harbour.range.30-days"),
                ]),
                chart,
                Text(cx.tr("chart.summary").replace("{count}", &total.to_string()))
                    .color(tokens.colors.text_secondary),
            ]))
                .padding_all(tokens.spacing.l)
                .bg(tokens.colors.surface)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.large),
        )
    } else {
        EmptyState(
            title: cx.tr("dashboard.empty.title"),
            description: Some(cx.tr("dashboard.empty.description")),
        )
    }
}

## Verify the dashboard on Android

Run the finished screen in an emulator at a narrow phone size, then rotate or resize it and repeat the same check. The summary should match the selected chart range, order details should wrap without hiding their status, and the chart should remain readable when its labels get longer. This example renders an empty state when no dashboard data exists. Before connecting a service, add and test separate loading and service-error states so a slow or failed request is not presented as an empty warehouse.

The chart filter is local presentation state. Keep shared date filters in `GlobalState` only if another route reads them; when the range needs a server query, dispatch an effect and preserve the last successful summary while the new range loads.

From the generated project root, run the app and confirm the Android host starts before making a release build:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
cargo test
fission build --target android --project-dir . --release
```

`fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. These commands check the Rust app and Android package; they do not replace a visual check at each window size.
