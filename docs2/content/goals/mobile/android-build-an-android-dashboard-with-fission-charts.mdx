## Create the project and add the target

Install the Fission command line, create the app, and add its native target.

```sh
cargo install cargo-fission
fission init android-build-an-android-dashboard-with-fission-charts
cd android-build-an-android-dashboard-with-fission-charts
fission add-target android --project-dir .
```

## Files created by Fission

This is the starter tree after `fission init` and `fission add-target`; the component and state used for this task are additions in the steps below. Keep shared Rust behavior under `src/` and leave target launch and packaging in `platforms/android/`.

```text
android-build-an-android-dashboard-with-fission-charts/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── android/              # generated Android host
```

Keep `src/app.rs`, shared state, reducers and reusable `fission_component!` components in the common Rust project. Add a state, service or effect module only when this feature needs that boundary, and use a name tied to the feature. The generated Android host owns launch and packaging details; shared components describe the user task without importing Android APIs.

## Give the warehouse team an operations home

At 8:30 each morning, the warehouse lead needs three answers before opening an order: how much work is waiting, are shipments leaving on time, and which orders need a closer look? We will build that screen for Harbour Supply, a small outdoor retailer. The order and metric values are sample records held in memory, so the example stays focused on Fission components and layout rather than a backend.

Start with the decisions the screen supports. The metric cards summarise today's workload and the review queue names the orders that need action. In the next step, a chart adds the trend behind those totals; the summary stays visible so a reader does not have to estimate the answer from bar heights.

## Build an Android dashboard with Fission Charts

Choose the chart from the decision it needs to support. The warehouse lead wants to compare completed picks over time, so a bar chart is a useful first view. The **7 days** and **30 days** controls change the selected window and update both the chart and its text summary using sample values held in the component.

Keeping the filter in this dashboard's local state is appropriate because no other screen reads it. When the app is connected to a service, the same button actions can dispatch a reducer effect to load the selected range; the component should still render the pending and no-data states described in the next section. Fission Charts supplies axis labels, a legend and tooltips, while the separate summary gives the total without asking someone to estimate bar heights. See the [Fission Charts reference](/reference/charts/overview/) for other chart types and interactions.

use fission::prelude::*;
use fission::charts::{Axis, BarSeries, Chart, Legend, Tooltip};

fission_component! {
    pub FulfilmentTrend<()> {
        state { thirty_days: bool = false }
    }
    view(trend, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let labels = if trend.thirty_days {
            vec!["Week 1", "Week 2", "Week 3", "Week 4"]
        } else {
            vec!["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
        };
        let picks = if trend.thirty_days {
            vec![118.0, 132.0, 126.0, 147.0]
        } else {
            vec![18.0, 24.0, 21.0, 31.0, 28.0, 16.0, 12.0]
        };
        let total: u32 = picks.iter().map(|count| *count as u32).sum();
        let chart_width = (cx.view.env().viewport_size.width - tokens.spacing.l * 2.0).max(260.0);
        let chart: Widget = Chart::new()
            .width(chart_width)
            .height(360.0)
            .x_axis(Axis::category(labels))
            .y_axis(Axis::value())
            .legend(Legend::top_right())
            .tooltip(Tooltip::axis_trigger())
            .series(vec![BarSeries::new("Orders picked")
                .data(picks)
                .into()])
            .into();
    } =>
    SemanticsRegion(
        identifier: Some("fulfilment-trend".to_string()),
        label: Some("Harbour Supply completed picks".to_string()),
        child: Container(
            Column(gap: tokens.spacing.m, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text("Completed picks").weight(tokens.typography.font_weight_semibold),
                        Text("Compare warehouse orders across the selected period.")
                            .color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: format!("{total} orders")),
                ]),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text("7 days"),
                        key: "range-seven-days",
                        variant: if trend.thirty_days { ButtonVariant::Outline } else { ButtonVariant::Primary },
                        on_press: reduce { trend.thirty_days = false; },
                    ),
                    Button(
                        child: Text("30 days"),
                        key: "range-thirty-days",
                        variant: if trend.thirty_days { ButtonVariant::Primary } else { ButtonVariant::Outline },
                        on_press: reduce { trend.thirty_days = true; },
                    ),
                ]),
                Row(gap: tokens.spacing.s, children: [chart]),
                Text(format!("{total} orders were picked in this period. The summary stays readable without comparing bar heights."))
                    .color(tokens.colors.text_secondary),
            ]),
        )
            .padding_all(tokens.spacing.l)
            .bg(tokens.colors.surface)
            .border(tokens.colors.border, 1.0)
            .border_radius(tokens.radii.large),
    )
}

## Verify the dashboard on Android

Run the finished screen in an emulator at a narrow phone size, then rotate or resize it and repeat the same check. The summary should match the selected chart range, order details should wrap without hiding their status, and the chart should remain readable when its labels get longer. In the real app, also test the pending, empty and service-error states before replacing the sample values with warehouse data.

The chart filter is local presentation state. Keep shared date filters in `GlobalState` only if another route reads them; when the range needs a server query, dispatch an effect and preserve the last successful summary while the new range loads.

From the generated project root, run the app and confirm the Android host starts before making a release build:

```sh
fission doctor android --project-dir .
fission run --target android --project-dir .
fission test --target android --project-dir .
cargo test
fission build --target android --project-dir . --release
```

`fission doctor` reports missing Android tools, `fission run` launches the selected emulator or connected device, and `fission test` checks that the generated host can start. These commands check the Rust app and Android package; they do not replace a visual check at each window size.

Use these references when you want to change the chart or move the selected range into shared app state:

- [Charts](/reference/charts/overview/)
- [Fission state, handles and providers guide](/docs/guides/state-handles-and-providers/)
- [Fission component and widget reference](/reference/widgets/catalog/)
