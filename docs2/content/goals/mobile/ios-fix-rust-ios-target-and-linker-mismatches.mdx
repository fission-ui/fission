## Create the project and add the target

Create a shared Rust app and add the iOS target. Fission generates the native host; keep the app behaviour in Rust.

```sh
cargo install cargo-fission
fission init ios-fix-rust-ios-target-and-linker-mismatches
cd ios-fix-rust-ios-target-and-linker-mismatches
cargo add serde_yaml
fission add-target ios --project-dir .
```

## Files created by Fission

Fission creates this starter tree. Shared Rust code stays in `src/`; the generated host under `platforms/ios/` handles iOS launch and packaging.

```text
ios-fix-rust-ios-target-and-linker-mismatches/
├── Cargo.toml                 # Rust package and dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                # generated app entrypoint
│   ├── lib.rs                 # shared app setup
│   └── app.rs                 # shared Fission screen
└── platforms/
    └── ios/                  # generated iOS host
```

Keep app behaviour in shared Rust. Add a feature module only when it creates a useful boundary, and keep iOS APIs behind the generated host.

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");

    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid Northbank translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }

    env
}

## Fix Rust iOS target and linker mismatches

Fission uses separate Rust targets for iPhone and iOS Simulator builds: `aarch64-apple-ios` and `aarch64-apple-ios-sim`. Their native libraries must match the destination. Check both Rust targets and both Xcode SDKs before changing linker settings; do not copy an archive built for the other target into the search path.

```sh
fission doctor ios --project-dir .
rustup target list --installed | rg 'aarch64-apple-ios'
xcode-select -p
xcrun --sdk iphoneos --show-sdk-path
xcrun --sdk iphonesimulator --show-sdk-path
```

If one Rust target is missing, install the pair Fission checks with `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`. If a dependency is the problem, rebuild it for the device or simulator target actually being packaged. The `fission run --target ios` path builds and launches an iOS Simulator; physical iPhone packaging is a separate signed IPA workflow.

## Build the simulator target and inspect the failure

Run these commands from the project root. The iOS `fission build` and `fission test` paths build the simulator target; they do not create a signed iPhone IPA.

```sh
fission doctor ios --project-dir .
fission build --target ios --project-dir .
fission test --target ios --project-dir .
```

Once the simulator build succeeds, launch it and follow its logs. For a physical iPhone, use the signed IPA path described in the [device installation tutorial](/blog/install-a-fission-app-on-a-physical-iphone/).

```sh
fission devices --project-dir .
fission run --target ios --project-dir .
```
