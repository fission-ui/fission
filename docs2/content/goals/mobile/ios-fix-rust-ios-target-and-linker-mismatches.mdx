An Apple Silicon Mac and a recent iPhone can both run ARM64 code, but that does not make their binaries interchangeable. A device build and a simulator build target different platforms even when the CPU architecture has the same name.

We will keep one shared Compose app and follow the target selected for its native build. The goal is to correct the incompatible input, not keep adding linker flags until an unrelated library happens to link.

## Check the intended destination first

For an existing app, start in its project root; do not initialize over it. For a separate practice project:

```sh
cargo install cargo-fission
fission init ios-fix-rust-ios-target-and-linker-mismatches
cd ios-fix-rust-ios-target-and-linker-mismatches
fission add-target ios --project-dir .
cargo add serde_yaml
```

Complete [iOS setup](/blog/set-up-rust-ios-development-with-fission/) for Xcode and SDK selection. The important target pair is `aarch64-apple-ios` for the physical device and `aarch64-apple-ios-sim` for an Apple Silicon simulator. Selecting one is a platform decision, not a filename convention.

## Use one real shared app as the build candidate

The journey editor from [the component tutorial](/blog/compose-an-ios-app-from-reusable-fission-widgets/) supplies a useful launch check: prepare a journey, edit its draft and verify the snapshot remains unchanged. The complete source is included here with its normal native and Web entrypoints, rather than compiling a browser-only work-order toggle whilst the native host still launches the starter counter.

Keep the generated `src/main.rs`. If you are diagnosing an existing product, keep its own core and apply the target checks below; replacing it with this example would hide the dependency which may be failing.

    pub JourneyScreen<JourneyState> {

            origin: String = String::new(),
            destination: String = String::new(),

    view(screen, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } => SafeArea(
        child: Scroll(
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("journey.heading")).size(tokens.typography.heading2_size),
                Text(cx.tr("journey.explanation")),
                Row(gap: tokens.spacing.s, children: [
                    Button(
                        child: Text(cx.tr("language.english")), key: "english",
                        on_press: reduce { state.locale = Locale::from("en-US"); },
                    ),
                    Button(
                        child: Text(cx.tr("language.spanish")), key: "spanish",
                        on_press: reduce { state.locale = Locale::from("es-ES"); },
                    ),
                ]),
                FormControl(
                    label: Some(cx.tr("journey.origin")),
                    required: true,
                    child: TextInput(
                        value: screen.origin.clone(),
                        bind(on_input): to(screen.origin),
                    ),
                ),
                FormControl(
                    label: Some(cx.tr("journey.destination")),
                    required: true,
                    child: TextInput(
                        value: screen.destination.clone(),
                        bind(on_input): to(screen.destination),
                    ),
                ),
                if !screen.origin.trim().is_empty() && !screen.destination.trim().is_empty() {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.draft")),
                        JourneySummary(
                            Journey {
                                origin: screen.origin.trim().to_owned(),
                                destination: screen.destination.trim().to_owned(),
                            },
                            key: "draft-summary",
                        ),
                    ])
                },
                Button(
                    child: Text(cx.tr("journey.prepare")), key: "prepare-journey",
                    disabled: screen.origin.trim().is_empty() || screen.destination.trim().is_empty(),
                    on_press: reduce {
                        state.prepared = Some(Journey {
                            origin: screen.origin.trim().to_owned(),
                            destination: screen.destination.trim().to_owned(),
                        });
                    },
                ),
                if let Some(journey) = &state.prepared {
                    Column(gap: tokens.spacing.s, children: [
                        Text(cx.tr("journey.prepared")),
                        JourneySummary(journey.clone(), key: "prepared-summary"),
                    ])
                },
            ]))
            .padding_all(tokens.spacing.l),
        ),
    )

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid journey translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}

pub fn sync_env(state: &crate::app::JourneyState, env: &mut Env) {
    env.locale = state.locale.clone();
}

## Compare the Rust target, SDK and native dependency

```sh
fission doctor ios --project-dir .
rustup target list --installed
xcode-select -p
xcrun --sdk iphoneos --show-sdk-path
xcrun --sdk iphonesimulator --show-sdk-path
```

Install the missing target rather than changing the intended destination:

```sh
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
```

The simulator package script defaults to `aarch64-apple-ios-sim`. The device IPA path selects `aarch64-apple-ios`. Check any explicit `IOS_SIM_TARGET`, `IOS_TARGET`, Cargo target configuration or native-library search path in your own build environment against that intended destination. Do not copy a device archive into a simulator directory and assume the directory changes its platform.

For a native Mach-O executable or library, inspect both architecture and platform. Replace the placeholder with the actual failing artifact:

```sh
file "<artifact>"
xcrun lipo -info "<artifact>"
xcrun vtool -show-build "<Mach-O artifact>"
```

`file` and `lipo` can establish ARM64, but ARM64 alone does not distinguish device from simulator. The build-platform information matters too. A static archive may need inspection of its contained Mach-O objects, and an XCFramework needs the slice whose platform variant matches the destination. Rebuild or select that dependency's correct variant; do not weaken the platform check.

<!-- fission:step id="edge-state" -->
## Rebuild narrowly and then launch

```sh
fission build --target ios --project-dir .
fission devices --project-dir .
fission run --target ios --project-dir .
fission test --target ios --project-dir .
```

Use [the simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) for selection. Keep the first useful compile or linker error and its artifact path. A later "build failed" line usually does not add enough information to choose a fix.

Do not erase a shared Cargo target to test a theory. Correct the incompatible target, SDK or dependency input and rebuild the affected candidate. A progressing build lock belongs to another active operation, not to the architecture failure.

After the build succeeds, repeat the journey task on the simulator. A linked binary is not yet a verified keyboard, layout or state workflow. Use [the physical-device guide](/blog/install-a-fission-app-on-a-physical-iphone/) for the distinct signed IPA path; simulator success does not qualify that device artifact.
