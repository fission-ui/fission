Create a Rust documentation site with three-column navigation, explicit sidebars, a page outline, highlighted code, search and reference links. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Fission component while you read. Search and navigation in the preview run in the browser. The final documentation site is generated as static pages, so its guides remain crawlable without a server request.

## What you will build

Create Atlas Docs with a left navigation tree, a readable article column and a right-hand page outline. Separate learning guides from reference pages so readers know whether to follow a task or look up a type.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init atlas-docs --template website
cd atlas-docs
```

The website template creates a Static site project with a static entrypoint in `src/main.rs`, route registration and the Web shell in `src/lib.rs`, and reusable page, navigation and footer components in their own modules. Add the task files shown in the tree as you work. The preview's `src/app.rs` is a separate, compiled browser harness for the interactive lesson; the production website uses the template modules and `fission.toml`. Do not copy `preview/lib.rs` into the website.

### Mount guide and reference content

Merge the site settings into the template’s existing `[site]` table and add explicit content routes. Do not create a second `[site]` table. The documentation template supplies the left navigation, article column, page outline and footer; a reader can open a saved route without running a search script.

```toml
[site]
title = "Atlas Docs"
description = "Guides and reference for Atlas users."
base_url = "https://docs.atlas.example.com"
out_dir = "dist/site"
asset_dirs = ["assets"]
generate_sitemap = true
generate_robots = true

[site.code_highlighting]
enabled = true

[site.search]
enabled = true
output_path = "search"
min_token_len = 2

[[site.routes]]
kind = "content"
path = "/docs"
source = "content/docs"
template = "fission::site::documentation"
sidebar = "site/docs-sidebar.toml"

[[site.routes]]
kind = "content"
path = "/reference"
source = "content/reference"
template = "fission::site::documentation"
sidebar = "site/reference-sidebar.toml"
```

Give each guide a descriptive title and description in Markdown front matter. Keep the sidebar order intentional instead of relying on alphabetical file names:

```toml
# site/docs-sidebar.toml
[[items]]
title = "Start here"
href = "/docs/overview/"
level = 1
group = true

[[items]]
title = "Quickstart"
href = "/docs/learn/quickstart/"
level = 2
```

Use the same sidebar format for the reference route, but link it to `/reference/` pages. Run a search for an exact API name, then disable JavaScript and open one guide URL directly; the article and route should remain readable. Code highlighting is an enhancement, not a requirement for finding or copying the example.

## Organize guides around reader tasks

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Row(gap: tokens.spacing.m,
                    children: [Text("Getting started"),
                        Text("Build an interface"),
                        Text("Reference")]),
                Text("Create your first app"),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```
<!-- fission:file path="preview/lib.rs" -->
```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::TutorialPreview::new(
        "Atlas Docs".to_string(),
        "Search guides from the documentation sidebar.".to_string(),
        "Search documentation".to_string(),
        "Matching guide results are shown.".to_string(),
        "Enter a term to browse popular guides.".to_string(),
    );
    WebApp::<(), _>::new(preview)
        .with_title("Build a documentation website in Rust")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Add search beside explanations and code

Mount Markdown directories at explicit paths and define sidebars in TOML. Keep the page title and description in frontmatter, use heading levels in order, and put versioned or related API links after the working instructions.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            query: String = String::new(),
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                TextInput(label: Some("Search guides".into()),
                    placeholder: Some("Try state or routing".into()),
                    bind: preview.query,
                    semantics_identifier: "tutorial.docs.search".to_string()),
                if preview.query.is_empty() { Column(children: [Text("Create your first app"),
                            Text("Build an interface"),
                            Text("Add routing")]) } else { Column(children: [Text("Guide: app state"),
                            Text("Guide: routing and links")]) },
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview no results".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("No guide matches. Try a broader term or browse the task sidebar.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Keep links and reading layout reliable

Enable code highlighting and search, then inspect keyboard order and narrow-screen behaviour. The sidebar and page outline should collapse or move out of the way on a phone instead of squeezing the article into a thin column.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
cargo test
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission site serve --project-dir . --host 127.0.0.1 --port 8123
fission test --target static-site --project-dir .
```

Expected result: A reader can reach a guide from the sidebar, search, or a saved URL, with code that stays readable on phones.
