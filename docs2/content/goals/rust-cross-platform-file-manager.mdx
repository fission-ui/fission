This tutorial builds the file-browser UI, not a complete file manager. The preview uses sample entries and never reads or writes host files. When you connect it to real storage, use Fission’s filesystem capability and its asynchronous reducer/effect flow; do not substitute guessed paths or synthetic permission results.

The screen lists folders and files, keeps a stable selection while you move through the sample hierarchy, and handles an empty folder. The [File System capability reference](/reference/capabilities/file-system/) covers the separate picker, listing, read, and write operations needed for host access.

Install the Fission CLI and scaffold a Web project for the interactive UI preview:

```sh
cargo install cargo-fission
fission init harbour-file-browser
cd harbour-file-browser
cargo add serde_yaml
fission add-target web --project-dir .
```

```text
│   ├── state.rs
│   ├── components/file_list.rs
├── platforms/

└── tests/                      # project-specific flow checks
```

`fission init` generates `Cargo.toml`, `fission.toml`, `src/main.rs`, `src/lib.rs` and `src/app.rs`. The first screen keeps its folder and selection as local component state. Once the list and preview become separate components, the later version moves the shared directory state into `FileManagerState` so both can observe it. This UI sample does not request filesystem access; when you add it, queue host work from a reducer through the filesystem capability rather than doing it during component conversion.

`preview/lib.rs` compiles the complete `src/app.rs` into WebAssembly with sample entries. Those entries are preview fixtures, not files from the host.

## Navigate with stable file identities

This step adds navigation over a small, preview-only directory tree. The records are sample data; selecting a file shows its name and details, not bytes read from the host. The filesystem capability reference describes the separate asynchronous picker and listing flow for real files.

The preview seeds shared state with a small sample directory. The list, keyed row components, and detail pane all read or update that state; the row sends a stable entry ID to a reducer instead of capturing a loop variable. In the real app, load entries through the filesystem capability. Keep a field local when only one component needs it, and put it in `GlobalState` when separately composed parts of the app share it.

```rust
use crate::app::FileEntry;
use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct FileManagerState {
    pub entries: Vec<FileEntry>,
    pub current_folder: String,
    pub selected_entry: Option<String>,
}

impl Default for FileManagerState {
    fn default() -> Self {
        Self {
            entries: Vec::new(),
            current_folder: "home".to_string(),
            selected_entry: None,
        }
    }
}

impl GlobalState for FileManagerState {}

#[fission_reducer(OpenFileEntry)]
pub fn open_file_entry(state: &mut FileManagerState, entry_id: String) {
    let Some((entry_id, is_folder)) = state
        .entries
        .iter()
        .find(|entry| entry.id == entry_id)
        .map(|entry| (entry.id.clone(), entry.is_folder))
    else {
        return;
    };

    if is_folder {
        state.current_folder = entry_id;
        state.selected_entry = None;
    } else {
        state.selected_entry = Some(entry_id);
    }
}
```

## Handle an empty folder

An empty folder is different from a denied folder. This preview demonstrates the empty state only; it does not simulate an operating-system permission result. When you connect the real picker and list effects, render their pending and error results from the actions returned by that capability.

The sample Shared folder has no entries. The screen says so and lets the user return Home; the browser preview does not request real filesystem access.

## Run, test and build the finished project

This project is deliberately scoped to the Web UI preview. From the project root, run the checks in order:

```sh
fission doctor --project-dir .
cargo test
fission build --target web --project-dir .
fission test --target web --project-dir .
```

Expected result: The Web preview browses the sample hierarchy, keeps selection tied to stable file IDs, and shows a genuine empty-folder state. It does not ask for host filesystem access. To build a real file manager, implement the picker/list/read flow with the [File System capability](/reference/capabilities/file-system/) and add targets only after testing their capability support.
