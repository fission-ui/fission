A WhatsApp-style app is easy to recognise: a coloured header, a list of people and a conversation made up of message bubbles. The more interesting part is what happens when you use it. Does a draft still belong to the same person after you search the list? Does opening another chat lose it? What happens when a narrow window becomes a wide one?

We will build those behaviours in Rust using Fission Compose. The visual starting point is [Pawan Kumar's Flutter WhatsApp clone](https://github.com/iampawan/FlutterWhatsAppClone); this is a new implementation rather than a translation of its Flutter source. We keep the familiar chat structure and extend it with an actual conversation view and a responsive desktop layout.

This is a local learning app, not a WhatsApp client. All people and conversations are fictional. Adding a message changes in-memory app data; it does not contact another person, provide encryption or acknowledge delivery. That distinction is visible in the interface, not left for the reader to discover afterwards.

You should be comfortable reading a Rust struct, an `enum` and a `match` expression. The [finished repository](https://github.com/fission-ui/rust-whatsapp-clone) lets you run the complete app first and then follow the pieces below.

## Create the project and add the target

Keep the generated `platforms/` folders. They launch the shared Rust app; they are not where the inbox or message behaviour belongs. The full source files below replace the generated counter and add the named app modules.

## Build an inbox around conversation identities

Start with the information the app needs to preserve. A `Chat` has an ID, a name and messages. A `Message` has its own ID. Neither identity depends on where an item happens to appear in a list. This matters because searching and reordering change positions, not which conversation a person is using.

`ChatState` owns shared app data. Its default is empty; `ChatState::demo()` explicitly loads the authored examples for this demo. The launchers make that choice once when the app starts. The view does not load data or mutate state while constructing widgets.

The state module also contains the finished message transition. It is ordinary Rust and can be tested independently of a window. We introduce the state model here so the second checkpoint can add the conversation interface without replacing its ownership rules.

use std::collections::BTreeMap;

use fission::prelude::GlobalState;
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Copy, Default, PartialEq, Eq, Serialize, Deserialize)]
pub enum Tab {
    #[default]
    Chats,
    Updates,
    Calls,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Message {
    pub id: u64,
    pub text: String,
    pub outgoing: bool,
    pub time: String,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Chat {
    pub id: u64,
    pub name: String,
    pub time: String,
    pub unread: u32,
    pub messages: Vec<Message>,
}

/// Shared conversation data survives changes between phone and desktop layouts.
/// This demo keeps it in memory; it does not claim to deliver messages remotely.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct ChatState {
    pub chats: Vec<Chat>,
    pub selected: Option<u64>,
    pub query: String,
    pub drafts: BTreeMap<u64, String>,
    pub tab: Tab,
    pub notice: Option<String>,
    pub locale: String,
}

impl Default for ChatState {
    fn default() -> Self {
        Self {
            chats: Vec::new(),
            selected: None,
            query: String::new(),
            drafts: BTreeMap::new(),
            tab: Tab::Chats,
            notice: None,
            locale: "en-US".into(),
        }
    }
}

impl GlobalState for ChatState {}

impl ChatState {
    /// Fictional content is an explicit demo choice, not a production default.
    pub fn demo() -> Self {
        Self {
            chats: crate::demo::chats(),
            ..Self::default()
        }
    }

    pub fn open_chat(&mut self, id: u64) {
        let Some(chat) = self.chats.iter_mut().find(|chat| chat.id == id) else {
            return;
        };
        chat.unread = 0;
        self.selected = Some(id);
        self.tab = Tab::Chats;
        self.notice = None;
    }

    pub fn back(&mut self) {
        self.selected = None;
    }

    pub fn set_tab(&mut self, tab: Tab) {
        self.tab = tab;
        self.selected = None;
        self.notice = None;
    }

    /// Append a local message. `true` means it was added, not sent to a service.
    pub fn send(&mut self) -> bool {
        let Some(chat_id) = self.selected else {
            return false;
        };
        let Some(text) = self
            .drafts
            .get(&chat_id)
            .map(|draft| draft.trim().to_owned())
        else {
            return false;
        };
        if text.is_empty() {
            return false;
        }
        let Some(chat_index) = self.chats.iter().position(|chat| chat.id == chat_id) else {
            return false;
        };
        // Allocate from existing identities rather than an index or list length.
        // Exhaustion fails without clearing the author's draft.
        let Some(id) = self
            .chats
            .iter()
            .flat_map(|chat| &chat.messages)
            .map(|message| message.id)
            .max()
            .unwrap_or(0)
            .checked_add(1)
        else {
            return false;
        };
        let chat = &mut self.chats[chat_index];
        // No clock dependency is needed for an in-memory demonstration. This
        // label describes a local action, not a server delivery acknowledgement.
        let time = if self.locale.starts_with("es") {
            "Ahora"
        } else {
            "Now"
        };
        chat.messages.push(Message {
            id,
            text,
            outgoing: true,
            time: time.into(),
        });
        chat.time = time.into();
        self.drafts.remove(&chat_id);
        true
    }

    pub fn filtered_chats(&self) -> Vec<&Chat> {
        let query = self.query.trim().to_lowercase();
        self.chats
            .iter()
            .filter(|chat| {
                query.is_empty()
                    || chat.name.to_lowercase().contains(&query)
                    || chat
                        .messages
                        .last()
                        .is_some_and(|message| message.text.to_lowercase().contains(&query))
            })
            .collect()
    }
}

mod tests {
    use super::*;
    use std::collections::BTreeSet;

    #[test]
    fn default_is_empty_and_demo_is_explicit() {
        assert!(ChatState::default().chats.is_empty());
        assert_eq!(ChatState::demo().chats.len(), 6);
    }

    #[test]
    fn empty_or_unselected_messages_do_not_change_state() {
        let mut state = ChatState::demo();
        let original = state.clone();
        assert!(!state.send());
        assert_eq!(state, original);

        state.open_chat(101);
        assert!(!state.send());
        state.drafts.insert(101, " \n\t ".into());
        let original = state.clone();
        assert!(!state.send());
        assert_eq!(state, original);
    }

    #[test]
    fn sends_trim_text_without_fake_replies_or_delivery_state() {
        let mut state = ChatState::demo();
        state.open_chat(101);
        let before = state.chats[0].messages.len();
        state.drafts.insert(101, "  See you at six! \n".into());
        assert!(state.send());
        let chat = &state.chats[0];
        assert_eq!(chat.messages.len(), before + 1);
        assert_eq!(chat.messages.last().unwrap().text, "See you at six!");
        assert!(chat.messages.last().unwrap().outgoing);
        assert!(!state.drafts.contains_key(&101));
    }

    #[test]
    fn sending_changes_only_the_selected_conversation() {
        let mut state = ChatState::demo();
        state.open_chat(102);
        let others: Vec<_> = state
            .chats
            .iter()
            .filter(|chat| chat.id != 102)
            .cloned()
            .collect();
        state.drafts.insert(101, "Keep this draft".into());
        state.drafts.insert(102, "Thanks for the notes".into());
        assert!(state.send());
        assert_eq!(state.drafts[&101], "Keep this draft");
        assert_eq!(
            state
                .chats
                .iter()
                .filter(|chat| chat.id != 102)
                .cloned()
                .collect::<Vec<_>>(),
            others
        );
        let selected = state.chats.iter().find(|chat| chat.id == 102).unwrap();
        assert_eq!(
            selected.messages.last().unwrap().text,
            "Thanks for the notes"
        );
    }

    #[test]
    fn draft_belongs_to_chat_not_current_screen() {
        let mut state = ChatState::demo();
        state.open_chat(101);
        state.drafts.insert(101, "Bring a picnic blanket".into());
        state.open_chat(102);
        state.drafts.insert(102, "Thanks for the notes".into());
        state.back();
        state.set_tab(Tab::Updates);
        state.open_chat(102);
        assert!(state.send());
        assert_eq!(state.drafts[&101], "Bring a picnic blanket");
        assert!(!state.drafts.contains_key(&102));
    }

    #[test]
    fn identities_remain_unique_after_reordering_and_sending() {
        let mut state = ChatState::demo();
        let chat_ids: BTreeSet<_> = state.chats.iter().map(|chat| chat.id).collect();
        assert_eq!(chat_ids.len(), state.chats.len());
        state.chats.reverse();
        for id in [101, 102, 101] {
            state.open_chat(id);
            state.drafts.insert(id, "A local note".into());
            assert!(state.send());
        }
        assert_eq!(chat_ids, state.chats.iter().map(|chat| chat.id).collect());
        let ids: Vec<_> = state
            .chats
            .iter()
            .flat_map(|chat| chat.messages.iter().map(|message| message.id))
            .collect();
        assert_eq!(ids.len(), ids.iter().collect::<BTreeSet<_>>().len());
    }

    #[test]
    fn search_matches_names_and_last_message_case_insensitively() {
        let mut state = ChatState::demo();
        state.query = "  MAYA ".into();
        assert_eq!(state.filtered_chats()[0].id, 101);
        state.query = "PICNIC".into();
        assert_eq!(state.filtered_chats()[0].id, 101);
        state.query = "not present anywhere".into();
        assert!(state.filtered_chats().is_empty());
        state.query.clear();
        assert_eq!(state.filtered_chats().len(), 6);
    }

    #[test]
    fn search_lowercases_unicode_names_and_message_text() {
        let mut state = ChatState::demo();
        state.chats[0].name = "Élodie García".into();
        state.query = "ÉLODIE".into();
        assert_eq!(state.filtered_chats()[0].id, 101);
        state.chats[0].messages.last_mut().unwrap().text = "До встречи завтра".into();
        state.query = "ВСТРЕЧИ".into();
        assert_eq!(state.filtered_chats()[0].id, 101);
    }

    #[test]
    fn next_message_id_is_above_every_conversations_existing_ids() {
        let mut state = ChatState::demo();
        let previous_ids: BTreeSet<_> = state
            .chats
            .iter()
            .flat_map(|chat| chat.messages.iter().map(|message| message.id))
            .collect();
        let previous_count: usize = state.chats.iter().map(|chat| chat.messages.len()).sum();
        assert_eq!(previous_ids.len(), previous_count);
        let expected = previous_ids.last().unwrap() + 1;
        state.open_chat(101);
        state.drafts.insert(101, "New local message".into());
        assert!(state.send());
        assert_eq!(state.chats[0].messages.last().unwrap().id, expected);
    }

    #[test]
    fn opening_marks_only_selected_chat_read_and_rejects_unknown_ids() {
        let mut state = ChatState::demo();
        let others = state.chats[1..].to_vec();
        state.open_chat(101);
        assert_eq!(state.chats[0].unread, 0);
        assert_eq!(&state.chats[1..], others.as_slice());
        let original = state.clone();
        state.open_chat(u64::MAX);
        assert_eq!(state, original);
    }

    #[test]
    fn missing_chat_and_exhausted_ids_preserve_drafts() {
        let mut state = ChatState::demo();
        state.selected = Some(999);
        state.drafts.insert(999, "Unsent".into());
        assert!(!state.send());
        assert_eq!(state.drafts[&999], "Unsent");
        state.open_chat(101);
        state.chats[0].messages[0].id = u64::MAX;
        state.drafts.insert(101, "Still unsent".into());
        let original = state.clone();
        assert!(!state.send());
        assert_eq!(state, original);
    }
}

The first view is deliberately an inbox rather than the whole app. Search by name or the latest message, then select a row. The small panel at the bottom confirms which conversation was selected; we will replace that panel with a real conversation in the next step.

`InboxRow` receives a chat ID as a prop. Its reducer uses that prop when the person presses the row. It does not capture a temporary reference to the `chat` found during the earlier view build. In the repeated collection, `key: chat.id` gives each retained component the same identity after filtering.

use crate::state::ChatState;
use fission::prelude::*;

fission_component! {
    pub ChatApp<ChatState> {}
    view(_app, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let selected = state.chats.iter().find(|chat| Some(chat.id) == state.selected);
    } =>
    SafeArea(child: Container(Column(children: [
        Container(Column(gap: tokens.spacing.xs, children: [
            Text("WhatsApp").size(tokens.typography.heading_size)
                .weight(tokens.typography.font_weight_semibold)
                .color(tokens.colors.on_primary),
            Text(cx.tr("app.demo")).size(tokens.typography.font_size_xs)
                .color(tokens.colors.on_primary),
        ])).padding_all(tokens.spacing.m).bg(tokens.colors.primary),
        Container(TextInput(
            bind: state.query,
            label: Some(cx.tr("search.label").into()),
            placeholder: Some(cx.tr("search.placeholder").into()),
            semantics_identifier: "inbox.search".to_string(),
        )).padding_all(tokens.spacing.m),
        Container(Scroll(flex_grow: 1.0, child: Column(children: [
            for chat in state.filtered_chats() {
                InboxRow(chat_id: chat.id, key: chat.id)
            },
            if state.filtered_chats().is_empty() {
                EmptyState(title: cx.tr("inbox.empty"), description: cx.tr("inbox.empty_help"))
            },
        ]))).flex_grow(1.0).min_height(0.0).align_child(BoxAlignment::Stretch),
        if let Some(chat) = selected {
            Container(Text(format!("{}: {}", cx.tr("action.open"), chat.name)))
                .padding_all(tokens.spacing.m).bg(tokens.colors.primary_subtle)
        },
    ]))
    .width_length(Length::percent(100.0))
    .height_length(Length::percent(100.0))
    .align_child(BoxAlignment::Stretch)
    .bg(tokens.colors.surface))
}

fission_component! {
    #[derive(Default)]
    pub InboxRow<ChatState> { props { chat_id: u64 } }
    view(row, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let chat = state.chats.iter().find(|chat| chat.id == row.chat_id);
    } =>
    if let Some(chat) = chat {
        Pressable(
            label: chat.name.clone(),
            semantics_identifier: format!("chat.open.{}", chat.id),
            on_press: reduce { state.open_chat(row.chat_id); },
            child: Container(Row(gap: tokens.spacing.m, children: [
                Avatar(name: chat.name.clone(), size: 48.0),
                Column(gap: tokens.spacing.xs, children: [

            ),

    } else { Spacer(height: 0.0) }

The shell installs the design system and translation bundles, then runs `ChatApp`. Desktop, Web, Android and iOS share the same state and components. The target-specific functions only configure their host.

For Web, `.mount("#fission-web-mount")` tells the shell where to put the app. The CLI's generated page and this tutorial's preview both provide that element, so the app stays inside the space its host gives it rather than being appended below the page. This is a Web host detail; the native launchers do not need it.

use fission::prelude::Env;

const ENGLISH: &str = include_str!("../i18n/en-US.yaml");
const SPANISH: &str = include_str!("../i18n/es-ES.yaml");

fn bundle(locale: &str, source: &str) -> anyhow::Result<TranslationBundle> {
    Ok(TranslationBundle {
        locale: Locale::from(locale),
        messages: serde_yaml::from_str::<HashMap<String, String>>(source)?,
    })
}

pub fn create_env() -> anyhow::Result<Env> {
    let mut env = Env::default();
    env.i18n.add_bundle(bundle("en-US", ENGLISH)?);
    env.i18n.add_bundle(bundle("es-ES", SPANISH)?);
    Ok(env)
}

#[cfg(test)]
mod tests {
    use super::*;
    use std::collections::BTreeSet;

    #[test]
    fn translations_have_matching_nonempty_keys() {
        let english = bundle("en-US", ENGLISH).unwrap();
        let spanish = bundle("es-ES", SPANISH).unwrap();
        let keys =
            |bundle: &TranslationBundle| bundle.messages.keys().cloned().collect::<BTreeSet<_>>();
        assert_eq!(keys(&english), keys(&spanish));
        assert!(english.messages.values().all(|value| !value.is_empty()));
        assert!(spanish.messages.values().all(|value| !value.is_empty()));
    }

    #[test]
    fn lookup_follows_current_environment_locale() {
        let mut env = create_env().unwrap();
        assert_eq!(env.tr("tabs.chats"), "Chats");
        env.locale = Locale::from("es-ES");
        assert_eq!(env.tr("tabs.chats"), "Conversaciones");
        env.locale = Locale::from("not-installed");
        assert_eq!(env.tr("tabs.chats"), "tabs.chats");
    }
}

## Keep drafts attached to the right conversation

A draft belongs to a conversation, not to the currently visible text field. That is why the shared state uses `BTreeMap<chat_id, draft>`. A person can leave one chat, type in another and return without borrowing the other person's draft. It also means changing between phone and desktop layouts does not give a newly constructed composer an empty copy of that data.

The message action trims the draft and rejects empty text. It checks that the selected conversation still exists before adding anything, allocates a new message ID and only clears the matching draft after the message has been appended. There is no fake reply or delivery receipt. The result is a local state transition, not evidence that a service received a message.

The input has an explicit identity containing the layout and conversation ID. A text-change event is accepted only when that identity still belongs to the selected conversation; an event arriving from the previous chat must not overwrite the new chat's draft. After adding a message, the reducer requests a scroll to the conversation's final marker through a Fission effect. The view describes the scroll region; it does not perform host work whilst building it.

The finished `ChatApp` selects independent phone and desktop trees through Fission's responsive widget. The phone shows the inbox or conversation; the desktop shows both. Both trees read the same `ChatState`, but neither reuses a retained `Widget` value constructed for the other branch.

The message history needs a bounded area, otherwise adding messages can push the composer out of the window. A stretching, full-height shell establishes that bound. Inside it, `Container(Scroll(...)).flex_grow(1.0).min_height(0.0)` gives the history the remaining space and lets that space shrink when necessary; its contents scroll rather than deciding how tall the whole conversation should be. The inbox uses the same arrangement so its header and actions stay outside the scrolling rows.

Replace `src/app.rs` and add the named presentation modules below. Each file owns a meaningful piece of the interface instead of hiding the entire app in one conversion function.

The tabs are real controls, not painted labels. Search updates the inbox, a chat row opens its conversation, the composer adds a local message, the language action updates the environment, and the information actions explain the demo's boundaries. Updates and call history are authored examples; a call button must not pretend that a connection was made.

Notice the difference between a component prop and a temporary view value. `Conversation` can decide its presentation from the current state; `ChatRow` passes its stable ID into a reducer. The code does not retain a build context or hold a reference to a row across an asynchronous boundary.

Installing on a physical iPhone requires signing and provisioning; use the [physical iPhone tutorial](/blog/install-a-fission-app-on-a-physical-iphone/). The Web preview checks shared app behaviour, not native keyboard handling, system integration or a device installation.

## Where to take it next

The useful result here is a recognisable, interactive messaging interface with clear ownership of conversations and drafts. It is not a secure messaging system. Restarting the app loses its in-memory messages, and no remote person receives them.

Persistence would need a deliberate store model. A real send operation would need authentication, an asynchronous effect, retry behaviour and separate pending, failed and acknowledged states. Delivery and end-to-end encryption require their own protocols; painting check marks next to a message does not provide either. Keep the local app honest whilst deciding which of those problems your next project actually needs to solve.

The [standalone source](https://github.com/fission-ui/rust-whatsapp-clone) includes the Apache-2.0 licence and attribution to the original Flutter reference. Its avatars use initials and its conversations are fictional; the reference project's photographs and story assets are not copied.
