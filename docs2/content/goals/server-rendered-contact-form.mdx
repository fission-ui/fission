Harbour Supply needs enough information to investigate a delivery problem. The form therefore asks for a reply address, a subject and the shipment details, rather than collecting a name and leaving the customer to explain the rest later.

There are two separate questions here: does the draft contain enough information to submit, and did the support system accept it? This tutorial addresses the first. It does not send email or call a server. Keeping that distinction visible matters; a successful local check is not evidence that anyone has received the message.

Scaffold the project and enable its Web target:

```sh
cargo install cargo-fission
fission init harbour-contact
cd harbour-contact
cargo add serde_yaml
fission add-target web --project-dir .
```

## Create labelled contact fields

A placeholder disappears as soon as someone types, so it cannot replace a label. Give each field a visible label, an input name and a stable semantic identifier. The email field also disables spelling corrections and requests an email keyboard; neither would be appropriate for a free-form message.

The component owns this unfinished draft. It has no shared application data yet, so there is no reason to put the draft in `GlobalState`. Read copy through the translation bundle and styling through the active theme.

```rust
use std::collections::HashMap;

    ("en-US", include_str!("../i18n/en-US.yaml")),
    ("es-ES", include_str!("../i18n/es-ES.yaml")),
];

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in SOURCES {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid contact form translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}
```

## Check the current draft without losing it

Validation is a small pure function. It returns the first field that needs correcting and does not mutate the draft. The email check catches missing address parts, extra `@` signs and whitespace; it is deliberately not a complete email-address parser or proof that the address exists.

Keep only one additional retained value: whether the customer has asked for a check. After that first attempt, derive the result from the current fields on every build. This avoids a subtle bug in forms that store a `submitted` flag: someone can change a previously valid field while the screen continues to claim that the form is ready.

Here the fields remain editable after a successful check. The check button never submits anything, and the feedback says so. In a connected application, submit through an effect, retain a loading state and handle success and failure explicitly. The server must repeat validation before accepting the request.

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Field {
    Name,
    Email,
    Subject,
    Message,
}

impl Field {
    pub fn error_key(self) -> &'static str {
        match self {
            Self::Name => "contact.error.name",
            Self::Email => "contact.error.email",
            Self::Subject => "contact.error.subject",
            Self::Message => "contact.error.message",
        }
    }
}

pub fn validate(name: &str, email: &str, subject: &str, message: &str) -> Result<(), Field> {
    if name.trim().is_empty() {
        return Err(Field::Name);
    }
    // A useful form check, not a complete email-address parser.
    let email = email.trim();
    let valid_email = email.split_once('@').is_some_and(|(local, domain)| {
        !local.is_empty() && !domain.is_empty() && !domain.contains('@')
    }) && !email.chars().any(char::is_whitespace);
    if !valid_email {
        return Err(Field::Email);
    }
    if subject.trim().is_empty() || subject.chars().count() > 120 {
        return Err(Field::Subject);
    }
    if message.trim().is_empty() || message.chars().count() > 2000 {
        return Err(Field::Message);
    }
    Ok(())
}
```

```rust
use fission::prelude::*;
use crate::validation::{validate, Field};

fission_component! {
    pub ContactForm<()> {
        state {
            name: String = String::new(),
            email: String = String::new(),
            subject: String = String::new(),
            message: String = String::new(),
            checked: bool = false,
        }
    }

    view(form, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let error = if form.checked {
            validate(&form.name, &form.email, &form.subject, &form.message).err()
        } else {
            None
        };
        let name_error = (error == Some(Field::Name)).then(|| cx.tr(Field::Name.error_key()));
        let email_error = (error == Some(Field::Email)).then(|| cx.tr(Field::Email.error_key()));
        let subject_error = (error == Some(Field::Subject)).then(|| cx.tr(Field::Subject.error_key()));
        let message_error = (error == Some(Field::Message)).then(|| cx.tr(Field::Message.error_key()));
    } =>
    Container(
        Scroll(
            id: Some(WidgetId::explicit("harbour-contact-scroll")),
            semantic_label: Some(cx.tr("contact.form.semantics")),
            child: Container(Column(gap: tokens.spacing.m, children: [
                Text(cx.tr("contact.form.title"))
                    .weight(tokens.typography.font_weight_bold),
                Text(cx.tr("contact.form.detail"))
                    .color(tokens.colors.text_secondary),
                TextInput(
                    label: Some(cx.tr("contact.name.label").into()),
                    placeholder: Some(cx.tr("contact.name.placeholder").into()),
                    name: Some("name".into()),
                    required: true,
                    autofill_hints: vec!["name".into()],
                    error_text: name_error.clone().map(Into::into),
                    validation_message: name_error.clone(),
                    bind: form.name,
                    key: "contact-name",
                    semantics_identifier: "harbour.contact.name".to_owned(),
                ),
                TextInput(
                    label: Some(cx.tr("contact.email.label").into()),
                    placeholder: Some(cx.tr("contact.email.placeholder").into()),
                    name: Some("email".into()),
                    required: true,
                    keyboard_type: TextInputType::EmailAddress,
                    autocorrect: false,
                    spell_check: false,
                    autofill_hints: vec!["email".into()],
                    error_text: email_error.clone().map(Into::into),
                    validation_message: email_error.clone(),
                    bind: form.email,
                    key: "contact-email",
                    semantics_identifier: "harbour.contact.email".to_owned(),
                ),
                TextInput(
                    label: Some(cx.tr("contact.subject.label").into()),
                    placeholder: Some(cx.tr("contact.subject.placeholder").into()),
                    name: Some("subject".into()),
                    required: true,
                    max_length: Some(120),
                    error_text: subject_error.clone().map(Into::into),
                    validation_message: subject_error.clone(),
                    bind: form.subject,
                    key: "contact-subject",
                    semantics_identifier: "harbour.contact.subject".to_owned(),
                ),
                TextInput(
                    label: Some(cx.tr("contact.message.label").into()),
                    placeholder: Some(cx.tr("contact.message.placeholder").into()),
                    name: Some("message".into()),
                    required: true,
                    multiline: true,
                    min_lines: Some(4),
                    max_lines: Some(7),
                    max_length: Some(2000),
                    error_text: message_error.clone().map(Into::into),
                    validation_message: message_error.clone(),
                    bind: form.message,
                    key: "contact-message",
                    semantics_identifier: "harbour.contact.message".to_owned(),
                ),
                Button(
                    child: Text(cx.tr("contact.action.send")),
                    key: "check-contact-message",
                    on_press: reduce { form.checked = true; },
                ).semantics_identifier("harbour.contact.check-message".to_owned()),
                if form.checked {
                    SemanticsRegion(
                        identifier: Some("harbour.contact.feedback".to_owned()),
                        label: Some(cx.tr(if error.is_some() {
                            "contact.error.generic"
                        } else {
                            "contact.success.preview"
                        })),
                        child: Text(cx.tr(if error.is_some() {
                            "contact.error.generic"
                        } else {
                            "contact.success.preview"
                        })),
                    )
                } else {
                    Text(cx.tr("contact.next"))
                },
                Button(
                    child: Text(cx.tr("contact.action.new")),
                    key: "clear-contact-message",
                    variant: ButtonVariant::Outline,
                    on_press: reduce {
                        form.name.clear();
                        form.email.clear();
                        form.subject.clear();
                        form.message.clear();
                        form.checked = false;
                    },
                ).semantics_identifier("harbour.contact.clear-message".to_owned()),
            ]))
                .width_length(Length::percent(100.0))
                .max_width(720.0)
                .padding_all(tokens.spacing.l)
                .bg(tokens.colors.surface),
        ),
    ).height_length(Length::vh(100.0))
}
```

## Test the rules independently of the screen

A name does not need an arbitrary minimum length. A subject does need a practical upper bound, but that bound should count characters rather than UTF-8 bytes. These are application rules, so test them directly instead of relying on a screenshot of a valid example.

The final case reproduces the stale-feedback problem: a valid message is edited into an invalid one. Since the view derives feedback from `validate`, it cannot keep an earlier success result after that edit.

```rust
    Email,
    Subject,
    Message,
}

impl Field {
    pub fn error_key(self) -> &'static str {
        match self {
            Self::Name => "contact.error.name",
            Self::Email => "contact.error.email",
            Self::Subject => "contact.error.subject",
            Self::Message => "contact.error.message",
        }
    }
}

pub fn validate(name: &str, email: &str, subject: &str, message: &str) -> Result<(), Field> {
    if name.trim().is_empty() {
        return Err(Field::Name);
    }
    // A useful form check, not a complete email-address parser.
    let email = email.trim();

        !local.is_empty() && !domain.is_empty() && !domain.contains('@')

        return Err(Field::Email);
    }
    if subject.trim().is_empty() || subject.chars().count() > 120 {
        return Err(Field::Subject);
    }
    if message.trim().is_empty() || message.chars().count() > 2000 {
        return Err(Field::Message);
    }
    Ok(())
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn names_are_required_not_subject_to_an_arbitrary_minimum_length() {
        assert_eq!(validate("李", "lee@example.com", "Order 42", "Parcel damaged."), Ok(()));
        assert_eq!(validate(" ", "lee@example.com", "Order 42", "Parcel damaged."), Err(Field::Name));
    }

    #[test]
    fn missing_address_parts_and_extra_at_signs_are_rejected() {
        for email in ["lee", "@example.com", "lee@", "lee@@example.com", "lee @example.com"] {
            assert_eq!(validate("Lee", email, "Order 42", "Parcel damaged."), Err(Field::Email));
        }
    }

    #[test]
    fn a_later_edit_is_checked_again() {
        let mut message = "The parcel arrived with a broken seal.".to_owned();
        assert_eq!(validate("Lee", "lee@example.com", "Order 42", &message), Ok(()));
        message.clear();
        assert_eq!(validate("Lee", "lee@example.com", "Order 42", &message), Err(Field::Message));
    }

    #[test]
    fn limits_count_characters_not_utf8_bytes() {
        assert_eq!(validate("李", "lee@example.com", &"件".repeat(120), "Parcel damaged."), Ok(()));
        assert_eq!(validate("Lee", "lee@example.com", &"件".repeat(121), "Parcel damaged."), Err(Field::Subject));
        assert_eq!(validate("Lee", "lee@example.com", "Order 42", &"x".repeat(2001)), Err(Field::Message));
    }
}
```
