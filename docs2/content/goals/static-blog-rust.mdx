Create a searchable static Rust blog with authored posts, category and tag pages, pagination, adjacent links, a hand-maintained RSS feed and a deployable build. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Fission component while you read. The preview demonstrates category and page selection in the browser. The generated static site contains crawlable post, category and tag pages with working pagination links. The RSS feed is a checked-in asset you maintain; Fission does not generate it.

## What you will build

Build Field Journal as a static blog where a reader can browse recent writing, filter by category, open an individual post and move to the previous or next article.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init field-journal --template website
cd field-journal
```

The website template creates a Static site project with a static entrypoint in `src/main.rs`, route registration and the Web shell in `src/lib.rs`, and reusable page, navigation and footer components in their own modules. Add the task files shown in the tree as you work. The preview's `src/app.rs` is a separate, compiled browser harness for the interactive lesson; the production website uses the template modules and `fission.toml`. Do not copy `preview/lib.rs` into the website.

### Configure the blog collection and post metadata

The blog template generates the post index, pagination, category and tag pages, and older/newer links. It does not generate RSS or Atom feeds; this tutorial serves a small feed file from the project's assets directory and updates it when a post is published.

Merge the blog metadata into the generated `[site]` table, then add the content route. Keep one `[site]` table in `fission.toml`:

```toml
[site]
title = "Field Journal"
description = "Practical notes on product development."
base_url = "https://journal.example.com"
out_dir = "dist/site"
asset_dirs = ["assets"]
generate_sitemap = true
generate_robots = true

[[site.routes]]
kind = "content"
path = "/blog"
source = "content/blog"
template = "fission::site::blog"
```

Write each article as a Markdown file such as `content/blog/2026-09-10-getting-started.mdx`:

```mdx
---
title: Getting started with Field Journal
description: Set up a small static blog with useful categories and a clear reading path.
authors:
  - Alex Morgan
categories:
  - Guides
tags:
  - rust
  - fission
show_adjacent_posts: true
---

# Getting started with Field Journal

Explain the reader's task and the result before listing implementation details.
```

For an RSS feed, create `assets/feed.xml` and keep each item URL and publication date in sync with the post. Because `asset_dirs = ["assets"]`, the built feed is copied to `dist/site/feed.xml` and can be linked from the site's footer. A minimal feed file is ordinary project content:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>Field Journal</title>
    <link>https://journal.example.com/blog/</link>
    <description>Practical notes on product development.</description>
    <item>
      <title>Getting started with Field Journal</title>
      <link>https://journal.example.com/blog/2026-09-10-getting-started/</link>
      <guid>https://journal.example.com/blog/2026-09-10-getting-started/</guid>
      <description>Set up a small static blog with useful categories and a clear reading path.</description>
    </item>
  </channel>
</rss>
```

## Create article index and full post pages

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("Latest articles"),
                Text("Build a Rust website"),
                Text("Create a desktop app"),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

}

## Filter by category and move between pages

Give each post a date-based filename, a useful title and summary, one author, categories and tags. Keep the author and tag registries in checked-in files so names stay consistent. A category should help readers find related posts, not exist only to repeat keywords.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            guides_only: bool = false,
            page: usize = 1,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text(if preview.guides_only { "Show all posts".to_string() } else { preview.action.clone() }),
                    key: "category-filter",
                    on_press: reduce { preview.guides_only = !preview.guides_only;
                        preview.page = 1; }),
                Text(if preview.guides_only { "Category: Tutorials" } else { "Category: All posts" }),
                Text(if preview.page == 1 { "Build a Rust website" } else { "Build a desktop app" }),
                Button(child: Text("Next page"),
                    key: "next-page",
                    on_press: reduce { preview.page += 1; }),
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview an empty category".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("There are no posts in this category yet. Choose All posts or another category.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Check links, feeds, and static output

Set `show_adjacent_posts = true` in the post front matter and publish enough articles to create more than one index page. The blog template builds category and tag pages from the post metadata. Maintain `assets/feed.xml` yourself; Fission copies it into the static output but does not generate or update feed entries. Test a category with no posts, the last pagination page and every item URL in the feed.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
cargo test
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission site serve --project-dir . --host 127.0.0.1 --port 8123
fission test --target static-site --project-dir .
```

Expected result: Readers can open an article directly, browse category and tag pages, page through the index and follow older/newer links. `dist/site/feed.xml` contains the hand-maintained RSS feed; Fission does not create RSS or Atom entries.
