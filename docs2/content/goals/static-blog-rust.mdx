Create a searchable static Rust blog with authored posts, category and tag pages, pagination, adjacent links, feeds and a deployable build. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Compose UI while you read. The preview demonstrates category and page selection in the browser. The generated static site contains crawlable post and category pages with working pagination links.

## What you will build

Build Field Journal as a static blog where a reader can browse recent writing, filter by category, open an individual post and move to the previous or next article.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init field-journal --template website
cd field-journal
```

The finished project is organised around the app boundary and the files that own each job:

```text
field-journal/
├── Cargo.toml
├── fission.toml
├── src/
│   ├── main.rs
│   ├── lib.rs
│   ├── app.rs
│   ├── state.rs
│   └── components/
└── content/blog/index.mdx
```

Fission generates a thin entrypoint for each target and starts the shared app from it. Keep shared UI in `src/app.rs`, and move a reusable presentation piece into `src/components/` when it has a clear job of its own. Use `GlobalState` for data read across screens and Compose `state` for retained interaction owned by one component. Keep host work such as persistence and network requests in a Fission service or effect, then show loading, success or failure in the UI.

The `preview/lib.rs` file is a documentation-only browser harness that mounts the step in the live preview. The `src/app.rs` component is compiled into that preview. Use its Compose patterns in your project, but do not copy the harness or treat its simulated host results as production behavior.

## Create article index and full post pages

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("Latest articles"),
                Text("Build a Rust website"),
                Text("Create a desktop app"),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```
<!-- fission:file path="preview/lib.rs" -->
```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::TutorialPreview::new(
        "Field Journal".to_string(),
        "Browse recent posts by category.".to_string(),
        "View the next posts".to_string(),
        "Page two is open with more posts.".to_string(),
        "Page one is open with the latest posts.".to_string(),
    );
    WebApp::<(), _>::new(preview)
        .with_title("Build a static blog in Rust")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Filter by category and move between pages

Give each post a date-based filename, a useful title and summary, one author, categories and tags. Keep the author and tag registries in checked-in files so names stay consistent. A category should help readers find related posts, not exist only to repeat keywords.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            guides_only: bool = false,
            page: usize = 1,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text(if preview.guides_only { "Show all posts".to_string() } else { preview.action.clone() }),
                    key: "category-filter",
                    on_press: reduce { preview.guides_only = !preview.guides_only;
                        preview.page = 1; }),
                Text(if preview.guides_only { "Category: Tutorials" } else { "Category: All posts" }),
                Text(if preview.page == 1 { "Build a Rust website" } else { "Build a desktop app" }),
                Button(child: Text("Next page"),
                    key: "next-page",
                    on_press: reduce { preview.page += 1; }),
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview an empty category".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("There are no posts in this category yet. Choose All posts or another category.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Check links, feeds, and static output

Turn on pagination and adjacent-post navigation, then confirm each generated page has a canonical route and a working feed entry. Test a category with no posts and a page beyond the first page so empty and pagination states are deliberate.

Keep I/O outside component conversion and reducers. Send host work through an asynchronous effect or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission test --target static-site --project-dir .
```

Expected result: Readers can open an article directly, browse by category, page through the index, and discover the feed.
