A technician queues an inspection note and then spots another problem. The queued copy and the editable draft are now different facts: changing one must not silently change the other. If another device has also updated the note, the app needs to preserve both copies until the technician chooses what to keep.

This tutorial builds that state model, not a complete offline service. The queue contains an actual snapshot rather than a counter claiming that work is waiting, but it still lives only in memory. No database write or network request occurs. The [mobile field-notes tutorial](/blog/build-an-offline-first-notes-app-for-android-and-ios/) covers the durable Store-backed path; its server integration must also be supplied before claiming end-to-end sync.

## Create the project

```sh
cargo install cargo-fission
fission init harbour-offline
cd harbour-offline
cargo add serde_yaml
fission add-target web --project-dir .
```

Keep the screen in `src/app.rs`, the model and transitions in `src/state.rs`, and the embedded language bundles behind `src/translations.rs`. The generated native launcher calls `run_desktop`; the Web target uses `run_web`. Replace `src/lib.rs` so both launch the model below rather than the starter counter.

## Separate the draft from the queued copy

`LocalChange` owns its text. Queueing therefore clones the current draft into a snapshot that later typing cannot modify. Repeatedly queueing the same text does not manufacture more changes.

There is another distinction worth making early. A local sequence number orders this device's edits. A server revision identifies the version those edits were based on. They come from different authorities and must not be compared as though the larger integer identifies the newer document. `base_revision` records the server version; `sequence` identifies the local change.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct LocalChange {
    pub sequence: u64,
    pub base_revision: u64,
    pub text: String,
}

#[derive(Clone, Debug, Default, PartialEq)]
pub struct OfflineState {
    pub draft: String,
    pub queued: Option<LocalChange>,
    pub base_revision: u64,
    pub local_sequence: u64,
    pub status: &'static str,
}
impl GlobalState for OfflineState {}

impl OfflineState {
    pub fn queue_note(&mut self) {
        if self.draft.trim().is_empty() {
            self.status = "note.required";
            return;
        }
        if self.queued.as_ref().is_some_and(|change| change.text == self.draft) {
            self.status = "note.unchanged";
            return;
        }
        self.local_sequence += 1;
        self.queued = Some(LocalChange {
            sequence: self.local_sequence,
            base_revision: self.base_revision,
            text: self.draft.clone(),
        });
        self.status = "note.queued";
    }
}

## Review another copy before applying it

A real sync completion would call `offer_remote` from its completion reducer. The documentation harness supplies a separate preview control so you can try that transition without a server. The control is not part of the production component and does not stand in for a successful network request.

While a conflict is visible, keep the two copies stable. Keeping the local draft creates a new change based on the reviewed server revision; choosing the incoming copy clears the obsolete queued change. A later incoming copy at or below the accepted server revision is ignored.

This model deliberately keeps one pending replacement per note, not an append-only history. That is appropriate here because a note is a replaceable document. A payment, stock movement or audit event cannot generally be collapsed this way; those operations need their own durable identities and acceptance rules.

use fission::prelude::*;

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct LocalChange {
    pub sequence: u64,
    pub base_revision: u64,
    pub text: String,
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ServerCopy {
    pub revision: u64,
    pub text: String,
}

#[derive(Clone, Debug, Default, PartialEq)]
pub struct OfflineState {
    pub draft: String,
    pub remote: Option<ServerCopy>,
    pub queued: Option<LocalChange>,
    pub base_revision: u64,
    pub local_sequence: u64,
    pub status: &'static str,
}
impl GlobalState for OfflineState {}

impl OfflineState {
    pub fn queue_note(&mut self) {
        if self.remote.is_some() { return; }
        if self.draft.trim().is_empty() {
            self.status = "note.required";
            return;
        }
        if self.queued.as_ref().is_some_and(|change| change.text == self.draft) {
            self.status = "note.unchanged";
            return;
        }
        self.local_sequence += 1;
        self.queued = Some(LocalChange {
            sequence: self.local_sequence,
            base_revision: self.base_revision,
            text: self.draft.clone(),
        });
        self.status = "note.queued";
    }
}
impl OfflineState {
    pub fn offer_remote(&mut self, copy: ServerCopy) {
        if copy.revision <= self.base_revision
            || self.remote.as_ref().is_some_and(|current| current.revision >= copy.revision)
        {
            return;
        }
        self.remote = Some(copy);
        self.status = "note.review";
    }

    pub fn keep_local(&mut self) {
        if self.draft.trim().is_empty() {
            self.status = "note.required";
            return;
        }
        let Some(remote) = self.remote.take() else { return };
        self.base_revision = remote.revision;
        self.local_sequence += 1;
        self.queued = Some(LocalChange {
            sequence: self.local_sequence,
            base_revision: self.base_revision,
            text: self.draft.clone(),
        });
        self.status = "note.kept";
    }

    pub fn use_server(&mut self) {
        let Some(remote) = self.remote.take() else { return };
        self.draft = remote.text;
        self.base_revision = remote.revision;
        self.queued = None;
        self.status = "note.selected";
    }
}

## Test the ownership rules, then add persistence

These tests exercise the part of the design that a screenshot cannot prove: a queued change owns its text, duplicate queueing does not create extra changes, conflict choices update the right base revision, and an old incoming revision cannot undo an accepted one.

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn queue_keeps_a_snapshot_not_a_reference_to_the_editable_draft() {
        let mut state = OfflineState::default();
        state.draft = "Pressure stable.".into();
        state.queue_note();
        state.draft = "Pressure rising.".into();
        assert_eq!(state.queued.as_ref().unwrap().text, "Pressure stable.");
    }

    #[test]
    fn duplicate_queue_does_not_create_another_change() {
        let mut state = OfflineState::default();
        state.draft = "Pressure stable.".into();
        state.queue_note();
        state.queue_note();
        assert_eq!(state.local_sequence, 1);
        assert_eq!(state.queued.as_ref().unwrap().sequence, 1);
    }

    #[test]
    fn keeping_local_rebases_the_change_on_the_reviewed_server_revision() {
        let mut state = OfflineState::default();
        state.draft = "My inspection.".into();
        state.queue_note();
        state.offer_remote(ServerCopy { revision: 7, text: "Other inspection.".into() });
        state.keep_local();
        let change = state.queued.as_ref().unwrap();
        assert_eq!(change.base_revision, 7);
        assert_eq!(change.text, "My inspection.");
        assert!(state.remote.is_none());
    }

    #[test]
    fn selecting_server_clears_the_obsolete_local_change() {
        let mut state = OfflineState::default();
        state.draft = "My inspection.".into();
        state.queue_note();
        state.offer_remote(ServerCopy { revision: 7, text: "Other inspection.".into() });
        state.use_server();
        assert_eq!(state.draft, "Other inspection.");
        assert!(state.queued.is_none());
        assert_eq!(state.base_revision, 7);
        state.offer_remote(ServerCopy { revision: 6, text: "Late old copy".into() });
        assert!(state.remote.is_none());
    }
}

## Continue to the real offline workflow

```sh
cargo test
fission doctor --project-dir .
fission run --target web --project-dir .
fission build --target web --project-dir .
```

Persistence changes when the app may claim success. Write the note and pending change atomically before saying “Saved on this device”, hydrate them once at startup, and only then request sync. Keep the pending change after a failed request and clear it only when the matching change has been accepted. A stale acknowledgement must not remove a newer queued edit.

The current model establishes none of that storage or transport behaviour by itself. Continue with the [Store-backed mobile notes app](/blog/build-an-offline-first-notes-app-for-android-and-ios/), then connect the actual server contract rather than replacing its result with a delay or a fabricated success.
