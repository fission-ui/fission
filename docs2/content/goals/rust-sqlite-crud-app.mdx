Create, list, edit and remove SQLite records in Rust with typed reducers, asynchronous storage effects and clear loading, empty and error states. This tutorial takes you from project setup to a runnable result in three steps. Each step’s `src/app.rs` component is compiled into the WebAssembly preview shown beside its code, so you can try the same Fission component while you read. The preview demonstrates create, edit, delete and error states in local component state. A real app performs SQLite queries in asynchronous service or effect code and keeps SQL out of the view.

## What you will build

Build a reading list that creates, lists, edits and removes books. The page shows loading while SQLite work runs, an empty state before the first record and an actionable error if a write fails.

Install the Fission CLI and scaffold the Web project:

```sh
cargo install cargo-fission
fission init reading-list
cd reading-list
fission add-target web --project-dir .
fission add-capability storage --project-dir .
```

## Project layout

```text
reading-list/
├── Cargo.toml                 # generated dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                 # generated desktop entrypoint
│   ├── lib.rs                  # shared app setup
│   ├── app.rs                  # the Fission component shown in this tutorial
│   ├── state.rs
│   ├── store/migrations.rs
│   ├── effects/books.rs
│   └── components/book_list.rs
├── platforms/                  # generated host files after add-target
└── tests/                      # project-specific flow checks
```

`fission init` generates `Cargo.toml`, `fission.toml`, `src/main.rs`, `src/lib.rs` and `src/app.rs`. Add the task modules in the tree as you build the feature. Keep data shared across routes in `GlobalState`, and keep retained interaction such as a disclosure or draft field in the owning `fission_component!`. Request database, filesystem, network and session work through a reducer effect, job or service; never run host work while a component view is being built.

`preview/lib.rs` is a documentation harness. The page compiles each complete `src/app.rs` component into WebAssembly so you can use the same UI while reading. Its host results are deterministic preview states; the target-specific host work described in this tutorial runs in each target project code, not in the browser preview.

## Render a reading list and its empty state

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Text("Reading list"),
                TextInput(label: Some("Book title".into()),
                    placeholder: Some("Add a title".into())),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```
<!-- fission:file path="preview/lib.rs" -->
```rust
mod app;

use fission::prelude::*;
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn run() -> Result<(), JsValue> {
    console_error_panic_hook::set_once();
    let preview = app::TutorialPreview::new(
        "Reading list".to_string(),
        "Add a book to start your list.".to_string(),
        "Save a reading-list entry".to_string(),
        "The saved book is in the reading list.".to_string(),
        "Your list is empty. Add the first book to begin.".to_string(),
    );
    WebApp::<(), _>::new(preview)
        .with_title("Build a CRUD app with Rust and SQLite")
        .mount("#fission-web-mount")
        .run()
        .map_err(|error| JsValue::from_str(&error.to_string()))
}
```

## Create, edit, and remove a book

Use typed actions for user intent and a storage effect for database work. Keep SQL out of component views and reducers. The async effect receives owned input, performs the query away from the UI thread, then returns a typed success or error result.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub TutorialPreview<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            draft: String = String::new(),
            book_title: String = String::new(),
            book_count: usize = 0,
            editing: bool = false,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).size(tokens.typography.heading2_size).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                TextInput(label: Some("Book title".into()),
                    placeholder: Some("Add a title".into()),
                    bind: preview.draft,
                    semantics_identifier: "tutorial.reading-list.title".to_string()),
                Button(child: Text(if preview.editing { "Update book".to_string() } else { preview.action.clone() }),
                    key: "save-book",
                    disabled: preview.draft.trim().is_empty(),
                    on_press: reduce { if !preview.draft.trim().is_empty() { preview.book_title = preview.draft.clone(); if !preview.editing { preview.book_count = 1; } preview.draft = String::new();
                            preview.editing = false; } }),
                if preview.book_count == 0 { Text(preview.empty.clone()) } else { Column(children: [Text(preview.book_title.clone()),
                            Row(gap: tokens.spacing.s,
                                children: [Button(child: Text("Edit title"),
                                        key: "edit-book",
                                        on_press: reduce { preview.draft = preview.book_title.clone();
                                            preview.editing = true; }),
                                    Button(child: Text("Delete book"),
                                        key: "delete-book",
                                        on_press: reduce { preview.book_count = 0;
                                            preview.book_title = String::new();
                                            preview.draft = String::new();
                                            preview.editing = false; })])]) },
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview a SQLite write failure".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("The book was not saved. Your title remains in the form.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Handle asynchronous SQLite results and errors

Handle stale completions by associating each request with the current list version or query. Disable duplicate submissions while a save is pending, preserve the draft after failure and refresh the list after a successful write.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
cargo fmt --all -- --check
cargo test
fission run --target web --project-dir .
fission build --target web --project-dir .
fission test --target web --project-dir .
```

Expected result: The list supports create, edit, delete, async storage, and a recoverable write error; confirmed records survive restart.
