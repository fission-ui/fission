A Products link and a control that reveals more links do different jobs. Combining both into one ambiguous target makes visitors guess whether activation navigates or expands something.

We will build Harbour with a separate overview link and a browser-owned disclosure for the other product pages. The Static site shell emits native links, details and summary elements from Compose. This is document navigation, not an ARIA application menu: ordinary Tab navigation is appropriate, and we are not promising menu-style arrow keys or Escape dismissal.

## Create the project

```sh
cargo install cargo-fission
fission init harbour-site --template website
cd harbour-site
cargo add serde_yaml
```

Keep the generated launcher, replace `src/lib.rs`, and add the modules below. Every checkpoint builds this actual HTML project. No local active_page enum or preview-only copy of its content is involved. Replace the reserved public origin before publishing.

## Establish the destinations before hiding them

Start with visible links. Each destination is a real route that can be opened directly, refreshed or shared. `Page` keeps stable paths separate from translated wording; `root` accounts for the route's depth so links also work beneath an embedded preview directory.

```rust
pub mod page;
mod navigation;
mod translations;
pub fn site_app() -> fission::site::FissionSite {
    use page::{Page, ProductPage};
    let mut site = fission::site::FissionSite::new().with_env(translations::create_env());
    for page in [Page::Home, Page::Overview, Page::Desktop, Page::Mobile] {
        site = site.route_widget::<(), _>(page.path(), page.title(),
            Some(page.description().into()), ProductPage::new(page));
    }
    site
}
pub fn build_site() -> anyhow::Result<()> {
    fission::site::build_from_cli(site_app())
}
```

```rust
use crate::navigation::ProductNavigation;
use fission::prelude::*;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Page { Home, Overview, Desktop, Mobile }
impl Page {
    pub fn path(self) -> &'static str {
        match self { Self::Home => "/", Self::Overview => "/products/",
            Self::Desktop => "/products/desktop/", Self::Mobile => "/products/mobile/" }
    }
    pub fn root(self) -> &'static str {
        match self { Self::Home => "", Self::Overview => "../", _ => "../../" }
    }
    pub fn title(self) -> &'static str {
        match self { Self::Home => "Harbour software", Self::Overview => "Harbour products",
            Self::Desktop => "Harbour desktop tools", Self::Mobile => "Harbour mobile tools" }
    }
    pub fn description(self) -> &'static str {
        match self {
            Self::Home => "Keep a project plan available at the desk and in the field.",
            Self::Overview => "Compare Harbour's desktop and mobile project tools.",
            Self::Desktop => "Review the plan and assign the next task from a desktop.",
            Self::Mobile => "Take the next task into the field on Android and iOS.",
        }
    }
    pub fn content_keys(self) -> (&'static str, &'static str) {
        match self { Self::Home => ("home.title", "home.body"),
            Self::Overview => ("overview.title", "overview.body"),
            Self::Desktop => ("desktop.title", "desktop.body"),
            Self::Mobile => ("mobile.title", "mobile.body") }
    }
}
fission_component! {
    pub ProductPage<()> { props { page: Page } }
    view(site, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let (title, body) = site.page.content_keys();
    } =>
    Container(Column(gap: tokens.spacing.xl, children: [
        ProductNavigation(site.page),
        SemanticsRegion(identifier: Some("site-main".into()), child:
            Column(gap: tokens.spacing.m, children: [
                SemanticsRegion(identifier: Some("site-heading-1:title".into()), child:
                    Text(cx.tr(title)).size(tokens.typography.heading1_size)),
                Text(cx.tr(body)),
                Link::to(cx.tr("nav.overview"), format!("{}products/", site.page.root())),
            ])),
    ])).padding_all(tokens.spacing.l).bg(tokens.colors.background)
}
```

```rust
use crate::page::Page;
use fission::prelude::*;
fission_component! {
    pub ProductNavigation<()> { props { page: Page } }
    view(nav, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let root = nav.page.root();
    } =>
    SemanticsRegion(identifier: Some("site-navigation".into()), label: Some(cx.tr("nav.label")), child:
        Row(gap: tokens.spacing.m, wrap: ir_op::FlexWrap::Wrap, children: [
            Link::to(cx.tr("brand"), if root.is_empty() { "./" } else { root }),
            Link::to(cx.tr("nav.overview"), format!("{root}products/")),
            Link::to(cx.tr("nav.desktop"), format!("{root}products/desktop/")),
            Link::to(cx.tr("nav.mobile"), format!("{root}products/mobile/")),
        ]))
}
```

```rust
use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;
pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("checked-in translations must be valid YAML");
        env.i18n.add_bundle(TranslationBundle { locale: Locale::from(locale), messages });
    }
    env
}
```

## Let the browser own the disclosure

The `site-disclosure:` and matching `site-disclosure-summary:` identifiers are the Static site shell's existing HTML conventions. The summary must belong to the disclosure with the same suffix. A named component owns that structure, so another screen cannot accidentally separate them.

The browser owns open and closed state. There is no effect, reducer or menu_open field to duplicate it. The Products overview remains an independent link, including when the disclosure is closed.

```rust
use crate::page::Page;
use fission::prelude::*;
fission_component! {
    pub ProductNavigation<()> { props { page: Page } }
    view(nav, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let root = nav.page.root();
    } =>
    SemanticsRegion(identifier: Some("site-navigation".into()), label: Some(cx.tr("nav.label")), child:
        Row(gap: tokens.spacing.m, wrap: ir_op::FlexWrap::Wrap, children: [
            Link::to(cx.tr("brand"), if root.is_empty() { "./" } else { root }),
            Link::to(cx.tr("nav.overview"), format!("{root}products/")),
            SemanticsRegion(identifier: Some("site-disclosure:products".into()), child:
                Column(children: [
                    SemanticsRegion(identifier: Some("site-disclosure-summary:products".into()), child:
                        Text(cx.tr("nav.pages"))),
                    SemanticsRegion(identifier: Some("product-links".into()), child:
                        Container(Column(gap: tokens.spacing.m, children: [
                            Link::to(cx.tr("nav.desktop"), format!("{root}products/desktop/")),
                            Link::to(cx.tr("nav.mobile"), format!("{root}products/mobile/")),
                        ])).padding_all(tokens.spacing.m).bg(tokens.colors.surface)
                            .border(tokens.colors.border, 1.0).border_radius(tokens.radii.medium)),
                ])),
        ]))
}
```

## Make the wide-screen dropdown fit a narrow page

On a wide screen the links can sit beneath their summary. On a phone they return to document flow, where opening them cannot cover the article or push a destination outside the viewport. The surface colours still come from the component's theme tokens; CSS supplies only the positioning rule.

Native details does not automatically close when you click elsewhere, and it is not a modal. Do not describe those behaviours as implemented. Following a link loads another document with its own initially closed disclosure.

```sh
fission site build --project-dir .
fission site check --project-dir .
fission site serve --project-dir . --port 8123
curl http://127.0.0.1:8123/products/desktop/
```

Inspect the response for real href destinations and a details/summary pair. A coloured rectangle that looks like a dropdown does not establish keyboard behaviour; activate the rendered controls and verify each destination.
