A dropdown that only works with a mouse is not enough for site navigation. It needs real page routes, keyboard support and links that still work when scripting is unavailable. We will build the Products menu as part of a static Rust site, then check the pointer, keyboard and touch paths in the preview.

Harbour's Products menu links to the overview, desktop apps and mobile apps. The Products label remains a normal link when the menu is closed, so a visitor does not have to discover a special interaction just to reach the overview.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init harbour-site --template website
cd harbour-site
```

The website template gives you a Static site entrypoint in `src/main.rs`, route registration and the Web shell in `src/lib.rs`, plus separate modules for the page, navigation and footer. Add the task files as you reach them. The preview's `src/app.rs` is a separate browser app used to try the lesson; the actual website uses the template modules and `fission.toml`. Keep those two pieces separate—`preview/lib.rs` is not the website entrypoint.

### Configure the site routes and Products dropdown

The Static site template turns `[[site.nav]]` into Fission's shared navigation component. Give the parent item its own useful destination, then add the nested product links beneath it. That way pointer and keyboard users can reach the same pages.

Merge the following fields into the template’s existing `[site]` table, then add the route and navigation entries below it. Edit the existing table instead of adding a second `[site]` table:

```toml
[site]
title = "Harbour"
description = "A project hub for Harbour desktop and mobile apps."
base_url = "https://harbour.example.com"
asset_dirs = ["assets"]
generate_sitemap = true
generate_robots = true

[[site.routes]]
kind = "content"
path = "/products"
source = "content/products"
template = "fission::site::documentation"

[[site.nav]]
title = "Products"
href = "/products/"

[[site.nav.children]]
title = "Desktop apps"
href = "/products/desktop/"

[[site.nav.children]]
title = "Mobile apps"
href = "/products/mobile/"
```

Create `content/products/index.mdx`, `desktop.mdx` and `mobile.mdx`. Give each page a distinct title and search description. Fission's navigation component already owns the menu interaction and semantics, so do not add another copy of that state to the page. Check that Products still works as a link, the nested items open from both keyboard and pointer input, and every direct URL loads after a refresh.

## Render product links in the site header

This first preview is a task card, not the site header. Its copy comes through props and its spacing uses theme tokens. Next, put Products and its destinations in the header before adding open and close behaviour.

<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub WebsiteNavigation<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Row(gap: tokens.spacing.m,
                    children: [Text("Harbour"),
                        Text("Products"),
                        Text("Desktop apps"),
                        Text("Mobile apps")]),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Add an open and close state

The Products menu needs one piece of retained state: whether it is open. Keep that state in the navigation component because no other screen needs it. Use a Fission `Button` for the toggle so focus, Enter, Space and pointer activation all use the same control.

Keep Products itself linked to the overview page. If the menu is closed, people can still get where they need to go. The preview below shows the menu state changing and lets you select a destination. This is view-only state; values shared across routes belong in `GlobalState` and change through reducers.
<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub WebsiteNavigation<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            menu_open: bool = false,
            active_page: usize = 0,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text(if preview.menu_open { "Close Products".to_string() } else { preview.action.clone() }),
                    key: "products-menu",
                    on_press: reduce { preview.menu_open = !preview.menu_open; }),
                if preview.menu_open { Column(children: [Button(child: Text("Desktop apps"),
                                key: "desktop-link",
                                on_press: reduce { preview.active_page = 1;
                                    preview.menu_open = false; }),
                            Button(child: Text("Mobile apps"),
                                key: "mobile-link",
                                on_press: reduce { preview.active_page = 2;
                                    preview.menu_open = false; })]) } else { Text(if preview.active_page == 1 { "Desktop apps" } else if preview.active_page == 2 { "Mobile apps" } else { "Product overview" }) },
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview a missing destination".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("That destination is unavailable. Return to Products and choose a current page.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Handle missing destinations and test keyboard use

Add the three Markdown routes and check that each one has a distinct title, a useful search description, a clear first heading and a next step. The compact layout stacks the menu entries so they still fit on a phone.

The preview also has a control that simulates a missing destination. It shows the error and recovery path, but it does not make a network, database or file-system request. In the real app, keep I/O out of component conversion: reducers make the state transition, then an effect, capability, job or service performs asynchronous work without blocking the UI.

## Run, test and build the finished project

Run these checks from the project root:

```sh
cargo test
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission site serve --project-dir . --host 127.0.0.1 --port 8123
fission test --target static-site --project-dir .
```

The menu should open and close, choosing a destination should update the preview, and the static build should contain every linked page.
