Create a responsive Rust website with a keyboard-accessible dropdown menu, crawlable page routes and a production-ready static build using Fission. The menu interaction runs in the browser preview. The finished site renders its pages as static HTML and keeps pointer, keyboard and touch navigation accessible.

The finished Harbour site has a Products menu with direct destinations for desktop and mobile products. A visitor can open the menu with a pointer or keyboard, select a destination and still follow ordinary page links when the menu is closed.

Install the Fission CLI and scaffold the Static site project:

```sh
cargo install cargo-fission
fission init harbour-site --template website
cd harbour-site
```

The website template creates a Static site project with a static entrypoint in `src/main.rs`, route registration and the Web shell in `src/lib.rs`, and reusable page, navigation and footer components in their own modules. Add the task files shown in the tree as you work. The preview's `src/app.rs` is a separate, compiled browser harness for the interactive lesson; the production website uses the template modules and `fission.toml`. Do not copy `preview/lib.rs` into the website.

### Configure the site routes and Products dropdown

The Static site template renders `[[site.nav]]` as the shared Fission navigation component. A parent keeps its own useful link, while the nested links expose destinations to pointer and keyboard users.

Merge the following fields into the template’s existing `[site]` table, then add the route and navigation entries below it. Edit the existing table instead of adding a second `[site]` table:

```toml
[site]
title = "Harbour"
description = "A project hub for Harbour desktop and mobile apps."
base_url = "https://harbour.example.com"
asset_dirs = ["assets"]
generate_sitemap = true
generate_robots = true

[[site.routes]]
kind = "content"
path = "/products"
source = "content/products"
template = "fission::site::documentation"

[[site.nav]]
title = "Products"
href = "/products/"

[[site.nav.children]]
title = "Desktop apps"
href = "/products/desktop/"

[[site.nav.children]]
title = "Mobile apps"
href = "/products/mobile/"
```

Create `content/products/index.mdx`, `desktop.mdx` and `mobile.mdx`. Give each page its own title and search description. The template's nested navigation is already a Fission component; leave its interaction and semantics there instead of adding a second menu state to the page. Test that Products remains a normal destination when closed, that its children open with keyboard and pointer input, and that each direct URL works after refresh.

## Render product links in the site header

Begin with the screen needed for this task. The first render gives you a concrete checkpoint before you add interaction state.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub WebsiteNavigation<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Row(gap: tokens.spacing.m,
                    children: [Text("Harbour"),
                        Text("Products"),
                        Text("Desktop apps"),
                        Text("Mobile apps")]),
                Text(format!("Next action: {}",
                        preview.action)),
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Add an open and close state

Give the Products button retained open and closed state inside its component. Use a real Fission Button so focus, Enter and Space work through the same input path as pointer activation. Keep the parent Products link pointed at a useful overview page; this avoids making the menu toggle the only way to reach product content.

The source below makes the main task interactive using retained component state and explicit controls.
This state belongs to the component because it only remembers this view's interaction. Durable data shared across routes belongs in GlobalState and changes through reducers.
<Tabs>
<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub WebsiteNavigation<()> {
        props {
            title: String,
            detail: String,
            action: String,
            success: String,
            empty: String,
        }
        state {
            menu_open: bool = false,
            active_page: usize = 0,
            has_error: bool = false,
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                Button(child: Text(if preview.menu_open { "Close Products".to_string() } else { preview.action.clone() }),
                    key: "products-menu",
                    on_press: reduce { preview.menu_open = !preview.menu_open; }),
                if preview.menu_open { Column(children: [Button(child: Text("Desktop apps"),
                                key: "desktop-link",
                                on_press: reduce { preview.active_page = 1;
                                    preview.menu_open = false; }),
                            Button(child: Text("Mobile apps"),
                                key: "mobile-link",
                                on_press: reduce { preview.active_page = 2;
                                    preview.menu_open = false; })]) } else { Text(if preview.active_page == 1 { "Desktop apps" } else if preview.active_page == 2 { "Mobile apps" } else { "Product overview" }) },
                Button(child: Text(if preview.has_error { "Try again".to_string() } else { "Preview a missing destination".to_string() }),
                    key: "preview-error",
                    on_press: reduce { preview.has_error = !preview.has_error; }),
                if preview.has_error { Text("That destination is unavailable. Return to Products and choose a current page.") } else { Text(preview.success.clone()) },
                Text(preview.empty.clone()).color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Handle missing destinations and test keyboard use

Create the nested Markdown routes and verify the whole route set before building. Every page should have a unique title, a useful search description, a descriptive first heading and a link to a next action. The compact layout stacks the menu entries so they do not overflow a phone-sized viewport.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The preview control below simulates an unsuccessful host result. It demonstrates the message and recovery path; it does not perform authentication, database, network, or filesystem work.

## Run, test and build the finished project

From the project root, run the checks in order:

```sh
cargo test
fission site routes --project-dir .
fission site check --project-dir .
fission site build --project-dir .
fission site serve --project-dir . --host 127.0.0.1 --port 8123
fission test --target static-site --project-dir .
```

Expected result: The menu opens and closes, destination selection updates the view, and each linked page exists in the static build.
