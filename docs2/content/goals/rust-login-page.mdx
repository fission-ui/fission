Harbour Supply staff open the app from a shift alert or an order task. This tutorial builds the login form, not authentication: the preview keeps its fields in the browser, checks that they look usable, and does not send credentials, sign anyone in, or create a session. A real app must verify credentials on the server and enforce access on every protected operation.

Install the Fission CLI and scaffold a Web project for the form preview:

```sh
cargo install cargo-fission
fission init harbour-login-form
cd harbour-login-form
cargo add serde_yaml
fission add-target web --project-dir .
```

The form owns only the values it displays. It does not own a user session or decide whether someone can access a protected page.

## Add labelled email and password fields

Start with the two fields a staff member needs and label them clearly. At this point the form only collects a work email and password; it does not submit them yet.

Read translated copy from `cx.tr(...)` and spacing, colour, and type from the active theme through `cx.view.env()`. That keeps this form aligned with the rest of the app.

```rust
use fission::prelude::*;
fission_component! {
    pub LoginForm<()> {
        state {
            email: String = String::new(),
            password: String = String::new(),
        }
    }
    view(login, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(cx.tr("login.brand")).weight(tokens.typography.font_weight_bold),
                Text(cx.tr("login.title")).color(tokens.colors.text_secondary),
                TextInput(label: Some(cx.tr("login.email.label").into()),
                    placeholder: Some(cx.tr("login.email.placeholder").into()),
                    required: true,
                    bind: login.email,
                    key: "login-email",
                    semantics_identifier: "harbour.login.email".to_string()),
                TextInput(label: Some(cx.tr("login.password.label").into()),
                    placeholder: Some(cx.tr("login.password.placeholder").into()),
                    required: true,
                    obscure_text: true,
                    bind: login.password,
                    key: "login-password",
                    semantics_identifier: "harbour.login.password".to_string()),
                Text(cx.tr("login.next"))
                    .color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;
use std::collections::HashMap;

const SOURCES: [(&str, &str); 2] = [
    ("en-US", include_str!("../i18n/en-US.yaml")),
    ("es-ES", include_str!("../i18n/es-ES.yaml")),
];

pub fn create_env() -> Env {
    let mut env = Env::default();
    env.locale = Locale::from("en-US");
    for (locale, source) in SOURCES {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid login tutorial translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(locale),
            messages,
        });
    }
    env
}
```

## Check input before handing it off

Keep this example on the form side of the boundary. It checks for an empty email, a basic email shape, and an empty password, then exposes a translated message through a semantic region. This is convenience validation only; it does not verify identity or send either field anywhere.

The form retains what the user entered so they can correct a value without starting again. The button uses a reducer for the local validation result; there is no fake request, demo account, or signed-in screen.

<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;

fn validate_login_form(email: &str, password: &str) -> Result<(), &'static str> {
    if email.trim().is_empty() {
        Err("login.validation.email_required")
    } else if !email.contains('@') {
        Err("login.validation.email_invalid")
    } else if password.is_empty() {
        Err("login.validation.password_required")
    } else {
        Ok(())
    }
}

fission_component! {
    pub LoginForm<()> {
        state {
            email: String = String::new(),
            password: String = String::new(),
            feedback: Option<String> = None,
        }
    }
    view(login, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("harbour-supply-login".to_string()),
        label: Some(cx.tr("login.semantics.form")),
        child: Container(Column(gap: tokens.spacing.m, children: [
            Column(gap: tokens.spacing.xs, children: [
                Text(cx.tr("login.brand")).weight(tokens.typography.font_weight_bold),
                Text(cx.tr("login.title")).weight(tokens.typography.font_weight_semibold),
                Text(cx.tr("login.detail")).color(tokens.colors.text_secondary),
            ]),
            TextInput(
                label: Some(cx.tr("login.email.label").into()),
                placeholder: Some(cx.tr("login.email.placeholder").into()),
                name: Some("email".into()),
                required: true,
                bind: login.email,
                key: "login-email",
                semantics_identifier: "harbour.login.email".to_string(),
            ),
            TextInput(
                label: Some(cx.tr("login.password.label").into()),
                placeholder: Some(cx.tr("login.password.placeholder").into()),
                name: Some("password".into()),
                required: true,
                obscure_text: true,
                bind: login.password,
                key: "login-password",
                semantics_identifier: "harbour.login.password".to_string(),
            ),
            if let Some(message_key) = &login.feedback {
                SemanticsRegion(
                    identifier: Some("harbour.login.feedback".to_string()),
                    label: Some(cx.tr(message_key)),
                    child: Text(cx.tr(message_key)).color(tokens.colors.text_secondary),
                )
            } else {
                Text(cx.tr("login.preview.note")).color(tokens.colors.text_secondary)
            },
            Button(
                child: Text(cx.tr("login.action.validate")),
                key: "validate-login-form",
                on_press: reduce {
                    login.feedback = Some(match validate_login_form(&login.email, &login.password) {
                        Ok(()) => "login.validation.not_connected",
                        Err(message_key) => message_key,
                    }.to_owned());
                },
            ).semantics_identifier("harbour.login.validate-form".to_string()),
        ]))
            .padding_all(tokens.spacing.l)
            .bg(tokens.colors.surface)
            .border(tokens.colors.border, 1.0)
            .border_radius(tokens.radii.large),
    )
}
```

## Keep authentication separate from the form

The `@` check here is only a small example of feedback while someone fills out a form. It is not a security check. A real service still needs to verify credentials on the server, avoid revealing whether an account exists, and authorize every protected operation independently.

This tutorial stops before that service boundary because the form alone cannot implement a trustworthy sign-in flow. Fission's protected-route widget controls which component tree is built; it is not a substitute for server authorization.
