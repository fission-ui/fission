Build a Rust SSR sign-in flow with accessible fields, server-side validation, signed form actions, rotated sessions and safe return navigation. The browser preview uses one fixed sample account and keeps its signed-in state in memory. It never sends credentials; the SSR form action still needs to verify the account and create the session on the server.

Harbour Supply warehouse staff arrive through links from shift alerts and order tasks. The sign-in route should return each teammate to that local destination after authentication, while a generic rejection message prevents the screen from confirming whether an email belongs to an account. The browser preview checks a fixed demo account in memory; credentials and session creation stay on the server.

Install the Fission CLI and scaffold the SSR project:

```sh
cargo install cargo-fission
fission init harbour-auth
cd harbour-auth
fission add-target ssr --project-dir .
```

## Project layout

```text
harbour-auth/
├── Cargo.toml                 # generated dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                 # generated desktop entrypoint
│   ├── lib.rs                  # shared app setup
│   ├── app.rs                  # the Fission component shown in this tutorial
│   ├── state.rs
│   ├── auth/session.rs
│   ├── server/login.rs
│   ├── components/login_form.rs
├── platforms/                  # generated host files after add-target
└── tests/                      # project-specific flow checks
```

Keep cookie handling in `auth/session.rs` and credential lookup in `server/login.rs`. The sign-in component owns only the values visible in this form. In production, the server checks a password hash, rotates the session after success, and sends the user only to a verified local return path.

## Add labelled email and password fields

Keep the first screen calm: warehouse staff should recognize which account to use and why the app needs them to sign in. Bind the visible fields to this component before wiring submission.

Use props for page copy and read theme tokens through cx.view.env(). The component below keeps presentation aligned with the active design system.

<TabItem label="src/app.rs">

```rust
use fission::prelude::*;
fission_component! {
    pub LoginForm<()> {
        props {
            title: String,
            detail: String,
        }
        state {
            email: String = String::new(),
            password: String = String::new(),
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                TextInput(label: Some("Work email".into()),
                    placeholder: Some("you@example.com".into()),
                    bind: preview.email,
                    key: "login-email",
                    semantics_identifier: "harbour.login.email".to_string()),
                TextInput(label: Some("Password".into()),
                    placeholder: Some("Enter your password".into()),
                    obscure_text: true,
                    bind: preview.password,
                    key: "login-password",
                    semantics_identifier: "harbour.login.password".to_string()),
                Text("Next, connect these fields to the server-side sign-in action.")
                    .color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Validate input and show submission state

Keep credential checks on the server. Validate the submitted fields there, sign the action token, and rotate the session after a successful authentication. Return a clear field-level error for an invalid submission without echoing a password or telling an attacker which account exists.

The sample account is demo@harbour.example with password CedarPeak-2026. Submit those values to open the warehouse shift screen; change either value to see the same generic rejection a server should return for unknown credentials. This deterministic check is local to the preview. In the SSR app, verify the password hash, rate-limit failures, rotate the session, and keep the return path on the server.

```rust
use fission::prelude::*;

fission_component! {
    pub LoginForm<()> {
        props {
            title: String,
            detail: String,
            action: String,
        }
        state {
            email: String = String::new(),
            password: String = String::new(),
            signed_in: bool = false,
            has_error: bool = false,
            feedback: String = String::new(),
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("harbour-supply-login".to_string()),
        label: Some("Harbour Supply sign-in".to_string()),
        child:
        if preview.signed_in {
            Container(Column(gap: tokens.spacing.l, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text("Harbour Supply").weight(tokens.typography.font_weight_bold),
                        Text("Morning fulfilment shift").color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: "Demo session".to_string()),
                ]),
                Column(gap: tokens.spacing.xs, children: [
                    Text(format!("Welcome, {}.", preview.email.clone()))
                        .weight(tokens.typography.font_weight_semibold),
                    Text("Your warehouse shift is ready to continue.")
                        .color(tokens.colors.text_secondary),
                ]),
                Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                    Badge(text: "6 orders ready to pick".to_string()),
                    Badge(text: "2 stock alerts to review".to_string()),
                ]),
                Text("Start with the six orders due before 10:00.")
                    .color(tokens.colors.text_secondary),
                Button(
                    child: Text("Sign out"),
                    key: "sign-out",
                    on_press: reduce {
                        preview.signed_in = false;
                        preview.email.clear();
                        preview.password.clear();
                        preview.has_error = false;
                        preview.feedback.clear();
                    },
                ),
            ]))
                .padding_all(tokens.spacing.l)
                .bg(tokens.colors.surface)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.large)
        } else {
            Container(Column(gap: tokens.spacing.m, children: [
                Column(gap: tokens.spacing.xs, children: [
                    Text("Harbour Supply").weight(tokens.typography.font_weight_bold),
                    Text(preview.title.clone()).weight(tokens.typography.font_weight_semibold),
                    Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                ]),
                TextInput(
                    label: Some("Work email".into()),
                    placeholder: Some("you@example.com".into()),
                    name: Some("email".into()),
                    required: true,
                    bind: preview.email,
                    key: "login-email",
                    semantics_identifier: "harbour.login.email".to_string(),
                ),
                TextInput(
                    label: Some("Password".into()),
                    placeholder: Some("Enter your password".into()),
                    name: Some("password".into()),
                    required: true,
                    obscure_text: true,
                    bind: preview.password,
                    key: "login-password",
                    semantics_identifier: "harbour.login.password".to_string(),
                ),
                if preview.has_error {
                    SemanticsRegion(
                        identifier: Some("harbour-login-error".to_string()),
                        label: Some(preview.feedback.clone()),
                        child: Text(preview.feedback.clone())
                            .color(tokens.colors.text_secondary),
                    )
                } else {
                    Column(gap: tokens.spacing.xs, children: [
                        Text("Preview account").weight(tokens.typography.font_weight_semibold),
                        Text("demo@harbour.example · CedarPeak-2026")
                            .color(tokens.colors.text_secondary),
                    ])
                },
                Button(
                    child: Text(preview.action.clone()),
                    key: "sign-in",
                    on_press: reduce {
                        if preview.email.trim().eq_ignore_ascii_case("demo@harbour.example")
                            && preview.password == "CedarPeak-2026"
                        {
                            preview.signed_in = true;
                            preview.has_error = false;
                            preview.feedback.clear();
                        } else {
                            preview.signed_in = false;
                            preview.has_error = true;
                            preview.feedback = "Email or password not recognized. Check the preview account details and try again.".to_string();
                        }
                    },
                ),
                Text("This preview checks one fixed account in memory. It does not send credentials to a server.")
                    .color(tokens.colors.text_secondary),
            ]))
                .padding_all(tokens.spacing.l)
                .bg(tokens.colors.surface)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.large)
        },
    )
}
```

## Keep authentication and redirects on the server

Accept a return destination only when it is a local path on this application. Preserve the entered email after a recoverable validation error, but clear secrets. Test an invalid password, a missing field, a session rotation and a hostile external return URL.

Keep I/O outside component conversion. Use reducers for explicit state transitions, then queue host work through an asynchronous effect, capability, job or service so the UI stays responsive.
The sign-in preview accepts only the displayed sample account and stores the result in component state. On the server, use the same generic rejection for an unknown email or incorrect password, and never send password values back in rendered HTML.

Configure the server-managed session cookie in `fission.toml`:

<!-- fission:file path="fission.toml" -->
```toml
[server.sessions]
cookie_name = "harbour_session"
signing_key_env = "HARBOUR_SESSION_SECRET"
secure = true
same_site = "lax"
```

Fission signs and protects the session cookie. Your authentication service still verifies credentials and stores the authenticated user id server-side; the cookie does not prove who the user is by itself.
