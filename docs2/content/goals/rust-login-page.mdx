Harbour Supply staff often open the app from a shift alert or an order task. After they sign in, send them back to that page—but only when the destination is on this site. Validate the fields and keep the credentials on the server. Use the same rejection message for an unknown email and a wrong password so the form does not reveal whether an account exists.

The browser preview uses a fixed demo account to show the flow. It does not send credentials or create a session; the SSR app performs those checks on the server.

Install the Fission CLI and scaffold the SSR project:

```sh
cargo install cargo-fission
fission init harbour-auth
cd harbour-auth
fission add-target ssr --project-dir .
```

## Project layout

```text
harbour-auth/
├── Cargo.toml                 # generated dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                 # generated desktop entrypoint
│   ├── lib.rs                  # shared app setup
│   ├── app.rs                  # the Fission component shown in this tutorial
│   ├── state.rs
│   ├── auth/session.rs
│   ├── server/login.rs
│   ├── components/login_form.rs
├── platforms/                  # generated host files after add-target
└── tests/                      # project-specific flow checks
```

Keep cookie handling in `auth/session.rs` and credential lookup in `server/login.rs`. The form component owns the values it displays; it does not own the authenticated session. In production, the server verifies a password hash, rotates the session after sign-in and accepts only a checked local return path.

## Add labelled email and password fields

Start with the two fields a staff member needs and label them clearly. At this point the form only collects a work email and password; it does not submit them yet.

Pass the page copy in as props, then read spacing, colour and type from the active theme through `cx.view.env()`. That keeps this form aligned with the rest of the app.

<TabItem label="src/app.rs">
<!-- fission:file path="src/app.rs" -->
```rust
use fission::prelude::*;
fission_component! {
    pub LoginForm<()> {
        props {
            title: String,
            detail: String,
        }
        state {
            email: String = String::new(),
            password: String = String::new(),
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Container(
        Column(
            gap: tokens.spacing.m,
            children: [
                Text(preview.title.clone()).weight(tokens.typography.font_weight_bold),
                Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                TextInput(label: Some("Work email".into()),
                    placeholder: Some("you@example.com".into()),
                    bind: preview.email,
                    key: "login-email",
                    semantics_identifier: "harbour.login.email".to_string()),
                TextInput(label: Some("Password".into()),
                    placeholder: Some("Enter your password".into()),
                    obscure_text: true,
                    bind: preview.password,
                    key: "login-password",
                    semantics_identifier: "harbour.login.password".to_string()),
                Text("Next, connect these fields to the server-side sign-in action.")
                    .color(tokens.colors.text_secondary),
            ]
        )
    )
    .padding_all(tokens.spacing.l)
    .bg(tokens.colors.surface)
    .border(tokens.colors.border, 1.0)
    .border_radius(tokens.radii.large)
}
```

## Validate input and show submission state

The preview now lets you try the sign-in flow with a fixed account. Use `demo@harbour.example` and `CedarPeak-2026` to see the signed-in screen. Change either value and the preview shows the same generic rejection. This is only an in-memory demo; no credentials leave the browser.

In the SSR app, the server must validate the submitted fields, verify the password hash, rate-limit failures and rotate the session after success. Show a useful field-level error, but do not echo a password or disclose whether an email is registered.

```rust
use fission::prelude::*;

fission_component! {
    pub LoginForm<()> {
        props {
            title: String,
            detail: String,
            action: String,
        }
        state {
            email: String = String::new(),
            password: String = String::new(),
            signed_in: bool = false,
            has_error: bool = false,
            feedback: String = String::new(),
        }
    }
    view(preview, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    SemanticsRegion(
        identifier: Some("harbour-supply-login".to_string()),
        label: Some("Harbour Supply sign-in".to_string()),
        child:
        if preview.signed_in {
            Container(Column(gap: tokens.spacing.l, children: [
                Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                    Column(gap: tokens.spacing.xs, children: [
                        Text("Harbour Supply").weight(tokens.typography.font_weight_bold),
                        Text("Morning fulfilment shift").color(tokens.colors.text_secondary),
                    ]),
                    Spacer(flex_grow: 1.0),
                    Badge(text: "Demo session".to_string()),
                ]),
                Column(gap: tokens.spacing.xs, children: [
                    Text(format!("Welcome, {}.", preview.email.clone()))
                        .weight(tokens.typography.font_weight_semibold),
                    Text("Your warehouse shift is ready to continue.")
                        .color(tokens.colors.text_secondary),
                ]),
                Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                    Badge(text: "6 orders ready to pick".to_string()),
                    Badge(text: "2 stock alerts to review".to_string()),
                ]),
                Text("Start with the six orders due before 10:00.")
                    .color(tokens.colors.text_secondary),
                Button(
                    child: Text("Sign out"),
                    key: "sign-out",
                    on_press: reduce {
                        preview.signed_in = false;
                        preview.email.clear();
                        preview.password.clear();
                        preview.has_error = false;
                        preview.feedback.clear();
                    },
                ),
            ]))
                .padding_all(tokens.spacing.l)
                .bg(tokens.colors.surface)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.large)
        } else {
            Container(Column(gap: tokens.spacing.m, children: [
                Column(gap: tokens.spacing.xs, children: [
                    Text("Harbour Supply").weight(tokens.typography.font_weight_bold),
                    Text(preview.title.clone()).weight(tokens.typography.font_weight_semibold),
                    Text(preview.detail.clone()).color(tokens.colors.text_secondary),
                ]),
                TextInput(
                    label: Some("Work email".into()),
                    placeholder: Some("you@example.com".into()),
                    name: Some("email".into()),
                    required: true,
                    bind: preview.email,
                    key: "login-email",
                    semantics_identifier: "harbour.login.email".to_string(),
                ),
                TextInput(
                    label: Some("Password".into()),
                    placeholder: Some("Enter your password".into()),
                    name: Some("password".into()),
                    required: true,
                    obscure_text: true,
                    bind: preview.password,
                    key: "login-password",
                    semantics_identifier: "harbour.login.password".to_string(),
                ),
                if preview.has_error {
                    SemanticsRegion(
                        identifier: Some("harbour-login-error".to_string()),
                        label: Some(preview.feedback.clone()),
                        child: Text(preview.feedback.clone())
                            .color(tokens.colors.text_secondary),
                    )
                } else {
                    Column(gap: tokens.spacing.xs, children: [
                        Text("Preview account").weight(tokens.typography.font_weight_semibold),
                        Text("demo@harbour.example · CedarPeak-2026")
                            .color(tokens.colors.text_secondary),
                    ])
                },
                Button(
                    child: Text(preview.action.clone()),
                    key: "sign-in",
                    on_press: reduce {
                        if preview.email.trim().eq_ignore_ascii_case("demo@harbour.example")
                            && preview.password == "CedarPeak-2026"
                        {
                            preview.signed_in = true;
                            preview.has_error = false;
                            preview.feedback.clear();
                        } else {
                            preview.signed_in = false;
                            preview.has_error = true;
                            preview.feedback = "Email or password not recognized. Check the preview account details and try again.".to_string();
                        }
                    },
                ),
                Text("This preview checks one fixed account in memory. It does not send credentials to a server.")
                    .color(tokens.colors.text_secondary),
            ]))
                .padding_all(tokens.spacing.l)
                .bg(tokens.colors.surface)
                .border(tokens.colors.border, 1.0)
                .border_radius(tokens.radii.large)
        },
    )
}
```

## Keep authentication and redirects on the server

Treat the return destination as untrusted input. Accept it only when it is a local path on this application; otherwise an attacker could send a signed-in user to an unrelated site. After a recoverable error, keep the email so the user does not have to type it again, but clear the password.

Component conversion should not perform I/O. Use a reducer for the state transition and queue server or host work through an asynchronous effect, job, capability or service. That keeps the UI responsive and makes success and failure explicit.

The preview accepts only its displayed sample account and stores the result in component state. A real server should return the same rejection for an unknown email and an incorrect password. Never put a password into rendered HTML.

Configure the server-managed session cookie in `fission.toml`:

<!-- fission:file path="fission.toml" -->
```toml
[server.sessions]
cookie_name = "harbour_session"
signing_key_env = "HARBOUR_SESSION_SECRET"
secure = true
same_site = "lax"
```

Fission signs and protects the session cookie. Your authentication service is still responsible for verifying the credentials and storing the authenticated user ID on the server. The cookie protects session data; it does not verify a user's identity on its own.

```sh
cargo test
fission build --target ssr --project-dir .
fission test --target ssr --project-dir .
```
