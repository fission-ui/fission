A technician should not have a different inspection record because they opened it on another kind of phone. The work order, its completion status and its saved note describe the job; Android and iOS provide different hosts for working with it.

We will keep those job facts in shared Rust and build the same Compose screen for both targets. A note remains a local draft until the technician chooses to retain it against the work order. Sharing that behaviour does not remove the need to check each platform's keyboard, available space and launch process.

Install the Fission CLI and scaffold the Android and iOS project:

```sh
cargo install cargo-fission
fission init harbour-mobile
cd harbour-mobile
cargo add serde_yaml
fission add-target android ios --project-dir .
```

## Project layout

```text
harbour-mobile/
├── Cargo.toml                 # generated dependencies
├── fission.toml               # app identity, targets and capabilities
├── src/
│   ├── main.rs                 # generated shared app entrypoint
│   ├── lib.rs                  # shared app setup
│   ├── app.rs                  # the Fission component shown in this tutorial
│   ├── state.rs              # the work order and its saved note
│   └── translations.rs
├── i18n/
│   ├── en-US.yaml
│   └── es-ES.yaml
├── platforms/
│   ├── android/
│   └── ios/
└── tests/                      # project-specific flow checks
```

`fission init` generates `Cargo.toml`, `fission.toml`, `src/main.rs`, `src/lib.rs` and `src/app.rs`. Add the task modules in the tree as you build the feature. Keep data shared across routes in `GlobalState`, and keep retained interaction such as a disclosure or draft field in the owning `fission_component!`. Request database, filesystem, network and session work through a reducer effect, job or service; never run host work while a component view is being built.

`preview/lib.rs` compiles the complete `src/app.rs` into WebAssembly so you can try the shared screen here. It does not emulate Android or iOS. Use the target-specific steps below to check native launch and interaction.

The preview seeds one work order in `preview/lib.rs`. `MobileTaskState::default()` stays empty; demo data does not become a production default.

Replace the generated `src/lib.rs` with the launcher below. Without that change, the normal target command would still run the scaffold's counter. The normal app starts with a form for entering an existing handover. It stores that record in memory on this installation; it does not authenticate a dispatcher or synchronise devices. The preview supplies one sample record so the later controls are immediately visible.

Keep user-facing labels in checked-in English and Spanish bundles. The launchers install both bundles and explicitly start in English. Selecting a supported device locale or adding an in-app language choice is a separate step; do not claim this example detects it automatically. The work-order details are supplied by the person entering the handover, so they are app data rather than translated interface labels. This example records an operator's status, not evidence that equipment is safe to use.

use crate::state::{InspectionTask, MobileTaskState};
use fission::prelude::*;

pub fn valid_details(values: [&str; 6]) -> bool {
    values.iter().all(|value| !value.trim().is_empty() && value.chars().count() <= 500)
}

fission_component! {
    pub AssignmentForm<MobileTaskState> {
        state {
            reference: String = String::new(),
            title: String = String::new(),
            site: String = String::new(),
            equipment: String = String::new(),
            due: String = String::new(),
            instructions: String = String::new(),
        }
    }
    view(form, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let ready = valid_details([&form.reference, &form.title, &form.site,
            &form.equipment, &form.due, &form.instructions]);
    } =>
    Column(gap: tokens.spacing.m, children: [
        Text(cx.tr("load.explanation")),
        FormControl(label: cx.tr("load.reference"), required: true, child:
            TextInput(bind: form.reference, semantics_identifier: "work.load.reference".to_string())),
        FormControl(label: cx.tr("load.title"), required: true, child:
            TextInput(bind: form.title, semantics_identifier: "work.load.title".to_string())),
        FormControl(label: cx.tr("load.site"), required: true, child:
            TextInput(bind: form.site, semantics_identifier: "work.load.site".to_string())),
        FormControl(label: cx.tr("load.equipment"), required: true, child:
            TextInput(bind: form.equipment, semantics_identifier: "work.load.equipment".to_string())),
        FormControl(label: cx.tr("load.due"), required: true, child:
            TextInput(bind: form.due, semantics_identifier: "work.load.due".to_string())),
        FormControl(label: cx.tr("load.instructions"), required: true, child:
            TextInput(bind: form.instructions, semantics_identifier: "work.load.instructions".to_string())),
        Button(child: Text(cx.tr("load.action")), key: "load-work-order",
            disabled: !ready,
            on_press: reduce {
                if state.task.is_none() && valid_details([&form.reference, &form.title,
                    &form.site, &form.equipment, &form.due, &form.instructions]) {
                    state.task = Some(InspectionTask {
                        reference: form.reference.trim().to_owned(),
                        title: form.title.trim().to_owned(),
                        site: form.site.trim().to_owned(),
                        equipment: form.equipment.trim().to_owned(),
                        due: form.due.trim().to_owned(),
                        instructions: form.instructions.trim().to_owned(),
                        complete: false, latest_note: None,
                    });
                }
            }).semantics_identifier("work.load.confirm"),
    ])
}

use crate::state::*;
use crate::assignment::AssignmentForm;
use fission::prelude::*;

fission_component! {
    pub MobileTaskPlanner<MobileTaskState>
    view(_planner, state, cx) {
        let tokens = &cx.view.env().theme.tokens;
        let shift_status = match &state.task {
            Some(task) if task.complete => cx.tr("shift.no_due"),
            Some(_) => cx.tr("shift.one_due"),
            None => cx.tr("shift.no_work"),
        };
    } =>
    Container(SafeArea(
        child: Scroll(
            direction: FlexDirection::Column,
            show_scrollbar: true,
            flex_grow: 1.0,
            child: Container(
                SemanticsRegion(
                    identifier: Some("mobile-field-work".to_string()),
                    label: Some(cx.tr("work.screen_label")),
                    child: Column(gap: tokens.spacing.l, children: [
                        Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                            Column(gap: tokens.spacing.xs, children: [
                                Text(cx.tr("shift.team"))
                                    .weight(tokens.typography.font_weight_bold),
                                Text(cx.tr("shift.morning"))
                                    .color(tokens.colors.text_secondary),
                            ]),
                            Spacer(flex_grow: 1.0),
                            Badge(text: shift_status),
                        ]),
                        match &state.task {
                            Some(task) => Container(Column(gap: tokens.spacing.m, children: [
                                Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                                    Text(task.reference.clone())
                                        .weight(tokens.typography.font_weight_semibold),
                                    Badge(text: if task.complete {
                                        cx.tr("work.complete")
                                    } else {
                                        format!("{} {}", cx.tr("work.due"), task.due)
                                    }),
                                ]),
                                Text(task.title.clone())
                                    .size(tokens.typography.heading2_size)
                                    .weight(tokens.typography.font_weight_bold),
                                Text(format!("{} · {}", task.site, task.equipment))
                                    .color(tokens.colors.text_secondary),
                                Text(task.instructions.clone()),
                            ]))
                                .padding_all(tokens.spacing.l)
                                .bg(tokens.colors.surface)
                                .border(tokens.colors.border, 1.0)
                                .border_radius(tokens.radii.large),
                            None => AssignmentForm(),
                        },
                    ]),
                ),
            )
                .padding_all(tokens.spacing.l),
        )
    ))
    .height_length(Length::vh(100.0))
    .bg(tokens.colors.background)
}

    let mut env = Env::default();
    env.locale = Locale::from(locale);
    for (bundle_locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),

        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(bundle_locale),
            messages,
        });
    }
    env
}

## Share state across Android and iOS

Use shared state and component modules for the product workflow. Give touch targets comfortable space, make the main action reachable without precise gestures, and keep labels visible when a control is selected. Check the same route or screen with long translated text.

The work order is shared application data, so changing its status updates `GlobalState`. The inline reducer stays beside the action here because this tutorial uses it only once; a transition shared by several screens should be a named reducer.

## Keep an unsent note local and save it to shared state

A saved note belongs to the work order, not to an unrelated app-wide “latest note” value. Store it inside that record. Saving below moves the non-empty draft into shared memory and clears the editor only after the record is updated; it does not write to disk or send a report.

The note draft belongs to this editor, so keep it in the component's retained `state`. Once the technician saves it, it becomes work-order data in `GlobalState` and both Android and iOS render the same result. The preview shows that state transition without pretending to save to a server or device.

use crate::state::*;
use crate::assignment::AssignmentForm;
use fission::prelude::*;

fission_component! {
    pub MobileTaskPlanner<MobileTaskState> {
        state {
            note_draft: String = String::new(),

    view(planner, state, cx) {

        let shift_status = match &state.task {
            Some(task) if task.complete => cx.tr("shift.no_due"),
            Some(_) => cx.tr("shift.one_due"),
            None => cx.tr("shift.no_work"),
        };
    } =>
    Container(SafeArea(
        child: Scroll(
            direction: FlexDirection::Column,
            show_scrollbar: true,
            flex_grow: 1.0,
            child: Container(
                SemanticsRegion(
                    identifier: Some("mobile-field-work".to_string()),
                    label: Some(cx.tr("work.screen_label")),
                    child: Column(gap: tokens.spacing.l, children: [
                        Row(gap: tokens.spacing.m, align_items: ir_op::AlignItems::Center, children: [
                            Column(gap: tokens.spacing.xs, children: [
                                Text(cx.tr("shift.team"))
                                    .weight(tokens.typography.font_weight_bold),
                                Text(cx.tr("shift.morning"))
                                    .color(tokens.colors.text_secondary),
                            ]),
                            Spacer(flex_grow: 1.0),
                            Badge(text: shift_status),
                        ]),
                        match &state.task {
                            Some(task) => Container(Column(gap: tokens.spacing.m, children: [
                                Row(gap: tokens.spacing.s, wrap: ir_op::FlexWrap::Wrap, children: [
                                    Text(task.reference.clone())
                                        .weight(tokens.typography.font_weight_semibold),
                                    Badge(text: if task.complete {
                                        cx.tr("work.complete")
                                    } else {
                                        format!("{} {}", cx.tr("work.due"), task.due)
                                    }),
                                ]),
                                Text(task.title.clone())
                                    .size(tokens.typography.heading2_size)
                                    .weight(tokens.typography.font_weight_bold),
                                Text(format!("{} · {}", task.site, task.equipment))
                                    .color(tokens.colors.text_secondary),

                                        cx.tr("work.action.complete")
                                    }),
                                    key: "toggle-inspection",
                                    on_press: reduce {
                                        if let Some(task) = state.task.as_mut() {
                                            task.complete = !task.complete;
                                        }

                                .semantics_identifier("mobile-work-order.complete".to_string()),

                                    on_press: reduce {
                                        let note = planner.note_draft.trim().to_string();

                                                task.latest_note = Some(note);

                                            }

use std::collections::HashMap;

use fission::i18n::{Locale, TranslationBundle};
use fission::prelude::*;

pub fn create_env(locale: &str) -> Env {
    let mut env = Env::default();
    env.locale = Locale::from(locale);
    for (bundle_locale, source) in [
        ("en-US", include_str!("../i18n/en-US.yaml")),
        ("es-ES", include_str!("../i18n/es-ES.yaml")),
    ] {
        let messages: HashMap<String, String> =
            serde_yaml::from_str(source).expect("valid work-order translations");
        env.i18n.add_bundle(TranslationBundle {
            locale: Locale::from(bundle_locale),
            messages,
        });
    }
    env
}

## Run, test and build the finished project

Before running the app, follow the [Android development setup guide](/blog/set-up-rust-android-gui-development-with-fission/) to install the SDK and NDK, and the [iOS development setup guide](/blog/set-up-rust-ios-development-with-fission/) to install Xcode and the Rust targets. Those guides also cover starting an emulator or Simulator and connecting a device.

From the project root, list available devices, launch each target, then run the checks:

```sh
fission doctor --project-dir .
fission devices --project-dir .
fission run --target android --project-dir .
fission run --target ios --project-dir .
cargo test
fission build --target android --project-dir .
fission build --target ios --project-dir .
fission test --target android --project-dir .
fission test --target ios --project-dir .
```

Expected result: The native launchers use the same work-order model and reducers on Android and iOS; without a working record, they let the operator enter an existing handover. The screen adapts to each shell, shared status changes remain app data, and the unsaved note stays local to its editor.

`fission run --target android` launches the selected emulator or connected Android device. `fission run --target ios` launches an iOS Simulator; it does not install the app on a physical iPhone. Use the [Android emulator guide](/blog/create-and-launch-a-fission-android-emulator/) or [Android phone guide](/blog/run-a-fission-app-on-a-physical-android-phone/) when you need those setup steps, and the [iOS Simulator guide](/blog/choose-boot-and-launch-an-ios-simulator-with-fission/) or [physical iPhone guide](/blog/install-a-fission-app-on-a-physical-iphone/) for iOS.
