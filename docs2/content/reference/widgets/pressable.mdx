# Pressable

An entire report tile may need to act as one control, rather than placing a
small button beside its contents. `Pressable` supplies that interaction
boundary without deciding what the tile looks like. It owns focus, activation,
semantics, pointer state, and optional motion and ripple feedback.

Use built-in widgets such as `Button`, `Link`, `MenuItem`, `Checkbox`, and `Switch` when they fit. Use `Pressable` when the visual shape is custom but the interaction is still a button, link, or menu item.

```rust
use fission::prelude::*;

fission_component! {
    pub ReportTile<()> {
        props {
            content: Widget,
            accessible_label: String,
            open_report: ActionEnvelope,
        }
    }
    view(tile, _state, cx) {
        let spacing = &cx.view.env().theme.tokens.spacing;
    } =>
    Pressable(
        child: tile.content.clone(),
        on_press: tile.open_report.clone(),
        label: tile.accessible_label.clone(),
        role: PressableRole::Button,
        layout: BoxStyle::default().padding_symmetric(
            Length::points(spacing.m),
            Length::points(spacing.s),
        ),
    )
}
```

The parent supplies the report content, translated accessible label, and an
action already bound to the correct report. For a dynamic collection, call
`ReportTile(content, label, open_report, key: report.id.clone())` so retained
interaction state follows the report rather than its list position. Do not
put another button inside a tile that already acts as one button.

## Important fields

| Field | Meaning |
| --- | --- |
| `child` | Content displayed inside the interaction surface. |
| `on_press` | Action dispatched for pointer, keyboard, or accessibility activation. |
| `label` | Accessible label. |
| `semantics_identifier` | Stable automation and accessibility identifier. |
| `role` | `Button`, `Link`, or `MenuItem`. |
| `focus_policy` | How pointer activation affects current focus. |
| `layout` | Shared `BoxStyle` sizing and placement contract. |
| `style` / state styles | Base, hover, pressed, focused, and disabled visual overlays. |

Always set a semantic identifier for product-important controls.
