# Responsive

`Responsive` selects one child from ordered breakpoint cases plus a required fallback.

```rust
const PHONE_BREAKPOINT: f32 = 720.0;
const TABLET_BREAKPOINT: f32 = 1_120.0;

Responsive::new_with_id(WidgetId::explicit("settings.responsive"), || DesktopLayout)
    .case_max_width_with(PHONE_BREAKPOINT, || PhoneLayout)
    .case_between_with(
        PHONE_BREAKPOINT,
        TABLET_BREAKPOINT,
        || TabletLayout,
    )
```

## Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `Option<WidgetId>` | Stable identity for diagnostics and retained branch structure. |
| `query` | `ResponsiveQuery` | Width source: viewport or parent container. |
| `cases` | `Vec<ResponsiveCase>` | Ordered breakpoint cases. First match wins. |
| `fallback` | `Widget` | Rendered when no case matches. |

## Cases

| Constructor | Meaning |
| --- | --- |
| `ResponsiveCase::min_width(width, child)` | Matches widths greater than or equal to `width`. |
| `ResponsiveCase::max_width(width, child)` | Matches widths below `width`. |
| `ResponsiveCase::between(min, max, child)` | Matches `min <= width < max`. |

Use `.container_query()` when a reusable component should respond to parent constraints instead of the full viewport.

The identity-aware constructors convert each branch beneath a separate
retained scope. Construct independent component values for each branch; never
clone one retained `Widget` into several cases. Every branch can be lowered,
so being hidden is not a guarantee that a component's resources are absent.
Use `ProtectedRoute` for an access prerequisite rather than a responsive case.
