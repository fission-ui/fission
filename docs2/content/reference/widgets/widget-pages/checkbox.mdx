# Checkbox

`Checkbox` represents an independent yes-or-no choice, including one item in
a multi-select list.

Use [`Radio`](/reference/widgets/radio) when the user must choose exactly one
option from a group.

## Example

```rust
use fission::prelude::*;
#[fission_action]
struct ToggleNewsletter;

fn on_toggle(state: &mut SettingsState, _action: ToggleNewsletter, _ctx: &mut ReducerContext<SettingsState>) {
state.receive_newsletter = !state.receive_newsletter;
}

let widget: Widget = Checkbox {
checked: view.state().receive_newsletter,
label: Some("Receive product updates".into()),
on_toggle: Some(ctx.bind(
    ToggleNewsletter,
    reduce_with!(on_toggle),
)),
..Default::default()
}
.into();
```

The checkbox does not flip itself. It emits an action, the reducer changes `GlobalState`, and the next conversion pass reads the new `checked` value from `ViewHandle`.

## Field table

| Field | Type | Meaning | Notes / default behavior |
| --- | --- | --- | --- |
| `id` | `Option<WidgetId>` | Stable widget identity. | Defaults to `None`. |
| `name` | `Option<String>` | Successful-control name for Static site and SSR forms. | Several checkboxes may share a repeated field name. |
| `form_id` | `Option<String>` | Associates the checkbox with a server form. | Must match the form schema id. |
| `form_value` | `Option<String>` | Machine value submitted when checked. | Leave unset for a Boolean field (`on`); set a distinct value for each repeated option. |
| `checked` | `bool` | Whether the checkbox is currently selected. | Defaults to `false`. |
| `on_toggle` | `Option<ActionEnvelope>` | Action dispatched when the user toggles the checkbox. | Defaults to `None`. |
| `label` | `Option<String>` | Visible text shown next to the indicator. | Defaults to `None`, but most real checkboxes should have a label. |

## Interaction and accessibility behavior

`Checkbox` lowers a semantic checkbox role with the current checked state, so assistive technology can report it correctly and automated tests can find it by role. The label text is also used as the semantic label when present.

Because the control is controlled by state, it is easy to test. Given a known `checked` value, the same build always produces the same visual and semantic result.

## Specific advice

Prefer a checkbox when the choice can stay pending until a later submit. If the control means an immediate app setting that turns behavior on or off right away, a [`Switch`](/reference/widgets/switch) often reads more naturally.

For a repeated server-form field, give every option the same `name` and a
distinct `form_value`:

```rust
Checkbox {
    name: Some("regions".into()),
    form_id: Some("connect".into()),
    form_value: Some(region.code.clone()),
    checked: selected_regions.contains(&region.code),
    ..Default::default()
}
```

Declare the matching schema field with `ServerFormField::repeated("regions")`
and deserialize it into `#[serde(default)] regions: Vec<String>`.

## Production checklist

- Bind `on_toggle` to explicit reducer actions and test that the reducer handles unavailable, duplicate, or invalid input safely.
- Set `id` only when identity must be stable across filtering, reordering, diagnostics, or tests; otherwise let Fission derive identity from structure.
- Check the semantics tree for the user-facing label or role that makes this widget understandable without relying only on pixels.
- Add at least one component or harness test that confirms the visible text, semantic role, action dispatch, and layout constraint that matter for this widget in context.
