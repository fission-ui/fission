# Timeline

`Timeline` is the chronological sequence widget.

Use it when order matters more than tabular comparison. Timelines work well for activity feeds, deployment history, message milestones, shipping updates, and audit trails.

Use `TimelineLayout` when entries contain retained interactive content or have
different heights. It keeps the marker rail and connector owned by Fission while
the application supplies cards, controls, or other semantic entry content.

## Example

```rust
use fission::prelude::*;

let widget: Widget = Timeline {
    items: vec![
        TimelineItem {
            title: "Queued".into(),
            description: Some("Waiting for an available runner".into()),
            timestamp: Some("09:58".into()),
        },
        TimelineItem {
            title: "Running".into(),
            description: Some("Tests are executing".into()),
            timestamp: Some("10:03".into()),
        },
    ],
}
.into();
```

For rich entries, give each entry a durable identity:

```rust
let widget: Widget = TimelineLayout::new(vec![
    TimelineEntry::new(
        WidgetId::explicit("deploy.build"),
        Card {
            child: Text::new("Build and test").into(),
            ..Default::default()
        },
    ),
    TimelineEntry::new(
        WidgetId::explicit("deploy.review"),
        Button {
            content: Some(ButtonContent::new("Review")),
            on_press: Some(review_action),
            ..Default::default()
        },
    ),
])
.spacing(12.0, 16.0)
.into();
```

## Field table

| Field | Type | Meaning | Notes / default behavior |
| --- | --- | --- | --- |
| `items` | `Vec<TimelineItem>` | Events shown from top to bottom. | Defaults to an empty list. |

`TimelineLayout` accepts `TimelineEntry` values with a stable `id`, retained
`child`, and optional retained `marker`. Its builders configure marker geometry,
entry spacing, and connector paint without making callers draw connector
segments themselves.

## Layout and usage guidance

The checked-in renderer draws a dot and vertical connector line for each item, then stacks the event content beside it. This makes the widget easy to scan in a single column.

A timeline is strongest when entries represent real moments in a meaningful order. If users mostly need to compare attributes across many rows, a table is usually the better fit.

## Specific advice

Avoid stuffing a full paragraph into every event. Timelines stay readable when the title carries the main meaning and the description adds only the context that helps the user decide what happened.

## Check the timeline in context

- Pass events in the order you want people to read them; keep the title short and put only useful context in the description.
- Use `TimelineLayout` when entries have different heights or contain controls, and give each retained entry a durable identity.
- Test long translated entries and narrow widths so text does not obscure the marker rail or connector.
