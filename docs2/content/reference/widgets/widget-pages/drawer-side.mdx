# DrawerSide

`DrawerSide` chooses which edge a [`Drawer`](/reference/widgets/drawer) opens
from. It is configuration, not a widget.

Keep the choice consistent across your app. A left drawer often holds
navigation; a right drawer often holds details, filters, or tools.

## Example

```rust
use fission::prelude::*;

fission_component! {
    pub NavigationDrawer<()> {
        props { is_open: bool, content: Widget, close: ActionEnvelope }
    }
    view(drawer, _state, _cx) =>
    Drawer(
        side: DrawerSide::Left,
        is_open: drawer.is_open,
        on_dismiss: drawer.close.clone(),
        content: drawer.content.clone(),
    )
}
```

The parent owns visibility and supplies a bound close action. Changing the
edge does not change that ownership or make the drawer route navigation by
itself. Compose supplies the retained widget identity.

## Variant table

| Variant | Type | Meaning | Notes / default behavior |
| --- | --- | --- | --- |
| `Left` | `DrawerSide` | Pins the drawer panel to the left edge of the viewport. | A good fit for navigation or app-wide browsing structure. |
| `Right` | `DrawerSide` | Pins the drawer panel to the right edge of the viewport. | A good fit for inspectors, filters, settings, or supporting tools. |

## Specific advice

`DrawerSide` only covers left and right. If your design really wants content to slide down from the top or up from the bottom, `Drawer` is the wrong tool. Use a different overlay pattern such as a [`Modal`](/reference/widgets/modal), a custom [`Portal`](/reference/widgets/portal), or a sheet-style widget once one exists in your design system.

On phones, pay extra attention to hand reach, safe areas, and whether the drawer is replacing primary navigation or supporting an already-visible screen. On desktop and large web layouts, a right-side drawer often works well for detail panels because it leaves the main reading flow undisturbed.
