# Single axis

![Single axis screenshot](/img/charts/single-axis.png)

Events or weighted points arranged along one numeric axis. Use it for timelines, distributions, and event density when a second axis would add noise. The screenshot is from Fission's chart gallery.

## What the chart is for

This chart is in the **Coordinates** family. Use it when a visual makes the pattern easier to spot.

Avoid it when readers need exact linear comparison; coordinate charts work best when the coordinate system carries meaning.

## Data model

`Vec<(value, size)> on a single horizontal scale.` Keep the source values in Rust types. Fission Charts uses typed series and options, not string-based configuration.

## Rust API

| Field | Type | Notes |
| --- | --- | --- |
| `title` | `&str` | Names the chart for the screen, accessibility tree, and test output. |
| `series` | `SingleAxisSeries` | Stores value/size pairs along one numeric axis. |
| `width / height` | `f32` | Optional fixed size; omit them when the chart should flex inside Fission layout. |

## Example

```rust
use fission::charts::{Chart, SingleAxisSeries};

let chart = Chart::new()
    .title("Single axis")
    .series(vec![SingleAxisSeries::new("Events")
        .data(vec![(2.0, 12.0), (7.0, 28.0), (13.0, 20.0), (22.0, 36.0)])
        .into()]);
```

## Interaction and animation

Only add interaction when it helps the user. Fission emits typed `ChartInteractionEvent` values for hover, press, release, scroll, selection, and brush actions; handle them in a reducer. Use `ChartAnimation` to set duration, delay, stagger, easing, and reduced-motion behavior. Those settings stay visible and testable.

## Testing guidance

Test that your data maps to the series you expect. If you change how the chart is built or rendered, capture a live screenshot. To refresh the gallery image, run the ignored chart-gallery screenshot test with `FISSION_UPDATE_CHART_DOCS=1`; it updates `documentation/static/img/charts` before the static-site build.

## Authoring from a Fission component

Add the chart to any Fission layout, including a `Card`, `Grid`, `Scroll`, or responsive section.

```rust
use fission::prelude::*;
use fission::charts::{Chart, SingleAxisSeries};



fission_component!
{
    pub SingleAxisChart<()> {
    }
    view(_component, _state, _cx) => rust {
        Chart::new()
                    .title("Single axis")
                    .series(vec![SingleAxisSeries::new("Events")
                        .data(vec![(2.0, 12.0), (7.0, 28.0), (13.0, 20.0), (22.0, 36.0)])
                        .into()])
                    .into()
    }
}
```
Load the data before building the chart. Put the request or other async work in a reducer, job, service, or server route, then read the result from state in the component.

## Options, accessibility, and diagnostics

| Area | What to decide | How to check it |
| --- | --- | --- |
| Data shape | Keep source rows in typed Rust structs, then map them into the series shown above. | Test that mapping separately from chart rendering. |
| Options | Pick axes, legends, labels, motion, and interaction to answer the screen's question. | Add a screenshot test when the chart's appearance changes. |
| Accessibility | Give the chart a clear title and explain important values in nearby text. Do not rely on color alone. | Inspect its semantics and check that the chart still makes sense without color. |
| Failure handling | Show a loading, empty, or error state when the data is not ready. | Test empty data, partial data, and a failed fetch. |
| Performance | Summarize or window very large datasets; keep the full history in your data layer. | Profile frame time and interaction latency with representative data. |
