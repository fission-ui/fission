# 3D service cloud

![3D service cloud screenshot](/img/charts/scene3d-service-cloud.png)

Service measurements are not physical coordinates. If latency, error rate and request volume become the three dimensions, their different units must be dealt with explicitly. Otherwise a large numeric request count can dominate the picture simply because it uses a larger unit.

Keep the raw observations and choose documented reference values for the display. A normalised position is a projection, not a replacement for the measured latency or traffic.

## Prepare the positions

This helper expresses each dimension relative to its reference value. It rejects invalid inputs rather than plotting them at zero. Values above a reference remain above one; they are not clamped into an ordinary-looking range.

```rust
use fission::three_d::Point3D;

pub struct ServiceObservation {
    pub latency_ms: f32,
    pub error_fraction: f32,
    pub requests_per_second: f32,
}

pub fn service_positions(
    observations: &[ServiceObservation],
    references: [f32; 3],
) -> Result<Vec<Point3D>, &'static str> {
    if references.iter().any(|value| !value.is_finite() || *value <= 0.0) {
        return Err("display references must be finite and positive");
    }
    observations.iter().map(|observation| {
        let values = [
            observation.latency_ms,
            observation.error_fraction,
            observation.requests_per_second,
        ];
        if values.iter().any(|value| !value.is_finite() || *value < 0.0)
            || observation.error_fraction > 1.0
        {
            return Err("invalid service observation");
        }
        let scaled = [
            values[0] / references[0],
            values[1] / references[1],
            values[2] / references[2],
        ];
        if scaled.iter().any(|value| !value.is_finite()) {
            return Err("display position exceeds the supported range");
        }
        Ok(Point3D::new(scaled[0], scaled[1], scaled[2]))
    }).collect()
}
```

Pass the positions to `PointCloudScene` from [Point cloud](./point-cloud), with a translated title and a constant marker radius. Enable Fission's `three-d` feature. Keep this projection with the analytics model and handle a rejected observation before building the scene.

## Interpretation and checks

Show the dimension meanings, units and reference values outside the image. The scene does not automatically draw measurement axes, classify service health or emit a chart event identifying each service.

Test normalisation, invalid fractions, zero references and values above the reference. Inspect a rendered view for overlapping services and retain a labelled table of the original measurements. The screenshot is the gallery fixture, not a claim about a real service's performance.
