# Relationships and hierarchy

Relationships and quantities need different representations. A dependency graph connects records, a tree gives each child one parent, and a treemap or sunburst adds an additive measure to that hierarchy. Choose the relationship before choosing the layout.

Prepare the model through ordinary Rust and the application's effect/reducer workflow. Components receive the prepared snapshot and localized labels rather than discovering dependencies, scanning storage or fetching report data during conversion.

## Variants

| Chart | Data shape | Use when |
| --- | --- | --- |
| [Force graph](./graph-force) | Vertex list plus edge list. | Use it for dependency, social, and topology diagrams. |
| [Funnel](./funnel-basic) | Ordered label/value pairs. | Use it for conversion stages and pipeline health. |
| [Parallel coordinates](./parallel-basic) | Vec&lt;Vec&lt;f32&gt;&gt; with one row per observation. | Compare prepared 0–100 dimensions; real filtering needs application controls. |
| [Radial tree](./tree-radial) | Nested nodes with required numeric values. | Use it when the hierarchy is shallow and symmetry matters more than linear reading. |
| [Sankey](./sankey-basic) | Vertex list plus unweighted links. | Show two-stage connections; current links do not encode quantitative flow. |
| [Sunburst](./sunburst-basic) | Nested nodes with values. | Use it when hierarchy depth should remain visible. |
| [Theme river](./theme-river) | Time, value, and category tuples. | Compare regular, preaggregated category buckets; labels are spaced evenly. |
| [Tree](./tree-basic) | Nested nodes with required numeric values. | Use it for navigation structures, ownership trees, and dependency drilldown. |
| [Treemap](./treemap-basic) | Nested nodes with values. | Use it for storage, budgets, or part-to-whole hierarchy. |

## Choosing within this family

Use a graph when relationships can be shared or cyclic, and a tree when the data has one parent per child. For a part-to-whole hierarchy, define a consistent non-negative measure and reconcile parent totals with their children before using a treemap or sunburst.

The current Sankey links are unweighted and use a two-column layout. Parallel coordinates use a fixed 0–100 scale without automatic named axes or filtering. Theme-river input is lexically ordered and zero-filled; its smooth-looking bands do not establish continuous measurement. Each variant page explains these boundaries.

## Authoring from a Fission component

A prepared budget hierarchy is one small presentation input. Financial arithmetic, aggregation and failure handling stay with the parent report.

```rust
use fission::prelude::*;
use fission::charts::{Chart, TreemapSeries, TreemapNode};

// The parent resolves display labels from its translation bundles.
fission_component! {
    pub BudgetHierarchyOverview<()> {
        props {
            chart_title: String,
            series_label: String,
            budget_gbp: Vec<TreemapNode>,
        }
    }
    view(report, _state, _cx) => Chart(
        title: Some(report.chart_title.clone()),
        series: vec![TreemapSeries::new(&report.series_label)
            .data(report.budget_gbp.clone())
            .into()],
    )
}
```

## Checks

Test node identity, missing link endpoints, repeated names and aggregation separately from rendering. Keep source IDs and exact quantities in the domain model rather than deriving them from a display index or rectangle.

Inspect the actual output for hidden nodes, overlapping labels and unreadable small regions. Provide the same relationships and important quantities in accessible text or a structured list. A chart does not automatically supply navigation, disclosure or domain filtering merely because its subject is a hierarchy.
