# Route map overlay

![Route map overlay screenshot](/img/charts/geo-route-map.png)

A delivery report may need a service-area map and a view of transfers between depots. The first represents area; the second represents relationships. Merely drawing them in one chart does not establish that their coordinates align.

Use [NetworkRegionReport](./geo-network) as a Compose boundary, with the regional map carrying coverage or demand and its connection panel carrying dispatch totals. The complete descriptions should be constructed with ordinary Rust struct literals so every required input is supplied.

For example, the connection records can be projected from dispatch data:

```rust
use crate::widgets::service_connections::ServiceConnection;

pub struct DepotDispatch {
    pub id: String,
    pub origin: (f32, f32),
    pub destination: (f32, f32),
    pub delivered_parcels: u32,
}

pub fn delivered_routes(rows: &[DepotDispatch]) -> Vec<ServiceConnection> {
    rows.iter().filter(|row| row.delivered_parcels > 0).map(|row| ServiceConnection {
        id: row.id.clone(),
        from: row.origin,
        to: row.destination,
        traffic: row.delivered_parcels as f32,
    }).collect()
}
```

The row type and projection belong in the report's data module; the reusable connection component is defined in [lines](../geographic-and-route/lines-basic) at `widgets/service_connections.rs`. Translate panel titles and explain the reporting window. Retain exact parcel counts and stable dispatch IDs.

This is a paired map and schematic, not a verified route overlay. `MapSeries` and `LinesSeries` currently use different fitting rules; the gallery does not remove that limitation. It is also not a road route or travel-time calculation. Test missing depots, reversed directions and no completed dispatches.
