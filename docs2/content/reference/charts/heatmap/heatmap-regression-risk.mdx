# Regression risk matrix

![Regression risk matrix screenshot](/img/charts/heatmap-regression-risk.png)

A regression-risk matrix helps a release review direct attention to combinations of components and change areas. Its value comes from making the assessment inspectable, not from giving a subjective score the appearance of precision. The screenshot is from Fission's chart gallery.

## What the chart is for

Here, higher means more review needed. Keep that direction and the scoring range consistent between releases. A missing assessment is not the same as a reviewed component with a score of zero.

## Data model

Each triple identifies a component, review area and score from zero to five. Define that scoring rule outside the chart and retain the evidence behind each assessment. The renderer cannot derive a probability of regression from these values.

`HeatmapSeries::data` takes `Vec<(usize, usize, f32)>`. The first two values are category indices; they must refer to the same ordered labels used by the axes.

## Rust API

| Setting | Type | Meaning |
| --- | --- | --- |
| `Chart::x_axis` | `Axis` | Supplies the column categories. |
| `Chart::y_axis` | `Axis` | Supplies the row categories, not the cell-value range. |
| `HeatmapSeries::data` | `Vec<(usize, usize, f32)>` | Supplies the indexed cells and their values. |
| `Chart::visual_map` | `VisualMap` | Sets the numeric range used for colour. |

## Example

```rust
use fission::charts::{Axis, Chart, HeatmapSeries, VisualMap};

let chart = Chart::new()
    .title("Release review scores by component and area")
    .x_axis(Axis::category(vec!["Billing", "Search", "Identity"]))
    .y_axis(Axis::category(vec!["Data changes", "User flows"]))
    .visual_map(VisualMap::new().min(0.0).max(5.0))
    .series(vec![HeatmapSeries::new("Review score (0–5)")
        .data(vec![
            (0, 0, 5.0),
            (1, 0, 1.0),
            (2, 0, 3.0),
            (0, 1, 4.0),
            (1, 1, 2.0),
            (2, 1, 4.0),
        ])
        .into()]);
```

## Authoring from a Fission component

Pass the prepared samples into the component. Fetching, aggregation and failure handling stay outside the build; the component presents values already available to its parent.

```rust
use fission::prelude::*;
use fission::charts::{Axis, Chart, HeatmapSeries, VisualMap};

// The parent resolves display labels from its translation bundles.
fission_component! {
    pub RegressionRiskMatrixChart<()> {
        props {
            chart_title: String,
            series_label: String,
            column_labels: Vec<String>,
            row_labels: Vec<String>,
            samples: Vec<(usize, usize, f32)>,
        }
    }
    view(chart, _state, _cx) =>
        Chart(
            title: Some(chart.chart_title.clone()),
            x_axis: Some(Axis::category(
                chart.column_labels.iter().map(String::as_str).collect(),
            )),
            y_axis: Some(Axis::category(
                chart.row_labels.iter().map(String::as_str).collect(),
            )),
            visual_map: Some(VisualMap::new().min(0.0).max(5.0)),
            series: vec![HeatmapSeries::new(&chart.series_label)
                .data(chart.samples.clone())
                .into()],
        )
}
```

## Testing and accessibility

Test unknown assessments separately from zero scores, and check category remapping when a component is added. Make the evidence available in text or a detail view rather than requiring a user to trust the colour.

Give the matrix a text summary and an exact-value view when decisions depend on its cells. Inspect the actual rendered width and label lengths; a correctly indexed matrix is still unusable if its category names cannot be read.
