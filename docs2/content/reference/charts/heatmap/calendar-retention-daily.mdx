# Daily retention calendar

![Daily retention calendar screenshot](/img/charts/calendar-retention-daily.png)

A retention calendar can show when existing users return to an app. The useful distinction is between returning users and all active users: a busy acquisition day can increase activity without showing that anyone came back. The screenshot is from Fission's chart gallery.

## What the chart is for

This example counts distinct users active on the day who had also used the app before that day. It is not a cohort-retention percentage. Use a cohort chart if the question is how many people return a fixed number of days after signing up.

## Data model

Each sample is an ISO date and a returning-user count. Deduplicate users within each day and use one timezone for both previous activity and the displayed day. Keep the return definition in the aggregation layer rather than hiding it in chart construction.

## Rust API

| Setting | Type | Meaning |
| --- | --- | --- |
| `CalendarHeatmapSeries::data` | `Vec<(&str, f32)>` | Converts date/value pairs into the series' owned `Vec<(String, f32)>`. |
| `CalendarHeatmapSeries::range` | `&str, &str` | Sets the displayed start and end dates. |
| `Chart::visual_map` | `VisualMap` | Sets the numeric colour range. |
| `Chart::series` | `Vec<Series>` | Adds the calendar series; Cartesian axes are not required. |

## Example

```rust
use fission::charts::{CalendarHeatmapSeries, Chart, VisualMap};

let chart = Chart::new()
    .title("Returning users per day")
    .visual_map(VisualMap::new().min(0.0).max(200.0))
    .series(vec![CalendarHeatmapSeries::new("Returning users")
        .range("2026-10-01", "2026-10-31")
        .data(vec![
            ("2026-10-01", 127.0),
            ("2026-10-02", 142.0),
            ("2026-10-03", 133.0),
        ])
        .into()]);
```

## Authoring from a Fission component

The parent supplies the daily values. This component presents them; it does not start a request during the build.

```rust
use fission::prelude::*;
use fission::charts::{CalendarHeatmapSeries, Chart, Series, VisualMap};

// The parent resolves display labels from its translation bundles.
fission_component! {
    pub DailyRetentionCalendarChart<()> {
        props {
            chart_title: String,
            series_label: String,
            daily_values: Vec<(String, f32)>,
        }
    }
    view(calendar, _state, _cx) =>
        Chart(
            title: Some(calendar.chart_title.clone()),
            visual_map: Some(VisualMap::new().min(0.0).max(200.0)),
            series: vec![Series::CalendarHeatmap(CalendarHeatmapSeries {
                name: calendar.series_label.clone(),
                data: calendar.daily_values.clone(),
                start: Some("2026-10-01".into()),
                end: Some("2026-10-31".into()),
            })],
        )
}
```

## Interaction and accessibility

Selecting a day can filter the underlying aggregate report through a reducer. Explain the returning-user definition beside the chart; colour and a date alone cannot distinguish this count from daily active users.

## Testing guidance

Check a user's first day, several visits on one day, and a return on a later day. Repeated visits must not increase a distinct-user count. Missing activity data also needs its own state rather than being recorded as no returning users. Check the rendered calendar at the dashboard's actual width as well as testing the aggregate values.
