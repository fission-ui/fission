# Monitoring

Monitoring views should make a particular operational question easier to answer. A request-rate trend, dependency graph and availability calendar describe different facts; they do not become interchangeable because they appear on the same dashboard.

Keep collection, aggregation and alert policy in the application model. Effects load observations, reducers update the report, and Compose presents the resulting state. Building a chart is not the place to start a monitoring request.

## Choosing within this family

Start with the measure, its unit and its reporting window. A count and a rate answer different questions, whilst an average can hide a tail-latency problem. Preserve missing observations instead of quietly converting them into successful zero readings.

Use spatial views only when position carries information. Use a graph for relationships, a calendar for day-level patterns and a line for ordered measurements. The gallery's 3D scenes use the `three-d` feature and a separate scene API, not 3D `Chart` series.

## Authoring from a Fission component

A small presentation boundary can receive a prepared report without owning the monitoring service or copying its data-fetching logic.

```rust
use fission::prelude::*;
use fission::charts::{Axis, Chart, LineSeries};

// The parent resolves display labels from its translation bundles.
fission_component! {
    pub MonitoringOverviewChart<()> {
        props {
            chart_title: String,
            series_label: String,
            labels: Vec<String>,
            requests_per_second: Vec<f32>,
        }
    }
    view(report, _state, _cx) {
        let labels = report.labels.iter().map(String::as_str).collect();
    } =>
        Chart(
            title: Some(report.chart_title.clone()),
            x_axis: Some(Axis::category(labels)),
            y_axis: Some(Axis::value().min(0.0)),
            series: vec![
                LineSeries::new(&report.series_label)
                    .data(report.requests_per_second.clone())
                    .into(),
            ],
        )
}
```

## Checks

Test aggregation, units, counter resets and the relation between labels and values independently of rendering. Exercise loading, failed collection and late responses in the parent workflow. A stale report needs an observation time so the reader can distinguish old data from a current healthy reading.

Then inspect the rendered view for clipped labels, overlapping marks and ambiguous scales. Keep the current values and operational findings available as text; colour, motion and pointer-only gestures must not be the only way to understand an incident.
