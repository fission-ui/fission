# Dataset and dynamic

A dynamic chart is still a projection of application state. Data arrives through the ordinary effect/reducer flow; the component receives a ready snapshot and constructs the matching series. The chart does not acquire a subscription merely because an example is named dynamic.

These sixteen examples cover actual dataset encodings, source changes, meaningful series choices and colour scales. They distinguish what the current renderer does from behaviour that still belongs to the application.

## Keep one report authority

Validate and aggregate source records in ordinary Rust. Named dataset dimensions are runtime schema keys, not compiler-checked struct fields. The current numeric extractor can turn malformed or absent cells into zero, so build complete typed projections rather than allowing that fallback to conceal an error.

Preserve domain identities outside the chart. A brushed or zoomed item index belongs to its displayed projection and snapshot; resolve it before treating it as an order, account or resource ID.

## Updates do not change interpretation

Use stable reporting windows, denominators and units when comparing updates. A gauge uses a fixed 0–100 dial, whilst polar extents are relative to the displayed maximum. Pictorial symbols follow their fixed count rule, and a radar polygon is not an overall health score.

Concentric effect-scatter rings are visual emphasis, not asynchronous effects or an alert subscription. Timeline and toolbox graphics likewise do not implement dataset switching, playback or export. The relevant examples use actual Compose controls and existing state transitions where application behaviour is required.

## Compose, accessibility and checks

Built-in chart fields use normal `Chart(...)` composition and explicit `Series` variants. Required-prop component reuse uses fully specified Rust struct literals, preserving required inputs without assuming a generated `Default`.

Supply translated visible labels and design-system colours. Keep exact values, IDs and essential explanations in accessible content, including missing/stale/error states. Use LiveTest to exercise actual gestures and controls, inspect both small and large layouts, and profile representative datasets rather than inferring performance from the gallery screenshots.
