# Scatter clusters

![Scatter clusters screenshot](/img/charts/scatter-clusters.png)

A scatter plot can make groups of observations visible without deciding how those groups should be classified. For delivery analysis, distance and elapsed delivery time may reveal several operating patterns. The screenshot is from Fission's chart gallery.

## What the chart is for

Treat apparent clusters as a reason to inspect route type, service level or traffic conditions. The chart does not run a clustering algorithm or establish that distance alone caused a delay.

## Data model

`ScatterSeries` takes `(x, y)` numeric pairs. Keep distance in one unit and time under one start/end definition. Preserve delivery IDs and other explanatory attributes in the source model rather than deriving them from vector positions.

## Authoring from a Fission component

The parent supplies validated completed-delivery observations, not generated cluster fixtures.

```rust
use fission::prelude::*;
use fission::charts::{Axis, Chart, ScatterSeries};

// The parent resolves display labels from its translation bundles.
fission_component! {
    pub DeliveryDistanceTimeScatter<()> {
        props {
            chart_title: String,
            series_label: String,
            axis_label: String,
            axis_label_2: String,
            observations: Vec<(f32, f32)>,
        }
    }
    view(report, _state, _cx) => Chart(
        title: Some(report.chart_title.clone()),
        x_axis: Some(Axis::value().name(&report.axis_label)),
        y_axis: Some(Axis::value().name(&report.axis_label_2)),
        series: vec![ScatterSeries::new(&report.series_label)
            .data(report.observations.clone())
            .into()],
    )
}
```

## Testing and accessibility

Test overlapping deliveries, an unusually long route and incomplete deliveries excluded by the report rule. Provide exact values and filters outside the plot; marker overlap can conceal how many deliveries share a position.
