# Analytics

An analytics chart is a projection of a report, not the report's source of truth. Before choosing a shape, decide what is counted, which records are eligible, and what period the values describe. Those choices determine whether the parts can be added and whether two values can reasonably be compared.

The twenty examples below use the ordinary chart widget through Compose. Their inputs come from application state; network requests and aggregation belong in the reporting layer and asynchronous effect flow, not component conversion.

## Decide the comparison first

Use a line for a trend over equal periods, bars for category comparisons, and a heatmap when two categorical dimensions matter. A pie or donut requires exclusive parts of one whole. A hierarchy requires the same additive measure at each level.

A rate needs a denominator as well as a numerator. A retention cohort needs a declared age and enough time to reach it. An unknown observation is not automatically a zero. Resolve those distinctions before projecting records into `Vec<f32>`.

## Compose and the application boundary

Enable Fission's `charts` feature, then use the named components in the individual examples. Pass translated labels and a ready snapshot from the parent; keep report filters in the appropriate application state and use reducers to update them.

The examples avoid a separate chart-authoring model. `Chart(...)` remains a normal Compose node, whilst typed series and axes are ordinary Rust values. A projection that needs validation should return a result in the reporting layer so the screen can show a meaningful loading, empty or error state.

## Read the current boundaries

The specific pages explain limits that affect interpretation: radar and parallel profiles use a fixed 0–100 scale; Sankey ribbons are unweighted; the treemap draws top-level nodes; geographic routes do not inherit a shared projection merely by appearing beside a map series. These are reasons to choose a suitable view, not details to conceal behind a convincing screenshot.

The gallery images are reference fixtures. Test the application's aggregation and mapping independently, then use LiveTest to inspect its actual small and large layouts. Keep exact values, category names and important conclusions available in text or tables rather than requiring colour, hover or shape alone.
