# Pie

![Pie screenshot](/img/charts/pie-basic.png)

A pie chart shows how a few categories make up a whole. Use it when the overall share matters more than precise ranking. The screenshot is from Fission's chart gallery.

## What the chart is for

This example is in the **Radial and polar** family. It uses `Label/value pairs` to show a small number of parts against the whole.

If there are many categories or the values are close together, use a bar chart instead. It is easier to compare exact values that way.

## Data model

The data is a set of `Label/value pairs`. Keep it in your app's Rust types and map it into the `PieSeries` shown below.

## Rust API

| Field | Type | Notes |
| --- | --- | --- |
| `title` | `&str` | Names the chart for the screen, accessibility tree, and test output. |
| `series` | `PieSeries` | Holds label/value pairs plus donut and rose settings. |
| `width / height` | `f32` | Optional fixed size; omit them when the chart should flex inside Fission layout. |

## Example

```rust
use fission::charts::{Chart, PieSeries};

let chart = Chart::new()
    .title("Share")
    .series(vec![PieSeries::new("Share")
        .data(vec![("Search", 1048.0), ("Direct", 735.0), ("Email", 580.0), ("Ads", 484.0)])
        .into()]);
```

## Interaction and animation

Only add interaction when it helps the user. Fission emits typed `ChartInteractionEvent` values for hover, press, release, scroll, selection, and brush actions; handle them in a reducer. Use `ChartAnimation` to set duration, delay, stagger, easing, and reduced-motion behavior. Those settings stay visible and testable.

## Testing guidance

Test that your data maps to the series you expect. If you change chart rendering, capture a live screenshot. To refresh the gallery image, run the ignored chart-gallery screenshot test with `FISSION_UPDATE_CHART_DOCS=1`; it updates `documentation/static/img/charts` before the static site build.

## Authoring from a Fission component

Use this example as a starting point for a Fission component. Put the chart inside a `Card`, `Grid`, `Scroll`, responsive section, or any other layout container.

```rust
use fission::prelude::*;
use fission::charts::{Chart, PieSeries};



fission_component!
{
    pub PieChart<()> {
    }
    view(_component, _state, _cx) => rust {
        Chart::new()
                    .title("Share")
                    .series(vec![PieSeries::new("Share")
                        .data(vec![("Search", 1048.0), ("Direct", 735.0), ("Email", 580.0), ("Ads", 484.0)])
                        .into()])
                    .into()
    }
}
```
Load chart data before the component builds. Use a reducer, job, service, or server route to fetch and prepare it, then read the result from state in the component.

## Options, accessibility, and diagnostics

| Area | What to decide | How to check it |
| --- | --- | --- |
| Data shape | Keep source rows in typed Rust structs, then map them into the series shown above. | Test that mapping separately from chart rendering. |
| Options | Pick axes, legends, labels, motion, and interaction to answer the screen's question. | Add a screenshot test when the chart's appearance changes. |
| Accessibility | Give the chart a clear title and explain important values in nearby text. Don't rely on color alone. | Inspect its semantics and check that the trend still makes sense without color. |
| Failure handling | Show a loading, empty, or error state when the data is not ready. | Test empty data, partial data, and a failed fetch. |
| Performance | Summarize or window very large datasets; keep the full history in your data layer. | Profile frame time and interaction latency with representative data. |
