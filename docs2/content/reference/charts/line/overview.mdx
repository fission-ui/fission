# Line

A line chart puts ordered measurements on a common scale so changes become visible. The order is part of the meaning: joining categories that have no meaningful sequence creates a trend that the source data does not contain.

Charts are regular Fission widgets, so use the same layout, theme, and state APIs as anywhere else in your app. Load the data before building the chart; reducers, resources, jobs, or services can update it.

## Choosing within this family

Start with the measure and reporting interval. Counts, rates and percentiles require different preparation even though each becomes a vector of numbers. Use steps for discrete transitions, a shared stack only for disjoint parts of a total, and marks for declared events or limits. Neither smoothing a path nor drawing a band calculates a statistical average, forecast or confidence interval.

## Authoring from a Fission component

This component receives the values and their reporting labels. Loading, aggregation and failures stay in the parent workflow; chart construction does not start another request.

```rust
use fission::prelude::*;
use fission::charts::{Axis, Chart, LineSeries};

// The parent resolves display labels from its translation bundles.
fission_component! {
    pub LineChart<()> {
        props {
            chart_title: String,
            series_label: String,
            labels: Vec<String>,
            completed_jobs: Vec<f32>,
        }
    }
    view(report, _state, _cx) {
        let labels = report.labels.iter().map(String::as_str).collect();
    } =>
        Chart(
            title: Some(report.chart_title.clone()),
            x_axis: Some(Axis::category(labels)),
            y_axis: Some(Axis::value()),
            series: vec![
                LineSeries::new(&report.series_label)
                    .data(report.completed_jobs.clone())
                    .into(),
            ],
        )
}
```
Keep a readable statement of the current value and reporting period alongside the visual. Test the source calculation independently from rendering, then inspect the actual plot at the widths where the app will use it.

## Options, accessibility, and diagnostics

| Area | What to decide | How to check it |
| --- | --- | --- |
| Data shape | Keep source rows in typed Rust structs, then map them into the series shown above. | Test that mapping separately from chart rendering. |
| Options | Pick axes, legends, labels, motion, and interaction to answer the screen's question. | Add a screenshot test when the chart's appearance changes. |
| Accessibility | Give the chart a clear title and explain important values in nearby text. Do not rely on color alone. | Inspect its semantics and check that the chart still makes sense without color. |
| Failure handling | Show a loading, empty, or error state when the data is not ready. | Test empty data, partial data, and a failed fetch. |
| Performance | Summarize or window very large datasets; keep the full history in your data layer. | Profile frame time and interaction latency with representative data. |
