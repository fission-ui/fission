# Build and ship a Fission application.

Follow the same path you’ll use in a real project: run an app, understand its state and rendering model, add useful product work, test your targets, and build the artifacts you’ll ship.

## Put an app on screen first

The [Quickstart](/docs/learn/quickstart/) creates a desktop app, shows where the shared product model lives, and explains each command before adding another target.

- [Open the Quickstart](/docs/learn/quickstart/)
- [Understand the application model](/docs/learn/overview/)

## A route through the documentation

Each stage should leave you with something concrete to run, inspect, or verify.

| Stage | What you will accomplish | Evidence |
| --- | --- | --- |
| Start | [Create the project and run it](/docs/learn/quickstart/) | Working window |
| Learn | [Understand where behaviour belongs](/docs/learn/runtime-model/) | Explainable flow |
| Build | [Add a real product workflow](/docs/guides/layout-and-widgets/) | Useful behaviour |
| Verify | [Test shared logic and target boundaries](/docs/test-and-debug/overview/) | Reproducible evidence |
| Ship | [Build the artifact customers receive](/docs/release-and-distribute/overview/) | Qualified artifact |

## Find guidance by the work in front of you

You don’t need to read the documentation front to back. Start with the job you’re trying to do.

### Build an interface

Start with the [layout and widgets guide](/docs/guides/layout-and-widgets/), then add [responsive behaviour](/docs/learn/responsive-ui/) and a typed [design system](/docs/guides/design-system/).

### Manage application state

Read [state, handles, and providers](/docs/guides/state-handles-and-providers/) to decide who owns each value. Use [resources and async](/docs/guides/resources-and-async/) for work that shouldn’t happen during component conversion.

### Add platform behaviour

Check the [capability matrix](/docs/capabilities/matrix/) first. The target shell is where platform-specific lifecycle, input, accessibility, and delivery behaviour belongs.

### Diagnose and ship

Use [testing and diagnostics](/docs/guides/testing-and-diagnostics/) as you develop, then follow [build and package](/docs/build-and-package/overview/) and the [release checklist](/docs/release-and-distribute/app-release-checklist/) to ship it.
