# Local publishing

Use local publishing to establish the release path on your machine before
turning it into unattended CI. The guided interface gathers missing decisions;
it still produces the same package manifest and provider receipt as the
direct commands.

For example, with a configured Play provider:

```console
fission publish --project-dir . --provider play-store
```

Work through the flow in this order:

- run preflight checks,
- show required and recommended release metadata,
- let the developer enter paths to signing and provider files,
- write stable non-secret settings to `fission.toml`,
- keep secrets in environment variables or local files outside the repository,
- build the app,
- capture or validate screenshots,
- upload to the selected provider,
- show provider receipts and next actions.

Use the local flow to prove the release process. Once it works, put the same non-interactive steps in CI.

Review the selected track, package identity, version/build, and artifact before
authorising upload. Keep credentials in the protected local release area or
environment; a convenient wizard does not make them suitable project files.
