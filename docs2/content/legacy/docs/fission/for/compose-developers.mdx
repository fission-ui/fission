# Fission for Compose developers

The two uses of “Compose” name different APIs. Jetpack Compose describes Android
interfaces with Kotlin composables. Fission Compose is Rust authoring syntax
which generates Fission components, retained state and reducer bindings. A
similar-looking widget tree does not imply the same execution model.

The useful comparison is ownership: who holds a value, where it changes, and
what happens when a request finishes. The excerpts below show those boundaries.
For a complete task app rather than another partial implementation, follow
[Build a single-page Web app in Rust](/blog/build-a-single-page-web-app-in-rust/).

## The state ownership rule

A remembered filter belongs to one list. Task records belong to the application
when detail screens, persistence or progress summaries need them too.

- `props { ... }` declares inputs supplied by the parent.
- `state { ... }` declares retained interface memory for one component identity.
- `GlobalState` holds shared product data.
- `reduce` changes state synchronously; an `effect` requests asynchronous work.
- Theme and locale live in `Env` rather than in each task record.

The lower-level `#[with_local_state]` and `#[local_state]` attributes still
exist. Compose generates their wiring from its `state` section.

## 1. Static UI

A Kotlin composable can receive a title directly:

```kotlin
@Composable
fun ChecklistTitle(title: String) {
    Text(title, style = MaterialTheme.typography.headlineMedium)
}
```

The Fission counterpart declares a typed prop and reads the active typography:

```rust
use fission::prelude::*;

fission_component! {
    pub ChecklistTitle<()> {
        props { title: String }
    }
    view(heading, _state, cx) {
        let tokens = &cx.view.env().theme.tokens;
    } =>
    Text(heading.title.clone())
        .size(tokens.typography.heading1_size)
}
```

A parent passes a translated title. The component does not create fixture
records or start a request while describing that text.

## 2. Product state and interaction

`remember` is useful for a local interaction value. In Fission the equivalent
lifetime is a component `state` field, but changes still use reducer dispatch:

```rust
fission_component! {
    pub TaskFilter<()> {
        state { query: String = String::new() }
    }
    view(filter, _state, cx) =>
    TextInput(
        label: Some(cx.tr("tasks.filter").into()),
        bind: filter.query,
        semantics_identifier: Some("tasks.filter".into()),
    )
}
```

That demonstrates editing ownership only. A real list reads `query` to derive
its visible rows; it does not overwrite the authoritative task collection with
the filtered subset. If another screen must share the filter, move it to app
state rather than keep two copies.

For shared task data, a row receives an ID and a view snapshot, then resolves
the current record when the event runs:

```rust
fission_component! {
    pub TaskRow<TaskState> {
        props {
            id: u64,
            title: String,
            done: bool,
        }
    }
    view(row, state, _cx) =>
    Checkbox(
        label: Some(row.title.clone()),
        checked: row.done,
        key: "toggle-task",
        on_toggle: reduce {
            if let Some(task) = state.tasks.iter_mut().find(|task| task.id == row.id) {
                task.done = !task.done;
            }
        },
    )
}
```

Here `TaskState` implements `GlobalState` and owns `tasks`; each record has
`id`, `title` and `done` fields. Repeated callers use `TaskRow(..., key: task.id)`.
The reducer does not keep a borrowed iterator value after the view has finished.

## 3. Outside work

A `LaunchedEffect` body is not a reason to perform I/O while converting a
Fission component. Conversion can run again for unrelated state changes.
Hydrate app-owned data once through a startup action and a job or resource.
Use component `effect` syntax for user-requested work with that component's
lifetime:

```rust
Button(
    child: Text(cx.tr("tasks.reload")),
    key: "reload-tasks",
    disabled: state.loading,
    on_press: effect fetch_tasks(panel.endpoint.clone()) {
        on_start {
            state.loading = true;
            state.error = None;
        }
        on_ok(tasks) {
            state.tasks = tasks;
            state.loading = false;
        }
        on_err(error) {
            state.error = Some(error);
            state.loading = false;
        }
    },
)
```

This is an excerpt from a component with an `endpoint: String` prop.
`fetch_tasks` is an async `#[fission_effect]` function taking an owned URL and
returning `Result<Vec<Task>, String>`. The app owns `loading`, `error` and `tasks`.
Render a `Spinner` while loading and an `Alert` on error; do not hide either
outcome in an unobserved future.

Reload replaces the list. Disable edits during that operation or use an
operation/generation check before applying a response which could overwrite a
newer edit. A request which must finish after this panel unmounts belongs in an
app-owned job or resource. See [Compose effects](/compose/) and
[Resources and async](/docs/guides/resources-and-async/).

## 4. Styling and theme

`MaterialTheme` and Fission's generated design system both centralise visual
decisions. Fission exposes its active values through
`cx.view.env().theme.tokens`. Use them for spacing, typography, surfaces and
radii rather than copying Kotlin `dp` literals into every Rust component.

```rust
Container(ChecklistTitle(cx.tr("tasks.title")))
    .bg(tokens.colors.surface)
    .padding_all(tokens.spacing.m)
    .border_radius(tokens.radii.medium)
```

This view excerpt assumes `tokens` was read in the setup block. The design
system belongs to app startup; a reusable widget consumes it, rather than
parsing DSP files or choosing a separate theme.

## 5. Routing

`NavHost` chooses a destination. Fission's native `Router` matches app-owned
route state and lazily builds its matching component:

```rust
fission_component! {
    pub ChecklistRoutes<TaskState>
    view(_routes, state, _cx) =>
    Router::<TaskState>::new()
        .with_path(state.current_path.clone())
        .route_component("/", TaskScreen)
        .route_component("/tasks/:id", TaskDetailRoute)
}
```

The shell's route handler keeps `current_path` synchronized with navigation.
`TaskDetailRoute` reads `RouteParams` and validates the raw string ID. A missing
or malformed ID is not task zero. Use
[ProtectedRoute](/reference/widgets/protected-route/) when a component must not
be constructed until an access prerequisite is resolved; backend authorization
remains a separate requirement.

## 6. Testing

Keep the semantic-testing instinct from Compose, but distinguish what each test
establishes. A pure transition test checks a state rule. A headless
`TestHarness` checks widgets and semantics. `LiveTestClient` and manual `/cmd`
requests drive input, focus and screenshots in the actual shell.

Use stable semantic identifiers for controls such as `tasks.filter` so a
translation does not break the test selector. Test on an Android emulator and
a physical phone where hardware or permission behaviour matters; a browser
preview does not qualify those paths.

## Vocabulary map

| Compose concept | Closest Fission concept | Important difference |
| --- | --- | --- |
| `@Composable` | `fission_component!` and `view(...)` | The view is not a suspending Kotlin composable or a Rust closure. |
| `remember` | `state { ... }` | Retained by widget identity, changed through reducers. |
| `ViewModel` state | `GlobalState` | Shared ownership is explicit; persistence remains separate. |
| `LaunchedEffect` | Effects, jobs and resources | I/O is not started during conversion. |
| `MaterialTheme` | Generated tokens in `Env` | The same declared values lower for each supported target. |
| `NavHost` | Native `Router` | The shell adapts platform history and deep links. |

## Common instincts to adjust

Do not translate all ViewModel state into component-local fields merely because
the UI syntax is concise. Likewise, do not promote every disclosure flag to
global state. Choose the owner from the value's lifetime and readers.

A named `view(component, state, cx)` header defines Compose scopes. It is not a
closure which can capture those handles into an async operation. Pass owned
snapshots to the operation and use current state in its completion reducers.
