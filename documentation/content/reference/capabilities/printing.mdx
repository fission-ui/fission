# PDF printing

`print_pdf` sends a PDF byte buffer or data stream to the active host's print UI or service. Call it from a user action after the app has generated the document. A success result reports what the host accepted or presented; it does not claim that paper was physically printed.

## API

```rust
let request = PrintPdfRequest {
    pdf: FileWriteSource::Stream(generated_pdf),
    job_name: Some("Quarterly report".into()),
    copies: 1,
    page_ranges: Vec::new(),
};
ctx.effects.print_pdf(request)
```

`PrintPdfRequest` defaults to one copy and all pages. Page numbers in `PrintPageRange` are one-based and inclusive. Callbacks receive `PrintPdfResult` or `PrintError`; bind both so the app can report a cancellation or an unsupported host accurately. Persist the original PDF and any app-owned output record before requesting print, because the host print service does not own application document data.

`FileWriteSource::Stream` is one-shot. Current providers buffer the stream before handing the PDF to the platform print API, so large PDFs still use memory proportional to their size.

An app job that generates a large PDF can register its output with `JobCtx::register_data_stream(...)` and return the handle. A reducer can pass that handle to `PrintPdfRequest` as `FileWriteSource::Stream`. On Web, keep the Print action separate from asynchronous PDF generation: the browser must open its print window during the user action, before the provider awaits the stream. Generate or load the PDF first, then let the user press Print.

## Outcomes

| Outcome | Meaning |
| --- | --- |
| `Submitted` | A native print service accepted the job or the Windows registered handler launched. |
| `Presented` | The browser or Android print UI opened; those APIs do not report the user's final choice. |
| `Cancelled` | The iOS sheet reported cancellation or the browser window closed before the PDF loaded. |

`Submitted` and `Presented` do not mean physical printing completed. Print service and stream failures arrive as typed `PrintError` values.

## Platform behavior

| Target | Behavior |
| --- | --- |
| Linux, macOS | Uses CUPS `lp` or `lpr`, including requested copy and page-range settings. |
| Windows | Uses the registered PDF handler's `print` verb. Explicit page/copy overrides are unsupported. |
| Web | Opens a print window before awaiting a stream, then loads the PDF and invokes the browser print UI. The site must be allowed to open popups. |
| Android | Opens the Android `PrintManager` sheet. The current adapter accepts all pages and reports an error if the system requests a filtered range. |
| iOS | Uses `UIPrintInteractionController`, whose completion handler reports submitted, cancelled, or failed outcomes. |
| Static site, SSR browser client | Uses the Web behavior when running in a browser. |
| Terminal, SSR server process | Returns a typed unsupported error. |
